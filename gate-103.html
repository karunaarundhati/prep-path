Decision Trees

A decision tree classifies an item by asking a series of simple questions, each with a yes or no answer, until it reaches a final label. You will learn how a tree is grown by choosing the best question at each step, how entropy, information gain and the Gini index measure a good question, and how pruning stops the tree from memorising noise.

The idea in plain words

Think of the game of twenty questions. One player thinks of an animal, and the other asks yes or no questions to find it. A good first question splits the possibilities roughly in half, such as "Does it live in water?" A poor first question, such as "Is it a cat?", rules out very little. Each answer narrows the search until the guess is certain.

A decision tree works the same way. It is a flowchart. At the top sits a question about one attribute. Each answer leads to another question, until the bottom of the tree gives a final class. For example, a bank might ask "Is income above 50,000?", then "Has the applicant missed payments?", and finally say "approve" or "reject". Trees are easy to read, which is one reason they are popular.

The hard part is choosing the questions. The learning algorithm must decide which attribute to ask about at each node, and where to cut a number if the attribute is continuous. The aim is to make the groups after each question as pure as possible, meaning each group contains mostly one class. For GATE, decision trees appear in the Machine Learning part of the Data Science and AI paper (DA). Typical questions ask you to compute entropy, information gain or Gini index for a split, to pick the best attribute, and to explain pruning. Only arithmetic with logarithms and fractions is needed.

Key terms

Post-pruning

The tree as a sequence of questions

Reading a tree

A tree has a root at the top, branches for each answer, and leaves at the bottom. To classify an item, start at the root, answer the question for that item, follow the matching branch, and repeat until you reach a leaf. The label on the leaf is the prediction.

Here is a small tree for deciding whether to play outside. The question at the root asks about the weather. If it is sunny, the tree asks about wind. If the wind is weak, it says Yes. If the wind is strong, it says No. If it is rainy, it says No. Read the tree from top to bottom, one question at a time, and every item ends in exactly one leaf.

How the tree is grown

The algorithm starts with all the training data at the root. It asks: which single question would separate the classes best? It chooses that attribute, splits the data, and then repeats the same process inside each child node. This is called recursive partitioning, and it stops when a rule says so, as explained later.

Key ideaEach split is a greedy choice. The algorithm picks the best question right now, without looking ahead. This is fast and usually good, though it does not always give the globally best tree.

What makes a question good?

Imagine a node with ten people, six who will play and four who will not. A good question creates two groups that are each mostly one answer. A poor question creates two groups that still look like the original mix. To compare questions, we need a number that measures mixedness. Two common choices are entropy and the Gini index. We study them next.

Question: what is a leaf?

A node at the bottom of the tree with no further question. It gives the predicted class, usually the majority class of the training items that reached it.

Question: why is the choice of question at the root important?

The root split affects every item and every later split. A good first question creates clean groups that are easier to split further, which usually gives a smaller and more accurate tree.

Entropy and information gain

Entropy: how mixed is a group?

Entropy comes from information theory. It measures the average surprise when you draw a random item and read its label. If every item has the same label, there is no surprise, and entropy is 0. If the labels are split evenly, every draw is uncertain, and entropy is at its largest.

H = minus Σ pi log2(pi)

Read it. The sum runs over the classes i. pi is the share of class i in the group. The logarithm base 2 gives an answer in bits. The minus sign makes the result positive, because logarithms of numbers below 1 are negative.

Worked example: entropy of a 3 to 1 group

A group has 3 positive and 1 negative items. The shares are 3/4 and 1/4.

  1. Positive term. p = 0.75. log2(0.75) is about minus 0.415. Multiply: 0.75 × (minus 0.415) = minus 0.311.
  2. Negative term. p = 0.25. log2(0.25) = minus 2. Multiply: 0.25 × (minus 2) = minus 0.5.
  3. Add and negate. The sum is minus 0.311 minus 0.5 = minus 0.811. Negate: H = 0.811 bits.
  4. Check. It lies between 0 (pure) and 1 (even split), as it should.

Information gain: how much did the question help?

Information gain compares the entropy before and after a split. The entropy after the split is the average of the children's entropies, weighted by how many items each child holds.

IG = H(parent) minus Σ (nv/n) H(childv)

Read it. n is the number of items at the parent, and nv is the number of items that answered v. Each child's entropy counts in proportion to its size. A large IG means the split removed a lot of mixedness.

TipInformation gain is always zero or positive for a real split, because a weighted average of entropies cannot exceed the parent's entropy. A negative gain is a sign of an arithmetic error.

Worked example: a split with a clear winner

Consider eight days, each with a Weather value (Sunny or Rain), a Wind value (Weak or Strong) and a label Play (Yes or No). Here are the eight rows.

  2. Split on Weather. Sunny has days 1, 2, 3, 7: two Yes and two No, entropy 1. Rain has days 4, 5, 6, 8: two Yes and two No, entropy 1. Weighted average = (4/8)×1 + (4/8)×1 = 1. IG = 1 minus 1 = 0. Weather tells us nothing.

  4. Choose. The algorithm asks about Wind at the root. Both children are pure, so they become leaves at once.

The code below checks these entropies and gains.

import math
from collections import Counter

rows = [("Sunny", "Weak", "Yes"), ("Sunny", "Strong", "No"), ("Sunny", "Weak", "Yes"),
        ("Rain", "Weak", "Yes"), ("Rain", "Weak", "Yes"), ("Rain", "Strong", "No"),
        ("Sunny", "Strong", "No"), ("Rain", "Strong", "No")]

def entropy(labels):
    n = len(labels)
    return -sum((c / n) * math.log2(c / n) for c in Counter(labels).values())

def gini(labels):
    n = len(labels)
    return 1 - sum((c / n) ** 2 for c in Counter(labels).values())

def info_gain(rows, col):
    labels = [r[-1] for r in rows]
    groups = {}
    for r in rows:
        groups.setdefault(r[col], []).append(r[-1])
    after = sum(len(g) / len(rows) * entropy(g) for g in groups.values())
    return entropy(labels) - after

labels = [r[-1] for r in rows]
print("parent entropy =", round(entropy(labels), 3))
print("parent gini =", round(gini(labels), 3))
print("IG Weather =", round(info_gain(rows, 0), 3))
print("IG Wind =", round(info_gain(rows, 1), 3))

parent gini = 0.5
IG Weather = 0.0

Question: a node has 5 Yes and 5 No. What is its entropy?

1 bit. The shares are 1/2 and 1/2, so each term is 0.5 × minus 1 = minus 0.5, and the sum negated is 1.

Question: can information gain be bigger than the parent's entropy?

No. The children's weighted entropy is never negative, so IG is at most H(parent). Here the maximum is 1 bit, reached by Wind.

Gini index and gain ratio

The Gini index

The Gini index measures the chance of picking two items at random from a group and finding that they have different labels. If a group is pure, that chance is zero. If the group is evenly mixed, the chance is high.

G = 1 minus Σ pi²

Read it. pi is the share of class i. Squaring each share and adding gives the chance that two random draws have the same label. Subtracting from 1 gives the chance they differ.

Worked example: Gini for 9 Yes and 5 No

  1. Shares. 9/14 and 5/14.
  2. Squares. (9/14)² = 81/196 and (5/14)² = 25/196.
  3. Add. 81/196 + 25/196 = 106/196.
  4. Subtract from 1. G = 1 minus 106/196 = 90/196, about 0.459.

For a two-class group, the Gini index is largest at 0.5, when the classes are equal. Like entropy, it is 0 for a pure group. The Gini gain of a split is the parent's Gini minus the weighted average of the children's Gini values. CART, the algorithm behind most tree libraries, uses Gini and makes binary splits, meaning each question has two answers.

Gain ratio and the many-values problem

Information gain has a weakness. An attribute with many distinct values, such as a day identifier, splits the data into many tiny groups. Each tiny group is pure, so the gain looks huge, even though the split is useless for new data.

Consider a day identifier with 8 distinct values, one per training day. Each child has one item, so each child is pure. The gain is the full parent entropy, 1 bit. But the split itself carries information, which we measure as the split information.

SplitInfo = minus Σ (nv/n) log2(nv/n)

For the identifier, each of the 8 groups has share 1/8, so SplitInfo = 8 × (minus (1/8) × log2(1/8)) = 8 × (1/8) × 3 = 3. The gain ratio is IG/SplitInfo = 1/3. Now compare Wind from the earlier table. Its two groups have sizes 4 and 4, so SplitInfo = 1, and the gain ratio is 1/1 = 1. Wind still wins, which is the desired result. C4.5 uses gain ratio for this reason.

AlgorithmMeasureSplit type
ID3Information gain (entropy)Many branches, categorical attributes

GATE loves thisMatch the measure to the algorithm: ID3 uses information gain, C4.5 uses gain ratio, and CART uses the Gini index. Questions often give one algorithm and ask for the matching measure.

Question: what is the Gini index of a 50 to 50 two-class node?

1 minus (0.5² + 0.5²) = 1 minus 0.5 = 0.5.

Question: why does gain ratio divide by split information?

To penalise attributes that split the data into many groups. Those splits look strong because the groups are small and pure, not because the attribute is informative.

Stopping, continuous attributes and pruning

When to stop splitting

If we kept splitting until every leaf was pure, the tree would become huge. The algorithm therefore uses stopping criteria. Common ones are:

  • The node is pure, so there is nothing left to separate.
  • No attributes are left to ask about.
  • The node holds fewer than a minimum number of items.
  • The tree has reached a maximum depth.
  • The best available split improves the impurity by less than a small threshold.

The first three rules are standard. A leaf that is not pure takes the majority class of its items.

Continuous attributes: finding a cut point

An attribute such as temperature is a number, not a category. The tree must choose a threshold, such as "temperature at most 15". The method is simple. Sort the distinct values. Place a candidate threshold halfway between each pair of neighbouring values where the class changes. Compute the gain for each candidate and keep the best.

Example. Temperatures 10, 12, 18 and 20 have labels No, No, Yes, Yes. The only useful candidate is the midpoint between 12 and 18, which is 15. The split "temperature at most 15" sends {10, 12} to No and {18, 20} to Yes. Both children are pure, so IG = 1 bit, the best possible.

TipCandidate thresholds only need to sit between values where the label changes. Testing every number in between wastes effort, because the gain cannot change inside a run of one class.

Overfitting and why trees need pruning

A tree grown until every leaf is pure can memorise the training data, including its noise. Its training accuracy is perfect, but on new data it does badly. This is overfitting. The remedy is pruning, which removes branches that do not help on unseen data.

  • Pre-pruning stops growth early using the stopping rules above. It is fast, but it can stop too soon, before a useful split that appears only after another split.
  • Post-pruning grows the full tree, then examines each subtree. If replacing it with a leaf does not hurt accuracy on a validation set, the subtree is cut. This is usually more reliable, but it costs more time.

TrapPost-pruning must use data the tree did not train on. If you judge pruning on the training data, every cut looks harmful, because the training data always favours the bigger tree.

Question: a tree has 100 percent training accuracy. Is it probably a good tree?

Not necessarily. Perfect training accuracy is a sign of possible overfitting. Check its accuracy on validation or test data.

Question: where should the threshold for temperature go if the labels change between 20 and 24?

At the midpoint, 22. The values on either side of the change are 20 and 24, and the midpoint between them is the natural cut.

Choosing the best split step by step

The procedure

Here is the full routine for one node. It is the same routine repeated at every node.

  1. Count the classes at the node and compute its entropy or Gini index.
  2. For each attribute, list its possible splits. For a continuous attribute, use the candidate thresholds.
  3. For each split, compute the weighted impurity of the children.
  4. Compute the gain for each split. Keep the attribute with the largest gain.
  5. If a stopping rule applies, make a leaf. Otherwise make the chosen attribute the question and repeat for each child.

A worked comparison

A node has 4 Yes and 4 No, so its entropy is 1 bit. Three attributes are available.

Question: which attribute should be asked first in the table above?

C, with the largest gain of about 0.549 bits.

Question: why does attribute B score zero?

Both children have the same mix as the parent, 2 Yes and 2 No, so they carry no more information about the label than the parent did.

Facts about impurity measures (MSQ)

Which statements are true? Select all that apply.

(A) A pure node has entropy 0.

(B) A 50 to 50 two-class node has Gini index 0.5.

(C) For two classes, entropy is largest when the classes are equally common.

(D) Information gain of a valid split can be negative.

How to think about it

  1. What is asked. Which facts about entropy, Gini and gain are correct.
  2. Which idea applies. Pure means one class only. The Gini value for an even split is 1 minus 0.5. Entropy peaks at the even split. Gain is never negative for a real split.
  3. Work it out. (A) is true. (B) is true, 1 minus (0.25 + 0.25) = 0.5. (C) is true. (D) is false.
  4. Check. The only false statement is the one about negative gain, which would require a weighted average above the parent.

Information gain of a split (NAT)

A node has 6 Yes and 2 No. A split creates two children: one with 4 Yes and 0 No, and one with 2 Yes and 2 No. Find the information gain, to three decimal places. (NAT)

How to think about it

  1. What is asked. The gain IG of this split.
  2. Which idea applies. IG = H(parent) minus the weighted average of the children's entropies.
  3. Work it out. Parent: shares 0.75 and 0.25, so H = 0.811. Child 1 is pure, H = 0. Child 2 has shares 0.5 and 0.5, so H = 1. Weights are 4/8 and 4/8. Weighted average = 0.5 × 0 + 0.5 × 1 = 0.5. IG = 0.811 minus 0.5 = 0.311.
  4. Check. The gain is positive and smaller than the parent's entropy, as it should be.

Gini index with three classes (NAT)

A node contains 4 items in total: 2 of class A, 1 of class B and 1 of class C. Find its Gini index. (NAT)

How to think about it

  1. What is asked. The Gini index of a three-class node.
  2. Which idea applies. G = 1 minus Σ pi².
  3. Work it out. The shares are 1/2, 1/4 and 1/4. Squares: 1/4, 1/16 and 1/16. Sum: 4/16 + 1/16 + 1/16 = 6/16. G = 1 minus 6/16 = 10/16 = 0.625.
  4. Check. With three classes the maximum Gini is 2/3, so 0.625 is below it, as expected.

Gain ratio of a wide split (NAT)

A split of 8 items creates four groups of 2 items each. The information gain of this split is 0.5 bits. Find the gain ratio. (NAT)

How to think about it

  1. What is asked. The gain ratio, which is IG divided by split information.
  2. Which idea applies. SplitInfo = minus Σ (nv/n) log2(nv/n).
  3. Work it out. Each group has share 2/8 = 1/4. Each term is 1/4 × log2(1/4) = 1/4 × (minus 2) = minus 0.5. Four such terms give SplitInfo = 2. Gain ratio = 0.5/2 = 0.25.
  4. Check. The gain ratio is smaller than the raw gain, which is the penalty for many groups working as intended.

Exam-level 1: Information gain of attribute A (NAT, 2 marks)

A decision tree node holds 10 training examples: 6 are yes and 4 are no. Attribute A splits them into a left group with 4 yes and 0 no, and a right group with 2 yes and 4 no. Use entropy, H = minus the sum of p times log base 2 of p, over the classes. Find the information gain of attribute A, which is the parent entropy minus the weighted average of the child entropies. Give the answer to three decimal places. (NAT)

How to think about it

  1. What is asked. The information gain of one split, to three decimals.
  2. Which idea applies. Entropy of each group, weighted by the group size, subtracted from the parent entropy.
  3. Work it out. Parent: p = 0.6 and 0.4, so H = minus (0.6 log2 0.6 + 0.4 log2 0.4) = 0.971. Left group is pure, so its entropy is 0. Right group has p = 1/3 and 2/3, so H = 0.918. Weighted average = 0.4 times 0 + 0.6 times 0.918 = 0.551. Gain = 0.971 minus 0.551 = 0.420.
  4. Check. The gain is positive, and it cannot exceed the parent entropy 0.971. A pure left group is a strong sign of a good split.

Answer: 0.420

Exam-level 3: Gini gain of attribute B (NAT, 2 marks)

The same 10 training examples, with 6 yes and 4 no, are split by attribute B into a left group with 3 yes and 1 no, and a right group with 3 yes and 3 no. The Gini index of a node is 1 minus the sum of the squared class proportions. The Gini gain of a split is the parent Gini minus the weighted average of the child Gini values. Find the Gini gain of attribute B to three decimal places. (NAT)

How to think about it

  1. What is asked. The Gini gain of attribute B only.
  2. Which idea applies. Compute the Gini of the parent and of each child, then weight the children by their sizes.
  3. Work it out. Parent Gini = 1 minus (0.6 squared plus 0.4 squared) = 1 minus 0.52 = 0.48. Left group (3 yes, 1 no): 1 minus (0.75 squared plus 0.25 squared) = 1 minus 0.625 = 0.375. Exam-level 4: Cost complexity pruning break-even (NAT, 2 marks)

A decision tree is pruned with cost complexity pruning. The cost of a tree is its number of training errors plus alpha times its number of leaves. A subtree has two leaves with 1 and 2 training errors, so it makes 3 errors in total. Replacing the subtree with one single leaf gives 4 training errors. Find the value of alpha at which the subtree and the single leaf have equal cost. (NAT)

How to think about it

  1. What is asked. The break-even value of alpha.
  2. Which idea applies. Write the cost of each option as errors plus alpha times leaves, then set the two costs equal.
  3. Work it out. Subtree cost = 3 plus 2 alpha, since it has 2 leaves. Single leaf cost = 4 plus 1 alpha. Setting them equal gives 3 plus 2 alpha = 4 plus alpha, so alpha = 1.
  4. Check. At alpha = 0.5 the subtree costs 4.0 and the leaf costs 4.5, so the subtree is kept. At alpha = 2 the subtree costs 7.0 and the leaf costs 6.0, so pruning wins. The break-even at 1 sits between these.

Answer: 1

import math

# Exam-level 1: entropy and information gain of attribute A
def H(pos, neg):
    n = pos + neg
    h = 0.0
    for c in (pos, neg):
        if c:
            p = c / n
            h = h - p * math.log2(p)
    return h
parent = H(6, 4)
gain_a = parent - (4 / 10 * H(4, 0) + 6 / 10 * H(2, 4))
print(f"E1 parent entropy = {parent:.3f}  right entropy = {H(2, 4):.3f}  information gain = {gain_a:.3f}")

# Exam-level 2: Gini facts
def gini(pos, neg):
    n = pos + neg
    return 1 - (pos / n) ** 2 - (neg / n) ** 2
print("E2 gini of pure node =", gini(5, 0))
print(f"E2 gini of 3 yes and 1 no = {gini(3, 1):.4f}")

# Exam-level 3: Gini gain of attribute B
parent_g = gini(6, 4)
gain_b = parent_g - (4 / 10 * gini(3, 1) + 6 / 10 * gini(3, 3))
print(f"E3 parent gini = {parent_g:.3f}  gini gain of B = {gain_b:.3f}")

# Exam-level 4: cost complexity pruning break-even
def subtree_cost(alpha):
    return 3 + alpha * 2
def pruned_cost(alpha):
    return 4 + alpha * 1
for a in (0.5, 1, 2):
    print(f"E4 alpha = {a}: subtree cost {subtree_cost(a):.1f}, pruned cost {pruned_cost(a):.1f}")

Summary

Here is every key term in one line each.

Decision tree
A flowchart of yes or no questions that ends in a class label at each leaf.
Root, node and leaf
The top question, any question in between, and the final label at the bottom.
Split
Dividing the data at a node by the answer to one question.
Pure node
A node whose items all share one class.
Entropy
minus Σ p log2 p, the mixedness of a group in bits.
Information gain
Parent entropy minus the weighted entropy of the children.
Gini index
1 minus Σ p², the chance two random items have different labels.
Split information
The entropy of the group sizes produced by a split.
Gain ratio
Information gain divided by split information, which penalises many-valued attributes.
ID3, C4.5, CART
Tree algorithms that use information gain, gain ratio and Gini respectively.
Recursive partitioning
Repeating the split process inside each child until a stopping rule applies.
Candidate threshold
A cut point between two neighbouring values where the class changes.
Overfitting
Learning the noise in training data, which hurts performance on new data.
Pre-pruning
Stopping growth early using a rule set in advance.
Post-pruning
Cutting back a full tree using validation data.

Remember these

  • A good split creates children that are purer than the parent.
  • Entropy is 0 for a pure node and 1 bit for an even two-class split.
  • Information gain is the drop in entropy caused by a split.
  • ID3 uses information gain, C4.5 uses gain ratio, and CART uses Gini.
  • Gain ratio penalises attributes that split the data into many small groups.
  • Continuous attributes are cut at midpoints where the class changes.
  • Prune with validation data to avoid overfitting.
