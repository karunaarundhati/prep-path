Normal forms (1NF-BCNF)

Normalization is the careful design of tables so that the same fact is stored only once. This topic explains functional dependencies, keys, the normal forms from 1NF to BCNF, and how to split a table safely.

The idea in plain words

Suppose you keep a list of students in a notebook. For every course a student takes, you write the student's name, department and phone number on that line. A student who takes five courses has the same name, department and phone number written five times.

Now the student changes phone number. You must find all five lines and change each one. If you miss one line, the notebook now disagrees with itself. This is the core problem that normalization solves. Normalization is the process of designing tables so that each fact is written in one place only.

GATE questions usually give a relation and its dependencies, then ask for the keys, the highest normal form, or a safe decomposition. The method is mechanical once you know the steps.

We will use one running example. Here is a table that stores enrolments with student details repeated on each row.

Key ideaNormalization is a way of finding and removing repeated facts. The rules tell you which facts depend on which, and the table is split so that each fact lives in one place.

Key terms

Redundancy
Storing the same fact more than once. Plain meaning: writing the same thing in two places.
Anomaly
A problem caused by redundancy or poor design. There are three kinds: update, insertion and deletion anomalies.
Functional dependency (FD)
A rule X → Y that says: if two rows agree on X, they must agree on Y. Plain meaning: X decides Y.
Trivial FD
An FD whose right side is a subset of its left side, such as AB → A. It always holds, so it tells you nothing new.
Armstrong's axioms
Three rules for deriving new FDs: reflexivity, augmentation and transitivity.
Attribute closure X+
All attributes that are determined by X. Plain meaning: everything X can tell you.
Superkey
A set of attributes whose closure is all attributes. Plain meaning: enough columns to identify each row.
Candidate key
A minimal superkey. Minimal means that no smaller set of its attributes is also a superkey.
Prime attribute
An attribute that belongs to at least one candidate key.
Nonprime attribute
An attribute that belongs to no candidate key.
Partial dependency
A nonprime attribute depends on part of a candidate key, not on the whole key.
Transitive dependency
A nonprime attribute depends on another nonprime attribute, which depends on the key. Plain meaning: a chain of two steps.
Normal form
A rule that a table must satisfy to avoid a certain kind of problem. The forms are 1NF, 2NF, 3NF and BCNF.
Decomposition
Splitting one table into several smaller tables. Plain meaning: cutting a table into pieces.
Lossless join
A decomposition where joining the pieces gives back exactly the original table, with no extra rows.
Dependency preservation
A decomposition where every original FD can still be checked inside one of the pieces.

Concept 1: Why normalization: redundancy and anomalies

Three kinds of trouble

Look again at Enrol_Full. The name and dept of Asha appear twice, and the same is true of Meena. This repetition causes three kinds of anomaly:

  • Update anomaly. If Asha changes dept, we must change both rows. If we change only one, the table contradicts itself.
  • Insertion anomaly. We cannot store a new student who has no course yet, because there is no cid to put in the row. We would need a fake cid or a NULL.
  • Deletion anomaly. If Ravi drops his only course and we delete that row, we lose Ravi's name and dept completely.

Normalization removes these anomalies by splitting the table, so student facts and enrolment facts each have their own table.

Question: Why is an insertion anomaly a problem for a new student who has no course yet?

In the single table, every row must include a cid and a grade. A student with no course cannot be stored without inventing values or using NULL in key columns.

Question: Which anomaly occurs when deleting Ravi's only enrolment also removes Ravi from the database?

The deletion anomaly. The student facts were stored only in the enrolment rows, so removing those rows removes the facts too.

Concept 2: Functional dependencies, Armstrong's axioms and closure

What X → Y means

A functional dependency is a rule about the data that must always hold. Read X → Y as "X functionally determines Y". Here is the meaning, in two steps:

  1. Take any two rows of the table.
  2. If the two rows have the same values on X, they must also have the same values on Y.

In Enrol_Full, sid → name holds, because each sid has one name. But cid alone does not determine grade, because CS101 has grade 9 for Asha and 10 for Meena.

TrapAn FD is a rule about the meaning of the data. A small sample can disprove an FD, but it can never prove one. In GATE, the FDs are given to you.

Trivial and nontrivial FDs

An FD is trivial when Y is a subset of X. For example, AB → A is trivial, because if two rows agree on A and B they also agree on A. Trivial FDs add nothing, so when we talk about FDs we mean nontrivial ones.

Armstrong's axioms

Three rules let us derive new FDs from given ones. They are sound (they never give a false FD) and complete (they give every FD that follows).

  • Reflexivity: if Y is a subset of X, then X → Y. Example: AB → A.
  • Augmentation: if X → Y, then XZ → YZ. Example: if A → B, then AC → BC.
  • Transitivity: if X → Y and Y → Z, then X → Z. Example: if A → B and B → C, then A → C.

Attribute closure

The closure X+ is the set of all attributes that X determines, using the given FDs and Armstrong's axioms. We compute it by a simple loop:

  1. Start with X+ equal to X.
  2. Look for an FD L → R in the given set where L is inside X+ and R is not yet inside X+.
  3. Add R to X+. Repeat step 2 until nothing new is added.

Example. Let R = (A, B, C, D) with F1 = {A → B, B → C}. Compute A+:

  • Start: A+ = {A}.
  • A → B applies, because A is in A+. Add B. Now A+ = {A, B}.
  • B → C applies, because B is in A+. Add C. Now A+ = {A, B, C}.
  • No more FDs add anything. So A+ = ABC. D is not determined by A.

The Python program below implements this loop, and checks the closure of AD as well.

from itertools import combinations

def closure(attrs, fds):
    result = set(attrs)
    changed = True
    while changed:
        changed = False
        for lhs, rhs in fds:
            if set(lhs) <= result and not set(rhs) <= result:
                result |= set(rhs)
                changed = True
    return "".join(sorted(result))

R = "ABCD"
F1 = [("A", "B"), ("B", "C")]
print("A+ =", closure("A", F1))
print("AD+ =", closure("AD", F1))
print("B+ =", closure("B", F1))

Question: Using transitivity, why does A → C follow from A → B and B → C?

Because A determines B, and B determines C. Any two rows that agree on A agree on B, and then they agree on C.

Question: Is AB → A a trivial FD?

Yes. A is a subset of AB, so it is trivial under reflexivity.

Concept 3: Candidate keys and the normal forms

Superkeys and candidate keys

A superkey is a set of attributes whose closure is all attributes of R. It identifies every row. A candidate key is a minimal superkey: remove any attribute and it stops being a superkey.

For R = (A, B, C, D) with F1, the closure of A is ABC, which lacks D. So A is not a key. The closure of AD is ABCD, which is everything. Removing A leaves D, whose closure is just D. Removing D leaves A, which is not enough. So AD is a candidate key, and it is the only one.

Once keys are known, we split attributes into two groups. Attributes that appear in some candidate key are prime. The rest are nonprime. Here, A and D are prime, and B and C are nonprime.

1NF: atomic values

A table is in first normal form (1NF) when every cell holds a single atomic value. A cell that holds a list of phone numbers, such as "9876, 9123", breaks 1NF. Most modern database designs assume 1NF from the start, so GATE questions on 1NF are usually simple.

2NF: no partial dependency

A table is in second normal form (2NF) when it is in 1NF and no nonprime attribute depends on part of a candidate key. This matters only when a key has two or more attributes.

Example with R = (A, B, C, D), F1, key AD. The FD A → B says that the nonprime B depends on A, which is only part of the key AD. This is a partial dependency. So R is not in 2NF.

3NF: no transitive dependency

A table is in third normal form (3NF) when, for every nontrivial FD X → Y, at least one of these holds:

  • X is a superkey, or
  • every attribute of Y is prime.

In R with F1: the FD B → C has B as a non-superkey (B+ = BC) and C as nonprime. So 3NF fails. C depends on B, and B depends on A: this is a transitive dependency through a nonprime attribute.

BCNF: the strict rule

Boyce-Codd normal form (BCNF) is stricter than 3NF. A table is in BCNF when, for every nontrivial FD X → Y, X is a superkey. There is no exception for prime attributes.

R with F1 fails BCNF in two places: A → B (A is not a superkey) and B → C (B is not a superkey). BCNF is the normal form most GATE questions ask for.

Key ideaThe normal forms form a ladder: every BCNF table is in 3NF, every 3NF table is in 2NF, and every 2NF table is in 1NF. Each rung removes one kind of dependency.

GATE loves thisTo find the highest normal form, check in this order: BCNF first. If it fails, check 3NF. Then 2NF, then 1NF. Stop at the first form that holds, because the forms are nested.

Question: In a table with key AB and FD C → B, why might 3NF hold while BCNF fails?

In 3NF, the right side B is prime if B is part of some key. If B is prime, the FD C → B is allowed by 3NF even though C is not a superkey. BCNF does not allow exceptions, so it fails.

Question: Is a table in BCNF always in 2NF?

Yes. BCNF is stricter than 2NF, and the normal forms are nested. A table that passes BCNF also passes 3NF, 2NF and 1NF.

Concept 4: Decomposition, lossless join and dependency preservation

Why decomposition needs care

To reach BCNF we split tables. A good split keeps two properties.

  • Lossless join. When we join the pieces again, we get back exactly the original rows, with no extra and no missing rows.
  • Dependency preservation. Every original FD can still be checked inside one of the pieces, without a costly join.

Lossless join with a common attribute

When a table R is split into two pieces R1 and R2, the split is lossless if the common attributes R1 ∩ R2 form a key of R1 or of R2. In words: the shared column must determine one of the pieces completely. A quick check uses the FDs: if (R1 ∩ R2) → R1 or (R1 ∩ R2) → R2 follows from F, the split is lossless.

Example. Split R = (A, B, C, D) with F1 into R1 = (B, C) and R2 = (A, B, D). The common attribute is B. B → C is given, so B determines all of R1. The split is lossless.

Counter-example. Split R into (A, B) and (C, D). They share nothing, so joining them pairs every AB row with every CD row. This split is lossy.

The chase test

For more than two pieces, GATE uses the chase. Write one row per piece, with "a" where the piece has the attribute and a unique symbol elsewhere. Apply each FD: when two rows agree on its left side, make them agree on its right side. If some row becomes all "a", the split is lossless. The code below applies this test.

Dependency preservation

If an FD can only be checked by joining two pieces, the database pays for an expensive join on every insert. A dependency preserving split avoids this. The test is a loop: start with the left side of an FD, and keep adding attributes that each piece can determine. If the right side is reached, the FD is preserved.

TrapBCNF decomposition can lose dependencies. Example: R = (A, B, C) with FDs AB → C and C → B. Its keys are AB and AC, and B is prime, so R is in 3NF. But C → B violates BCNF, so we split into (C, B) and (A, C). The FD AB → C is now lost, because A, B and C never sit together in one piece.

This is the reason 3NF exists. A 3NF decomposition always keeps dependencies, while a BCNF decomposition may not. GATE questions often ask you to pick the correct statement about this trade-off.

from itertools import combinations

def closure(attrs, fds):
    result = set(attrs)
    changed = True
    while changed:
        changed = False
        for lhs, rhs in fds:
            if set(lhs) <= result and not set(rhs) <= result:
                result |= set(rhs)
                changed = True
    return "".join(sorted(result))

def lossless(attributes, fds, decomposition):
    cols = list(attributes)
    rows = [[("a", c) if c in frag else ("b", r, c) for c in cols]
            for r, frag in enumerate(decomposition)]
    changed = True
    while changed:
        changed = False
        for lhs, rhs in fds:
            li = [cols.index(x) for x in lhs]
            for r1 in rows:
                for r2 in rows:
                    if all(r1[i] == r2[i] for i in li):
                        for y in rhs:
                            k = cols.index(y)
                            if r1[k] != r2[k]:
                                new, old = min(r1[k], r2[k]), max(r1[k], r2[k])
                                for row in rows:
                                    for j in range(len(cols)):
                                        if row[j] == old:
                                            row[j] = new
                                changed = True
    return any(all(cell == ("a", c) for cell, c in zip(row, cols)) for row in rows)

def dependency_preserved(fds, decomposition):
    for lhs, rhs in fds:
        z = set(lhs)
        changed = True
        while changed:
            changed = False
            for frag in decomposition:
                new = set(closure(z & set(frag), fds)) & set(frag)
                if not new <= z:
                    z |= new
                    changed = True
        if not set(rhs) <= z:
            return False
    return True

R = "ABCD"
F1 = [("A", "B"), ("B", "C")]
print("BC and ABD lossless:", lossless(R, F1, [("B", "C"), ("A", "B", "D")]))
print("AB and CD lossless:", lossless(R, F1, [("A", "B"), ("C", "D")]))
print("BC and ABD preserves F1:", dependency_preserved(F1, [("B", "C"), ("A", "B", "D")]))

F3 = [("AB", "C"), ("C", "B")]
print("CB and AC lossless:", lossless("ABC", F3, [("C", "B"), ("A", "C")]))
print("CB and AC preserves all FDs:", dependency_preserved(F3, [("C", "B"), ("A", "C")]))

AB and CD lossless: False
BC and ABD preserves F1: True

Question: Why is the split of R into (A, B) and (C, D) lossy?

The two pieces share no attribute, so joining them pairs every row of one with every row of the other. The result has extra rows that were not in R.

Question: Which dependency is lost when (A, B, C) with AB → C and C → B is split into (C, B) and (A, C)?

AB → C. No piece contains A, B and C together, so the FD cannot be checked inside a single piece.

Concept 5: Normalizing a relation step by step

The algorithm

The usual BCNF procedure for a relation R with FDs F is:

  1. Find the candidate keys of R.
  2. Check BCNF: for each nontrivial FD X → Y in F, is X a superkey? If yes for all, R is in BCNF and we stop.
  3. If some FD X → Y violates BCNF, split R into R1 = X ∪ Y and R2 = R minus (Y without X).
  4. Repeat the procedure on R1 and R2, with the FDs that apply to each piece.

Worked example

Take R = (A, B, C, D) with F1 = {A → B, B → C}.

  1. Keys. The only candidate key is AD, found in Concept 3.
  2. Highest form. A → B fails 2NF, because A is part of the key AD and B is nonprime. So R is only in 1NF.
  3. Split on B → C. B is not a superkey. Split into R1 = (B, C) and R2 = (A, B, D). The FD B → C goes to R1, and the remaining FD A → B goes to R2.
  4. Check R1 = (B, C). Its only FD is B → C, and B is its key. R1 is in BCNF.
  5. Check R2 = (A, B, D). Its key is AD, and the FD A → B has A that is not a superkey. Split on A → B into R21 = (A, B) and R22 = (A, D).
  6. Check the pieces. R21 = (A, B) has key A, so it is in BCNF. R22 = (A, D) has only trivial FDs, so it is in BCNF.

The final decomposition is (B, C), (A, B) and (A, D). The Python program checked earlier shows that the first split is lossless and preserves the FDs.

Solved GATE-style problems

These problems are original, written in the GATE style. They are not past exam questions.

Closure of a chain

For R(P, Q, R, S) with FDs P → Q, Q → R and R → S, find P+.

How to think about it

  1. What is asked. Everything P determines.
  2. Which idea applies. Start with P, then apply each FD whose left side is already in the set.
  3. Work it out. Start: {P}. P → Q adds Q, giving {P, Q}. Q → R adds R, giving {P, Q, R}. R → S adds S, giving {P, Q, R, S}.
  4. Check. The closure has all four attributes, so P is a superkey.

Answer: PQRS. P is a superkey of R.

A cell with two values

A table stores, in one cell, a list of two phone numbers for each student. Which is the highest normal form that this table satisfies?

How to think about it

  1. What is asked. The highest normal form that holds.
  2. Which idea applies. 1NF requires every cell to hold a single atomic value.
  3. Work it out. A cell with a list is not atomic, so 1NF fails. Higher forms are defined only for tables that are already in 1NF.

Answer: none. The table is not even in 1NF.

Keys and normal form check

Select all that apply. For R(A, B, C, D) with FDs A → B and B → C:

(A) AD is a candidate key.

(B) A is a candidate key.

(C) R is in BCNF.

(D) R is in 1NF.

How to think about it

  1. What is asked. Which statements are true.
  2. Which idea applies. Compute closures, then test the normal forms.
  3. Work it out. A+ = ABC, which lacks D, so A is not a key. AD+ = ABCD, and neither A nor D alone is a key, so AD is the candidate key. (A) is true, (B) is false. Since B → C has a non-superkey on the left, R is not in BCNF, so (C) is false. All cells are atomic, so R is in 1NF, and (D) is true.

Answer: (A) and (D).

Counting candidate keys

How many candidate keys does R(A, B, C) have with FDs AB → C and C → B? Give a whole number.

How to think about it

  1. What is asked. The number of minimal superkeys.
  2. Which idea applies. Test the closure of each small set.
  3. Work it out. A+ = A, B+ = B, C+ = BC. None is all of ABC. AB+ = ABC, so AB is a key. AC+ = ABC (C gives B), so AC is a key. BC+ = BC, not a key.
  4. Check. Two keys, AB and AC, and neither contains the other.

Answer: 2.

Is the split lossless?

R(A, B, C) has the FD B → A. Is the decomposition into (A, B) and (B, C) lossless? Answer yes or no.

How to think about it

  1. What is asked. Lossless or not.
  2. Which idea applies. For a two-piece split, check whether the common attribute determines one piece.
  3. Work it out. The common attribute is B. The FD B → A says B determines A, so B determines the whole piece (A, B).

Answer: yes.

Number of attributes in the key

R(A, B, C, D, E) has FDs A → B and C → D. How many attributes does its candidate key contain?

How to think about it

  1. What is asked. The size of the candidate key.
  2. Which idea applies. E appears on no right side, so E must be in every key. A and C appear only on left sides, so they must also be in the key.
  3. Work it out. Start with ACE. Its closure is ACE, then A → B adds B, then C → D adds D, giving ABCDE. So ACE is a superkey. Removing any attribute leaves a set whose closure is smaller, so ACE is minimal.

Answer: 3 (the key is ACE).

Which statements about the split are true

Select all that apply. For R(A, B, C) with FDs AB → C and C → B:

(A) The split into (C, B) and (A, C) is lossless.

(B) The split into (C, B) and (A, C) preserves AB → C.

(C) R is in 3NF.

(D) R is in BCNF.

How to think about it

  1. What is asked. Lossless, dependency preservation, and normal forms.
  2. Which idea applies. The common attribute of the split is C, and C → B holds. For preservation, check whether A, B and C ever sit in one piece.
  3. Work it out. (A) C is common, and C → B means C determines (C, B). Lossless. True. (B) No piece contains A, B and C together, so AB → C is lost. False. (C) B is prime, because AB is a key, and C → B has B prime. So 3NF holds. True. (D) C is not a superkey, since C+ = BC, but C → B violates BCNF. False.

Answer: (A) and (C).

Highest normal form of a chain

R(A, B, C, D) has FDs A → B, B → C and C → D. What is the highest normal form that R satisfies? Choose from 1NF, 2NF, 3NF or BCNF.

How to think about it

  1. What is asked. The highest form that holds.
  2. Which idea applies. Find the key, then test the forms from BCNF downward.
  3. Work it out. A+ = ABCD, so A is the only candidate key. BCNF fails, because B → C has B that is not a superkey. 3NF fails, because C is not a superkey and C is nonprime (C → D). 2NF holds, because the key A has only one attribute, so no partial dependency is possible.
  4. Check. The forms are nested, so 2NF is the answer once BCNF and 3NF are ruled out.

Answer: 2NF.

Exam-level 1: counting candidate keys (NAT, 2 marks)

Relation R(A, B, C, D) has the functional dependencies AB → C, C → D and D → A. A candidate key is a minimal set of attributes whose closure contains all four attributes. Use attribute closure to test each set of attributes, starting from single attributes. Remember that a key must be minimal, so a set that contains a smaller key is not a candidate key. How many candidate keys does R have?

How to think about it

  1. What is asked. The number of minimal keys.
  2. Which idea applies. The attribute closure X+ shows everything X determines. X is a superkey when X+ contains all of ABCD.
  3. Work it out. AB+ gives C, then D, so ABCD: AB is a key. BC+ gives D, then A, so BC is a key. BD+ gives A, then C, so BD is a key. A+, C+, D+, AC+, AD+ and CD+ never reach B, so none of them is a key.
  4. Check. No single attribute is a key, and any three-attribute set without B fails. The three pairs are the only minimal keys, so the count is 3.

Answer: 3 (AB, BC and BD).

attrs='ABCD'
fds=[('AB','C'),('C','D'),('D','A')]

    changed=True

        changed=False
        for l,r in fds:
            if set(l).issubset(res) and not set(r).issubset(res):
                res|=set(r); changed=True
    return res

Exam-level 2: highest normal form (MCQ, 2 marks)

Relation R(A, B, C, D, E) has the functional dependencies A → B, B → C, C → D and D → E. Which is the highest normal form that R satisfies? Find the candidate keys first, test each form in order from the top down, and then choose one.

(A) 1NF

(B) 2NF

(C) 3NF

(D) BCNF

How to think about it

  1. What is asked. The highest normal form that R satisfies.
  2. Which idea applies. Find the candidate keys first, then test BCNF, then 3NF, then 2NF.
  3. Work it out. A+ = ABCDE, so A is the only candidate key. B → C has a left side that is not a superkey, so BCNF fails. For 3NF, C is not prime (it is in no key), so B → C breaks 3NF too. The key has one attribute, so there is no partial dependency and 2NF holds.
  4. Check. The chain A → B → C → D → E is a transitive dependency, which is exactly what 3NF forbids.

Answer: (B) 2NF.

Exam-level 3: closure size under functional dependencies (NAT, 2 marks)

Relation R(A, B, C, D, E, F) has the functional dependencies AB → C, C → D, D → B and E → F. Start from the set {A, B} and repeatedly apply any dependency whose left side is already inside the set, adding its right side. How many attributes are in the closure of {A, B}?

How to think about it

  1. What is asked. The size of the closure {A, B}+.
  2. Which idea applies. Attribute closure: keep adding the right side of any dependency whose left side is covered, until nothing changes.
  3. Work it out. Start with A and B. AB → C adds C. C → D adds D. D → B adds nothing new, since B is already there. E → F never fires, because E is not in the set.
  4. Check. The closure is {A, B, C, D}, which has 4 attributes. E and F cannot be reached.

Answer: 4 (A, B, C and D).

fds=[('AB','C'),('C','D'),('D','B'),('E','F')]
def closure(X):
    res=set(X)
    changed=True
    while changed:
        changed=False
        for l,r in fds:
            if set(l).issubset(res) and not set(r).issubset(res):
                res|=set(r); changed=True
    return res
c=closure('AB')
print(sorted(c))
print(len(c))

Exam-level 4: lossless-join splits (MSQ, 2 marks)

Relation R(A, B, C, D) has the functional dependencies A → B and B → C. Each option splits R into two relations. A split is lossless-join when joining the two parts gives back exactly R for every legal instance. Select all that apply.

(A) R1(A, B) and R2(A, C, D)

(B) R1(A, B, C) and R2(C, D)

(C) R1(B, C) and R2(A, D)

(D) R1(A, B, D) and R2(C, D)

How to think about it

  1. What is asked. Which splits are lossless.
  2. Which idea applies. For a split into two parts, the test is Heath's rule: the attributes the two parts share must determine all of one part.
  3. Work it out. (A) shares A, and A+ = ABC contains all of R1 = AB, so it is lossless. (B) shares C, and C+ = C contains neither ABC nor CD, so it is lossy. (C) shares nothing, so nothing determines either part, which makes it lossy. (D) shares D, and D+ = D contains neither part, so it is lossy.
  4. Check. Only option (A) has a shared attribute that determines a whole part.

Answer: (A) only.

fds=[('A','B'),('B','C')]

    return res

for name,(r1,r2) in options.items():

Summary

Redundancy
Storing the same fact more than once.
Update anomaly
A change must be made in many rows, and one may be missed.
Insertion anomaly
A fact cannot be stored without an unrelated value.
Deletion anomaly
Removing one fact also removes another, unrelated fact.
Functional dependency
X → Y: rows agreeing on X must agree on Y.
Armstrong's axioms
Reflexivity, augmentation and transitivity for deriving FDs.
Attribute closure
X+, all attributes determined by X.
Superkey
A set whose closure is all attributes.
Candidate key
A minimal superkey.
Prime attribute
Belongs to at least one candidate key.
Nonprime attribute
Belongs to no candidate key.
1NF
Every cell holds one atomic value.
2NF
No nonprime attribute depends on part of a candidate key.
3NF
For each X → A, X is a superkey or A is prime.
BCNF
For each nontrivial X → A, X is a superkey.
Decomposition
Splitting a table into smaller tables.
Lossless join
Joining the pieces gives back exactly the original rows.
Dependency preservation
Every original FD can be checked inside one piece.

Remember these

  1. Compute closures to find keys. A set is a key when its closure is all attributes and no smaller subset is.
  2. Check normal forms from BCNF downward. The first form that holds is the answer.
  3. In BCNF, every left side of an FD must be a superkey, with no exceptions.
  4. A split is lossless when the common attributes determine one of the pieces.
  5. BCNF can lose dependencies. 3NF always keeps them.
