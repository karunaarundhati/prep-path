Relational model & relational algebra

A relational database stores data in tables, and relational algebra is a small set of operations that takes tables and produces new tables. This topic covers the relational model and its keys, the operations selection, projection, set operations, product, join and rename, and how to read an algebra expression as a SQL query, which GATE uses in its numerical questions.

The idea in plain words

Think of a school register. Each row is one student, and each column is one fact about the student, such as roll number, name or department. The register is a table. A database is a collection of such tables.

Now think of a cook following a recipe. The cook takes ingredients, chops some of them, mixes two bowls together, and sets some aside. Each step uses one or two bowls and makes a new bowl. Relational algebra works in exactly this way. Its ingredients are tables. Its steps are operations, such as choosing some rows, choosing some columns, or combining two tables. Each operation produces a new table, so steps can be chained.

The relational model is the rule book behind this. A table is called a relation. A row is a tuple. A column is an attribute. The rows of a relation form a set, so there are no duplicate rows and the order of rows does not matter.

Why this matters for GATE: GATE DA asks questions where you are given tables and a relational algebra expression, and you must work out the resulting rows. It also asks about keys, and about translating a query between algebra and SQL. The method is always the same: follow each operation in order, and write the table you get after each step.

Key terms

Relation
A table with a name and a fixed set of columns. Precisely: a set of tuples over a fixed list of attributes.
Tuple
One row of a relation.
Attribute
One named column of a relation.
Degree
The number of attributes (columns) in a relation.
Cardinality
The number of tuples (rows) in a relation.
Super key
Any set of attributes whose values are unique for each tuple.
Candidate key
A super key from which no attribute can be removed and still be unique. A minimal super key.
Primary key
The candidate key chosen to identify tuples. It is never empty.
Foreign key
An attribute in one relation whose values must appear as primary key values in another relation.
Selection (σ)
Keeps only the tuples that satisfy a condition.
Projection (π)
Keeps only the chosen attributes, and removes duplicate tuples.
Union-compatible
Two relations with the same number of attributes, in the same order, with matching types. Only such relations can be combined with union or difference.
Cartesian product (×)
Pairs every tuple of one relation with every tuple of the other.
Join (⋈)
A product followed by a selection on matching values. The natural join matches equal values on the common attribute names.
Rename (ρ)
Gives a relation or its attributes a new name.

Keys

Look at Student. The value sid is different for every row, so sid identifies each tuple. The set {sid, name} is also unique, but it is not minimal, because sid alone already works. So sid is a candidate key. In this relation, name is not a candidate key, because two students could share a name.

Look at Enrol. The attribute sid alone repeats (S1 appears twice), and cid alone repeats too. The pair (sid, cid) is unique in every row. So (sid, cid) is the candidate key, and we choose it as the primary key.

A foreign key links two relations. In Enrol, sid must match a sid in Student, and cid must match a cid in Course. So sid and cid are foreign keys in Enrol.

Key ideaA key is decided by the meaning of the data and by the rules the database must enforce, not by the sample rows alone. Sample rows can show that an attribute is not a key, but they cannot prove that it is one.

TrapA relation has no duplicate tuples. If a question shows two identical rows, the relation as a set keeps only one of them.

What is the degree and cardinality of the Course relation?

Degree 3 (cid, title, credits), and cardinality 3 (three rows).

Is grade alone a candidate key of Enrol?

No. Grade A appears in more than one row, so grade does not identify each tuple.

Selection and projection

Selection, written σ, chooses rows. The condition goes under the sigma. For example, σdept = 'CS'(Student) keeps only the rows where dept is CS.

sidnamedept
S1AshaCS
S3MeeraCS

The result has the same attributes as the input. It has at most as many rows as the input, because it only removes rows. Conditions can use =, ≠, <, >, ≤, ≥, and can be joined with AND and OR.

Projection, written π, chooses columns. For example, πname(Student) keeps only the name column. Projection also removes duplicate tuples, because a relation is a set. So a projection can have fewer rows than its input.

EE

The table above is πdept(Student). The input had four rows, but CS appeared twice, so the result has three rows.

TrapIn relational algebra, projection removes duplicates. In SQL, SELECT does not remove duplicates unless you write SELECT DISTINCT. This difference is often tested, so read the question carefully.

Selection and projection can be combined. πname(σdept = 'CS'(Student)) first keeps the CS students, then keeps only their names. The result is one column, with the values Asha and Meera.

How many rows does σdept = 'EE'(Student) have?

One row, the tuple for Ravi.

How many rows does πgrade(Enrol) have?

Three rows: A, B and C. Grade A appears twice and grade B appears twice, but duplicates are removed.

Union, intersection and difference

Relations are sets of tuples, so the usual set operations apply. Two relations can be combined only if they are union-compatible. This means they have the same number of attributes, in the same order, with matching types. A student table and a course table cannot be combined with union, because their attributes do not match.

  • Union (∪) gives all tuples that appear in either relation, with duplicates removed.
  • Difference (−) gives the tuples in the first relation that do not appear in the second.
  • Intersection (∩) gives the tuples that appear in both. It is not a basic operation, but it equals A − (A − B).

Example. Let X be the sids that appear in Enrol, and Y be the sids of CS students. X = πsid(Enrol) has the values S1, S2 and S3. Y = πsid(σdept = 'CS'(Student)) has the values S1 and S3.

ExpressionResult
XS1, S2, S3
YS1, S3
X − YS2
X ∪ YS1, S2, S3
X ∩ YS1, S3

Key ideaThe difference is not symmetric. X − Y is not the same as Y − X. For this example Y − X is empty, because every CS student is enrolled in some course.

TrapStudents often write A − B and expect the answer to include rows of B. It never does. The difference keeps only rows of A.

What is X ∪ Y when X = {S1, S2, S3} and Y = {S1, S3}?

{S1, S2, S3}. Union keeps each value once.

Why can we not take the union of Student and Course?

They are not union-compatible. They have different numbers of attributes and different attribute types.

Cartesian product and joins

The Cartesian product, written ×, pairs every tuple of the first relation with every tuple of the second. If the first has m tuples and the second has n tuples, the product has m × n tuples. Its attributes are all the attributes of both relations.

Product alone is rarely useful, because most pairs are meaningless. For example, Student × Course has 4 × 3 = 12 rows, and most of them pair a student with a course that the student did not take. The join removes the meaningless pairs.

The natural join, written ⋈, takes the product and keeps only the pairs where the common attributes have equal values. Student and Enrol have the common attribute sid. So Student ⋈ Enrol keeps each enrolment and attaches the student's name and dept to it.

The result has 5 rows. Kiran (S4) is missing, because he has no row in Enrol. The natural join drops tuples that have no match on the other side.

A theta join uses any condition, written under the join symbol. An equi-join is a theta join where the condition is only equality. If the two relations have no common attribute, the natural join is the same as the Cartesian product.

def select(rel, pred):
    return [r for r in rel if pred(r)]

def project(rel, attrs):
    out = []
    for r in rel:
        t = {a: r[a] for a in attrs}
        if t not in out:
            out.append(t)
    return out

def natural_join(r1, r2):
    common = [a for a in r1[0] if a in r2[0]]
    out = []
    for x in r1:
        for y in r2:
            if all(x[a] == y[a] for a in common):
                t = dict(x)
                t.update(y)
                out.append(t)
    return out

def product(r1, r2):
    return [dict(x, **y) for x in r1 for y in r2]

GATE loves thisFor a natural join with no common attributes, the result size is |R| × |S|. For a natural join where one attribute is a key of S, each tuple of R matches at most one tuple of S, so the result has at most |R| tuples.

If R has 6 tuples and S has 4 tuples, how many tuples does R × S have?

24, because 6 × 4 = 24.

Why does Kiran not appear in Student ⋈ Enrol?

Because the natural join keeps only pairs with a matching sid in Enrol. Kiran has no enrolment, so his tuple has no match.

Rename and building expressions

Rename, written ρ, gives a new name to a relation or to its attributes. It is needed when two copies of the same relation are joined with themselves, or when attribute names must match for a natural join. For example, if we want to join Student with itself on dept, we rename one copy so that its attributes do not clash.

Operations can be nested. An expression such as πname, title(σgrade = 'A'(Student ⋈ Enrol) ⋈ Course) reads from the inside out:

  1. Join Student and Enrol on sid. This is the table from the join section.
  2. Select the rows with grade A. This keeps the rows for Asha in C1 and Meera in C2.
  3. Join the result with Course on cid. Asha gains Databases and Meera gains Algorithms.
  4. Project onto name and title. The final table has two rows: Asha with Databases, and Meera with Algorithms.
nametitle
AshaDatabases
MeeraAlgorithms

TipWhen you evaluate a long expression, write a new small table after each operator, with a label such as "step 2". This habit prevents most mistakes in GATE numerical questions.

In the expression above, why is the selection done before the join with Course?

The selection reduces the number of rows before the second join. The result is the same either way, but the work is smaller.

What does the rename operator add to an expression that joins a relation with itself?

It gives one copy a different name, so that its attributes can be distinguished.

Translating algebra to SQL

SQL is the language most databases use. Every basic algebra operation has a matching SQL form. Learn the matches, and you can move between the two notations in either direction.

AlgebraSQLNote
σcond(R)SELECT * FROM R WHERE condRows chosen
πA, B(R)SELECT DISTINCT A, B FROM RDISTINCT removes duplicates, as in algebra
R × SSELECT * FROM R, SNo condition, so every pair is kept
R ⋈ S (natural)SELECT * FROM R NATURAL JOIN SMatches the common attributes
R ⋈cond SSELECT * FROM R JOIN S ON condTheta join
R ∪ SSELECT ... FROM R UNION SELECT ... FROM SRemoves duplicates
R − SSELECT ... FROM R EXCEPT SELECT ... FROM SKeeps rows of R only

Take πname(σdept = 'CS'(Student)). In SQL, this is:

SELECT DISTINCT name
FROM Student
WHERE dept = 'CS';

The WHERE clause is the selection, the column list is the projection, and DISTINCT is the duplicate removal that algebra does automatically. The result is the single column with the values Asha and Meera.

TrapThe product in SQL with no WHERE clause keeps every pair. Adding a condition that matches the common attribute turns it into a join. Forgetting that condition is a common source of wrong answers.

Which SQL keyword plays the role of projection duplicate removal in algebra?

DISTINCT, when used with the column list.

Which SQL keyword matches the difference operator?

EXCEPT.

Solved GATE-style problems

These problems are original, written in the GATE style. They are not real past questions. Write each intermediate table on paper, then check with code.

Degree and cardinality

The relation Enrol has the attributes sid, cid and grade, and five tuples. What are its degree and its cardinality? Give the degree first.

How to think about it

  1. What is asked. Two numbers: the columns, then the rows.
  2. Which idea applies. Degree counts attributes. Cardinality counts tuples.
  3. Work it out. There are three attributes, so the degree is 3. There are five tuples, so the cardinality is 5.
  4. Check. Run the code below, which stores the tuples as lists of three values.
enrol = [("S1", "C1", "A"), ("S1", "C2", "B"), ("S2", "C1", "C"),
         ("S3", "C2", "A"), ("S3", "C3", "B")]
print(len(enrol[0]), len(enrol))
3 5

Answer: degree 3, cardinality 5.

Candidate key test

Is sid alone a candidate key of Enrol, given the five tuples above? Is the pair (sid, cid) a candidate key? Answer both questions.

How to think about it

  1. What is asked. Whether each attribute set identifies every tuple.
  2. Which idea applies. A candidate key takes unique values for every tuple, with no spare attribute.
  3. Work it out. sid repeats: S1 appears in two tuples, so sid alone is not a key. The pair (sid, cid) is unique in every tuple, so it is a candidate key.
  4. Check. Run the code below. The first line tests the pair. The second line tests sid alone.
enrol = [("S1", "C1", "A"), ("S1", "C2", "B"), ("S2", "C1", "C"),
         ("S3", "C2", "A"), ("S3", "C3", "B")]
print(len(set((s, c) for s, c, g in enrol)) == len(enrol))
print(len(set(s for s, c, g in enrol)) == len(enrol))
True
False

Answer: sid alone is not a candidate key. The pair (sid, cid) is.

Size of a product

Student has 4 tuples and Course has 3 tuples. How many tuples does Student × Course have? This is a NAT question.

How to think about it

  1. What is asked. The number of pairs.
  2. Which idea applies. Every tuple of the first is paired with every tuple of the second.
  3. Work it out. Each of the 4 student tuples pairs with 3 course tuples, so 4 × 3 = 12.
  4. Check. Run the code below, which lists every pair.
students = ["S1", "S2", "S3", "S4"]
courses = ["C1", "C2", "C3"]
pairs = [(s, c) for s in students for c in courses]
print(len(pairs))
12

Answer: 12.

Credits of grade A enrolments

Consider the grade A rows of Enrol, joined with Course on cid. What is the sum of the credits over those rows? This is a NAT question.

How to think about it

  1. What is asked. A sum of credits over selected joined rows.
  2. Which idea applies. Select, then join, then add.
  3. Work it out. The grade A rows are (S1, C1) and (S3, C2). Joined with Course, they bring the credits 4 (Databases) and 3 (Algorithms). The sum is 4 + 3 = 7.

Exam-level practice

Exam-level 1: Natural join size (NAT, 2 marks)

R(A, B) = {(1, 2), (2, 3), (3, 3)} and S(B, C) = {(2, 5), (3, 6), (3, 7), (4, 8)}. How many tuples are in R ⋈ S?

How to think about it

  1. What is asked. The size of the natural join.
  2. Which idea applies. Match tuples on equal B.
  3. Work it out. B = 2: 1 · 1 = 1. B = 3: 2 · 2 = 4. Total 5.
  4. Check. The code joins them.
R = [(1, 2), (2, 3), (3, 3)]; S = [(2, 5), (3, 6), (3, 7), (4, 8)]
print(len([(a, b, c) for a, b in R for b2, c in S if b == b2]))

5

Answer: 5.

Exam-level 2: Division (MCQ, 2 marks)

Enrolled(S, C) has tuples (s1, c1), (s1, c2), (s2, c1), (s3, c1), (s3, c2), (s3, c3). Course(C) = {c1, c2}. What is Enrolled ÷ Course? (A) {s1} (B) {s1, s3} (C) {s3} (D) {s1, s2, s3}

How to think about it

  1. What is asked. Students enrolled in every listed course.
  2. Which idea applies. Division keeps the S values paired with all C values in the divisor.
  3. Work it out. s1 has c1, c2. s3 has c1, c2, c3. s2 lacks c2.
  4. Check. Extra courses do not hurt, so s3 qualifies.

Answer: (B).

Exam-level 3: Expression equivalence (MSQ, 2 marks)

Which are always TRUE? (A) σp(σq(R)) = σp∧q(R) (B) πA(R ∪ S) = πA(R) ∪ πA(S) (C) πA(R − S) = πA(R) − πA(S) (D) σp(R ∪ S) = σp(R) ∪ σp(S)

How to think about it

  1. What is asked. Which algebraic rewrites are valid.
  2. Which idea applies. Projection does not distribute over set difference because it can merge tuples.
  3. Work it out. (A) True. (B) True. (C) R = {(1, 1), (1, 2)}, S = {(1, 2)}: left is {1}, right is empty. False. (D) True.
  4. Check. The code shows the counterexample.
R = {(1, 1), (1, 2)}; S = {(1, 2)}
pi = lambda X: {t[0] for t in X}
print(pi(R - S), pi(R) - pi(S))

{1} set()

Answer: (A), (B) and (D).

Remember these

  • Work through an algebra expression from the inside out, writing a table after each operation.
  • Projection removes duplicates, because a relation is a set.
  • Selection never adds rows, and its result has at most as many rows as its input.
  • A product of R and S has exactly |R| × |S| tuples.
  • Union and difference need union-compatible relations.
  • A candidate key is decided by the meaning of the data, not by a few sample rows.
