NumPy: fast arrays for numerical work

Python lists are flexible but slow for numerical work. Each element is a full Python object, and a loop over a million numbers sends every step through the interpreter. NumPy provides the ndarray, an array in which every element has the same type (the dtype) and the values sit side by side in memory. Operations on whole arrays run in compiled code. That is why NumPy is the foundation of the Python data stack: Pandas, scikit-learn and most plotting libraries use arrays under the hood, and PyTorch tensors follow the same ideas.

The usual import is import numpy as np. The np alias is a convention you will see in every tutorial, and interviewers expect it.

Shapes, creation and axes

An array has a shape, a tuple that gives the length along each axis. A one-dimensional array of three numbers has shape (3,). A two-dimensional array with two rows and three columns has shape (2, 3). Common constructors are np.array (from a list), np.arange(start, stop, step) (like range, but it returns an array), np.zeros, np.ones, np.linspace (evenly spaced values that include both ends) and np.random.default_rng(seed) for random numbers. A fixed seed makes random results reproducible.

The axis argument chooses the direction of an operation. For a two-dimensional array, axis=0 runs down the rows, so it works column by column. axis=1 runs across the columns, so it works row by row. Many candidates mix these up, so say the direction out loud when you answer.

import numpy as np

a = np.array([1, 2, 3])                # shape (3,)
b = np.array([[1, 2, 3], [4, 5, 6]])   # shape (2, 3)
b.reshape(3, 2)    # shape (3, 2), the same six values in a new layout
b.sum(axis=0)      # array([5, 7, 9]), one sum per column
b.sum(axis=1)      # array([ 6, 15]), one sum per row

These examples do not print, so no output block follows them. The comments show the values that NumPy returns. Note that reshape does not copy the data when it can avoid it. It only changes how the same values are indexed.

Broadcasting: arithmetic on arrays of different shapes

Broadcasting is NumPy's rule for combining arrays whose shapes differ. Here is the rule, step by step. Line up the shapes from the right. For each pair of dimensions, they are compatible if they are equal, or if one of them is 1. A missing leading dimension counts as 1. NumPy then stretches the size-1 dimensions to match the other array, without copying the data in memory.

Worked example: adding a row vector of shape (3,) to a matrix of shape (2, 3). The row is treated as shape (1, 3), and the first dimension stretches from 1 to 2. So the same row is added to each of the two rows of the matrix. A column of shape (3, 1) plus a row of shape (4,) gives a grid of shape (3, 4), where each cell is the column value plus the row value.

import numpy as np

col = np.array([[1], [2], [3]])   # shape (3, 1)
row = np.array([10, 20, 30, 40]) # shape (4,), treated as (1, 4)
grid = col + row                 # shape (3, 4)
# grid[0] is array([11, 21, 31, 41])
# grid[2] is array([13, 23, 33, 43])

To see what broadcasting does without NumPy, here is the same row addition written with plain Python lists. NumPy does this loop in compiled code, without building the intermediate lists:

matrix = [[1, 2, 3], [4, 5, 6]]
row = [10, 20, 30]
result = [[x + y for x, y in zip(line, row)] for line in matrix]
print(result)
[[11, 22, 33], [14, 25, 36]]

TrapShapes that look close are not compatible. A shape (3,) cannot be added to (4,), and NumPy raises a ValueError. The usual fix is to reshape one operand so that the dimension you want to stretch is 1 and the others line up.

Vectorisation: replace loops with whole-array expressions

Vectorisation means writing an operation on whole arrays instead of a Python loop over the elements. It is shorter, easier to read and much faster, because the work happens inside NumPy's compiled code. The following code computes the total cost of several items. The loop version is correct too, but it is slower and longer.

import numpy as np

prices = np.array([120.0, 45.5, 300.0])
quantities = np.array([2, 10, 1])

# Vectorised: one expression, no Python loop
total = np.sum(prices * quantities)   # 995.0

# The same idea as a loop, for comparison
total_loop = 0.0
for p, q in zip(prices, quantities):
    total_loop += p * q               # also 995.0

An interviewer may ask why vectorised code is faster. The answer has three parts: the loop over elements runs inside compiled code rather than the interpreter, the data is stored contiguously so the processor reads it efficiently, and the operation avoids creating a Python object for every element.

Views versus copies

This is the most common NumPy trap. A view is an array that shares memory with another array. A copy owns its own memory. Slicing with a range, such as a[1:4], returns a view. Indexing with a list of positions (fancy indexing) or with a boolean mask returns a copy. Changing a view changes the original array.

import numpy as np

a = np.arange(6)     # array([0, 1, 2, 3, 4, 5])
b = a[1:4]           # a slice: a view that shares memory with a
b[0] = 99            # this also changes a, because b is a view
# a is now array([0, 99, 2, 3, 4, 5])

c = a[[0, 2]]        # a list of positions: fancy indexing gives a copy
c[0] = -1            # a is unchanged by this line

d = a[a > 3].copy()  # a boolean mask gives a copy; .copy() makes it explicit

To check whether two arrays share memory, use np.shares_memory(a, b). The rule to remember: a basic slice is a view, and fancy or boolean indexing is a copy. If you need to keep the original values, call .copy() on the slice first.

TrapA function that receives an array slice can modify the caller's data without making it obvious. If a function must not change its input, copy the array at the start of the function.

What is the difference between a view and a copy in NumPy, and which indexing creates which?

A view shares memory with the array it came from, so writing to it changes the original. A copy has its own memory. Basic slicing such as a[1:4] returns a view, while fancy indexing with a list of positions and boolean masking return copies. Use .copy() when you need an independent array.

Explain broadcasting for an array of shape (3, 1) plus an array of shape (4,).

Align the shapes from the right. The last dimensions are 1 and 4, so the 1 stretches to 4. The first dimensions are 3 and missing, which counts as 1, so the result has 3 rows. The result has shape (3, 4), and each cell is the column value plus the row value.

Pandas: tables for data work

Pandas builds on NumPy and adds labelled tables. A DataFrame is a table with named columns and a row index. A Series is one column with its index. Pandas is where most real data cleaning happens, so interviewers often ask you to explain what a selection or a join returns.

import pandas as pd

df = pd.DataFrame({
    "name": ["Asha", "Ravi", "Meera", "Dev"],
    "city": ["Pune", "Delhi", "Pune", "Chennai"],
    "score": [82, 67, 91, None],
})

The table this creates looks like this. The first column is the index, which pandas adds automatically. The None in the score column is treated as a missing value, which pandas shows as NaN (not a number). Because a numeric column with a missing value must store floating-point numbers, the score column becomes a float column, and the integers display with a decimal point.

Inspecting data first

Before any analysis, look at the data. df.head() shows the first rows, df.shape gives the number of rows and columns, df.dtypes lists each column's type, df.info() summarises types and non-missing counts, and df.describe() gives count, mean, standard deviation, minimum, quartiles and maximum for numeric columns. df.isna().sum() counts the missing values in each column. These checks take a minute and prevent most surprises later.

Selection: loc versus iloc

Selection is the most tested pandas skill. loc selects by label, and iloc selects by integer position. The difference matters at the ends of a slice. With loc, a slice includes the end label. With iloc, it excludes the end position, as in plain Python.

df["score"]                        # one column, returned as a Series
df[["name", "score"]]              # several columns, returned as a DataFrame
df.loc[1, "score"]                 # row labelled 1, column score: 67.0
df.iloc[0:2]                       # positions 0 and 1 only: Asha and Ravi
df.loc[0:2]                        # labels 0, 1 and 2: Asha, Ravi and Meera
df.loc[df["score"] > 80, "name"]   # boolean mask: Asha and Meera

These examples do not print, so no output block follows them. The comments give the results. In the last line, Dev has a missing score, and a comparison with a missing value is false, so Dev is not selected.

TrapChained indexing, such as df[df["score"] > 80]["name"] = "x", may write to a temporary copy and change nothing, and pandas warns about it. Assign with one call instead: df.loc[df["score"] > 80, "name"] = "x".

groupby: split, apply, combine

groupby splits the table into groups by a key, applies an aggregate to each group, and combines the results. The pattern is often described as split-apply-combine. Here the average score for each city:

df.groupby("city")["score"].mean()

The result is a Series indexed by city, in alphabetical order. Chennai shows NaN because its only row has a missing score, and the mean skips missing values, so the group has nothing left to average. Delhi has one score of 67.0, and Pune has the scores 82 and 91, so its mean is 86.5. To count rows per group instead, use df.groupby("city").size(). To apply several aggregates at once, use .agg(["mean", "max"]).

merge: joining tables on a key

merge joins two tables on matching key columns, like a SQL join. The how argument chooses which rows are kept. Suppose a second table maps cities to states:

states = pd.DataFrame({"city": ["Pune", "Delhi"], "state": ["Maharashtra", "Delhi"]})

df.merge(states, on="city", how="left")    # keep every row of df
df.merge(states, on="city", how="inner")   # keep only cities found in both tables

With how="left", all four people stay. Asha, Ravi and Meera get their states, and Dev gets NaN in the state column because Chennai is not in the states table. With how="inner", Dev is dropped entirely and the result has three rows. The other options are "right", which keeps every row of the second table, and "outer", which keeps every row from both.

pivot: reshaping from long to wide

A long table has one row per observation, and a wide table spreads one variable across columns. pivot turns long data into wide data. For example, df.pivot(index="name", columns="city", values="score") gives one row per name and one column per city, with the score in each cell. Cells with no matching row are NaN. Pivot needs each index and column pair to be unique. When duplicates exist, use pivot_table, which aggregates them with a function such as the mean.

Missing data: find it, then decide

Missing values appear as NaN for numbers and None or NaN for objects. The rule is that NaN is not equal to anything, not even to itself, so you must test for missing values with isna() and never with == np.nan. Three tools handle most cases:

  • dropna() removes rows (or columns) that contain missing values. It is simple, but it can throw away a lot of data.
  • fillna(value) replaces missing values with a constant, or with a column mean or median. Carrying the previous value forward is a separate call, ffill().
  • interpolate() estimates missing numbers from their neighbours, which suits ordered data such as time series.
df.dropna()                                          # Dev is removed
df.assign(score=df["score"].fillna(df["score"].mean()))  # Dev gets 80.0

The mean of the three known scores is (82 + 67 + 91) / 3 = 80.0, so filling Dev's score with the mean gives 80.0. Mean imputation keeps the average unchanged for that column but reduces its spread, which is a trade-off to mention in an interview. Always decide why a value is missing before you fill it. A missing score might mean the test was not taken, which is different from a score of zero.

What is the difference between loc and iloc, and what does each include at the end of a slice?

loc selects by label and iloc selects by integer position. A loc slice includes the end label, so df.loc[0:2] returns labels 0, 1 and 2. An iloc slice excludes the end position, so df.iloc[0:2] returns positions 0 and 1. This difference matters whenever the index is not the default 0, 1, 2 sequence.

What does groupby do, and why does Chennai show NaN in the mean?

groupby splits the rows into groups by a key, applies an aggregate to each group, and combines the results into one object. Chennai has only one row, and its score is missing. The mean skips missing values, so the group has no values left, and its result is NaN.

What do the how options of merge mean, and when would you use an inner join?

how="left" keeps all rows of the left table and fills missing matches with NaN. how="right" keeps all rows of the right table. how="outer" keeps all rows of both. how="inner" keeps only rows whose key exists in both tables. Use inner when you need complete records only, and left when the main table must stay complete.

Why must you test for missing values with isna() rather than with equality?

NaN is not equal to any value, including itself, so an expression such as x == np.nan is always false. The reliable test is isna(), which returns True for each missing value. It is the test that works for both NaN and None in object columns.

Plots and exploratory data analysis

Exploratory data analysis (EDA) is the stage where you examine the data before modelling. Its goals are to find errors, understand the distributions, see how variables relate, and form hypotheses. A good EDA is cheap, and it often shows that the question needs a different answer than the one first asked.

Matplotlib: the figure and the axes

Matplotlib is the base plotting library. Its object-oriented style is the one to use in code and in interviews. A figure is the whole picture, and an axes is one plot inside it. You create both with plt.subplots(), draw on the axes with methods such as ax.hist and ax.scatter, and label the axes with ax.set_title, ax.set_xlabel and ax.set_ylabel.

import matplotlib.pyplot as plt

fig, ax = plt.subplots(figsize=(6, 4))
ax.hist(df["score"].dropna(), bins=5)
ax.set_title("Distribution of scores")
ax.set_xlabel("Score")
ax.set_ylabel("Number of students")
plt.show()

The histogram counts how many values fall into each bin. Always label the axes, because a plot without units or titles is hard to trust. Pass dropna() first, because the histogram cannot draw missing values.

Seaborn: statistical plots from a DataFrame

Seaborn is built on Matplotlib and works directly with DataFrames. You name the columns, and it takes care of grouping, colours and confidence intervals. It is the quickest way to draw distributions, box plots, scatter plots and correlation heatmaps.

import seaborn as sns

sns.histplot(data=df, x="score", bins=5)
sns.boxplot(data=df, x="city", y="score")

numeric = df.select_dtypes("number")
sns.heatmap(numeric.corr(), annot=True)

A box plot shows the median, the middle half of the data (the box), and the points far from the box, which are candidate outliers. A heatmap of corr() shows the correlation between each pair of numeric columns. Correlation only measures linear association, so a strong curved relationship can show a correlation near zero.

An EDA workflow you can follow every time

  1. State the question. Write down what decision the analysis should support.
  2. Load and inspect. Check the shape, the column types, the first rows and the summary statistics with describe().
  3. Check quality. Count missing values, look for duplicate rows with df.duplicated().sum(), and check that categories are spelled consistently.
  4. Look at each variable alone. Plot distributions, and note skew, impossible values and suspicious spikes.
  5. Look at relationships. Compare groups with groupby, plot pairs of variables, and inspect the correlation matrix.
  6. Decide about outliers. Keep, cap or remove them, but record the reason. An outlier can be a data-entry error or the most important case.
  7. Clean and create features. Fix types, handle missing values, and create columns that express the question more directly.
  8. Write down hypotheses. List the patterns that a model or a test should check, and note what you still do not know.
What is the difference between a figure and an axes in Matplotlib?

The figure is the whole canvas, and it can hold several plots. The axes is one plot inside a figure, with its own x and y ranges, labels and drawing methods. You draw on the axes, and you lay out or save the figure.

Which chart would you use to find outliers in a numeric column for several groups?

A box plot with one box per group. It shows the median, the interquartile range and the points beyond the whiskers, which makes outliers and differences in spread easy to compare across groups.

Why is a correlation of 0 not proof that two variables are unrelated?

The Pearson correlation measures only linear association. Two variables can have a strong non-linear relationship, such as y equal to x squared on values symmetric around zero, and still show a correlation of 0. A scatter plot reveals such patterns.

Linear algebra for machine learning

Linear algebra is the language of data and models. A row of features is a vector, a table of rows is a matrix, and most model computations are matrix products. Three ideas come up again and again in interviews: the dot product, eigenvectors and the singular value decomposition.

Vectors and the dot product

The dot product of two vectors of the same length multiplies matching entries and adds the results: a dot b equals the sum of a_i times b_i. For example, [1, 2, 3] dot [4, 5, 6] is 1*4 + 2*5 + 3*6 = 4 + 10 + 18 = 32. The dot product of a weight vector and a feature vector is exactly the score a linear model computes. The cosine similarity divides the dot product by the two vector lengths. It measures the angle between vectors, not their size, and it is the standard way to compare text embeddings.

Matrix multiplication

A matrix of shape (m, n) times a matrix of shape (n, p) gives shape (m, p). The inner sizes must match, and the outer sizes give the result. Each result entry (i, j) is the dot product of row i of the left matrix and column j of the right matrix. For example, [[1, 2], [3, 4]] times [[0, 1], [1, 0]] gives [[2, 1], [4, 3]]. Entry (1, 1) is row (1, 2) dot column (0, 1), which is 0 + 2 = 2.

Matrix multiplication is not commutative: A times B is usually different from B times A. A linear model with many examples is written as y = Xw, where X holds one row per example and w is the weight vector. The whole prediction is one matrix-vector product.

Eigenvalues and eigenvectors

A matrix usually rotates and stretches a vector. An eigenvector is a special vector that keeps its direction when the matrix is applied, so only its length changes. The change in length is the eigenvalue lambda. The definition is A v = lambda v. For a symmetric matrix, all eigenvalues are real, and eigenvectors for different eigenvalues are perpendicular.

In data science, the covariance matrix of centred data is symmetric. Its eigenvectors are the principal components, the directions of greatest variance, and its eigenvalues tell how much variance lies along each direction. Principal component analysis (PCA) keeps the top eigenvectors and drops the rest. The fraction of variance kept by component i is lambda_i divided by the sum of all eigenvalues.

Here is a small check with a symmetric matrix [[2, 1], [1, 2]]. Its eigenvalues come from the characteristic equation lambda squared minus the trace times lambda plus the determinant equals zero. The trace is 4 and the determinant is 3, so the eigenvalues are 3 and 1. The vector (1, 1) is an eigenvector with eigenvalue 3.

import math

# Symmetric matrix A = [[2, 1], [1, 2]]
a, b, c, d = 2, 1, 1, 2
trace = a + d
det = a * d - b * c
disc = trace * trace - 4 * det
l1 = (trace + math.sqrt(disc)) / 2
l2 = (trace - math.sqrt(disc)) / 2
print("eigenvalues:", l1, l2)

# Check that A v = lambda v for v = (1, 1)
v1 = (1, 1)
Av1 = (a * v1[0] + b * v1[1], c * v1[0] + d * v1[1])
print("A v1 =", Av1, "lambda1 * v1 =", (l1 * v1[0], l1 * v1[1]))
eigenvalues: 3.0 1.0
A v1 = (3, 3) lambda1 * v1 = (3.0, 3.0)

The output confirms the definition. Applying A to (1, 1) gives (3, 3), which is three times the original vector, so the eigenvalue is 3.

Singular value decomposition (SVD)

The singular value decomposition factors any matrix A, even a rectangular one, as A = U times Sigma times V transpose. U and V have orthonormal columns, and Sigma is a diagonal matrix of non-negative singular values, sorted from largest to smallest. The singular values are the square roots of the eigenvalues of A transpose times A. SVD underlies PCA, low-rank approximation, recommender systems and the pseudo-inverse used in least squares.

The most useful consequence is the truncated SVD. Keeping only the largest k singular values gives the best rank-k approximation of A in the least squares sense, which is the Eckart-Young theorem. This is how image compression and latent-factor models work: the data is replaced by a smaller set of directions that captures most of its energy.

The next program computes the singular values of [[1, 2], [3, 4]] from the eigenvalues of A transpose times A, using only the standard library:

import math

M = [[1, 2], [3, 4]]
AtA = [[sum(M[k][i] * M[k][j] for k in range(2)) for j in range(2)] for i in range(2)]
tr = AtA[0][0] + AtA[1][1]
dt = AtA[0][0] * AtA[1][1] - AtA[0][1] * AtA[1][0]
dd = math.sqrt(tr * tr - 4 * dt)
s1 = math.sqrt((tr + dd) / 2)
s2 = math.sqrt((tr - dd) / 2)
print("A^T A =", AtA)
print("singular values:", round(s1, 4), round(s2, 4))
A^T A = [[10, 14], [14, 20]]
singular values: 5.465 0.366

The singular values are about 5.465 and 0.366. The first is much larger, so most of the matrix's energy lies in one direction. A rank-one approximation built from the first singular value and its vectors would keep most of the information, which is the idea behind truncated SVD.

What is an eigenvector, and why does a symmetric covariance matrix matter for PCA?

An eigenvector is a non-zero vector whose direction does not change when the matrix is applied, so A v = lambda v, and lambda is its eigenvalue. The covariance matrix of centred data is symmetric, so it has real eigenvalues and perpendicular eigenvectors. PCA uses those eigenvectors as the principal components and the eigenvalues as the variance along each one.

How are singular values related to eigenvalues, and what is truncated SVD used for?

The singular values of A are the square roots of the eigenvalues of A transpose times A. Keeping only the k largest singular values gives the best rank-k approximation of A in the least squares sense. It is used for compression, denoising, latent-factor models and dimensionality reduction.

Calculus: gradients and gradient descent

Training a model means choosing parameters that make a loss function small. The loss measures how wrong the predictions are. Calculus tells you which way to move the parameters. The derivative of the loss with respect to a parameter is the slope of the loss at the current value, so moving against the slope lowers the loss.

Derivatives and the chain rule

The derivative of f at x, written f'(x), is the instantaneous rate of change of f. For f(x) = x squared, f'(x) = 2x. At x = 3 the slope is 6, so increasing x increases f at that point. A function of several variables has partial derivatives, one per variable, obtained by treating the others as constants. The vector of all partial derivatives is the gradient. It points in the direction in which the function increases fastest.

The chain rule computes the derivative of a function built from other functions. If y = g(u) and u = h(x), then dy/dx = (dy/du) times (du/dx). Here is a worked example: f(x) = (3x + 1) squared. Let u = 3x + 1, so f = u squared. Then df/du = 2u and du/dx = 3, so df/dx = 6u = 6(3x + 1). At x = 1, the derivative is 6 times 4, which is 24. Backpropagation, the algorithm that trains neural networks, is the chain rule applied layer by layer, from the output back to the input, reusing intermediate results.

Gradient descent

Gradient descent repeatedly moves the parameters a small step against the gradient. The update rule is w_new = w_old minus eta times the gradient, where eta is the learning rate. A learning rate that is too small makes progress slow. One that is too large overshoots the minimum and can diverge. For a loss computed over many examples, the gradient can be taken over all examples (batch gradient descent), over one example at a time (stochastic), or over small groups (mini-batch). Mini-batch training is the usual choice for deep learning because it balances cost and noise.

Take the simple function f(w) = (w - 3) squared. Its minimum is at w = 3, and its derivative is 2(w - 3). Starting at w = 0 with learning rate 0.1, each step moves w toward 3. The following program prints the first five steps, using only the standard library:

w = 0.0
lr = 0.1
for step in range(1, 6):
    grad = 2 * (w - 3)          # derivative of (w - 3) ** 2
    w = w - lr * grad           # move against the gradient
    print(f"step {step}: w = {w:.4f}")
step 1: w = 0.6000
step 2: w = 1.0800
step 3: w = 1.4640
step 4: w = 1.7712
step 5: w = 2.0170

Each step moves w closer to 3, and the steps shrink as the slope flattens. Increasing the learning rate to 0.5 would make the first step jump to exactly 3, while a rate above 1 for this function would overshoot further on every step and diverge. That is the trade-off you describe in an interview.

Why does gradient descent subtract the gradient instead of adding it?

The gradient points in the direction in which the loss increases fastest. To decrease the loss, the parameters must move in the opposite direction, so the update subtracts the learning rate times the gradient.

Differentiate f(x) = (3x + 1) squared and evaluate it at x = 1.

Use the chain rule. With u = 3x + 1, the derivative is 2u times 3, which is 6(3x + 1). At x = 1, u = 4, so the derivative is 6 times 4, which is 24.

Probability: Bayes, maximum likelihood and cross-entropy

Machine learning is applied probability. A classifier estimates the chance of each class, a training procedure chooses parameters that make the observed data most likely, and the loss function is often a probability measured in bits or nats. The ideas below appear in almost every ML interview.

Conditional probability and Bayes theorem

Conditional probability P(A given B) is the probability of A when we already know B happened. It is defined as P(A and B) divided by P(B). Rearranging gives the product rule, and combining it with the symmetric version gives Bayes theorem: P(A given B) equals P(B given A) times P(A), divided by P(B). The denominator P(B) is found with the law of total probability, which adds up the chance of B under each possible cause of A.

The classic example is a medical test. Suppose 1 in 100 people has a disease, the test detects it 99% of the time, and it gives a false positive for 5% of healthy people. If you test positive, what is the probability you have the disease? Most people guess 99%, but the answer is much lower because the disease is rare. Work it out step by step. P(positive) = 0.99 times 0.01 plus 0.05 times 0.99 = 0.0099 plus 0.0495 = 0.0594. Then P(disease given positive) = 0.0099 divided by 0.0594, which is 1/6, or about 16.7%.

from fractions import Fraction

prevalence = Fraction(1, 100)      # P(disease)
sensitivity = Fraction(99, 100)    # P(positive | disease)
false_alarm = Fraction(5, 100)     # P(positive | no disease)

p_positive = sensitivity * prevalence + false_alarm * (1 - prevalence)
posterior = sensitivity * prevalence / p_positive
print("P(positive) =", p_positive)
print("P(disease | positive) =", posterior, "about", f"{float(posterior):.4f}")
P(positive) = 297/5000
P(disease | positive) = 1/6 about 0.1667

Key ideaThe base rate matters. A test with 99% sensitivity can still produce mostly false positives when the condition is rare. Bayes theorem is the tool that combines the base rate with the test evidence.

Maximum likelihood estimation (MLE)

A model with parameters theta assigns a probability to the observed data. The likelihood is that probability, viewed as a function of theta. Maximum likelihood estimation picks the theta that makes the observed data most probable. In practice we maximise the log-likelihood instead. The logarithm turns products of many small probabilities into sums, which avoids numerical underflow, and it does not move the maximum because log is increasing.

For a coin, each flip is a Bernoulli trial with heads probability p. With h heads in n flips, the log-likelihood is h log p plus (n - h) log(1 - p). Setting its derivative to zero gives p = h / n. So the MLE for a coin is simply the observed fraction of heads. For a Gaussian distribution, the MLE of the mean is the sample mean, and the MLE of the variance divides the sum of squared deviations by n, not n - 1. Dividing by n - 1 gives the unbiased estimate, which is what most statistics software reports by default. Mentioning that distinction is a good interview point.

The next program checks the coin result by brute force. It evaluates the log-likelihood on a grid of candidate values for p, using eight flips with six heads:

import math

flips = [1, 0, 1, 1, 0, 1, 1, 1]          # 1 = heads, 0 = tails

def log_likelihood(p):
    return sum(math.log(p) if f == 1 else math.log(1 - p) for f in flips)

grid = [i / 20 for i in range(1, 20)]    # candidate values 0.05, 0.10, ..., 0.95
best = max(grid, key=log_likelihood)
print("best p on grid:", best, "log-likelihood:", f"{log_likelihood(best):.4f}")
print("sample mean:", sum(flips) / len(flips))

Cross-entropy: the loss used for classification

Suppose a classifier outputs a probability for each class, and the true class is known. The cross-entropy between the true distribution p and the predicted distribution q is H(p, q) = minus the sum of p_i times log q_i. When the true label is one-hot (1 for the correct class, 0 elsewhere), this collapses to minus the log of the probability given to the correct class. The loss is small when the model gives the correct class a high probability, and it grows without bound as that probability approaches zero.

The link to MLE is the key idea. Minimising cross-entropy over a training set is the same as maximising the likelihood of the labels under the model, because the negative log-likelihood is the sum of the negative logs of the probabilities given to the correct labels. This is why logistic regression and neural network classifiers are trained with cross-entropy, often called log loss in scikit-learn. Predicted probabilities usually come from a softmax, which turns raw scores into positive numbers that sum to 1.

import math

probs = [0.1, 0.7, 0.2]    # predicted probabilities for three classes
true_index = 1             # the correct class is class 1

loss = -math.log(probs[true_index])
print(f"loss when the true class has 0.7: {loss:.4f}")
print(f"loss when the true class has 0.1: {-math.log(0.1):.4f}")
loss when the true class has 0.7: 0.3567
loss when the true class has 0.1: 2.3026

The two losses show the behaviour clearly. Giving the correct class 0.7 costs about 0.36, while giving it only 0.1 costs about 2.30. Confident wrong predictions are punished heavily, which pushes the model to spread its probability sensibly.

Explain Bayes theorem with the disease test example, and why the answer is about 17%.

Bayes theorem says P(disease given positive) equals P(positive given disease) times P(disease), divided by P(positive). The disease is rare (1%), so most positives come from the large healthy group, even though the false positive rate is only 5%. The numbers give 0.0099 divided by 0.0594, which is 1/6, about 16.7%.

What is the maximum likelihood estimate for a coin with 6 heads in 8 flips, and why do we use the log-likelihood?

The MLE is the observed fraction of heads, 6 divided by 8, which is 0.75. The log-likelihood is used because it turns a product of probabilities into a sum, which is numerically stable, and log is increasing so the maximiser is the same.

Why is cross-entropy the standard loss for classification?

For a one-hot label, cross-entropy is minus the log of the probability given to the correct class. Minimising it is equivalent to maximising the likelihood of the labels under the model, which is the principled MLE objective. It also gives strong gradients for confidently wrong predictions, which speeds up learning.

Interview questions

Answer each question in two or three sentences before reading the model answer. Where a question asks for a calculation, do the calculation on paper first.

What is broadcasting in NumPy?

Broadcasting lets arrays of different shapes combine in an element-wise operation. Shapes are aligned from the right, and a dimension of size 1 (or a missing dimension) is stretched to match the other operand, without copying data. A shape (2, 3) array plus a shape (3,) array adds the vector to each row.

Why are vectorised NumPy operations faster than Python loops?

The element-wise loop runs in compiled code rather than the interpreter, the data is stored contiguously in memory, and no Python object is created for each element. Writing the operation on whole arrays lets NumPy use all of these advantages.

What is the difference between a Series and a DataFrame?

A Series is a one-dimensional labelled array, such as one column. A DataFrame is a two-dimensional table whose columns are Series that share the same row index. Selecting one column with a single bracket returns a Series, and selecting several returns a DataFrame.

What does groupby followed by an aggregate do, step by step?

It first splits the rows into groups by the key columns. Then it applies the aggregate, such as mean or sum, to each group separately. Finally it combines the group results into a new object indexed by the group keys. Missing values are usually skipped by the aggregate.

When would you use an inner merge rather than a left merge?

Use an inner merge when a row is only useful if it has a match in both tables, such as orders that must have a known customer. Use a left merge when the main table must keep every row, and missing matches can be filled with NaN or a default value.

What is PCA, and what do its eigenvectors and eigenvalues mean?

PCA finds the directions along which centred data varies most. The directions are the eigenvectors of the covariance matrix, and the eigenvalues are the variances along them. Keeping the top k eigenvectors reduces the dimensions while keeping the largest share of the variance, which is the sum of the top k eigenvalues over the total.

What does the chain rule have to do with training a neural network?

A network is a long composition of functions, one per layer. Its loss depends on each weight through a chain of intermediate values. The chain rule multiplies the local derivatives along that chain, and backpropagation does this efficiently from the output back to the input, reusing intermediate results.

Explain the effect of the learning rate in gradient descent.

The learning rate scales each step. A small rate converges slowly but safely. A large rate can overshoot the minimum, oscillate or diverge. In practice it is tuned, often with a schedule that reduces it over time.

What is the maximum likelihood estimate of the variance for a Gaussian, and how does it differ from the unbiased estimate?

The MLE divides the sum of squared deviations from the sample mean by n. The unbiased estimate divides by n minus 1, which corrects for the fact that the sample mean is estimated from the same data. The MLE is slightly too small on average, but the difference shrinks as n grows.

Why do we use cross-entropy instead of accuracy as a training loss?

Accuracy is piecewise constant, so a small change in parameters often does not change it, and its gradient is zero almost everywhere. Cross-entropy is smooth and differentiable, and it rewards higher probabilities on the correct class, so it gives a useful gradient at every step. Accuracy is still reported as a metric.

Lowest Common Ancestor of a Binary Tree (LeetCode 236)

Given a binary tree and two nodes p and q that are in the tree and are different, return their lowest common ancestor (LCA). The LCA is the deepest node that has both p and q as descendants, where a node counts as its own descendant. Example 1: in the tree with values 3, 5, 1, 6, 2, 0, 8, 7 and 4 (the level-order list [3, 5, 1, 6, 2, 0, 8, null, null, 7, 4]), the LCA of 5 and 1 is 3. Example 2: the LCA of 5 and 4 is 5, because 5 is an ancestor of 4, so 5 counts as its own descendant.

How to think about it

  1. Understand. Both nodes exist and are distinct, so the answer always exists. A node is allowed to be the answer even when it is one of the two targets. Values are not unique in general, so compare node references, not values.
  2. Brute force. Find the path from the root to p and the path from the root to q, each as a list of nodes. Then walk both lists together and keep the last node they share. This is correct and runs in O(n) time, but it needs two full searches and two lists of up to n nodes.
  3. Find the waste. The two searches and the stored paths are only needed to find where the paths split. The split can be found in one pass, if each call reports what it found in its subtree.
  4. Optimise. Run a post-order search. Each call returns the node it found: p, q, or the LCA, or None if neither is below it. If the left and right calls both return a node, one target is in each subtree, so the current node is the LCA. If only one side returns a node, that node moves up unchanged. If the current node is p or q, return it immediately. This is correct even when the other target is below it, because the search stops at the ancestor, which is the answer.
  5. Dry run. Trace LCA(5, 1) and LCA(5, 4) in the example tree.
CallWhat it seesReturns
node 5 (it is p)Returns at once, without searching its children5
node 1 (it is q)Returns at once1
node 3 (root) for LCA(5, 1)Left returned 5 and right returned 1, so both sides found a target3
node 3 (root) for LCA(5, 4)Left returned 5. The right subtree under 1 holds neither target, so it returns None. Only one side has a result5

In the LCA(5, 4) case, the search never visits node 4. That is safe, because node 5 is returned as soon as it is found, and 5 is an ancestor of 4, so 5 is the answer.

Code

from collections import deque

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def build_tree(values):
    # LeetCode-style level order: None marks a missing child
    if not values or values[0] is None:
        return None
    root = TreeNode(values[0])
    queue = deque([root])
    i = 1
    while queue and i < len(values):
        node = queue.popleft()
        if i < len(values) and values[i] is not None:
            node.left = TreeNode(values[i])
            queue.append(node.left)
        i += 1
        if i < len(values) and values[i] is not None:
            node.right = TreeNode(values[i])
            queue.append(node.right)
        i += 1
    return root

def find_node(root, val):
    if root is None:
        return None
    if root.val == val:
        return root
    return find_node(root.left, val) or find_node(root.right, val)

def lowest_common_ancestor(root, p, q):
    # Returns p or q when it is found, and None when neither is below this node
    if root is None or root is p or root is q:
        return root
    left = lowest_common_ancestor(root.left, p, q)
    right = lowest_common_ancestor(root.right, p, q)
    if left and right:
        return root        # p and q were found in different subtrees
    return left if left else right

root = build_tree([3, 5, 1, 6, 2, 0, 8, None, None, 7, 4])
five, one, four, six = find_node(root, 5), find_node(root, 1), find_node(root, 4), find_node(root, 6)
print("LCA(5, 1) =", lowest_common_ancestor(root, five, one).val)
print("LCA(5, 4) =", lowest_common_ancestor(root, five, four).val)
print("LCA(6, 4) =", lowest_common_ancestor(root, six, four).val)
LCA(5, 1) = 3
LCA(5, 4) = 5
LCA(6, 4) = 5

Time O(n) · Space O(h) for the recursion stack, where h is the height of the tree

Pattern to rememberWhen an answer depends on both subtrees, let each call return a result upward and decide at the node where two results meet. Returning a value up the tree often replaces a second pass and stored paths.

Pacific Atlantic Water Flow (LeetCode 417)

You are given a grid of heights. Water can flow from a cell to a neighbouring cell (up, down, left or right) whose height is less than or equal to its own. The Pacific Ocean touches the top and left edges, and the Atlantic Ocean touches the bottom and right edges. Return every cell from which water can flow to both oceans. Example: [[1, 2, 2, 3, 5], [3, 2, 3, 4, 4], [2, 4, 5, 3, 1], [6, 7, 1, 4, 5], [5, 1, 1, 2, 4]] gives [[0, 4], [1, 3], [1, 4], [2, 2], [3, 0], [3, 1], [4, 0]], with the coordinates in row and column order.

How to think about it

  1. Understand. Water moves downhill or flat. A cell reaches an ocean if it can reach an edge cell of that ocean by a path that never goes uphill. The answer lists cells, so the grid coordinates matter.
  2. Brute force. For each cell, run a search over downhill moves and check whether it reaches the Pacific edge and the Atlantic edge. With m rows and n columns there are m times n cells, and each search can visit all of them, so the cost is O((mn) squared).
  3. Find the waste. Every search repeats work that other searches already did. Reverse the direction of flow instead. Ask which cells the ocean can reach by moving uphill from its edge, because water that starts at those cells can flow back down to the ocean.
  4. Optimise. Run two searches, each starting from all the edge cells of one ocean. From a cell, step to a neighbour only if the neighbour is at least as high. Mark every visited cell. The cells marked by both searches are the answer. Each search visits each cell at most once, so the total time is O(m times n).
  5. Dry run. Use the 2 by 2 grid [[1, 2], [4, 3]]. Its answer is [[0, 1], [1, 0], [1, 1]].
Cell (row, col)HeightReached from Pacific edgeReached from Atlantic edgeIn answer
(0, 0)1Yes, it is on the top and left edgesNo, both neighbours are higher, so uphill climbing from the Atlantic side cannot reach itNo
(0, 1)2Yes, it is on the top edgeYes, it is on the right edgeYes
(1, 0)4Yes, it is on the left edgeYes, it is on the bottom edgeYes
(1, 1)3Yes, the search climbs from (0, 1), height 2, to height 3Yes, it is on the bottom and right edgesYes

Code

def pacific_atlantic(heights):
    if not heights or not heights[0]:
        return []
    rows, cols = len(heights), len(heights[0])
    pacific = [[False] * cols for _ in range(rows)]
    atlantic = [[False] * cols for _ in range(rows)]

    def climb(starts, reached):
        # Walk uphill from the ocean edge: a cell that can climb to an edge cell
        # can let water flow back down to that edge.
        stack = []
        for r, c in starts:
            reached[r][c] = True
            stack.append((r, c))
        while stack:
            r, c = stack.pop()
            for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                nr, nc = r + dr, c + dc
                if 0 <= nr < rows and 0 <= nc < cols and not reached[nr][nc]:
                    if heights[nr][nc] >= heights[r][c]:
                        reached[nr][nc] = True
                        stack.append((nr, nc))

    pacific_edge = [(0, c) for c in range(cols)] + [(r, 0) for r in range(rows)]
    atlantic_edge = [(rows - 1, c) for c in range(cols)] + [(r, cols - 1) for r in range(rows)]
    climb(pacific_edge, pacific)
    climb(atlantic_edge, atlantic)
    return [[r, c] for r in range(rows) for c in range(cols) if pacific[r][c] and atlantic[r][c]]

print(pacific_atlantic([[1, 2, 2, 3, 5], [3, 2, 3, 4, 4], [2, 4, 5, 3, 1], [6, 7, 1, 4, 5], [5, 1, 1, 2, 4]]))
print(pacific_atlantic([[1, 2], [4, 3]]))
print(pacific_atlantic([[1]]))
[[0, 4], [1, 3], [1, 4], [2, 2], [3, 0], [3, 1], [4, 0]]
[[0, 1], [1, 0], [1, 1]]
[[0, 0]]

The last call is an edge case: a single cell touches both oceans, so it is in the answer. The rows and columns are both checked, so no special case is needed.

Time O(m · n) · Space O(m · n) for the two reached tables and the stacks

Pattern to rememberWhen many starting points must reach a common target, reverse the direction of the edges and search once from the target side. Two reversed searches replace many forward searches.

Vertical Order Traversal of a Binary Tree (LeetCode 987)

Give each node a position: the root is at column 0 and row 0, a left child is at column minus one and the next row, and a right child is at column plus one and the next row. Return the values grouped by column, from the leftmost column to the rightmost. Inside a column, list the values from top row to bottom row. If two nodes share the same row and column, list the smaller value first. Example 1: [3, 9, 20, null, null, 15, 7] gives [[9], [3, 15], [20], [7]]. Example 2: [1, 2, 3, 4, 5, 6, 7] gives [[4], [2], [1, 5, 6], [3], [7]].

How to think about it

  1. Understand. Each output list is a column. The order has three levels: column from left to right, row from top to bottom, then value for ties. The root's column is 0, and columns can be negative.
  2. Brute force. Walk the tree with a depth-first search, and record a triple of (column, row, value) for every node. Then sort all triples by column, row and value, and group them. This is correct. It costs O(n log n) for the sort, and it stores every triple before grouping.
  3. Find the waste. The sort does work that a traversal can provide. A breadth-first search visits the nodes row by row, from top to bottom, so within each column the rows arrive in order already. The only ordering left to fix is the value tie-break inside the same row.
  4. Optimise. Use a queue that carries (node, column, row). Append each node's value to a list for its column, using a dictionary keyed by column. Children go to columns one less or one more, one row lower. When the queue is empty, visit the columns in sorted order, and sort each column's list of (row, value) pairs so that ties are ordered by value. Each node is visited once, and each sort is over one column.
  5. Dry run. Trace Example 2, where the tree has 1 at the root, 2 and 3 as its children, and 4, 5, 6 and 7 at the next levels.

from collections import defaultdict, deque

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def build_tree(values):
    # LeetCode-style level order: None marks a missing child
    if not values or values[0] is None:
        return None
    root = TreeNode(values[0])
    queue = deque([root])
    i = 1
    while queue and i < len(values):
        node = queue.popleft()
        if i < len(values) and values[i] is not None:
            node.left = TreeNode(values[i])
            queue.append(node.left)
        i += 1
        if i < len(values) and values[i] is not None:
            node.right = TreeNode(values[i])
            queue.append(node.right)
        i += 1
    return root

def vertical_order(root):
    if root is None:
        return []
    columns = defaultdict(list)           # column -> list of (row, value)
    queue = deque([(root, 0, 0)])         # (node, column, row)
    while queue:
        node, col, row = queue.popleft()  # breadth-first: top rows come first
        columns[col].append((row, node.val))
        if node.left:
            queue.append((node.left, col - 1, row + 1))
        if node.right:
            queue.append((node.right, col + 1, row + 1))
    result = []
    for col in sorted(columns):           # left to right
        # top to bottom, and smaller value first for the same row
        result.append([val for row, val in sorted(columns[col])])
    return result

print(vertical_order(build_tree([3, 9, 20, None, None, 15, 7])))
print(vertical_order(build_tree([1, 2, 3, 4, 5, 6, 7])))
print(vertical_order(build_tree([])))
