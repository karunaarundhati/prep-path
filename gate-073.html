Trees & Binary Search Trees

A tree is a way to store data in levels, like a family tree or the folders on your computer. A binary search tree is a tree where smaller keys sit on the left and bigger keys sit on the right, so you can find a key quickly. GATE asks you to name tree parts, trace the four traversal orders, and find the cost of searching, inserting and deleting.

The idea in plain words

Imagine a company org chart. One person sits at the top. Each person has some people who report to them, and those people have their own reports. That picture is a tree. In computer science, a tree is a set of boxes (called nodes) joined by lines (called edges). There is one top box, the root, and every other box hangs below exactly one box above it.

A binary tree is a tree where every box has at most two children, one on the left and one on the right. Why would anyone want this? Because it gives a useful middle path between two simpler ways to store a list of numbers:

  • An array is fast to read by position, but inserting in the middle means shifting many items.
  • A linked list is fast to insert into, but to find a key you may have to walk through every item.

A binary search tree (BST) keeps the list in a shape that lets you throw away about half of the remaining choices at each step. Think of a dictionary. You open it near the middle, see whether your word comes before or after that page, and then ignore the other half. Each step cuts the problem down. A BST does exactly that, one box at a time.

Where does this appear in GATE DA? Tree questions usually ask you to trace a traversal (the order in which you visit every box), to build a BST from a list of keys, to count comparisons during a search, or to state the time complexity of an operation. Each of these needs the vocabulary and the rules on this page, so read the terms carefully.

Key ideaThe cost of searching, inserting or deleting in a BST depends on the height of the tree, not directly on the number of keys. A short, bushy tree is fast. A tall, thin tree behaves almost like a plain list.

Key terms

Read this list once now and come back to it whenever a word feels unclear.

Node
A box in the tree that holds one key (one value). Precisely: a node holds a key and links to its children.
Edge
A line joining a parent node to a child node. Precisely: the pair (parent, child) is an edge.
Root
The top node, which has no parent. Precisely: the only node that is not the child of any node.
Parent and child
The node above is the parent, the node below is its child. Precisely: a node with an edge pointing down to another node is that node's parent.
Sibling
Two nodes with the same parent. Precisely: children of one node are siblings of each other.
Leaf
A node with no children at all. Precisely: a node with zero children is a leaf.
Depth
How far a node is from the root, counted in edges. Precisely: depth of the root is 0, and depth of any other node is one more than its parent's depth.
Level
All nodes with the same depth form one level. Level 0 holds the root.
Height
How deep the tree goes. Precisely: the height of a node is the number of edges on the longest path from that node down to a leaf. The height of the tree is the height of the root.
Binary tree
A tree where each node has at most two children, called left and right. Precisely: each node has zero, one or two children.
Full binary tree
Every node has either zero or two children. Precisely: no node has exactly one child.
Complete binary tree
Every level is full except possibly the last, and the last level is filled from the left. Precisely: this is the shape used by heaps on the next page.
Binary search tree (BST)
A binary tree with an ordering rule. Precisely: for every node, all keys in its left subtree are smaller and all keys in its right subtree are bigger.
Subtree
A node together with all the nodes below it. Precisely: the subtree rooted at node v contains v and all of v's descendants.
Traversal
A rule for visiting every node exactly once in some order. Precisely: the four standard traversals are inorder, preorder, postorder and level-order.
Inorder, preorder, postorder
Three depth-first orders. Precisely: they differ only in when the root is visited compared with the left and right subtrees (before, between, or after).
Level-order
Visit the tree one level at a time, from left to right. Precisely: a breadth-first traversal that uses a queue.
Skewed tree
A tree that is almost a straight chain. Precisely: every node has at most one child, so the height is close to the number of nodes.
Balanced tree
A tree whose height stays small, close to log of the number of nodes. Precisely: the two subtrees of every node differ in height by at most a small amount (for AVL trees, by at most 1).
Inorder successor
The next key in sorted order after a given node. Precisely: the smallest key in that node's right subtree.

Tree words and how big a tree can get

Before you can answer any question about trees, you must read the shape. Here is the tree we will use on this whole page. Call it tree T. Its keys are 8, 3, 10, 1, 6, 14, 4, 7 and 13.

            8            <- root (level 0)
         /     \
        3       10          (level 1)
       / \        \
      1   6        14       (level 2)
         / \      /
        4   7    13         (level 3)

Read it top to bottom. Node 8 is the root because nothing is above it. Node 3 is the left child of 8, and node 10 is the right child of 8. Nodes 1, 4, 7 and 13 have no children, so they are leaves.

To find the depth of a node, count the edges you cross going from the root down to it. Node 8 has depth 0. Node 3 has depth 1, because one edge joins it to 8. Node 6 has depth 2, because the path is 8, 3, 6. Node 4 has depth 3, because the path is 8, 3, 6, 4.

To find the height of the whole tree, look for the longest path from the root down to any leaf and count its edges. The path 8, 3, 6, 4 has 3 edges. The path 8, 10, 14, 13 also has 3 edges. Nothing is longer, so the height of T is 3.

TrapTextbooks disagree about whether height counts edges or levels. Some say a single node has height 0 (edges), others say height 1 (levels). Always check which convention the question uses. This page counts edges unless it says otherwise.

How many nodes can fit?

A binary tree gets wider as you go down. The root is one node. Each node can have two children, so level 1 can hold at most 2 nodes, level 2 at most 4, and level 3 at most 8. In general, level k can hold at most 2k nodes.

If you add up all the levels from 0 up to height h, you get a total of 1 + 2 + 4 + ... + 2h. This sum equals 2h+1 - 1. So a binary tree of height h holds at most 2h+1 - 1 nodes.

max nodes at level k = 2k
max nodes in a binary tree of height h = 2h+1 - 1

Worked example. A binary tree has height 3. How many nodes can it have at most? Substitute h = 3: 23+1 - 1 = 24 - 1 = 16 - 1 = 15. Tree T has only 9 nodes, which is well under the limit.

In tree T, what is the depth of node 13?

The path is 8, 10, 14, 13. That path has 3 edges, so the depth of node 13 is 3.

Can a binary tree of height 2 hold 8 nodes?

No. The most it can hold is 23 - 1 = 7 nodes (levels 0, 1 and 2 hold 1, 2 and 4 nodes).

Four ways to visit every node

A traversal is a recipe for visiting every node exactly once. Think of how you might read every room in a house. You could go room by room in one wing before moving on, or you could go floor by floor. The three depth-first orders (inorder, preorder and postorder) all use the same recipe at each node: visit the node, visit the left subtree, visit the right subtree. Only the position of "visit the node" changes.

  • Preorder: node, then left subtree, then right subtree. The root comes first. Mnemonic: "pre" means before.
  • Inorder: left subtree, then node, then right subtree. The root sits in the middle. For a BST, this gives the keys in sorted order.
  • Postorder: left subtree, then right subtree, then node. The root comes last. Mnemonic: "post" means after.
  • Level-order: go level by level, from top to bottom, and from left to right within each level. This one is not recursive. It uses a queue, the same first-in, first-out line you would use at a bank.

Worked example on tree T

Let us do inorder by hand on the subtree under node 3 first, because that is the smallest piece. The subtree under 3 has left child 1 and right subtree rooted at 6 (which has children 4 and 7). Inorder on this piece is: inorder of 1, which is just 1; then 3; then inorder of the subtree at 6, which is 4, then 6, then 7. So the piece gives 1, 3, 4, 6, 7.

Now the whole tree. Inorder of the left subtree of 8 is 1, 3, 4, 6, 7. Then comes 8. The right subtree of 8 is rooted at 10, with no left child and right child 14. Its inorder is 10, then the inorder of 14, which is 13, then 14. So the right side gives 10, 13, 14. The full inorder is 1, 3, 4, 6, 7, 8, 10, 13, 14.

Preorder starts at the root, so the first key is 8. Then we walk the left subtree in preorder: 3, then 1, then the subtree at 6 which gives 6, 4, 7. Then the right subtree: 10, 14, 13. Full preorder: 8, 3, 1, 6, 4, 7, 10, 14, 13.

Postorder puts the root last. The left subtree gives 1, 4, 7, 6, 3 and the right subtree gives 13, 14, 10. Then 8 comes last. Full postorder: 1, 4, 7, 6, 3, 13, 14, 10, 8.

Level-order reads the levels from the diagram: level 0 is 8; level 1 is 3, 10; level 2 is 1, 6, 14; level 3 is 4, 7, 13. Full level-order: 8, 3, 10, 1, 6, 14, 4, 7, 13.

Here is the same work done by a Python program. It builds the tree by inserting the keys in the order 8, 3, 10, 1, 6, 14, 4, 7, 13. You will see the BST insertion rule in the next unit. Notice that the program prints exactly what we found by hand.

class Node:
    def __init__(self, key):
        self.key = key
        self.left = None
        self.right = None

def insert(root, key):
    if root is None:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
    elif key > root.key:
        root.right = insert(root.right, key)
    return root

def inorder(node):
    if node is None:
        return []
    return inorder(node.left) + [node.key] + inorder(node.right)

def preorder(node):
    if node is None:
        return []
    return [node.key] + preorder(node.left) + preorder(node.right)

def postorder(node):
    if node is None:
        return []
    return postorder(node.left) + postorder(node.right) + [node.key]

def level_order(root):
    result = []
    queue = [root] if root is not None else []
    while queue:
        node = queue.pop(0)
        result.append(node.key)
        if node.left is not None:
            queue.append(node.left)
        if node.right is not None:
            queue.append(node.right)
    return result

root = None
for key in [8, 3, 10, 1, 6, 14, 4, 7, 13]:
    root = insert(root, key)

print("inorder:", inorder(root))
print("preorder:", preorder(root))
print("postorder:", postorder(root))
print("level order:", level_order(root))
inorder: [1, 3, 4, 6, 7, 8, 10, 13, 14]
preorder: [8, 3, 1, 6, 4, 7, 10, 14, 13]
postorder: [1, 4, 7, 6, 3, 13, 14, 10, 8]
level order: [8, 3, 10, 1, 6, 14, 4, 7, 13]

GATE loves thisInorder of any BST is sorted in increasing order. This is true for every BST, whatever its shape. Many questions give you a tree and ask which traversal produces sorted output. The answer is always inorder.

Which traversal visits the root before both subtrees?

Preorder. The root is visited first, then the left subtree, then the right subtree.

What is the last key printed by postorder on any tree?

The root. In postorder the node is visited after both of its subtrees, so the root is always the last one printed.

The BST rule, search, insert and delete

A binary search tree follows one rule. For every node, every key in its left subtree is smaller than the node's key, and every key in its right subtree is bigger. Duplicates are usually not allowed in the basic version. Tree T is a valid BST: at node 8, the left side holds 1, 3, 4, 6, 7 (all less than 8) and the right side holds 10, 13, 14 (all greater than 8). The same check works at every other node.

Key ideaThe BST rule means you can decide the direction at every node. If the key you want is smaller than the node, go left. If it is bigger, go right. You never need to look at the other side.

Search

To search for key x, start at the root. Compare x with the node's key. If they are equal, you found it. If x is smaller, move to the left child. If x is bigger, move to the right child. If you reach an empty spot (no child), the key is not in the tree.

Example: search for 13 in tree T. Start at 8: 13 is bigger, go right to 10. At 10: 13 is bigger, go right to 14. At 14: 13 is smaller, go left to 13. At 13: equal, found. That took 4 comparisons (8, 10, 14 and 13).

Search for 5 in tree T. Start at 8: 5 is smaller, go left to 3. At 3: 5 is bigger, go right to 6. At 6: 5 is smaller, go left to 4. At 4: 5 is bigger, go right. The right child of 4 is empty, so 5 is not in the tree. That took 4 comparisons.

The program below counts the comparisons. It uses the same insert function as before, so the tree is identical.

class Node:
    def __init__(self, key):
        self.key = key
        self.left = None
        self.right = None

def insert(root, key):
    if root is None:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
    elif key > root.key:
        root.right = insert(root.right, key)
    return root

def search(root, key):
    steps = 0
    node = root
    while node is not None:
        steps += 1
        if key == node.key:
            return True, steps
        if key < node.key:
            node = node.left
        else:
            node = node.right
    return False, steps

root = None
for key in [8, 3, 10, 1, 6, 14, 4, 7, 13]:
    root = insert(root, key)

print(search(root, 13))
print(search(root, 5))
(True, 4)
(False, 4)

Insert

Insertion is search that ends in an empty spot. You walk down exactly as in search. When you reach an empty child position, you put the new node there. Nothing else moves. So inserting 5 into tree T would hang a new node as the right child of 4.

Delete

Deletion has three cases. First search for the key. Then:

  1. The node is a leaf. Remove it. Its parent's pointer becomes empty. Example: delete 13 from T, and the left child of 14 becomes empty.
  2. The node has one child. Remove the node and let its single child take its place. Example: delete 10 from T. Node 10 has only one child, 14, so 14 moves up to be the right child of 8. The node 13 stays under 14.
  3. The node has two children. Find the inorder successor: the smallest key in the right subtree. Copy that key into the node, then delete the successor from the right subtree (the successor has at most one child, so this is case 1 or 2). Example: delete 3 from T. Its right subtree is rooted at 6, and the smallest key there is 4. Copy 4 into the node that held 3, then delete the old 4 from below 6. The result still obeys the BST rule: 1, 4, 6, 7, 8, 10, 13, 14 in inorder.

TrapIn case 3, students often copy the wrong key. You may also use the inorder predecessor (the largest key in the left subtree). Both are correct. Use the one the question uses, and never forget to delete the copied node afterwards.

Which key is the inorder successor of 6 in tree T?

The smallest key in the right subtree of 6. Node 6 has children 4 and 7, but 4 is on the left. The right subtree is just 7, so the successor is 7. (In inorder the list reads 6, 7, so 7 comes next.)

When you delete a node with two children, why must you copy a key and then delete the successor?

Because the node has two subtrees, and you cannot remove it without breaking one of them. Copying the successor keeps the BST rule and leaves a node with at most one child to remove.

Balanced and skewed trees: why the shape matters

Search, insert and delete all follow one path from the root down to some node. The number of steps is the length of that path, which is at most the height h of the tree. So each of these operations costs O(h) time.

Now the shape decides everything. Insert the sorted keys 1, 2, 3, 4, 5 into an empty BST. Each new key is bigger than all the ones before it, so it always goes right. The result is a chain: 1 at the root, 2 to its right, and so on down to 5. The height is 4 and the tree is skewed. Searching for 5 takes 5 comparisons, the same as scanning a plain list.

Now insert the keys 3, 1, 4, 2, 5 in that order. The root is 3. Then 1 goes left, 4 goes right, 2 goes right of 1, and 5 goes right of 4. The height is 2 and the tree is much shorter. Searching for 5 takes 3 comparisons.

search, insert, delete cost = O(h), where h = height of the tree

For a tree that stays balanced, the height is about log2 n, where n is the number of keys. For n = 1,000,000 keys, log2 n is about 20. So a balanced BST needs only about 20 comparisons for a million keys. For a skewed tree, the height is n - 1, so searching a million keys could take a million steps.

balanced tree: h = O(log n), so operations take O(log n)
skewed tree: h = n - 1, so operations take O(n)

TrapThe O(log n) cost is the best case and the typical case for random insertions, not the worst case. The worst case for a plain BST is O(n), when the input is sorted and the tree becomes a chain. Many GATE options say "O(log n) in the worst case". That is false for an ordinary BST.

Self-balancing trees such as AVL trees and red-black trees use small rotations after each change to keep the height at O(log n) in the worst case.

Why does inserting sorted keys produce a skewed tree?

Each new key is bigger than every key already in the tree, so at every node the rule sends it right. The tree becomes one long chain going right.

What is the worst-case time to search an ordinary BST with n keys?

O(n). The search can visit every node if the tree is a chain, so its cost equals the height, which is n - 1 in the worst case.

Depth and height of tree T

In tree T (root 8), what is the depth of node 4, and what is the height of the whole tree? Use edges as the unit.

How to think about it

  1. What is asked. Two numbers: the depth of one node and the height of the tree.
  2. Which idea applies. Depth counts edges from the root down to the node. Height is the longest such path from the root to any leaf.
  3. Work it out. The path from 8 to 4 is 8, 3, 6, 4. It has 3 edges, so depth(4) = 3. The longest root-to-leaf path is 8, 3, 6, 4 or 8, 10, 14, 13. Both have 3 edges, so the height is 3.
  4. Check. The levels of T are 0, 1, 2 and 3. The deepest level is 3, which matches the height.

Answer: depth of node 4 is 3. Height of the tree is 3.

Traversals of a small tree

A binary tree has root 50. Its left child is 30 and its right child is 70. Node 30 has children 20 (left) and 40 (right). Node 70 and nodes 20 and 40 are leaves. Write the preorder and the postorder of this tree.

How to think about it

  1. What is asked. Two orders: preorder and postorder.
  2. Which idea applies. Preorder visits the node, then left, then right. Postorder visits left, then right, then the node.
  3. Work it out. Preorder: 50 first. Then the left subtree at 30 in preorder is 30, 20, 40. Then 70. So 50, 30, 20, 40, 70. Postorder: left subtree at 30 in postorder is 20, 40, 30. Then the right subtree 70. Then 50. So 20, 40, 30, 70, 50.
  4. Check. Each list has 5 entries, one per node, and the root is first in preorder and last in postorder.

Answer: preorder is 50, 30, 20, 40, 70. Postorder is 20, 40, 30, 70, 50.

Which statements about tree capacity are true?

Select all that apply. Consider binary trees with the root at level 0.

  • (A) Level 3 can hold at most 8 nodes.
  • (B) A binary tree of height 3 can hold at most 15 nodes.
  • (C) A binary tree of height 3 must have at least 4 leaves.
  • (D) A binary tree with 7 nodes can have height 2.

How to think about it

  1. What is asked. Which of the four options are true. More than one may be true.
  2. Which idea applies. Level k holds at most 2k nodes. A tree of height h holds at most 2h+1 - 1 nodes.
  3. Work it out. (A) 23 = 8, so true. (B) 24 - 1 = 15, so true. (C) A chain of 4 nodes has height 3 and only one leaf, so the claim is false. (D) A perfect tree with levels 0, 1 and 2 has 1 + 2 + 4 = 7 nodes and height 2, so true.
  4. Check. Option C fails because a chain is allowed. Ask yourself whether you can make a counterexample. You can, so C is false.

Answer: (A), (B) and (D). Option (C) is false.

Comparisons during a search

In tree T (root 8, as on this page), how many key comparisons does a standard BST search make when it looks for 13, counting the comparison that finds 13?

How to think about it

  1. What is asked. The number of comparisons, including the final one that succeeds.
  2. Which idea applies. At each visited node, compare the key with the node. Stop when equal.
  3. Work it out. Compare with 8 (13 is bigger, go right). Compare with 10 (bigger, go right). Compare with 14 (smaller, go left). Compare with 13 (equal, stop). That is 4 comparisons.
  4. Check. The number of comparisons equals the number of nodes on the path, here 8, 10, 14 and 13. The depth of 13 is 3, and depth plus 1 gives 4.

Answer: 4 comparisons.

Two insertion orders, two shapes

Insert the keys 1, 2, 3, 4, 5 into an empty BST in that order. Call this tree P. Then insert the same five keys in the order 3, 1, 4, 2, 5 into a second empty BST. Call this tree Q. Find the height (in edges) of P and of Q, and the number of comparisons needed to search for 5 in each.

How to think about it

  1. What is asked. Two heights and two comparison counts.
  2. Which idea applies. The order of insertion sets the shape. Sorted input gives a chain. Search cost equals the path length.
  3. Work it out. P: each key goes right of the previous one, so the chain is 1, 2, 3, 4, 5 going right. Height 4. Searching for 5 visits 1, 2, 3, 4, 5, which is 5 comparisons. Q: root 3, left 1, right 4, then 2 goes right of 1 and 5 goes right of 4. Height is 2 (path 3, 1, 2 or 3, 4, 5). Searching for 5 visits 3, 4, 5, which is 3 comparisons.
  4. Check. Both trees hold the same five keys, so their inorder lists are both 1, 2, 3, 4, 5. Only the shape differs. The Python check below confirms the heights.

Answer: P has height 4 and needs 5 comparisons for 5. Q has height 2 and needs 3 comparisons for 5.

def insert(node, key):
    if node is None:
        return [key, None, None]
    if key < node[0]:
        node[1] = insert(node[1], key)
    else:
        node[2] = insert(node[2], key)
    return node

def height(node):
    if node is None:
        return -1
    return 1 + max(height(node[1]), height(node[2]))

for order in ([1, 2, 3, 4, 5], [3, 1, 4, 2, 5]):
    root = None
    for k in order:
        root = insert(root, k)
    print(order, "height", height(root))

Which statements about BSTs and traversals are true?

Select all that apply.

  • (A) Inorder traversal of any BST lists its keys in sorted order.
  • (B) Preorder traversal of any BST always lists its keys in sorted order.
  • (C) Searching an ordinary BST with n keys takes O(log n) time in the worst case.
  • (D) The number of different BST shapes that can store 3 distinct keys is 5.
  • (E) Postorder traversal visits the root before its children.

How to think about it

  1. What is asked. Which of the five claims are true for ordinary BSTs.
  2. Which idea applies. Inorder is sorted for every BST. Preorder is not. Worst-case search is O(height), and the height can be n - 1. The number of BST shapes for n keys is the Catalan number Cn.
  3. Work it out. (A) True, by the inorder rule. (B) False: tree T gives preorder 8, 3, 1, 6, which is not sorted. (C) False: a chain of n keys has height n - 1, so search takes O(n) in the worst case. (D) The Catalan number C3 = (6 choose 3) / 4 = 20 / 4 = 5, so true. (E) False: postorder visits the root last.
  4. Check. Run the calculation for D in Python to be sure of the number.

Answer: (A) and (D).

from math import comb

n = 3
print(comb(2 * n, n) // (n + 1))

Exam-level 1: BST height after inserts (NAT, 2 marks)

Insert 50, 30, 70, 20, 40, 60, 80, 35, 45, 42 into an empty BST. What is the height (edges on the longest root to leaf path)?

How to think about it

  1. What is asked. The height of the resulting tree.
  2. Which idea applies. Trace each insert down the tree.
  3. Work it out. 42 goes 50 → 30 → 40 → 45 → left of 45. Path length 4 edges.
  4. Check. The code builds the tree.
def ins(t, k):
    if t is None: return [k, None, None]
    if k < t[0]: t[1] = ins(t[1], k)
    else: t[2] = ins(t[2], k)
    return t
def h(t): return -1 if t is None else 1 + max(h(t[1]), h(t[2]))
t = None
for k in (50, 30, 70, 20, 40, 60, 80, 35, 45, 42): t = ins(t, k)
print(h(t))

4

Answer: 4.

Exam-level 2: Traversal reconstruction (MCQ, 2 marks)

A binary tree has preorder A B D E C F and inorder D B E A F C. What is its postorder? (A) D E B F C A (B) D B E F C A (C) E D B F C A (D) D E F B C A

How to think about it

  1. What is asked. The postorder of the tree defined by two traversals.
  2. Which idea applies. Preorder gives the root first. Inorder splits left and right subtrees around it.
  3. Work it out. Root A. Left inorder D B E with root B (children D and E). Right inorder F C with root C and left child F. Postorder: D E B F C A.
  4. Check. The code rebuilds and prints the postorder.
def post(pre, ino):
    if not pre: return ""
    r = pre[0]; i = ino.index(r)
    return post(pre[1:i + 1], ino[:i]) + post(pre[i + 1:], ino[i + 1:]) + r
print(post("ABDECF", "DBEAFC"))

DEBFCA

Answer: (A).

Exam-level 3: Counting BSTs (NAT, 2 marks)

How many structurally different BSTs can store the keys 1, 2, 3, 4, 5?

How to think about it

  1. What is asked. The Catalan number C5.
  2. Which idea applies. Choose each key as root: Cn = Σ CiCn−1−i.
  3. Work it out. C0 to C5: 1, 1, 2, 5, 14, 42.
  4. Check. The code computes it.
C = [1]
for n in range(1, 6): C.append(sum(C[i] * C[n - 1 - i] for i in range(n)))
print(C)

[1, 1, 2, 5, 14, 42]

Answer: 42.

Summary

Tree
Nodes joined by edges, with one root at the top. Precisely: a connected structure with no cycles.
Root
The one node with no parent.
Leaf
A node with no children.
Depth
Edges from the root down to a node. The root has depth 0.
Height
Edges on the longest path from the node down to a leaf.
Binary tree
Every node has at most two children, left and right.
Level-order
Visit the tree one level at a time, using a queue.
Preorder
Node, then left subtree, then right subtree.
Inorder
Left subtree, then node, then right subtree. Sorted for a BST.
Postorder
Left subtree, then right subtree, then node.
BST rule
Left subtree keys are smaller than the node, right subtree keys are bigger.
Search in a BST
Walk from the root, going left or right by comparison, until found or empty.
Insert in a BST
Search for the key; put the new node in the empty spot where the search ends.
Delete in a BST
Leaf: remove. One child: child takes the place. Two children: copy the inorder successor, then delete it.
Inorder successor
Smallest key in the right subtree of a node.
Skewed tree
Almost a chain, so its height is close to n.
Balanced tree
Height is about log2 n, so operations are fast.
Time of BST operations
O(h), where h is the height of the tree.
Worst case of a plain BST
O(n), when the input is sorted and the tree is a chain.
Capacity of height h
At most 2h+1 - 1 nodes in a binary tree.
Catalan number
Cn = (2n choose n) / (n + 1) counts the distinct BST shapes for n keys.

Remember these

  1. Inorder traversal of a BST gives the keys in sorted order.
  2. The cost of a BST operation is the height, not the number of keys.
  3. Sorted input produces a skewed tree with height n - 1 and O(n) operations.
  4. Always check whether height is counted in edges or in levels.
  5. Preorder visits the root first, postorder visits it last.
  6. Delete a node with two children by copying its inorder successor and deleting that successor.
