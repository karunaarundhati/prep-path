Cloud computing, service models and responsibility

Cloud computing means renting computing resources (servers, disks, networks, databases and software) over the internet, instead of buying hardware and running it yourself. You ask for what you need, use it for as long as you need it, and pay for what you used. The US National Institute of Standards and Technology (NIST) describes cloud services with five traits: on-demand self-service (you provision resources yourself, without asking a person), broad network access (you reach them over standard networks), resource pooling (many customers share the same physical hardware, kept apart by software), rapid elasticity (capacity can grow or shrink quickly), and measured service (you are billed for what you consume).

Most cloud resources are made possible by virtualization. A piece of software called a hypervisor splits one physical server into several isolated virtual machines (VMs). Each VM looks like its own computer with its own operating system, even though many VMs share the same metal. When you rent a server in the cloud, you almost always get a VM.

IaaS, PaaS and SaaS

Cloud services are grouped by how much of the stack the provider runs for you. Picture the stack from bottom to top: physical data centers, hardware, virtualization, operating system, runtime (for example the Python interpreter), middleware (databases, message brokers), the application code, and finally the data. The further down the stack the provider takes responsibility, the less you have to manage, and the less control you have.

  • IaaS (Infrastructure as a Service) gives you raw building blocks: virtual machines, disks, networks and load balancers. You install the operating system, the runtime, your software and your data. Example: Amazon EC2.
  • PaaS (Platform as a Service) gives you a platform on which you deploy code. The provider manages the operating system and the runtime, and usually handles patching and scaling of the platform. You manage your application and your data. Examples: AWS Elastic Beanstalk, Google App Engine, Heroku.
  • FaaS (Function as a Service) is a special kind of PaaS, often called serverless. You upload a single function, and the platform runs it each time an event happens (an HTTP request, a file upload, a message). You never see a server. Example: AWS Lambda.
  • SaaS (Software as a Service) gives you a finished application that you use through a browser or an app. You manage only your settings, your users and the data you type in. Examples: Gmail, Salesforce, Microsoft 365.

The shared responsibility model

Cloud security is always shared between the provider and the customer. AWS puts it this way: AWS is responsible for security of the cloud, and the customer is responsible for security in the cloud. Security of the cloud covers the physical data centers, the hardware, the network backbone and the virtualization layer. Security in the cloud covers everything you configure and put there: your data, who may access it, how your operating system is patched, and how your firewall rules are written.

The split moves depending on the service. For an EC2 virtual machine, you patch the operating system, because you control it. For Amazon RDS (a managed relational database), AWS patches the database engine and the underlying operating system, but you still decide who can connect and whether the data is encrypted. The rule of thumb: whoever controls a layer is responsible for securing it.

Regions and availability zones

AWS organizes its infrastructure in three layers. A region is a separate geographic area, such as us-east-1 (Northern Virginia). Each region is independent: data stored in one region stays there unless you copy it. Inside a region there are several availability zones (AZs). An AZ is one or more physical data centers with their own power, cooling and networking. AZs in the same region are connected by fast, low-latency links, but a failure in one AZ (a power cut, a fire, a network fault) should not take down the others. Finally, edge locations are many smaller sites around the world, used by services such as CloudFront to cache content close to users.

Zone names such as us-east-1a are mapped to physical data centers differently for each account, so two accounts may see "1a" as different buildings. If you need to refer to the same physical zone across accounts, AWS provides zone IDs such as use1-az1.

Why does this matter? There are three reasons to choose a region carefully. The first is latency: a region near your users answers faster, because light in fiber needs time to travel. The second is data residency: some laws require personal data to stay in a given country. The third is availability: you spread a system across at least two AZs so that one failing zone does not stop your application, and for disaster recovery you may copy data to a second region.

Key ideaA region is a place, an availability zone is a data center inside that place, and high availability means running in at least two AZs.

What is the difference between IaaS and PaaS?

With IaaS you rent raw infrastructure such as virtual machines, disks and networks, and you manage the operating system, the runtime and your application. With PaaS the provider also manages the operating system and runtime, and you deploy only your code and data.

Who patches the operating system on an EC2 instance, and who patches the engine of an RDS database?

You patch the operating system on EC2, because you control that machine. For RDS, AWS patches the database engine and the underlying operating system, while you choose who may connect and whether the data is encrypted.

Why do production systems usually run in two or more availability zones?

An availability zone is a separate data center with its own power and cooling. If one zone fails, instances in another zone in the same region keep serving traffic, so the system stays available.

Compute: EC2, Auto Scaling and Lambda

Compute means the processing power that runs your code. On AWS there are three common ways to get it. You can rent virtual machines (EC2), you can run a fleet of them that grows and shrinks automatically (Auto Scaling), or you can run single functions without managing any machine (Lambda).

EC2 (Elastic Compute Cloud)

An EC2 instance is a virtual machine that you launch in a region and an availability zone. Four choices shape it. The first is the AMI (Amazon Machine Image), which is a template holding the operating system and any preinstalled software. The second is the instance type, which sets the CPU, memory and network capacity. Instance types are grouped in families named by a letter: t for burstable general purpose, m for balanced general purpose, c for compute-heavy work, r for memory-heavy work, and g or p for GPU work. The third is the storage, usually an EBS volume (covered in the storage section below). The fourth is the network placement: the subnet and security groups, which come later in this page.

There are several ways to pay for an instance. With On-Demand you pay for the time the instance runs, with no commitment. With Savings Plans or Reserved Instances you promise a level of usage for one or three years and get a lower price. With Spot Instances you use spare AWS capacity at a large discount, but AWS can reclaim the instance, and you receive a two-minute interruption notice. Spot suits batch jobs that can be stopped and restarted, not a primary database.

Every instance is created from a launch template: the AMI, the type, the key pair used for SSH login, the subnet, the security groups and the user data script. User data is a script that runs once at first boot. It is how a fresh server installs its software automatically.

# Launch one instance from an AMI (the IDs are placeholders)
aws ec2 run-instances \
  --image-id ami-0123456789abcdef0 \
  --instance-type t3.micro \
  --key-name my-key \
  --subnet-id subnet-0abc1234 \
  --security-group-ids sg-0def5678 \
  --count 1

# List the IDs of running instances
aws ec2 describe-instances \
  --filters "Name=instance-state-name,Values=running" \
  --query "Reservations[].Instances[].InstanceId"

The commands above are real AWS CLI syntax, but the IDs are placeholders, so they will not run unchanged on your account. The first command returns a large JSON description of the new instance. The second returns the IDs of the running instances.

Auto Scaling groups

A single server is a single point of failure, and a fixed number of servers wastes money at quiet times. An Auto Scaling group keeps a fleet of identical instances between a minimum and a maximum size. You set three numbers: minimum (never go below this), desired (the current target), and maximum (never go above this). The launch template describes what each new instance looks like. A scaling policy changes the desired number. The most common is target tracking, where you say "keep average CPU near 50 percent" and AWS adds or removes instances to hold that target. Scheduled actions are another option, for example "add capacity every weekday at 9 am".

The group also runs health checks. If an instance fails, the group terminates it and starts a replacement. When you spread the group across several AZs, the group balances instances between them, so one zone failure leaves the others running. An Elastic Load Balancer (covered on day 26) usually sits in front of the group and sends traffic only to healthy instances.

# Set the desired number of instances in an Auto Scaling group
aws autoscaling set-desired-capacity \
  --auto-scaling-group-name web-asg \
  --desired-capacity 4

AWS Lambda

Lambda runs a function in response to an event, without you managing a server. You write a function, choose a runtime (Python, Node.js, Java and others), set a memory size and a timeout, and attach a trigger. Triggers include an HTTP request through API Gateway, a file upload to S3, a message in SQS, or a scheduled rule in EventBridge. Each run is an invocation. You pay per request and for the duration of each run, measured as memory multiplied by time.

Three facts matter in interviews. Lambda functions are stateless: nothing you keep in memory is guaranteed to survive to the next call, so keep state in S3, DynamoDB or a cache. A function has a maximum timeout of 15 minutes, so long jobs belong on EC2, containers or a batch service. Memory can be set from 128 MB up to 10,240 MB, and CPU power grows with the memory setting. When AWS has to create a new execution environment, the first call pays a start-up delay called a cold start. Environments that already exist are reused for later calls, which are "warm".

The handler is the function Lambda calls. Its signature is handler(event, context): event is the input (a dictionary for JSON triggers) and context carries runtime information. The code below is a complete program. It defines the handler and calls it locally with fake events, which is how you test a handler before deploying it.

import json

def handler(event, context):
    # The event is a dictionary, here built by hand for the local test
    name = event.get("name", "world")
    body = {"message": "hello " + name}
    return {"statusCode": 200, "body": json.dumps(body)}

if __name__ == "__main__":
    # Simulate invocations: context is None because we are not inside Lambda
    print(handler({"name": "Ada"}, None))
    print(handler({}, None))
{'statusCode': 200, 'body': '{"message": "hello Ada"}'}
{'statusCode': 200, 'body': '{"message": "hello world"}'}

Step by step: event.get("name", "world") reads the key name and falls back to "world" when the key is missing, which is why the second call prints "hello world". json.dumps turns the Python dictionary into a JSON string, because HTTP bodies are text. The returned dictionary has the shape that API Gateway expects from a Lambda proxy integration. When Lambda runs for real, it calls handler with the actual event and context, and your local test block is ignored.

What is a launch template and what does an Auto Scaling group do with it?

A launch template describes the configuration of each new instance: the AMI, instance type, key pair, security groups and user data. The Auto Scaling group uses it to create identical instances whenever it needs to grow, and it replaces instances that fail health checks.

Why must a Lambda function not rely on data kept in a global variable?

Lambda functions are stateless. An execution environment may be reused for later calls, but AWS can discard it at any time, and parallel requests use different environments. Anything that must survive belongs in S3, DynamoDB or another external store.

What is a Spot Instance, and what kind of work fits it?

A Spot Instance uses spare AWS capacity at a large discount. AWS can interrupt it with a two-minute notice, so it suits fault-tolerant batch jobs, rendering or data processing that can be checkpointed, and not a single primary database.

Storage: S3, EBS and EFS

Storage in the cloud comes in three shapes, and interviewers often ask you to choose between them. Block storage behaves like a hard disk attached to one machine: the operating system formats it and reads and writes small blocks. Amazon EBS is block storage. File storage is a shared folder tree that many machines mount at the same time over a network protocol. Amazon EFS is file storage. Object storage stores whole files, called objects, in a flat namespace and reaches them over HTTP with an API. Amazon S3 is object storage.

S3 (Simple Storage Service)

An S3 bucket is a container with a globally unique name, created in one region. Inside it you store objects. Each object has a key (its name, such as reports/2026/q1.csv), the data itself, and metadata. S3 has no real folders. The slashes in a key are only a naming convention that the console displays as folders, which is why the key is the right word for the name and not "path".

S3 is designed for 11 nines of durability (99.999999999 percent) for its standard classes. Durability means the chance that an object is lost. Availability is a different number: it is the chance that you can read the object right now, and it is lower. A durable object can still be temporarily unreachable.

Storage classes trade cost against access speed and retrieval fees. The main classes are S3 Standard (frequent access), S3 Intelligent-Tiering (moves objects between tiers automatically when access patterns change), S3 Standard-IA and S3 One Zone-IA (cheaper storage for data you read rarely, with retrieval fees; One Zone keeps data in a single AZ), S3 Glacier Instant Retrieval, S3 Glacier Flexible Retrieval (retrieval in minutes to hours) and S3 Glacier Deep Archive (the cheapest, with retrieval in hours). A lifecycle rule moves objects to a cheaper class after a number of days, or deletes them when they expire, without anyone running a job by hand.

{
  "Rules": [
    {
      "ID": "archive-logs",
      "Filter": {"Prefix": "logs/"},
      "Status": "Enabled",
      "Transitions": [
        {"Days": 30, "StorageClass": "STANDARD_IA"},
        {"Days": 180, "StorageClass": "GLACIER"}
      ],
      "Expiration": {"Days": 365}
    }
  ]
}

The rule above applies to every object whose key starts with logs/. After 30 days the object moves to Standard-IA, after 180 days to Glacier Flexible Retrieval (GLACIER is its API name), and after 365 days it is deleted. Lifecycle rules are one of the simplest ways to cut storage costs.

Other S3 features you should know: versioning keeps every previous version of an object when you overwrite or delete it, which protects against mistakes. Bucket policies are resource-based access rules attached to the bucket. Presigned URLs are links that include a signature and an expiry time, so a user can download or upload one object without holding AWS credentials. Server-side encryption is applied to new objects by default.

# Upload a file and choose a cheaper storage class at upload time
aws s3 cp report.csv s3://my-reports-bucket/2026/report.csv --storage-class STANDARD_IA

# List the objects under a prefix (a pretend folder)
aws s3 ls s3://my-reports-bucket/2026/

EBS (Elastic Block Store)

An EBS volume is a virtual disk that you attach to one EC2 instance. The volume lives in one availability zone, so the instance must be in that same zone. Unlike the disk inside a physical server, an EBS volume survives when the instance is stopped, and you can detach it and attach it to another instance in the same zone. You take snapshots of a volume to back it up. A snapshot is incremental (after the first one, only changed blocks are stored), and it is kept in AWS-managed storage that you can copy to another region for disaster recovery.

Volume types differ by performance. gp3 is a general-purpose SSD and the usual default. io2 is a provisioned-performance SSD for demanding databases. st1 is a throughput-optimized hard disk for large sequential reads, such as log processing. The rule of thumb: SSD for random access patterns, HDD for big sequential scans.

An instance store is different. It is physical disk attached directly to the host server. It is very fast, but its data is lost when the instance stops or terminates, or when the host fails. Use it for caches and scratch space, never for the only copy of anything.

EFS (Elastic File System)

An EFS file system is a managed NFS (Network File System) share. Many EC2 instances, in several availability zones, mount the same file system and see the same files at the same time. It grows and shrinks automatically, and you pay for the data you store. EFS works with Linux instances over NFS. It costs more per gigabyte than EBS, so you pay for it when many machines need shared files, such as a content directory for a fleet of web servers.

Why is S3 durability described as eleven nines, and why is that different from availability?

Durability is the probability that stored data is not lost, and S3 standard classes are designed for 99.999999999 percent. Availability is the probability that the service answers a request at a given moment, which is a smaller number. Data can be safe but temporarily unreachable.

A database needs a fast disk for one server. Which storage type fits, and what is the catch?

An EBS SSD volume such as gp3 or io2 fits, because it is block storage attached to one instance with high performance. The catch is that the volume lives in one availability zone, so the server and its disk cannot move to another zone, and you need snapshots for backup.

When would you choose EFS over S3?

Choose EFS when many Linux instances need to read and write the same files as a normal file system, with standard paths and file locking. Choose S3 when you store whole objects and access them through an API or a URL, such as backups, images and data files.

Networking: VPC, subnets, route tables and gateways

A VPC (Virtual Private Cloud) is your own isolated network inside AWS. Nothing reaches your resources unless your network rules allow it. When you create a VPC you give it an IPv4 address range written in CIDR notation, for example 10.0.0.0/16. The number after the slash is the prefix length: it says how many leading bits are fixed. A /16 fixes 16 bits and leaves 16 bits free, so it holds 2 to the power 16 addresses, which is 65,536. Each region has a default VPC that AWS creates for convenience, but production systems usually get their own.

Subnets

A subnet is a slice of the VPC's address range, for example 10.0.1.0/24. Every subnet lives in exactly one availability zone. To be highly available, you create matching subnets in two or three zones. A subnet is called public or private depending only on its route table, not on a special setting. A public subnet has a route to the internet. A private subnet does not.

AWS reserves five addresses in every subnet: the first four and the last one. They are the network address, the VPC router, the DNS server, a reserved address for future use, and the broadcast address. A /24 subnet therefore gives 251 usable addresses, not 256. The Python program below shows the arithmetic with the standard ipaddress module.

import ipaddress

vpc = ipaddress.ip_network("10.0.0.0/16")
print("Addresses in the VPC:", vpc.num_addresses)

# Carve the VPC into /24 subnets
subnets = list(vpc.subnets(new_prefix=24))
print("Number of /24 subnets:", len(subnets))
for subnet in subnets[:3]:
    print(subnet)

# AWS keeps 5 addresses per subnet, so subtract 5
usable = subnets[0].num_addresses - 5
print("Usable addresses in one /24 after AWS reserves 5:", usable)

Step by step: ip_network("10.0.0.0/16") builds the VPC range. num_addresses is 2 to the power (32 minus 16), which is 65,536. subnets(new_prefix=24) produces every /24 block inside it. Each /24 has 2 to the power 8 addresses, which is 256, so there are 256 subnets. Subtracting the five reserved addresses leaves 251 for your instances.

Route tables

A route table is a list of rules that decide where packets leaving a subnet should go. Each rule has a destination CIDR range and a target. Every VPC contains a local route for its own address range, so traffic between subnets in the same VPC works without any extra rule. Each subnet is associated with exactly one route table, and several subnets may share one.

When a packet leaves an instance, AWS compares its destination with the routes and picks the most specific match. A destination inside 10.0.0.0/16 matches the local route. Anything else matches 0.0.0.0/0, the route that means "every address", if one exists. If no route matches, the packet is dropped.

Internet gateways and NAT gateways

An internet gateway (IGW) is the connection between the VPC and the public internet. It is highly available and you attach one to each VPC. To make a subnet public, you add a route 0.0.0.0/0 pointing at the IGW. An instance in that subnet also needs a public IP address (an Elastic IP, or a public address assigned at launch) before traffic from outside can reach it. The IGW translates between that public address and the instance's private address.

Private subnets usually hold application servers and databases. These resources need to reach the internet for software updates and calls to external APIs, but they must not be reachable from it. A NAT gateway (network address translation) solves that. It sits in a public subnet, has an Elastic IP address, and the private subnet's route table sends 0.0.0.0/0 to it. An outbound connection starts in the private instance, the NAT gateway rewrites the source address, and the reply is translated back. A connection that starts from the internet has no entry in the translation table, so it is not forwarded to the private instance.

Walk through one request. A user's browser sends an HTTPS request to the public address of a load balancer in the public subnet. The internet gateway delivers it, the load balancer forwards it over the local route to a web server in a private subnet, and the web server replies along the same local route. If that web server then calls a payment API on the internet, the packet follows the private subnet's default route to the NAT gateway, which sends it out with its own Elastic IP. The payment API's reply returns to the NAT gateway and is forwarded back to the web server.

TrapA public subnet is not "less secure" by default, and a private subnet is not "safe" by default. Security comes from the security groups and NACLs described next. Also, a NAT gateway is billed per hour and per gigabyte, so a busy private fleet can make it an expensive part of the bill.

Key ideaA subnet is public only because its route table has a route to an internet gateway. A private subnet reaches out through a NAT gateway but cannot be reached from outside.

Why does a /24 subnet have 251 usable addresses instead of 256?

AWS reserves five addresses in every subnet: the network address, the VPC router, the DNS server, one reserved address for future use, and the broadcast address. Subtracting them from 256 leaves 251.

How does a private instance download updates from the internet without being reachable from it?

The private subnet's route table sends 0.0.0.0/0 to a NAT gateway in a public subnet. The NAT gateway forwards outbound connections using its Elastic IP and returns the replies. Connections that start from the internet have no translation entry, so they cannot reach the private instance.

What makes a subnet public?

Its route table has a route for 0.0.0.0/0 whose target is an internet gateway. The subnet itself has no public flag. Instances in it also need a public IP address to be reachable from outside.

Security: security groups, network ACLs and IAM

AWS security works in layers. The network layer uses security groups and network ACLs. The identity layer uses IAM. The data layer uses encryption. This is called defense in depth: if one layer is misconfigured, another can still stop an attacker. Interviewers often ask how a request is allowed or blocked, so know which layer does which job.

Security groups

A security group is a virtual firewall attached to a network interface, usually of an EC2 instance, or of a managed service such as RDS. Each rule has a direction (inbound or outbound), a protocol and port range, and a source (for inbound) or destination (for outbound). The source can be a CIDR range, another security group, or a prefix list.

Three properties matter. First, security groups contain only allow rules. You cannot write a deny rule, so anything not allowed is denied. Second, they are stateful: when an inbound connection is allowed, the reply traffic is allowed automatically, even if no outbound rule mentions it. Third, a new security group allows no inbound traffic and allows all outbound traffic by default. Security groups can reference each other. A database group can allow port 5432 (the default PostgreSQL port) only from the web tier's security group, so the rule follows the role of the server rather than an IP address that may change.

# Allow HTTPS from anywhere, and PostgreSQL only from the web security group
aws ec2 authorize-security-group-ingress --group-id sg-web --protocol tcp --port 443 --cidr 0.0.0.0/0
aws ec2 authorize-security-group-ingress --group-id sg-db --protocol tcp --port 5432 --source-group sg-web

Network ACLs (NACLs)

A network ACL works at the subnet boundary. Each subnet has one NACL, and it inspects traffic entering and leaving that subnet. NACL rules have a number, an action (allow or deny), a protocol, a port range and a CIDR. Rules are checked in ascending order of rule number, and the first rule that matches decides the outcome. An implicit final rule denies anything that no rule matched. The default NACL that AWS creates for a new VPC allows all traffic, while a custom NACL you create denies everything until you add rules.

NACLs are stateless. Each packet is judged on its own, in each direction. A web request to port 443 must be allowed inbound, and the reply must be allowed outbound on the client's ephemeral port range (AWS documents 1024 to 65535 as a safe choice). Forgetting the return path is the most common NACL mistake: the request arrives, but the response is silently blocked.

IAM: identities, policies and roles

IAM (Identity and Access Management) controls who can do what in your AWS account. An IAM user is a long-lived identity for a person or a program that needs a password or access keys. An IAM group is a collection of users that share the same policies. An IAM role is an identity with no permanent password. Someone or something assumes it and receives temporary credentials. An EC2 instance uses a role through an instance profile, so the application on the server gets temporary keys automatically, and you never store long-lived secret keys on the machine.

A policy is a JSON document that lists permissions. Each statement has an Effect (Allow or Deny), an Action (for example s3:GetObject), and a Resource (an ARN, or Amazon Resource Name, such as arn:aws:s3:::reports/*). An optional Condition narrows when the statement applies, for example only from a certain range of IP addresses.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject"],
      "Resource": "arn:aws:s3:::reports/*",
      "Condition": {"IpAddress": {"aws:SourceIp": "203.0.113.0/24"}}
    }
  ]
}

This policy lets callers read and write objects in the reports bucket, but only when the request comes from the documentation range 203.0.113.0/24. A trust policy is a different document. It is attached to a role and says who may assume that role, while the permissions policy says what the role can do.

IAM decides a request with three rules, applied in this order. First, everything is denied by default (an implicit deny). Second, an explicit Allow in any applicable policy grants the permission. Third, an explicit Deny always wins, even when another policy allows the same action. The next program is a simplified model of that logic using wildcard matching. The real IAM engine has more features, such as conditions and permission boundaries, but the priority of deny over allow is the same idea.

import fnmatch

policy = [
    {"Effect": "Allow", "Action": "s3:*", "Resource": "arn:aws:s3:::reports/*"},
    {"Effect": "Deny", "Action": "s3:DeleteObject", "Resource": "arn:aws:s3:::reports/*"},
]

def evaluate(statements, action, resource):
    decision = "implicit deny"
    for statement in statements:
        matches = (fnmatch.fnmatchcase(action, statement["Action"])
                   and fnmatch.fnmatchcase(resource, statement["Resource"]))
        if not matches:
            continue
        if statement["Effect"] == "Deny":
            return "explicit deny"   # a deny ends the search at once
        decision = "allow"           # remember the allow, keep checking for denies
    return decision

requests = [
    ("s3:GetObject", "arn:aws:s3:::reports/2026/q1.csv"),
    ("s3:DeleteObject", "arn:aws:s3:::reports/2026/q1.csv"),
    ("s3:GetObject", "arn:aws:s3:::payroll/salaries.csv"),
]
for action, resource in requests:
    print(action, resource, "->", evaluate(policy, action, resource))
s3:GetObject arn:aws:s3:::reports/2026/q1.csv -> allow
s3:DeleteObject arn:aws:s3:::reports/2026/q1.csv -> explicit deny
s3:GetObject arn:aws:s3:::payroll/salaries.csv -> implicit deny

Walk through the three requests. The first matches the s3:* allow and no deny, so it is allowed. The second also matches the allow, but it matches the explicit deny for s3:DeleteObject too. The loop returns "explicit deny" as soon as it reaches that statement, even though the allow came first in the list. The third request matches nothing, so the function falls back to the implicit deny. The model shows the key rule: a deny ends the decision, and no allow can override it.

TrapHardcoding access keys in source code or in a config file that gets committed to Git is a common leak. Use an IAM role on AWS compute, or a short-lived credential from AWS SSO for your own laptop.

Key ideaSecurity groups allow traffic per resource and are stateful, NACLs filter whole subnets and are stateless, and IAM decides which API actions an identity may perform, with an explicit deny always winning.

Why does a security group not need an outbound rule for the reply to an allowed inbound request, while a NACL does?

A security group is stateful: it remembers allowed connections and lets their replies through automatically. A NACL is stateless: it judges each packet separately in each direction, so the reply must match an allowed outbound rule, such as one for the ephemeral port range.

A policy allows s3:* on a bucket, and another policy denies s3:DeleteObject on the same bucket. Can the user delete an object?

No. An explicit Deny always overrides an Allow, wherever the allow comes from. The user can read and write but not delete.

Why should an application on EC2 get its AWS permissions from an IAM role rather than from access keys in a config file?

A role gives temporary credentials that AWS rotates automatically, and nothing long-lived sits on the server to be stolen. Access keys in a file do not expire on their own, and a copy of the file is a permanent security risk.

Interview questions

Answer each question out loud before you open the answer. A strong answer names the service or concept, explains the mechanism in one or two sentences, and gives one concrete example.

Explain IaaS, PaaS and SaaS with one example each.

IaaS gives you virtual machines and networks you configure yourself, such as EC2. PaaS gives you a platform to deploy code to, while the provider manages the operating system and runtime, such as Elastic Beanstalk. SaaS gives you a finished application, such as Gmail.

What is the shared responsibility model?

The provider secures the cloud itself: data centers, hardware and the virtualization layer. The customer secures what is in the cloud: data, access policies, operating system patches on IaaS resources, and firewall rules. The split moves depending on how managed a service is.

What is the difference between a region and an availability zone?

A region is a geographic area, such as Northern Virginia, containing several availability zones. An availability zone is one or more data centers with independent power and networking inside that region. You spread workloads across zones for availability and choose regions for latency, data residency and disaster recovery.

When would you use EBS, EFS and S3 respectively?

EBS is a block disk for one EC2 instance in one zone, used for the operating system and databases. EFS is a shared NFS file system that many instances mount across zones. S3 is object storage reached over HTTP, used for backups, media and data lakes.

Why would an Auto Scaling group use a launch template?

The launch template defines exactly how every new instance is configured, so each instance the group creates is identical and correct. The group uses it when scaling out and when replacing an instance that failed a health check.

How does a private subnet reach the internet without being reachable from it?

Its route table sends 0.0.0.0/0 to a NAT gateway in a public subnet. Outbound connections are translated through the NAT gateway's Elastic IP and the replies come back. Unsolicited inbound connections have no translation entry, so they cannot reach the private instances.

Compare security groups and network ACLs.

Security groups are attached to instances or network interfaces, contain only allow rules, and are stateful. Network ACLs are attached to subnets, support allow and deny rules evaluated in number order, and are stateless, so return traffic needs its own rule.

How does IAM decide whether a request is allowed?

Everything starts denied. An explicit Allow in an applicable policy grants the action. An explicit Deny in any applicable policy overrides every Allow. If there is no matching Allow, the request is refused.

What is a cold start in Lambda, and how can you reduce it?

A cold start is the delay when Lambda creates a new execution environment, which includes loading the runtime and your code. You can reduce it with smaller deployment packages, lighter initialization code, and provisioned concurrency, which keeps environments ready in advance.

Why is a /24 subnet in a VPC not 256 usable addresses?

AWS reserves five addresses in each subnet: the network address, the VPC router, the DNS server, one reserved address, and the broadcast address. That leaves 251 addresses for instances.

What is an S3 lifecycle rule, and why is it useful?

A lifecycle rule automatically moves objects to cheaper storage classes after a set number of days, or deletes them when they expire. It cuts costs for logs and backups that are rarely read, without a manual clean-up job.

DSA: tries (prefix trees)

The pattern: a tree of characters

A trie (also called a prefix tree) stores strings one character at a time. The root is an empty node. Each edge is labeled with one character, so the path from the root to any node spells a prefix. Each node has a flag that says whether a complete word ends there. The flag matters because one word can be a prefix of another: "app" sits inside "apple", and the node for "app" must be marked as the end of a word of its own.

Here is the trie for the words "apple" and "app". Nodes marked with a star end a word.

root
 └─ a
     └─ p
         └─ p*        (end of "app")
             └─ l
                 └─ e*    (end of "apple")

Why not use a hash set? A hash set answers "is this exact word stored?" in constant time, but it cannot answer "does any word start with app?" without checking every stored word. A trie answers both questions by walking one node per character. Each insert, search or prefix check costs O(L), where L is the length of the word, no matter how many words are stored. Shared prefixes are stored once, so the space is roughly the total number of characters inserted.

Tries appear in autocomplete, spell checking, IP routing (longest-prefix matching), and word search on a grid. Whenever a problem has many strings and asks about prefixes, or has many words to match against one input, think trie.

Pattern to rememberMany strings plus prefix questions means a trie. The walk follows one edge per character, so each query costs the length of the string, not the number of words.

Implement Trie (Prefix Tree) (LeetCode 208)

Implement a trie with three methods. insert(word) adds a word. search(word) returns true only if that exact word was inserted. startsWith(prefix) returns true if at least one inserted word begins with the prefix. Example: after insert("apple"), search("apple") is true, search("app") is false, and startsWith("app") is true. After a later insert("app"), search("app") becomes true.

How to think about it

  1. Understand. The words are made of lowercase English letters. The methods are called many times, so each call should be fast. An empty prefix or word is a valid input that the code handles naturally.
  2. Brute force. Keep a Python list of the inserted words. search loops over the list and compares each word with the query. startsWith loops and calls startswith on each word. With n words of length about L, each query costs O(n × L).
  3. Find the waste. Words that share a prefix, such as "apple" and "application", are compared letter by letter again and again. The list has no idea that they start the same way, so the shared letters are read for every word on every query.
  4. Optimise. Store each character once. Every node keeps a dictionary from a character to a child node. Walking from the root along the letters of a word follows the shared prefix for free. A query costs one step per character, O(L), no matter how many words are stored.
  5. Dry run. The table walks through the sample sequence of calls.
StepCallWhat happens in the trieReturns
1insert("apple")Creates the nodes a, p, p, l, e and marks e as the end of a wordnothing
2search("apple")Walks a, p, p, l, e; the node e is marked as an endTrue
3search("app")Walks a, p, p; the second p is not marked as an endFalse
4startsWith("app")Walks a, p, p; the path exists, so some word has this prefixTrue
5insert("app")Walks a, p, p (already there) and marks the second p as an endnothing
6search("app")Walks a, p, p; this node is now markedTrue

Code

class TrieNode:
    def __init__(self):
        self.children = {}     # character to child TrieNode
        self.is_end = False    # True if a word ends at this node

class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word):
        node = self.root
        for ch in word:
            if ch not in node.children:
                node.children[ch] = TrieNode()   # create the missing node
            node = node.children[ch]
        node.is_end = True

    def _walk(self, prefix):
        # Follow the characters of prefix from the root; return the last node, or None
        node = self.root
        for ch in prefix:
            node = node.children.get(ch)
            if node is None:
                return None
        return node

    def search(self, word):
        node = self._walk(word)
        return node is not None and node.is_end

    def startsWith(self, prefix):
        return self._walk(prefix) is not None

t = Trie()
t.insert("apple")
print(t.search("apple"))     # True
print(t.search("app"))       # False
print(t.startsWith("app"))   # True
t.insert("app")
print(t.search("app"))       # True

Step by step: insert walks the word one character at a time. When the next child is missing, it creates it, so the path grows only where needed. At the end it sets is_end on the last node. _walk is the shared helper: it follows a prefix and returns the node where the walk stops, or None as soon as a character has no child. search needs both a node and the end flag, which is why "app" is false before it is inserted, even though the path for "app" exists inside "apple". startsWith needs only the node, so it is true for any prefix that the trie contains.

Time O(L) per call · Space O(total characters inserted)

TrapDo not confuse "the path exists" with "the word exists". The end flag is the only thing that separates a stored word from a mere prefix.

Design Add and Search Words Data Structure (LeetCode 211)

Design a structure that supports addWord(word) and search(word). The search word may contain the dot character ., which matches any single letter. Example: after adding "bad", "dad" and "mad", search("pad") is false, search("bad") is true, search(".ad") is true, search("b..") is true, and search("b.d.") is false because the length differs from every stored word.

How to think about it

  1. Understand. Words contain letters only. Search words contain letters and dots. A dot is a wildcard for exactly one letter, so the length of the search word must equal the length of the stored word it matches.
  2. Brute force. Keep a list. For a search, compare the query with each stored word, letter by letter, treating a dot as a match for any letter. This costs O(n × L) per search.
  3. Find the waste. The brute force re-checks the same prefix of every word for every query. Words that share the prefix "ba" are checked as separate words each time.
  4. Optimise. Use a trie from the previous problem. A letter in the query follows exactly one child, as before. A dot must try every child of the current node, so the search becomes a depth-first search that explores each branch, and stops as soon as one branch reaches a complete word of the right length.
  5. Dry run. The table follows search(".ad") on the trie for "bad", "dad" and "mad".
StepNodeCharacter of the queryAction
1root. (dot)Try the children b, d and m in turn
2baFollow the child a
3a (under b)dFollow the child d
4d (under b, a)end of queryThe node is marked as an end, so return True

class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_end = False

class WordDictionary:
    def __init__(self):
        self.root = TrieNode()

    def addWord(self, word):
        node = self.root
        for ch in word:
            if ch not in node.children:
                node.children[ch] = TrieNode()
            node = node.children[ch]
        node.is_end = True

    def search(self, word):
        return self._dfs(self.root, word, 0)

    def _dfs(self, node, word, i):
        # i is the index of the query character we are matching now
        if i == len(word):
            return node.is_end
        ch = word[i]
        if ch == ".":
            # A dot matches any child, so try every branch
            for child in node.children.values():
                if self._dfs(child, word, i + 1):
                    return True
            return False
        child = node.children.get(ch)
        if child is None:
            return False
        return self._dfs(child, word, i + 1)

Step by step: search starts the recursion at the root with index 0. _dfs handles one query character per call. Word Search II (LeetCode 212)

You are given an m by n grid of letters and a list of words. Return every word that can be built by moving from cell to cell horizontally or vertically, using each cell at most once per word. Example: the grid has rows "oaan", "etae", "ihkr" and "iflv", and the words are "oath", "pea", "eat" and "rain". The answer is "eat" and "oath". "pea" is not in the grid at all, and "rain" has no path because no a is next to the r.

How to think about it

  1. Understand. The grid can be large, and there can be many words. Two words can share cells, but one word cannot use the same cell twice. The output can be in any order, and this solution returns it sorted so the result is predictable.
  2. Brute force. Solve Word Search (one word) for each word. For one word, start a depth-first search from every cell, moving in four directions and marking cells already used. That costs about m × n × 4 to the power L in the worst case, for a word of length L. Repeating it for all W words costs W times that.
  3. Find the waste. The searches repeat the same work. If many words start with "oa", the grid is searched from scratch for each of them, even though the first two letters of every search are the same. The brute force never shares the common prefixes of the words.
  4. Optimise. Put all the words in a trie, then run one depth-first search over the grid that moves through the trie at the same time. Each step asks the current trie node whether it has a child for the letter of the new cell. If not, that whole branch of the grid is abandoned at once. When a path reaches a node that ends a word, record the word. Two more savings help: clear the word from the node once it is found, so it is not reported twice, and remove leaf nodes that no longer lead to any word, so later searches stop sooner.
  5. Dry run. The table follows the search from the top-left cell for "oath".
StepCellLetterTrie node reachedAction
1(0, 0)oroot to child oo has no word yet, mark the cell as used, try the neighbours
2(0, 1)ao to child aa has no word yet, explore its neighbours
3(1, 1)ta to child tt has no word yet, explore its neighbours
4(2, 1)ht to child hh holds "oath": record it and clear the word
5back at (2, 1)hhNo neighbour continues the word and h has no children, so h is removed from its parent

The search from every other cell proceeds the same way. Cells whose letter has no matching child under the root, such as the r in the third row, are dismissed in a single step.

Code

DIRS = ((1, 0), (-1, 0), (0, 1), (0, -1))

# Method 1: brute force, one Word Search per word
def find_words_bruteforce(board, words):
    rows, cols = len(board), len(board[0])

    def dfs(r, c, word, i, seen):
        if i == len(word):
            return True
        if not (0 <= r < rows and 0 <= c < cols):
            return False
        if (r, c) in seen or board[r][c] != word[i]:
            return False
        seen.add((r, c))
        found = any(dfs(r + dr, c + dc, word, i + 1, seen) for dr, dc in DIRS)
        seen.remove((r, c))
        return found

    def exists(word):
        for r in range(rows):
            for c in range(cols):
                if dfs(r, c, word, 0, set()):
                    return True
        return False

    return sorted(w for w in words if exists(w))

# Method 2: one trie of all words, one search over the grid
class TrieNode:
    def __init__(self):
        self.children = {}
        self.word = None          # the complete word that ends here, if any

def build_trie(words):
    root = TrieNode()
    for w in words:
        node = root
        for ch in w:
            if ch not in node.children:
                node.children[ch] = TrieNode()
            node = node.children[ch]
        node.word = w
    return root

def find_words(board, words):
    root = build_trie(words)
    rows, cols = len(board), len(board[0])
    found = []

    def dfs(r, c, parent):
        ch = board[r][c]
        node = parent.children.get(ch)
        if node is None:              # no word starts with this path: prune
            return
        if node.word is not None:
            found.append(node.word)
            node.word = None          # report each word only once
        board[r][c] = "#"             # mark the cell as used on this path
        for dr, dc in DIRS:
            nr, nc = r + dr, c + dc
            if 0 <= nr < rows and 0 <= nc < cols and board[nr][nc] != "#":
                dfs(nr, nc, node)
        board[r][c] = ch             # unmark, so other paths can use the cell
        if not node.children and node.word is None:
            del parent.children[ch]   # nothing below this node is left: prune it

    for r in range(rows):
        for c in range(cols):
            dfs(r, c, root)
    return sorted(found)

    ["o", "a", "a", "n"],
    ["e", "t", "a", "e"],
    ["i", "h", "k", "r"],
    ["i", "f", "l", "v"],
]

print(find_words([row[:] for row in board], words))   # copy: find_words edits the board

Step by step through the optimised version. build_trie inserts each word once, and each node stores the full word when a word ends there. dfs receives the grid position and the trie node of the path so far. It first asks whether the parent node has a child for the current letter. If not, the function returns at once, which is the pruning that makes the trie fast. It then records any word that ends here, marks the cell with a placeholder so the same cell is not used twice in one path, explores the four neighbours from the child node, and restores the cell before returning. The last step removes a node that has no children and no word left, so a later search does not walk into a dead end. The small example shows the "no reuse" rule: "abcb" needs two b cells, and the grid has only one, so the answer is empty.

Time: brute force O(W × m × n × 4 to the power L). Trie version O(total letters) to build, and a search that is usually far smaller than the worst case · Space O(total letters) for the trie plus the recursion stack

TrapForgetting to unmark the cell after the recursion returns is the classic bug. Then the search wrongly blocks paths that should be allowed, and the answer is missing words.

Pattern to rememberMany words plus one grid means build a trie of the words and search the grid once, letting the trie prune the search at each step.
