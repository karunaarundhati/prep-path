Binary search tree (recap)

A binary search tree is a way to store numbers so that you can find, add and remove them quickly. This quick recap covers the ordering rule, the three main operations, and why an inorder walk gives sorted output, all of which GATE uses in data structure questions.

The idea in plain words

Imagine a long shelf of books sorted by title. To find one book, you do not start at the left end and walk along. You go to the middle, see whether your title comes before or after the book there, and then search only the half where it must be. Each look throws away half the shelf.

A binary search tree (BST) copies this idea using nodes linked together. Each node holds one key, a number, and points to at most two children: a left child and a right child. The shape is an upside-down tree, with the root at the top.

The whole structure depends on one rule. Every key in the left subtree of a node is smaller than the node's key, and every key in the right subtree is larger. This rule lets each comparison decide which side to explore.

Why this matters for GATE: BST questions ask you to draw the tree after some insertions or deletions, to count comparisons, to give the height, or to say what an inorder walk prints. These are fast marks if you know the rule well.

Key terms

Node
One box in the tree. It holds a key and links to its children.
Key
The number stored in a node, used for ordering.
Root
The top node, which has no parent.
Leaf
A node with no children.
Subtree
A node together with everything below it.
Height
The number of nodes on the longest path from the root down to a leaf. A single node has height 1. Some books count edges instead, so always read the question's definition.
Inorder traversal
Visit the left subtree, then the node, then the right subtree.
Inorder successor
The smallest key that is larger than a given key. In a BST it is the smallest key in the right subtree of the node.
Comparison
One test of the form "is the key smaller, equal or larger than this node's key?"

The binary search tree rule

Take the keys 50, 30, 70, 20, 40, 60 and 80. Insert them in that order. The first key, 50, becomes the root. Each later key goes left or right by comparing with the nodes it meets on the way down. The resulting tree is:

NodeLeft childRight childCheck of the rule
50 (root)307030 is smaller and 70 is larger
30204020 is smaller and 40 is larger
70608060 is smaller and 80 is larger
20, 40, 60, 80nonenoneleaves

Key ideaThe rule applies to every node, not only the root. All keys under the left child are smaller than the node. All keys under the right child are larger.

TrapChecking only a node and its two children is not enough. Test each key against all of its ancestors. For example, if 6 were placed as the right child of 3, it would sit in the left subtree of 50, so it must be smaller than 50. It is smaller, so that placement is valid. A key such as 60 in the same place would break the rule.

The shape of the tree depends on the order of insertion. If you insert 10, 20, 30 and 40 in that order, each key is larger than the one before, so every new key goes right. The tree becomes a single long chain. This is the worst case, and its height is 4 for four keys. The first tree above has height 3 for seven keys, which is much better.

In the tree above, where does the key 45 go when it is inserted?

Start at 50. 45 is smaller, so go left to 30. 45 is larger than 30, so go right to 40. 45 is larger than 40, and 40 has no right child, so 45 becomes the right child of 40.

Is this a valid BST? Root 5, left child 3, and 6 is the right child of 3.

No. The key 6 is inside the left subtree of 5, because 3 is the left child of 5. Every key in that subtree must be smaller than 5, but 6 is larger.

Search

To search for a key, start at the root. If the key equals the node's key, you are done. If the key is smaller, go to the left child. If it is larger, go to the right child. If you reach an empty place where a child should be, the key is not in the tree.

Searching for 60 in the tree above visits 50, then 70, then 60. That is 3 comparisons. Searching for 65 visits 50, 70 and 60, and then finds that 60 has no right child, so 65 is not present. That is also 3 comparisons.

Each comparison moves one level down. So the number of comparisons is at most the height of the tree. For a balanced tree with n keys this is about log2(n), which is small. For a chain it can be n, which is slow.

GATE loves thisFor a successful search that ends at node x, the number of comparisons equals the depth of x, when the root has depth 1.

How many comparisons does a successful search for 40 make in the tree above?

Three: 50, then 30, then 40.

Why does a search in a chain take so many steps?

Each comparison removes only one node from consideration, because the tree is a single line. The search has to walk down the whole line.

Insert

Insertion uses the same path as search. Walk down from the root, going left or right by comparison, until you reach an empty child position. Put the new node there. A new key always becomes a leaf, and existing keys do not move.

Example: insert 45 into the tree above. The path is 50, 30, 40, and then 45 becomes the right child of 40.

TrapDuplicate keys are usually not allowed in a basic BST. If a question inserts a key that already exists, read the question to see what it says should happen.

After inserting 45 as described, what is the depth of 45?

Depth 4, with the root at depth 1: 50 (depth 1), 30 (depth 2), 40 (depth 3), 45 (depth 4).

Can an ordinary insertion change the key stored in an existing node?

No. A basic insertion only adds a new leaf. Existing keys stay where they are.

Delete

Deletion has three cases. Learn them as a list.

  1. The node is a leaf. Remove it. Nothing else changes.
  2. The node has one child. Replace the node by its only child. The child moves up.
  3. The node has two children. Find its inorder successor, which is the smallest key in its right subtree. Copy that key into the node. Then delete the successor from the right subtree. The successor has no left child, so this last step is easy.

Why the successor? It is the next larger key after the deleted one, so it can take its place without breaking the rule. Every key in the left subtree is smaller than it, and every key in the right subtree is larger.

Example: delete 30 from the tree above. Node 30 has two children, 20 and 40. Its right subtree holds only 40, so the successor is 40. Copy 40 into the node that held 30, then delete the leaf 40 from its old place. The node that now holds 40 has 20 on its left.

TrapMany students delete a node with two children by removing it and attaching its children to its parent. That can break the rule. Always use the successor, or the predecessor, which is the largest key in the left subtree.

What is the inorder successor of 50 in the tree above?

60. Go to the right child 70, then keep going left as far as possible: 70 to 60. 60 has no left child, so it is the smallest key in that right subtree.

When you delete a leaf, does the order of the remaining keys in the inorder walk change?

No. Only the deleted key disappears from the walk. The other keys stay in the same order.

Inorder traversal and height

An inorder traversal visits the left subtree first, then the node, then the right subtree. Apply this rule recursively from the root. For a BST the result is the keys in sorted order. The reason is simple. Everything to the left of a node is smaller and everything to the right is larger, so the walk lists keys from smallest to largest.

The code below builds the tree from this page and prints the inorder walk, the height and some searches. Each function is short, so read them one at a time.

class Node:
    def __init__(self, key):
        self.key = key
        self.left = None
        self.right = None

def insert(root, key):
    if root is None:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
    elif key > root.key:
        root.right = insert(root.right, key)
    return root

def inorder(root, out):
    if root is None:
        return
    inorder(root.left, out)
    out.append(root.key)
    inorder(root.right, out)

def height(node):
    if node is None:
        return 0
    return 1 + max(height(node.left), height(node.right))

def search(root, key):
    if root is None:
        return False
    if key == root.key:
        return True
    if key < root.key:
        return search(root.left, key)
    return search(root.right, key)

def find_min(node):
    while node.left is not None:
        node = node.left
    return node

def delete(root, key):
    if root is None:
        return None
    if key < root.key:
        root.left = delete(root.left, key)
    elif key > root.key:
        root.right = delete(root.right, key)
    else:
        if root.left is None:
            return root.right
        if root.right is None:
            return root.left
        succ = find_min(root.right)
        root.key = succ.key
        root.right = delete(root.right, succ.key)
    return root

def build(keys):
    root = None
    for k in keys:
        root = insert(root, k)
    return root

tree = build([50, 30, 70, 20, 40, 60, 80])
out = []
inorder(tree, out)
print("inorder:", out)
print("height:", height(tree))
print("search 60:", search(tree, 60), "search 65:", search(tree, 65))
tree = delete(tree, 30)
out = []
inorder(tree, out)
print("after deleting 30:", out)
print("height:", height(tree))
skewed = build([10, 20, 30, 40])
print("skewed height:", height(skewed))
inorder: [20, 30, 40, 50, 60, 70, 80]
height: 3
search 60: True search 65: False
after deleting 30: [20, 40, 50, 60, 70, 80]
height: 3
skewed height: 4

Notice two things. The inorder walk is sorted, as promised. The tree built from 10, 20, 30, 40 has height 4, the worst case for four keys.

TipYou do not need to memorise the code for GATE. Learn the three cases of delete and the fact that an inorder walk is sorted. Use code only to check your hand traces.

Why does the inorder walk of any valid BST come out sorted?

For each node, the keys on the left are smaller and the keys on the right are larger. Visiting left, then node, then right therefore lists keys from smallest to largest.

What is the height of a chain of 6 keys inserted in increasing order?

6. Each key is added as the right child of the previous one, so the chain has 6 nodes on one path.

Solved GATE-style problems

These problems are original, written in the GATE style. They are not real past questions. Draw the tree on paper before you check with code.

Inorder walk of a small tree

Keys 8, 3, 10, 1 and 6 are inserted into an empty BST in that order. What is the inorder traversal?

How to think about it

  1. What is asked. The inorder list of the keys in the tree.
  2. Which idea applies. An inorder walk of a BST gives the keys in sorted order.
  3. Work it out. The keys are 1, 3, 6, 8 and 10. Sorted, they are 1, 3, 6, 8, 10.
  4. Check. Run the code below.
print(sorted([8, 3, 10, 1, 6]))
[1, 3, 6, 8, 10]

Answer: 1, 3, 6, 8, 10.

Comparisons for a successful search

The tree has root 8, left child 3 (with children 1 and 6) and right child 10. How many comparisons does a successful search for 6 make? Count the root.

How to think about it

  1. What is asked. The number of nodes visited to find 6.
  2. Which idea applies. Search follows one path from the root, with one comparison per node visited.
  3. Work it out. Compare 6 with 8: 6 is smaller, go left. Compare with 3: 6 is larger, go right. Compare with 6: equal, found. That is 3 comparisons.
  4. Check. Run the code below, which follows the same path.
left = {8: 3, 3: 1}
right = {8: 10, 3: 6}
node = 8
count = 0
while node != 6:
    count = count + 1
    node = left[node] if 6 < node else right[node]
count = count + 1
print(count)
3

Answer: 3.

Select all true statements about a chain

Keys 1, 2, 3 and 4 are inserted into an empty BST in that order. Select all that apply.

  • (A) The height of the tree is 4.
  • (B) A successful search for 4 makes 4 comparisons.
  • (C) The inorder traversal is 1, 2, 3, 4.
  • (D) The tree is balanced.

How to think about it

  1. What is asked. Which statements are true.
  2. Which idea applies. Each key is larger than the one before, so each goes right of the last. The result is a chain.
  3. Work it out. The chain is 1, with 2 to its right, then 3, then 4. The height is 4, so (A) is true. Searching for 4 visits 1, 2, 3, 4, which is 4 comparisons, so (B) is true. The inorder walk is sorted, so (C) is true. A chain is the opposite of balanced, so (D) is false.
  4. Check. Run the code below. It uses lists in place of nodes, with each list holding the key and two children.
def insert(root, key):
    if root is None:
        return [key, None, None]
    if key < root[0]:
        root[1] = insert(root[1], key)
    else:
        root[2] = insert(root[2], key)
    return root

def height(node):
    if node is None:
        return 0
    return 1 + max(height(node[1]), height(node[2]))

root = None
for k in [1, 2, 3, 4]:
    root = insert(root, k)
print(height(root))
4

Answer: (A) and (B) and (C). Statement (D) is false.

Root after deleting a key with two children

The keys 50, 30, 70, 20, 40, 60 and 80 are inserted in that order. Then the key 50 is deleted using the inorder successor rule. Which key is now at the root? This is a NAT question.

How to think about it

  1. What is asked. The key at the root after the deletion.
  2. Which idea applies. A node with two children is replaced by its inorder successor, the smallest key in its right subtree.
  3. Work it out. The right subtree of 50 holds 60, 70 and 80. The smallest of these is 60. So 60 is copied into the root position, and the old 60 leaf is removed.
  4. Check. Run the code below, which finds the smallest key larger than 50.
right_keys = [60, 70, 80]
print(min(k for k in right_keys if k > 50))
60

Answer: 60.

Comparisons for an unsuccessful search

The tree has root 15, with left child 10 and right child 20. Node 10 has left child 8 and right child 12. Node 8 has left child 6. Node 20 has left child 17 and right child 25. How many comparisons does an unsuccessful search for 9 make? This is a NAT question.

How to think about it

  1. What is asked. The number of comparisons before the search ends with no match.
  2. Which idea applies. The search goes down one path and ends when it reaches an empty child.
  3. Work it out. Compare 9 with 15: 9 is smaller, go left to 10. Compare with 10: smaller, go left to 8. Compare with 8: 9 is larger, go right. The right child of 8 is empty, so the search ends. That is 3 comparisons.
  4. Check. Run the code below, which follows the same path.
left = {15: 10, 10: 8, 8: 6, 20: 17}
right = {15: 20, 10: 12, 20: 25}
node = 15
count = 0
while node is not None:
    count = count + 1
    if node == 9:
        break
    node = left.get(node) if 9 < node else right.get(node)
print(count)
3

Answer: 3.

Height of a tree built from a sequence

The keys 15, 10, 20, 8, 12, 17, 25 and 6 are inserted into an empty BST in that order. What is the height of the tree, counting the root as height 1? This is a NAT question.

How to think about it

  1. What is asked. The longest path length, in nodes.
  2. Which idea applies. Each key goes down the tree by comparison. The height is the longest of these paths.
  3. Work it out. 6 is smaller than 15, then smaller than 10, then smaller than 8. Its path is 15, 10, 8, 6, which has 4 nodes. The other branches are shorter: 25 has path 15, 20, 25, which has 3 nodes. So the height is 4.
  4. Check. Run the code below, which builds the tree from the list of lists approach.
def insert(root, key):
    if root is None:
        return [key, None, None]
    if key < root[0]:
        root[1] = insert(root[1], key)
    else:
        root[2] = insert(root[2], key)
    return root

def height(node):
    if node is None:
        return 0
    return 1 + max(height(node[1]), height(node[2]))

root = None
for k in [15, 10, 20, 8, 12, 17, 25, 6]:
    root = insert(root, k)
print(height(root))
4

Answer: 4.

Select all true statements about deletion

Select all that apply to deletion in a BST.

  • (A) Deleting a leaf does not change the relative order of the other keys.
  • (B) Replacing a deleted node that has two children by its inorder successor keeps the BST rule.
  • (C) Deleting the root always makes its old left child the new root.
  • (D) After any deletion, the inorder traversal is no longer sorted.

How to think about it

  1. What is asked. Which statements are true.
  2. Which idea applies. The three deletion cases, and the rule that inorder is sorted.
  3. Work it out. (A) is true, because a leaf is simply removed. (B) is true, because the successor is larger than all keys in the left subtree and smaller than all keys left in the right subtree. (C) is false. If the root has two children, its successor replaces it, and the left child is not necessarily the new root. (D) is false, because deletion keeps the inorder walk sorted.
  4. Check. The statements have been checked by the case analysis above. No code is needed.

Answer: (A) and (B).

Exam-level practice

Exam-level 1: Deleting a node with two children (MCQ, 2 marks)

In the BST built by inserting 50, 30, 70, 20, 40, 60, 80, 65, the root 50 is deleted using the inorder successor. What is the new root? (A) 40 (B) 60 (C) 65 (D) 70

How to think about it

  1. What is asked. The key that replaces the root.
  2. Which idea applies. The inorder successor is the smallest key in the right subtree.
  3. Work it out. Right subtree of 50: 70 with left child 60. 60 has no left child. Successor 60. Its right child 65 moves up.
  4. Check. The new inorder is 20 30 40 60 65 70 80, still sorted.

Answer: (B).

Exam-level 2: Range count (NAT, 2 marks)

In a BST holding keys 1 to 100, how many keys lie in [25, 60]?

How to think about it

  1. What is asked. The count of keys in a closed range.
  2. Which idea applies. All integers from 25 to 60 are present.
  3. Work it out. 60 − 25 + 1 = 36.
  4. Check. An inorder traversal visits them consecutively.

Answer: 36.

Exam-level 3: Height bounds (MSQ, 2 marks)

For a BST with n = 31 nodes, which are TRUE? (A) Minimum height is 4. (B) Maximum height is 30. (C) Search is O(log n) in every BST. (D) Inserting keys in sorted order gives maximum height.

How to think about it

  1. What is asked. Height range of BSTs.
  2. Which idea applies. Height is measured in edges. A perfect tree with 31 nodes has height 4.
  3. Work it out. (A) True. (B) A chain has 30 edges. True. (C) Only for balanced trees. False. (D) True.
  4. Check. 25 − 1 = 31 fits the perfect tree.

Answer: (A), (B) and (D).

Summary

Binary search tree
A tree where each left subtree is smaller than the node and each right subtree is larger.
Node
One box in the tree, holding a key and two child links.
Root
The top node of the tree.
Leaf
A node with no children.
Height
The number of nodes on the longest root-to-leaf path.
Search
Start at the root, go left or right by comparison, and stop on a match or an empty child.
Insert
Search for the key, then add it as a new leaf where the search ends.
Delete
Remove a leaf, or replace a node with its only child, or replace it with its inorder successor.
Inorder successor
The smallest key in the right subtree, which is the next larger key.
Inorder traversal
Left subtree, then node, then right subtree. It lists the keys in sorted order.
Chain
A tree where every node has one child, so the height equals the number of keys.
Successful search
Comparisons equal the depth of the node found, with the root at depth 1.
Unsuccessful search
Comparisons equal the nodes on the path to an empty child.
Balanced tree
A tree whose height is close to log2(n) for n keys.

Remember these

  • Every left subtree is smaller than its node, and every right subtree is larger.
  • Search and insert follow one path from the root, one comparison per node.
  • A new key is always inserted as a leaf.
  • For two children, delete using the inorder successor.
  • An inorder walk of any BST lists the keys in sorted order.
  • Insertion in sorted order produces a chain, the worst case.
