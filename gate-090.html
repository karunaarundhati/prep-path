SQL: queries, joins, aggregation

SQL is the everyday language for asking questions of a relational database. This topic teaches its main clauses, joins, aggregate functions and nested queries, and how to predict the output of a query, a skill GATE tests often.

The idea in plain words

Think of a shopping list with rules. You write "milk, from the dairy shelf, under 50 rupees, sorted by price". You do not walk the shop yourself in the query. The shop assistant reads your list and finds the items. SQL works in the same way. You write a list of rules, and the database finds the rows.

SQL stands for Structured Query Language. It is declarative, which means you describe the answer, not the steps. The most common query has three parts that you read in this order:

  • SELECT says which columns you want back.
  • FROM says which tables to read.
  • WHERE says which rows to keep.

GATE Data Science and AI (paper DA) often gives you a few small tables and a query, and asks for the output. You must be able to read SQL slowly and carefully. You will need to know joins, the aggregate functions (COUNT, SUM, AVG, MIN, MAX), nested queries and the set operations.

Key terms

SQL
The language for asking and changing data in a relational database. Plain meaning: a question language for tables.
Clause
One named part of a query, such as WHERE. Plain meaning: one section of the sentence.
SELECT
The clause that lists the output columns or expressions.
FROM
The clause that names the input tables.
WHERE
The clause that keeps only the rows where a condition is true.
Alias
A short nickname for a table or column, written after the name, such as Student s. Plain meaning: a short name you choose.
Join
Combining rows of two tables where a condition holds, usually equal keys. Plain meaning: putting matching records side by side.
Inner join
A join that keeps only the matched pairs.
Outer join
A join that also keeps unmatched rows, filling the missing side with NULL. The kinds are LEFT, RIGHT and FULL.
NULL
A marker that a value is missing or unknown. Plain meaning: "no value here". It is not zero and not an empty string.
Self join
A join of a table with itself, using two aliases.
Cross join
Every row of one table paired with every row of another. Plain meaning: all combinations.
Aggregate function
A function that turns many rows into one value. Examples: COUNT, SUM, AVG, MIN, MAX.
GROUP BY
The clause that splits rows into groups that share a value, so an aggregate can be computed for each group.
HAVING
A condition applied to groups, after the aggregates are computed.
ORDER BY
The clause that sorts the output rows.
DISTINCT
A keyword that removes duplicate output rows.
Subquery
A query placed inside another query, inside brackets.
Set operation
UNION, INTERSECT or EXCEPT, which combine the results of two queries as sets.

Concept 1: SELECT, FROM, WHERE and the order of evaluation

The simplest query

To list all student names, we write:

SELECT name
FROM Student;

The FROM clause says "read the Student table". The SELECT clause says "keep only the name column". The result has five rows: Asha, Ravi, Meena, Dev and Kiran.

Adding a condition with WHERE

SELECT name, cgpa
FROM Student
WHERE dept = 'CS' AND cgpa >= 8.5
ORDER BY cgpa DESC;

Step by step:

  1. FROM reads all five Student rows.
  2. WHERE keeps rows where dept is CS and cgpa is at least 8.5. Asha (CS, 9.1) and Meena (CS, 8.7) pass. Kiran (CS, 8.2) fails. Ravi and Dev are not CS.
  3. SELECT keeps the name and cgpa columns.
  4. ORDER BY sorts by cgpa, from high to low (DESC means descending).

The answer is Asha (9.1) then Meena (8.7).

The order of evaluation

The order in which you write the clauses is not the order in which they are run. For a single query block, the logical order is:

FROM, then WHERE, then GROUP BY, then HAVING, then SELECT, then DISTINCT, then ORDER BY

This matters. For example, you cannot use a column alias from SELECT inside WHERE, because WHERE runs first. The alias does not exist yet at that stage.

TrapWriting SELECT cgpa * 10 AS score FROM Student WHERE score > 85 fails in standard SQL, because WHERE runs before SELECT creates the alias score. Repeat the expression in WHERE instead.

Question: What is the difference between WHERE and HAVING?

WHERE filters single rows before grouping. HAVING filters groups after the aggregates are computed.

Concept 2: Joins

Why we join

The student's name is in Student. The course code is in Enrol. A join puts the two side by side, using a matching condition. The most common condition compares keys: s.sid = e.sid.

Inner join

An inner join keeps only the pairs that match. Here is the join of Student and Enrol, with the rows shown by hand:

Student JOIN Enrol ON sid (inner)

Dev is missing, because Dev has no row in Enrol that matches. An inner join drops unmatched rows.

Outer joins

An outer join keeps unmatched rows too, and fills the missing side with NULL.

  • LEFT JOIN keeps every row of the left table. Dev is kept, with NULL for cid and grade.
  • RIGHT JOIN keeps every row of the right table. It is the mirror image of LEFT JOIN.
  • FULL OUTER JOIN keeps unmatched rows from both sides.

TrapNULL is not equal to anything, not even to another NULL. So NULL = NULL is not true. To test for missing values, use IS NULL.

Self join and cross join

A self join joins a table with itself. You need two aliases so that SQL knows which copy is which. To pair students in the same department, with the lower sid first:

SELECT a.name, b.name
FROM Student a JOIN Student b
  ON a.dept = b.dept AND a.sid < b.sid;

A cross join pairs every row of one table with every row of another. Five students and three courses give 5 × 3 = 15 rows. Cross joins are rarely wanted, but they appear in GATE questions to test counting.

Question: How many rows does Student LEFT JOIN Enrol give on the sample data?

Seven. Six enrolment rows match, and Dev adds one row with NULL.

Question: Why does the self join not pair a student with themselves?

The condition a.sid < b.sid is never true when both aliases are the same row, so each pair appears only once and in one order.

Concept 3: Aggregate functions, GROUP BY and HAVING

From many rows to one number

An aggregate function reads a set of rows and returns one value:

  • COUNT(*) counts rows. COUNT(col) counts rows where col is not NULL.
  • SUM(col) adds the values.
  • AVG(col) is the sum divided by the count of non-NULL values.
  • MIN(col) and MAX(col) give the smallest and largest value.

Aggregates ignore NULL values, except COUNT(*), which counts every row. Keep that in mind.

GROUP BY

GROUP BY splits the rows into groups that share a value, then computes the aggregate for each group. Think of sorting students into department boxes, then counting each box.

SELECT dept, COUNT(*), AVG(cgpa)
FROM Student
GROUP BY dept;

The CS box has Asha, Meena and Kiran. Their cgpa values are 9.1, 8.7 and 8.2, so the average is (9.1 + 8.7 + 8.2) / 3 = 26.0 / 3 = 8.67 when rounded. The EE box has Ravi alone, and the ME box has Dev alone.

TrapEvery column in SELECT must either be inside an aggregate or appear in GROUP BY. Writing SELECT name, COUNT(*) FROM Student GROUP BY dept is an error, because a department has several names.

HAVING

WHERE cannot test an aggregate such as COUNT(*), because WHERE runs before grouping. HAVING runs after grouping, so it can:

SELECT cid, COUNT(*) AS n
FROM Enrol
GROUP BY cid
HAVING COUNT(*) >= 2;

CS101 has two enrolments, CS301 has three, and EE201 has one. HAVING keeps the groups with at least two, so the answer is CS101 and CS301.

db = sqlite3.connect(":memory:")

INSERT INTO Enrol VALUES (101,'CS101',9),(101,'CS301',8),(102,'EE201',7),
  (103,'CS101',10),(103,'CS301',9),(105,'CS301',6);

print("by dept:", db.execute("SELECT dept, COUNT(*), ROUND(AVG(cgpa), 2) FROM Student GROUP BY dept ORDER BY dept").fetchall())

Question: Why does COUNT(*) give 7 but COUNT(e.cid) give 6 in the last line?

COUNT(*) counts all 7 rows of the left join, including Dev's row. COUNT(e.cid) skips the NULL in Dev's row, so it counts 6.

Question: Can WHERE use COUNT(*) to keep only groups with two or more rows?

No. WHERE runs before grouping, so the count does not exist yet. Use HAVING COUNT(*) >= 2.

Concept 4: Nested subqueries

A question inside a question

A subquery is a query inside brackets. You can think of it as a helper question whose answer is used by the outer question. Read the inner query first, then the outer one.

Subquery with IN

"Names of students who take CS301":

SELECT name
FROM Student
WHERE sid IN (SELECT sid FROM Enrol WHERE cid = 'CS301')
ORDER BY name;

Step by step: the inner query returns the sids 101, 103 and 105. The outer query keeps students whose sid is in that list: Asha, Kiran and Meena.

Scalar subquery

A subquery that returns exactly one value can be used like a number. The average cgpa of all students is 40.7 / 5 = 8.14. Students above that average are:

SELECT name
FROM Student
WHERE cgpa > (SELECT AVG(cgpa) FROM Student)
ORDER BY name;

The inner query runs once and returns 8.14. Asha (9.1), Kiran (8.2) and Meena (8.7) are above it. Ravi (7.8) and Dev (6.9) are not.

EXISTS and NOT EXISTS

EXISTS asks whether the inner query returns at least one row. It is the SQL form of the ∃ quantifier from the calculus topic. NOT EXISTS is the form of ∀ we used before. "Students with no enrolment":

SELECT name
FROM Student s
WHERE NOT EXISTS (SELECT * FROM Enrol e WHERE e.sid = s.sid);

Only Dev has no matching row, so the answer is Dev. The inner query refers to s.sid from the outer query, which is why it is called a correlated subquery. It is re-run for each outer row.

TrapNOT IN behaves badly when the subquery returns a NULL. If any value in the list is NULL, x NOT IN (...) is never true, so the query returns no rows. Prefer NOT EXISTS when NULL is possible.

Question: What does the inner query in the IN example return?

The sids of students enrolled in CS301: 101, 103 and 105.

Question: Why is NOT EXISTS usually safer than NOT IN?

NOT EXISTS checks rows one at a time and is not affected by NULL in the inner result. NOT IN returns no rows if the inner list contains a NULL.

Concept 5: Set operations and predicting output

UNION, INTERSECT and EXCEPT

Each query returns a set of rows, and set operations combine two such results. Both queries must have the same number of columns, with compatible types.

  • UNION gives all rows from either query, with duplicates removed.
  • UNION ALL gives all rows from either query, keeping duplicates.
  • INTERSECT gives rows that appear in both.
  • EXCEPT gives rows in the first query that are not in the second.

Use the Enrol table. Query X is "course ids with grade at least 9" and query Y is "course ids that student 101 takes". X returns CS101, CS101 and CS301. Y returns CS101 and CS301.

OperationResultRows
X UNION YCS101, CS3012
X UNION ALL YCS101, CS101, CS301, CS101, CS3015
X INTERSECT YCS101, CS3012
All cids EXCEPT cids with grade below 8CS1011

Key ideaUNION and INTERSECT remove duplicates. UNION ALL keeps them, so it is faster and counts every row.

Predicting the output, step by step

Use the clause order from Concept 1 and follow these steps for any single query block:

  1. Write down the tables in FROM, and the join rows they produce.
  2. Apply WHERE and keep only the rows that pass.
  3. Group the rows with GROUP BY, if present, and compute the aggregates.
  4. Apply HAVING to the groups.
  5. Keep the SELECT columns and compute any expressions.
  6. Remove duplicates if DISTINCT is written.
  7. Sort with ORDER BY.

Here is the full program, with the set operations checked.

import sqlite3

db = sqlite3.connect(":memory:")
db.executescript("""
CREATE TABLE Student (sid INTEGER, name TEXT, dept TEXT, cgpa REAL);
INSERT INTO Student VALUES (101,'Asha','CS',9.1),(102,'Ravi','EE',7.8),
  (103,'Meena','CS',8.7),(104,'Dev','ME',6.9),(105,'Kiran','CS',8.2);
CREATE TABLE Enrol (sid INTEGER, cid TEXT, grade INTEGER);
INSERT INTO Enrol VALUES (101,'CS101',9),(101,'CS301',8),(102,'EE201',7),
  (103,'CS101',10),(103,'CS301',9),(105,'CS301',6);
""")

print("in CS301:", db.execute("SELECT name FROM Student WHERE sid IN (SELECT sid FROM Enrol WHERE cid = 'CS301') ORDER BY name").fetchall())
print("above average:", db.execute("SELECT name FROM Student WHERE cgpa > (SELECT AVG(cgpa) FROM Student) ORDER BY name").fetchall())
print("no enrolment:", db.execute("SELECT name FROM Student s WHERE NOT EXISTS (SELECT * FROM Enrol e WHERE e.sid = s.sid)").fetchall())
print("UNION:", db.execute("SELECT cid FROM Enrol WHERE grade >= 9 UNION SELECT cid FROM Enrol WHERE sid = 101 ORDER BY cid").fetchall())
print("UNION ALL count:", db.execute("SELECT COUNT(*) FROM (SELECT cid FROM Enrol WHERE grade >= 9 UNION ALL SELECT cid FROM Enrol WHERE sid = 101)").fetchone()[0])
print("INTERSECT:", db.execute("SELECT cid FROM Enrol WHERE grade >= 9 INTERSECT SELECT cid FROM Enrol WHERE sid = 101 ORDER BY cid").fetchall())
print("EXCEPT:", db.execute("SELECT cid FROM Enrol EXCEPT SELECT cid FROM Enrol WHERE grade < 8 ORDER BY cid").fetchall())

Question: How many rows does X UNION ALL Y return if X has 3 rows and Y has 2 rows?

Five. UNION ALL keeps every row from both queries, including duplicates.

Question: Which operation would you use to find courses that student 101 does not take?

EXCEPT, applied to all course ids minus the course ids of student 101. Read it as "in the first set but not in the second".

Solved GATE-style problems

These problems are original, written in the GATE style. They are not past exam questions. Use the sample tables from the top of this page.

High grades

How many rows does SELECT * FROM Enrol WHERE grade >= 9 return?

How to think about it

  1. What is asked. A row count.
  2. Which idea applies. A WHERE filter with a comparison.
  3. Work it out. The grades are 9, 8, 7, 10, 9 and 6. Those at least 9 are 9, 10 and 9.
  4. Check. Three values, three rows.

Answer: 3.

First name after sorting

What is the first name in the output of SELECT name FROM Student WHERE dept = 'CS' ORDER BY cgpa?

How to think about it

  1. What is asked. The first output row after ascending sort.
  2. Which idea applies. WHERE first, then ORDER BY, which sorts from low to high by default.
  3. Work it out. The CS students are Asha (9.1), Meena (8.7) and Kiran (8.2). The lowest cgpa is Kiran's 8.2.
  4. Check. Ascending order puts the smallest value first.

Answer: Kiran.

Statements about a left join

Select all that apply. For Student s LEFT JOIN Enrol e ON s.sid = e.sid:

(A) The result has 7 rows.

(B) Dev appears with NULL as the cid.

(C) Ravi appears exactly once.

(D) Adding WHERE e.grade > 5 leaves 7 rows.

How to think about it

  1. What is asked. Which statements are true.
  2. Which idea applies. A left join keeps all left rows. A WHERE on the right table removes NULL rows.
  3. Work it out. (A) Six matched rows plus Dev makes 7. True. (B) True. (C) Ravi has one enrolment, so one row. True. (D) Dev's grade is NULL, so NULL > 5 is not true and Dev is removed. The result has 6 rows. False.
  4. Check. Count the rows: Asha 2, Meena 2, Kiran 1, Ravi 1, Dev 1 gives 7 before the WHERE.

Answer: (A), (B) and (C).

Distinct course count

Give the value returned by SELECT COUNT(DISTINCT cid) FROM Enrol.

How to think about it

  1. What is asked. The number of different course ids that appear in Enrol.
  2. Which idea applies. DISTINCT removes repeated values before counting.
  3. Work it out. The cid values are CS101, CS301, EE201, CS101, CS301 and CS301. The distinct values are CS101, CS301 and EE201.
  4. Check. Six rows, but only three different courses.

Answer: 3.

Credits for student 101

What value does SELECT SUM(c.credits) FROM Course c JOIN Enrol e ON c.cid = e.cid WHERE e.sid = 101 return?

How to think about it

  1. What is asked. The total credits of the courses taken by student 101.
  2. Which idea applies. Join on cid, filter by sid, then add.
  3. Work it out. Student 101 takes CS101 (4 credits) and CS301 (4 credits). 4 + 4 = 8.
  4. Check. Only two enrolment rows match sid 101, so only two credit values are added.

LEFT JOIN with a WHERE trap

What does this query return?

SELECT s.name
FROM Student s LEFT JOIN Enrol e ON s.sid = e.sid
WHERE e.cid = 'CS301'
ORDER BY s.name;

How to think about it

  1. What is asked. The names in the output.
  2. Which idea applies. The LEFT JOIN creates rows with NULL for Dev, but WHERE on the right table then removes NULL rows, so the outer join behaves like an inner join here.
  3. Work it out. Rows with cid CS301 are Asha, Meena and Kiran. Dev's cid is NULL, so Dev is removed.
  4. Check. Three names, sorted alphabetically.

Answer: Asha, Kiran, Meena.

Students with no enrolment

Which student is returned by SELECT name FROM Student WHERE sid NOT IN (SELECT sid FROM Enrol)?

How to think about it

  1. What is asked. The names of students whose sid is not in the Enrol list.
  2. Which idea applies. A NOT IN subquery. It is safe here because the inner list has no NULL.
  3. Work it out. Enrol contains sids 101, 102, 103 and 105. Students 104 (Dev) is not in that list.
  4. Check. Five students, four enrolled, one left over.

Answer: Dev.

Which queries return Ravi

Select all that apply. Which queries return Ravi?

(A) SELECT name FROM Student WHERE sid IN (SELECT sid FROM Enrol WHERE grade < 8)

(B) SELECT name FROM Student s WHERE EXISTS (SELECT * FROM Enrol e WHERE e.sid = s.sid AND e.cid = 'EE201')

(C) SELECT name FROM Student WHERE cgpa < 8

(D) SELECT name FROM Student WHERE dept = 'EE' INTERSECT SELECT name FROM Student WHERE cgpa > 9

How to think about it

  1. What is asked. Which of the four queries include Ravi in their output.
  2. Which idea applies. Evaluate each subquery or set operation separately.
  3. Work it out. (A) Enrol grades below 8 belong to sid 102 (Ravi, grade 7) and sid 105 (Kiran, grade 6). Ravi is returned. (B) Ravi has an EE201 row, so EXISTS is true. Ravi is returned. (C) Ravi's cgpa is 7.8, below 8. Ravi is returned. (D) The first part gives Ravi, and the second part gives Asha only. INTERSECT leaves nothing, so Ravi is not returned.
  4. Check. Three queries include Ravi, and the INTERSECT query has an empty result.

Exam-level 1: a filter inside LEFT JOIN ON (NAT, 2 marks)

Dept(did, name) has three rows: (1, Sales), (2, Research) and (3, HR). Emp(eid, did, salary) has five rows: (10, 1, 50), (11, 1, 30), (12, 2, 45), (13, 2, 44) and (14, 2, 20). The query is SELECT d.name, COUNT(e.eid) FROM Dept d LEFT JOIN Emp e ON e.did = d.did AND e.salary > 40 GROUP BY d.name. Add up the COUNT values over all output rows and give the total as a whole number.

How to think about it

  1. What is asked. The sum of the COUNT column.
  2. Which idea applies. A LEFT JOIN keeps every department even when nothing matches. A condition inside ON only removes matches. The same condition in WHERE would also remove the unmatched departments.
  3. Work it out. Sales: eid 10 (salary 50) matches, eid 11 (salary 30) does not, so COUNT is 1. Research: salaries 45 and 44 match, 20 does not, so COUNT is 2. HR has no match, so its padded row has a NULL eid, and COUNT ignores NULL, giving 0.
  4. Check. 1 + 2 + 0 = 3, and all three departments appear in the output.

Answer: 3.

dept=[(1,'Sales'),(2,'Research'),(3,'HR')]
emp=[(10,1,50),(11,1,30),(12,2,45),(13,2,44),(14,2,20)]
counts={}
for did,dname in dept:
    matched=[e for e in emp if e[1]==did and e[2]>40]
    counts[dname]=len(matched)
print(counts)
print(sum(counts.values()))
{'Sales': 1, 'Research': 2, 'HR': 0}

Exam-level 2: NULL and three-valued logic (MSQ, 2 marks)

Student(name, grade) has four rows: (Asha, A), (Ravi, B), (Meena, NULL) and (Dev, C). Three queries are run. Q1 is WHERE grade <> 'A'. Q2 is WHERE NOT (grade = 'A'). Q3 is WHERE grade <> 'A' OR grade IS NULL. Select all that apply. Which of these statements are true?

(A) Q1 returns Ravi and Dev only.

(B) Q2 returns Meena.

(C) Q3 returns the same rows as Q1.

(D) Q1 and Q2 return the same rows.

How to think about it

  1. What is asked. Which of the four statements are true.
  2. Which idea applies. Three-valued logic. A comparison with NULL gives UNKNOWN, and WHERE keeps only the rows that are TRUE.
  3. Work it out. Q1: Asha fails, Ravi and Dev pass, and Meena is UNKNOWN, so she is dropped. Q2: NOT applied to UNKNOWN is still UNKNOWN, so Meena is dropped again and the answer is Ravi and Dev. Q3 adds Meena through IS NULL, giving Ravi, Meena and Dev.
  4. Check. Q1 and Q2 match, and Q3 has one extra row. So (A) and (D) are true, and (B) and (C) are false.

Answer: (A) and (D). Why the others fail: (B) NOT of an unknown value is still unknown, so Meena is not returned; (C) Q3 adds Meena through IS NULL, so its rows differ from Q1.

rows=[('Asha','A'),('Ravi','B'),('Meena',None),('Dev','C')]
def neq(g): return None if g is None else g!='A'
def not_eq(g): return None if g is None else not (g=='A')
q1=[n for n,g in rows if neq(g) is True]
q2=[n for n,g in rows if not_eq(g) is True]
q3=[n for n,g in rows if neq(g) is True or g is None]
print(q1)
print(q2)
print(q3)
['Ravi', 'Dev']
['Ravi', 'Dev']
['Ravi', 'Meena', 'Dev']

Exam-level 3: HAVING after a WHERE filter (NAT, 2 marks)

Emp(eid, dept, salary, age) has seven rows: (1, CS, 50, 30), (2, CS, 35, 45), (3, EE, 42, 28), (4, ME, 60, 50), (5, EE, 28, 33), (6, CS, 44, 38) and (7, ME, 40, 26). The query is SELECT dept FROM Emp WHERE age >= 30 GROUP BY dept HAVING AVG(salary) > 40. How many rows does the query return?

How to think about it

  1. What is asked. The number of output rows, one per department that survives.
  2. Which idea applies. WHERE filters single rows before grouping. HAVING filters whole groups after the averages are computed.
  3. Work it out. Rows with age 30 or more are 1, 2, 4, 5 and 6. CS has salaries 50, 35 and 44, with an average of 43, so it passes. EE has only 28, with an average of 28, so it fails. ME has only 60, with an average of 60, so it passes.
  4. Check. Rows 3 and 7 were removed by WHERE before grouping. Two departments remain.

Answer: 2 (CS and ME).

emp=[(1,'CS',50,30),(2,'CS',35,45),(3,'EE',42,28),(4,'ME',60,50),(5,'EE',28,33),(6,'CS',44,38),(7,'ME',40,26)]
groups={}
for eid,dept,sal,age in emp:
    if age>=30:
        groups.setdefault(dept,[]).append(sal)
res=[d for d in groups if sum(groups[d])/len(groups[d])>40]
print(groups)
print(sorted(res))
print(len(res))
{'CS': [50, 35, 44], 'ME': [60], 'EE': [28]}
['CS', 'ME']

Exam-level 4: UNION ALL keeps duplicates (NAT, 2 marks)

Table A has the single column x with values 1, 2, 2 and 3. Table B has the single column x with values 2, 3, 3 and 4. The query is SELECT x FROM (SELECT x FROM A UNION ALL SELECT x FROM B) u GROUP BY x HAVING COUNT(*) > 1. How many rows does the query return?

How to think about it

  1. What is asked. The number of groups whose count is above 1.
  2. Which idea applies. UNION ALL keeps duplicates, unlike UNION, so all 8 values are present. GROUP BY then counts each value.
  3. Work it out. The value 1 appears once, 2 appears three times, 3 appears three times, and 4 appears once. The groups with a count above 1 are 2 and 3.
  4. Check. The counts add to 8: 1 + 3 + 3 + 1 = 8. A plain UNION would remove duplicates first, so every count would be 1 and no rows would return.

Answer: 2 (the groups for 2 and 3).

from collections import Counter
A=[1,2,2,3]
B=[2,3,3,4]
c=Counter(A+B)
print(sorted(c.items()))
print(sum(1 for v in c.values() if v>1))
[(1, 1), (2, 3), (3, 3), (4, 1)]

Summary

SQL
The declarative language for asking questions of a relational database.
SELECT
Lists the output columns or expressions.
FROM
Names the input tables.
WHERE
Keeps rows where a condition is true, before grouping.
Alias
A short name given to a table or column for reading and self joins.
Inner join
Keeps only matched pairs.
LEFT JOIN
Keeps every left row, with NULL where there is no match.
FULL OUTER JOIN
Keeps unmatched rows from both sides, with NULL on the missing side.
Self join
A table joined with itself, using two aliases.
Cross join
All pairs of rows, giving m × n rows.
NULL
A missing value. Not equal to anything, tested with IS NULL.
Aggregate function
A function that turns many rows into one value: COUNT, SUM, AVG, MIN or MAX.
GROUP BY
Splits rows into groups for aggregates.
HAVING
Filters groups after the aggregates are computed.
ORDER BY
Sorts the output rows.
DISTINCT
Removes duplicate output rows.
Subquery
A query inside brackets, used by an outer query.
Correlated subquery
A subquery that refers to a column of the outer query and is re-run for each outer row.
IN
Tests whether a value appears in a subquery result.
EXISTS and NOT EXISTS
Test whether a subquery returns at least one row, or none.
UNION
Combines two results and removes duplicates.
UNION ALL
Combines two results and keeps duplicates.
INTERSECT
Keeps rows that appear in both results.
EXCEPT
Keeps rows of the first result that are not in the second.

Remember these

  1. Read a query in clause order: FROM, WHERE, GROUP BY, HAVING, SELECT, DISTINCT, ORDER BY.
  2. An outer join keeps unmatched rows. A WHERE on the outer side can undo that.
  3. WHERE cannot test an aggregate. HAVING can.
  4. COUNT(*) counts rows. COUNT(col) skips NULL values.
  5. Prefer NOT EXISTS over NOT IN when NULL may be present.
  6. UNION and INTERSECT remove duplicates. UNION ALL keeps them.
