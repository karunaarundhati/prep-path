Shortest path algorithms

A shortest path algorithm answers one everyday question: what is the cheapest way to get from here to everywhere else? Dijkstra's algorithm solves it quickly when every road cost is zero or positive. Bellman-Ford also handles negative costs and warns you when a negative loop makes the question meaningless. GATE often asks you to trace both step by step.

The idea in plain words

A navigation app that finds the fastest route to your friend's house is solving a shortest path problem. The map is a graph. Each junction is a vertex, each road is an edge, and each edge has a weight, such as the travel time in minutes. The length of a path is the sum of the weights along it. The shortest path is the path with the smallest sum.

There are two main questions in this area. The first is single-source shortest path: fix one start vertex and find the shortest path from it to every other vertex. The second is all pairs, where you want the answer for every start and every end. This page covers single-source problems, which are the common GATE type.

The two algorithms in this page work in different ways. Dijkstra is greedy: it always fixes the nearest unfinished vertex and never looks back. Bellman-Ford is patient: it relaxes every edge again and again until nothing improves. The trade-off is speed against the ability to handle negative weights.

Key ideaBoth algorithms keep a table of best-known distances, starting with 0 for the source and infinity for everything else. They improve the table one edge at a time. This improvement step is called relaxation.

Key terms

Weight
The number attached to an edge, such as a cost or a time. Precisely: a value w(u, v) for each edge from u to v.
Path length
The sum of the weights of the edges on a path. Precisely: for path v0, v1, ..., vk, the length is w(v0, v1) + ... + w(vk-1, vk).
Source
The start vertex for a single-source problem. Its distance to itself is 0.
Distance table
A record of the best distance found so far for each vertex. Precisely: dist[v] is an upper bound on the true shortest distance, starting at infinity.
Infinity
A value bigger than any real distance, used before a vertex is reached. Written as inf or as the symbol for infinity.
Relaxation
Checking an edge u to v and improving dist[v] if going through u is cheaper. Precisely: if dist[u] + w(u, v) < dist[v], set dist[v] = dist[u] + w(u, v).
Settled (finalised) vertex
A vertex whose distance can no longer change. Precisely: Dijkstra settles a vertex when it removes the vertex with the smallest tentative distance.
Greedy algorithm
An algorithm that makes the locally best choice at each step. Precisely: Dijkstra always settles the closest unsettled vertex.
Negative weight
An edge with a value below zero. It represents a gain, such as a refund, rather than a cost.
Negative cycle
A cycle whose total weight is below zero. Precisely: going around it again and again makes the path cost fall without limit.
Priority queue
A structure that returns the item with the smallest key quickly. Precisely: a binary heap, as on the previous recap page, is the usual choice.

Weighted paths and the distance table

Here is the running example for this page. It is a directed weighted graph with vertices S, A, B, C and D. Each arrow shows a one-way road and its weight.

  S --4--> A
  S --1--> B
  B --2--> A
  A --5--> C
  B --8--> C
  B --6--> D
  C --3--> D

The picture is busy, so the list underneath is the reliable version. Every edge is one-way. Notice that S to A directly costs 4, but S to B to A costs 1 + 2 = 3, which is cheaper. A shortest path is not always the path with the fewest edges.

To keep track of progress, we use a distance table. It has one entry per vertex. At the start, the source S has distance 0, and every other vertex has distance infinity, because nothing has been reached yet. Each algorithm then improves entries by relaxation. When an entry can no longer improve, the algorithm has found the exact shortest distance.

relax(u, v): if dist[u] + w(u, v) < dist[v], then dist[v] = dist[u] + w(u, v)

Worked example. Suppose dist[S] = 0 and dist[A] = infinity. Relax the edge S to A with weight 4. Is 0 + 4 less than infinity? Yes, so dist[A] becomes 4. Now relax S to B with weight 1: 0 + 1 = 1 is less than infinity, so dist[B] becomes 1. The table is now S = 0, A = 4, B = 1, C = inf, D = inf.

TipRelaxation is a question you ask about one edge at a time: "Is there a cheaper way to reach this vertex by going through this edge?" Keep asking it until no edge gives a better answer.

What is the cost of the path S, B, A?

1 + 2 = 3, because S to B costs 1 and B to A costs 2.

Why is the edge S to A (weight 4) not part of the final shortest path to A?

Because the route S, B, A costs 3, which is less than 4. Relaxation finds the cheaper route and replaces the direct edge.

Dijkstra's algorithm: always take the nearest vertex

Dijkstra's algorithm works like a ripple spreading outward from the source. At each step it picks the unsettled vertex with the smallest tentative distance. That vertex's distance is now final, because no later path can beat it (all weights are zero or positive, so going further can only add cost). It then relaxes the edges leaving that vertex, and the process repeats.

The steps are:

  1. Set dist[source] = 0 and all others to infinity. Mark nothing as settled.
  2. Pick the unsettled vertex u with the smallest dist. Mark u as settled.
  3. For each edge u to v, relax it.
  4. Repeat from step 2 until every vertex is settled or no vertex has a finite distance.

The program below runs Dijkstra with a binary heap as the priority queue. The heap holds pairs (distance, vertex), and stale entries are skipped.

import heapq

def dijkstra(graph, source):
    dist = {v: float("inf") for v in graph}
    dist[source] = 0
    heap = [(0, source)]
    while heap:
        d, u = heapq.heappop(heap)
        if d > dist[u]:
            continue
        for v, w in graph[u]:
            if d + w < dist[v]:
                dist[v] = d + w
                heapq.heappush(heap, (dist[v], v))
    return dist

graph = {
    "S": [("A", 4), ("B", 1)],
    "A": [("C", 5)],
    "B": [("A", 2), ("C", 8), ("D", 6)],
    "C": [("D", 3)],
    "D": [],
}
print(dijkstra(graph, "S"))
{'S': 0, 'A': 3, 'B': 1, 'C': 8, 'D': 7}

Key ideaDijkstra is correct only when no edge is negative. Its guarantee rests on the fact that a settled vertex can never be improved later.

Which vertex does Dijkstra settle second in the running example?

B, with distance 1. After S, the smallest tentative distance is 1 (for B), since A is still at 4.

What is the time complexity of Dijkstra with a binary heap?

O((V + E) log V), which is usually written as O(E log V) for a connected graph. With a plain array instead of a heap, the cost is O(V2).

Why Dijkstra fails with negative weights, and Bellman-Ford

Dijkstra's guarantee depends on one assumption. When it settles a vertex, no later path can be cheaper. A negative edge breaks this, because a long detour can end with a big saving.

Here is a small trap. Take three vertices with edges S to A (weight 2), S to B (weight 5) and B to A (weight -4). Dijkstra settles A first, with distance 2, because it is the nearest tentative vertex. Later it settles B with distance 5, and relaxes B to A: 5 - 4 = 1, which is less than 2. But A is already settled, so the algorithm never revisits it. It reports A = 2. The true shortest distance to A is 1, through S, B, A.

TrapWhen a question has a negative edge, do not use Dijkstra. Use Bellman-Ford. A common GATE trick gives a graph with one negative edge and asks for the distance that Dijkstra would wrongly report.

Bellman-Ford: relax every edge, again and again

Bellman-Ford does not try to settle vertices. It simply goes through the full list of edges and relaxes each one. It repeats this pass V - 1 times, where V is the number of vertices. Why V - 1? A shortest path that uses at most V - 1 edges is found after that many passes, because each pass extends every known path by one more edge.

Worked trace. Use edges in this order: S to X (4), S to Y (5), X to Y (-2), Y to Z (3), X to Z (6). The vertices are S, X, Y and Z, so V = 4 and there are 3 passes.

  • Start: S = 0, X = inf, Y = inf, Z = inf.
  • Pass 1, edge S to X: 0 + 4 = 4 is less than inf, so X = 4.
  • Pass 1, edge S to Y: 0 + 5 = 5, so Y = 5.
  • Pass 1, edge X to Y: 4 - 2 = 2, which is less than 5, so Y = 2.
  • Pass 1, edge Y to Z: 2 + 3 = 5, so Z = 5.
  • Pass 1, edge X to Z: 4 + 6 = 10, which is not less than 5, so Z stays 5.
  • Pass 2 and pass 3 change nothing, so the table is final: S = 0, X = 4, Y = 2, Z = 5.

The Python code below uses this method. It also includes the trap graph, which Bellman-Ford handles correctly.

def bellman_ford(edges, vertices, source):
    dist = {v: float("inf") for v in vertices}
    dist[source] = 0
    for _ in range(len(vertices) - 1):
        for u, v, w in edges:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
    for u, v, w in edges:
        if dist[u] + w < dist[v]:
            return None
    return dist

edges = [("S", "X", 4), ("S", "Y", 5), ("X", "Y", -2), ("Y", "Z", 3), ("X", "Z", 6)]
print(bellman_ford(edges, ["S", "X", "Y", "Z"], "S"))

trap = [("S", "A", 2), ("S", "B", 5), ("B", "A", -4)]
print(bellman_ford(trap, ["S", "A", "B"], "S"))
{'S': 0, 'X': 4, 'Y': 2, 'Z': 5}
{'S': 0, 'A': 1, 'B': 5}

Read the output carefully. In the second graph, Bellman-Ford found the value 1 for A, which is the correct answer that Dijkstra missed.

How many passes does Bellman-Ford make over the edge list for a graph with 10 vertices?

9 passes (V - 1), followed by one extra check pass to look for negative cycles.

In the Bellman-Ford trace above, why does pass 2 make no changes?

Every vertex already has its shortest distance after pass 1 (X = 4, Y = 2, Z = 5), so no edge can improve any entry.

Negative cycles, complexity and choosing an algorithm

A negative cycle is a loop whose total weight is below zero. Suppose vertices A, B and C form the cycle A to B (weight 1), B to C (weight -3) and C to A (weight 1). Going once around costs 1 - 3 + 1 = -1. Going around twice costs -2, and so on. A path from S into this loop could be made cheaper without limit, so the shortest distance is undefined (minus infinity).

Bellman-Ford detects this. After V - 1 passes, every shortest path with at most V - 1 edges is final. If one more pass can still relax some edge, a negative cycle must exist (reachable from the source). The code above returns None in that case.

GATE loves thisA shortest path question with a negative cycle has no answer. If the question asks for the shortest distance, check first whether a negative cycle is reachable from the source. If one is, say so.

Comparing the two algorithms

FeatureDijkstraBellman-Ford
Negative edge weightsNot allowed (answers can be wrong)Allowed

Typical useRoad maps, network routing with positive costsGraphs with negative costs or a need to detect negative cycles

Some facts follow from the table. Bellman-Ford is always slower on large graphs, because O(V E) is larger than O((V + E) log V) for typical graphs. Dijkstra is faster, but only if the weights are non-negative. Both work on undirected graphs with non-negative weights, because each undirected edge is treated as two directed edges.

TrapBellman-Ford is not "always faster" or "always better". It is the right tool only when negative weights or negative cycle checks are needed. Do not pick it for ordinary positive-weight maps.

Is a graph with a negative edge but no negative cycle a problem for Bellman-Ford?

No. Bellman-Ford handles negative edges correctly as long as no negative cycle is reachable from the source.

Can Dijkstra be used on an undirected graph with positive weights?

Yes. Each undirected edge is treated as two directed edges with the same non-negative weight.

Solved GATE-style problems

These problems are original GATE-style questions written for practice. They are not past exam questions. Use a distance table for every trace.

Shortest distance from S to T

A directed graph has edges S to P (3), S to Q (7), P to Q (2), Q to T (1) and P to T (9). All weights are positive. What is the shortest distance from S to T?

How to think about it

  1. What is asked. One number: the least total weight from S to T.
  2. Which idea applies. List the routes from S to T and add their weights. The shortest distance is the smallest sum.
  3. Work it out. Route S, P, Q, T costs 3 + 2 + 1 = 6. Route S, P, T costs 3 + 9 = 12. Route S, Q, T costs 7 + 1 = 8. The smallest is 6.
  4. Check. The cheapest route uses three edges, not two, which is a reminder that the fewest edges is not always cheapest. The code below prints the minimum of the three sums.

Answer: 6, through S, P, Q, T.

print(min(3 + 2 + 1, 3 + 9, 7 + 1))
6

Which algorithm handles negative edges?

A road network has one edge with weight -2, and no cycle of negative total weight. Select the correct algorithm: (A) Dijkstra's algorithm, (B) Bellman-Ford. Select one.

How to think about it

  1. What is asked. Which algorithm is safe to use here.
  2. Which idea applies. Dijkstra needs all weights to be zero or positive. Bellman-Ford allows negative weights as long as no negative cycle is reachable.
  3. Work it out. The graph has a negative edge, so Dijkstra is ruled out. There is no negative cycle, so Bellman-Ford gives a correct answer.
  4. Check. Dijkstra would be fine if the -2 edge were removed, which confirms that the negative edge is the reason.

Answer: (B) Bellman-Ford.

Which statements about shortest paths are true?

Select all that apply.

  • (A) Dijkstra's algorithm with a binary heap runs in O((V + E) log V) time.
  • (B) Bellman-Ford can detect a negative cycle reachable from the source.
  • (C) Dijkstra can return a wrong answer when some edge weight is negative.
  • (D) Bellman-Ford is always faster than Dijkstra.
  • (E) Dijkstra works on an undirected graph with non-negative weights.

How to think about it

  1. What is asked. Which claims are true.
  2. Which idea applies. Use the complexity and assumptions from this page.
  3. Work it out. (A) True. (B) True, by the extra pass. (C) True, the trap graph shows this. (D) False, O(V E) is usually larger than O((V + E) log V). (E) True, each undirected edge becomes two directed edges with the same weight.
  4. Check. For (D), a graph with 1,000 vertices and 5,000 edges gives about 5,000,000 operations for Bellman-Ford and about 60,000 for Dijkstra with a heap.

Answer: (A), (B), (C) and (E).

What does this heap program print?

Dijkstra keeps pairs of (distance, vertex) in a heap. Trace the program.

import heapq

h = []
for d, v in [(5, "B"), (2, "A"), (9, "C"), (3, "D")]:
    heapq.heappush(h, (d, v))

How to think about it

  1. What is asked. Two popped items and the size of the heap afterwards.
  2. Which idea applies. A heap pops the smallest item first. Tuples compare by their first element, so the distance decides the order.
  3. Work it out. Pushing gives four items. The smallest distance is 2, from (2, "A"), so the first pop returns it. The next smallest is 3, from (3, "D"). After two pops, two items remain.
  4. Check. 4 items minus 2 pops leaves 2. The printed tuples are in increasing distance, as a min-heap must give.

Answer: the program prints (2, 'A'), then (3, 'D'), then 2.

How many vertices are settled before T?

Run Dijkstra from S on a directed graph with edges S to P (2), S to Q (6), P to Q (3), P to T (9) and Q to T (1). How many vertices are settled before T is settled? Do not count T itself.

How to think about it

  1. What is asked. A count of settled vertices that come before T.
  2. Which idea applies. Dijkstra settles vertices in increasing order of final distance.
  3. Work it out. Start: S = 0 is settled first. Relaxing gives P = 2 and Q = 6. P (2) is settled next. Relaxing P gives Q = min(6, 2 + 3) = 5 and T = 2 + 9 = 11. Q (5) is settled next. Relaxing Q gives T = min(11, 5 + 1) = 6. Now T (6) is the smallest tentative vertex and is settled. Before T, the settled vertices are S, P and Q.
  4. Check. The true distance to T is 6, which the code below confirms by listing all routes.

Answer: 3 vertices (S, P and Q) are settled before T.

print(min(2 + 9, 2 + 3 + 1, 6 + 1))
6

Final distances after Bellman-Ford

Run Bellman-Ford from S on the edges listed in this order: S to A (5), S to B (2), B to A (-4), A to C (1), B to C (6). What is the final distance to C?

How to think about it

  1. What is asked. The final value of dist[C].
  2. Which idea applies. Relax the edges in the given order, pass after pass, until nothing changes.
  3. Work it out. Pass 1: S to A gives A = 5. S to B gives B = 2. B to A gives 2 - 4 = -2, which beats 5, so A = -2. A to C gives -2 + 1 = -1, so C = -1. B to C gives 2 + 6 = 8, not better. Pass 2 changes nothing: B to A gives -2, equal to the current value, which is not strictly less. So the final table is S = 0, A = -2, B = 2, C = -1.
  4. Check. The path S, B, A, C costs 2 - 4 + 1 = -1, and the code below confirms the table.

Answer: dist[C] = -1.

def bellman_ford(edges, vertices, source):
    dist = {v: float("inf") for v in vertices}
    dist[source] = 0
    for _ in range(len(vertices) - 1):
        for u, v, w in edges:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
    return dist

edges = [("S", "A", 5), ("S", "B", 2), ("B", "A", -4), ("A", "C", 1), ("B", "C", 6)]
print(bellman_ford(edges, ["S", "A", "B", "C"], "S"))
{'S': 0, 'A': -2, 'B': 2, 'C': -1}

Total weight of a negative cycle

A graph has the cycle A to B (weight 1), B to C (weight -3) and C to A (weight 1). Compute the total weight of one trip around this cycle. Is the cycle negative?

How to think about it

  1. What is asked. The sum of the three weights, and whether it is below zero.
  2. Which idea applies. A cycle is negative if its total weight is less than zero.
  3. Work it out. 1 + (-3) + 1 = -1. This is below zero, so the cycle is negative.
  4. Check. Going around twice gives -2. Each trip makes the total smaller, so no shortest path through this cycle exists.

Answer: the total is -1, so the cycle is negative.

print(1 + (-3) + 1)
-1

Exam-level practice

Exam-level 1: Dijkstra distances (NAT, 2 marks)

Directed edges with weights: S→A 4, S→B 1, B→A 2, A→C 1, B→C 5, C→D 3, A→D 6. Find the shortest distance from S to D.

How to think about it

  1. What is asked. The shortest S to D distance.
  2. Which idea applies. Dijkstra relaxes from the closest settled vertex.
  3. Work it out. B = 1, A = min(4, 1 + 2) = 3, C = min(1 + 5, 3 + 1) = 4, D = min(3 + 6, 4 + 3) = 7.
  4. Check. The code runs Dijkstra.
import heapq
G = {"S": [("A", 4), ("B", 1)], "B": [("A", 2), ("C", 5)], "A": [("C", 1), ("D", 6)], "C": [("D", 3)], "D": []}
d = {"S": 0}; pq = [(0, "S")]
while pq:
    du, u = heapq.heappop(pq)
    if du > d[u]: continue
    for v, w in G[u]:
        if du + w < d.get(v, 1e9): d[v] = du + w; heapq.heappush(pq, (d[v], v))
print(d)

{'S': 0, 'A': 3, 'B': 1, 'C': 4, 'D': 7}

Answer: 7.

Exam-level 2: Negative edges (MSQ, 2 marks)

Which are TRUE? (A) Dijkstra may give wrong answers with negative edges. (B) Bellman-Ford detects negative cycles reachable from the source. (C) Bellman-Ford runs in O(VE). (D) Adding a constant to every edge preserves shortest paths.

How to think about it

  1. What is asked. Facts about shortest path algorithms.
  2. Which idea applies. Adding a constant penalises paths with more edges.
  3. Work it out. (A) True. (B) True. (C) True. (D) A path with more edges gains more. False.
  4. Check. Paths S→T of weight 3 (1 edge) and S→A→T of weight 1 + 1: adding 2 makes them 5 and 6, so the winner changes.

Exam-level 3: Floyd-Warshall entry (NAT, 2 marks)

Weights: 1→2 3, 2→3 −2, 1→3 4, 3→1 1. Run Floyd-Warshall. What is the shortest distance from 2 to 1?

How to think about it

  1. What is asked. One entry of the all pairs distance matrix.
  2. Which idea applies. The only route from 2 to 1 goes through 3.
  3. Work it out. 2→3→1 = −2 + 1 = −1.
  4. Check. The cycle 1→2→3→1 has weight 3 − 2 + 1 = 2, positive, so distances are well defined.
INF = float("inf")
D = [[0, 3, 4], [INF, 0, -2], [1, INF, 0]]
for k in range(3):
    for i in range(3):
        for j in range(3):
            D[i][j] = min(D[i][j], D[i][k] + D[k][j])
print(D)

[[0, 3, 1], [-1, 0, -2], [1, 4, 0]]

Answer: −1.
