Recursion (recap)

Recursion means a function that calls itself to solve a smaller copy of the same problem. It is a neat way to write factorials, tree walks and puzzles such as the Tower of Hanoi. This quick recap covers the base case and the recursive case, how the call stack works, why some recursive programs become very slow, and the counting facts GATE asks about.

The idea in plain words

Imagine you are in a long queue and want to know your position. You cannot see the front, so you ask the person in front of you. They ask the person ahead, and so on, until the first person says "I am first, so my position is 1". Each person then adds one and passes the answer back. That is recursion. The question is passed down a line of smaller questions until one can be answered directly, and then the answers travel back up.

Every correct recursive function has two parts. The base case is the simple case that is answered directly, with no further calls. The recursive case reduces the problem to a smaller one and calls itself on it. If the base case is missing, or the calls never get closer to it, the function runs forever (or until Python stops it with an error).

Key ideaRecursion needs a base case that stops it, and a recursive step that moves towards that base case. Check both before you trust any recursive program.

Key terms

Recursion
A function that calls itself. Precisely: the function body contains a call to the same function with a smaller input.
Base case
The input for which the answer is given directly, without a further call.
Recursive case
The part where the function calls itself on a smaller problem.
Call stack
The record of calls that are still waiting for an answer. Precisely: each active call is a frame holding its variables, and the newest frame is on top.
Frame
One entry on the call stack, for one active call.
Factorial
n! is the product 1 x 2 x ... x n, with 0! defined as 1.
Fibonacci numbers
F(0) = 0, F(1) = 1, and F(n) = F(n - 1) + F(n - 2) for n at least 2.
Tower of Hanoi
A puzzle with three pegs and n disks of different sizes. Move all disks to another peg, one at a time, never placing a bigger disk on a smaller one.
Iteration
Repeating code with a loop instead of with calls. Precisely: a for or while loop.
Recursion depth
The largest number of frames on the call stack at one time.

The base case and the recursive case

Let us write the simplest useful recursion: the number of items in a list, counted one at a time. The base case says: an empty list has 0 items. The recursive case says: a non-empty list has 1 item plus the number of items in the rest of the list. Each call works on a shorter list, so the calls reach the base case after one call per item.

Writing the rule as an equation helps. If L is the list, then count(L) = 0 when L is empty, and count(L) = 1 + count(rest of L) otherwise. The same pattern works for every recursion: an equation with a base value and a formula that uses a smaller input.

count(empty list) = 0
count(L) = 1 + count(L without its first item)

Common mistakes are a wrong base case (for example, stopping at n == 1 when n == 0 is also possible), and a recursive call that does not get smaller (for example, calling f(n) instead of f(n - 1)). Always ask: "what is the smallest input I answer directly, and does every call move towards it?"

What is the base case for counting the items in a list?

An empty list, whose count is 0.

What goes wrong if the recursive call uses n instead of n - 1?

The input never gets smaller, so the calls never reach the base case and the program does not stop.

Factorial and the call stack

The factorial of n, written n!, is 1 x 2 x 3 x ... x n. For example 4! = 4 x 3 x 2 x 1 = 24. The base case is 0! = 1, which is a convention that makes the formulas work. The recursive case uses the rule n! = n x (n - 1)!.

def fact(n):
    if n == 0:
        return 1
    return n * fact(n - 1)

print(fact(5))
120

To see how Python runs this, follow the call stack for fact(3). Each call starts, then waits for the call below it to return:

  • fact(3) needs fact(2). It waits.
  • fact(2) needs fact(1). It waits.
  • fact(1) needs fact(0). It waits.
  • fact(0) is the base case. It returns 1.
  • fact(1) computes 1 x 1 = 1 and returns it.
  • fact(2) computes 2 x 1 = 2 and returns it.
  • fact(3) computes 3 x 2 = 6 and returns it.

At the deepest point there are four frames on the stack: fact(3), fact(2), fact(1) and fact(0). Each frame holds its own copy of n. Frames are removed one at a time as answers return. This is the picture behind almost every recursion question.

TipWhen tracing a recursive call, write the call, then the reason it waits, then the value that comes back. A small table like the list above avoids most mistakes.

How many frames are on the stack when fact(4) reaches its base case?

Five: fact(4), fact(3), fact(2), fact(1) and fact(0).

Fibonacci and the cost of repeated work

The Fibonacci numbers start 0, 1, 1, 2, 3, 5, 8, 13, and each one after the first two is the sum of the two before it. The recursive definition copies this rule directly. The program below also counts the calls, so you can see the cost.

calls = 0

def fib(n):
    global calls
    calls += 1
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(5), calls)
5 15

The answer to fib(5) is 5, and it took 15 calls. The reason is that fib(5) asks for fib(4) and fib(3), and fib(4) asks for fib(3) again. The same smaller values are recomputed many times. Let C(n) be the number of calls for fib(n). Then C(0) = C(1) = 1, and C(n) = 1 + C(n - 1) + C(n - 2). This gives C(2) = 3, C(3) = 5, C(4) = 9, C(5) = 15 and C(6) = 25. The count grows exponentially, roughly like 1.6 to the power n, which is far too slow for large n.

naive recursive Fibonacci: about 1.6n calls

A loop avoids the repeated work. It keeps only the last two values and moves forward once.

def fib_iter(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a

print(fib_iter(10))
55

TrapA recursive function can be correct and still be far too slow. Count the calls before you accept a recursive design, and remember that memoization (storing answers already computed) also removes the repeated work.

Why does fib(5) make 15 calls?

Because each call with n of 2 or more makes two more calls, and the smaller values are recomputed many times. Counting all calls gives 15.

What is the value of fib_iter(7)?

13. The sequence is 0, 1, 1, 2, 3, 5, 8, 13, so index 7 holds 13.

Tower of Hanoi: a recursion that is natural

The puzzle has three pegs, A, B and C, and n disks. All disks start on peg A, the smallest on top and the largest at the bottom. Move them all to peg C, one disk at a time, and never put a larger disk on a smaller one. Peg B is a spare.

The recursive idea has three steps. To move n disks from A to C: first move the top n - 1 disks from A to B (using C as the spare). Then move the largest disk from A to C, which is now free. Then move the n - 1 disks from B to C (using A as the spare). The base case is zero disks, which needs no moves.

moves(n) = 2 x moves(n - 1) + 1, with moves(0) = 0, so moves(n) = 2n - 1

For three disks the answer is 23 - 1 = 7 moves. The program below prints the moves for three disks. Notice that the moves are written with an arrow, and the code escapes the greater-than sign as >.

def hanoi(n, src, dst, aux, moves):
    if n == 0:
        return
    hanoi(n - 1, src, aux, dst, moves)
    moves.append(src + "->" + dst)
    hanoi(n - 1, aux, dst, src, moves)

moves = []
hanoi(3, "A", "C", "B", moves)
print(len(moves))
print(moves)
7
['A->C', 'A->B', 'C->B', 'A->C', 'B->A', 'B->C', 'A->C']

GATE loves thisThe smallest disk moves on every other move, so it moves 2n-1 times in total. For three disks that is 4 times, which is the first, third, fifth and seventh move.

How many moves does the puzzle need for 4 disks?

15, because 24 - 1 = 15.

What is the first move for 3 disks from A to C?

A to C. The first move in the list above is A->C, the smallest disk going to the target peg.

Recursion versus iteration

Every recursive function can be written with a loop, and every loop can be written with recursion. The choice depends on the problem. Recursion matches problems that split naturally into smaller copies, such as trees, Hanoi and divide-and-conquer sorting. Iteration is usually faster and uses less memory, because a loop keeps only a few variables rather than a frame for each call.

Recursion has a memory cost. Each pending call needs a frame on the call stack. Python stops a chain of nested calls after about 1,000 by default, with a RecursionError. A loop has no such limit.

TipIf a question asks for the stack space used by a recursive call, count the depth. If it asks for the time of a naive recursion, count the calls.

Which is usually faster, a loop or the equivalent recursion?

A loop, because it avoids the overhead of creating a frame for each call.

What error does Python raise when recursion is too deep?

RecursionError.

Doubling recursively

What does this program print?

def f(n):
    if n == 0:
        return 1
    return 2 * f(n - 1)

print(f(4))

How to think about it

  1. What is asked. The value of f(4).
  2. Which idea applies. Base case: f(0) = 1. Recursive case: f(n) = 2 x f(n - 1).
  3. Work it out. f(4) = 2 x f(3). f(3) = 2 x f(2). f(2) = 2 x f(1). f(1) = 2 x f(0) = 2 x 1 = 2. Then f(2) = 4, f(3) = 8, f(4) = 16.
  4. Check. Doubling four times from 1 gives 16, which is 24.

Answer: 16

def f(n):
    if n == 0:
        return 1
    return 2 * f(n - 1)

print(f(4))
16

Moves for four disks

What is the minimum number of moves for the Tower of Hanoi with 4 disks? Verify with a calculation.

How to think about it

  1. What is asked. The minimum number of moves for 4 disks.
  2. Which idea applies. The minimum is 2n - 1.
  3. Work it out. With n = 4, 24 = 16, and 16 - 1 = 15.
  4. Check. Using moves(n) = 2 x moves(n - 1) + 1: 1, 3, 7, 15 for n = 1 to 4.

Answer: 15

print(2 ** 4 - 1)
15

Which statements about recursion are true?

Select all that apply.

  • (A) Every correct recursive function needs a base case.
  • (B) The naive recursive Fibonacci makes an exponential number of calls.
  • (C) Each recursive call must move towards the base case.
  • (D) Recursion uses no extra memory compared with a loop.
  • (E) Any recursion can be rewritten as a loop that keeps its own stack.

How to think about it

  1. What is asked. Which claims are true.
  2. Which idea applies. Base case, progress, call counts, and the call stack.
  3. Work it out. (A) True, without a base case the calls never stop. (B) True, the counts grow like 1.6n. (C) True, otherwise the base case is never reached. (D) False, each pending call needs a frame on the call stack. (E) True, an explicit stack in a loop can replace the call stack.
  4. Check. For (D), recall that fact(5) holds six frames at its deepest point, which is memory that a simple loop does not need.

Answer: (A), (B), (C) and (E).

Sum by recursion

What does this program print?

def f(n):
    if n == 0:
        return 0

How to think about it

  1. What is asked. The value of f(4).
  2. Which idea applies. f(n) adds n to the answer for n - 1, and f(0) = 0.
  3. Work it out. f(4) = 4 + f(3) = 4 + 3 + f(2) = 4 + 3 + 2 + f(1) = 4 + 3 + 2 + 1 + f(0) = 10 + 0 = 10.
  4. Check. The sum 1 + 2 + 3 + 4 is 10.

Enter and leave

What does this program print, in order?

def g(n):
    if n <= 0:
        print("base")
        return
    print("enter", n)
    g(n - 1)
    print("leave", n)

g(2)

How to think about it

  1. What is asked. Every printed line in order.
  2. Which idea applies. Code before the recursive call runs on the way down, and code after the call runs on the way back up.
  3. Work it out. g(2) prints "enter 2" and calls g(1). g(1) prints "enter 1" and calls g(0). g(0) prints "base" and returns. Back in g(1), it prints "leave 1". Back in g(2), it prints "leave 2".
  4. Check. Each "enter" has exactly one matching "leave", in reverse order, and "base" appears once in the middle.

Answer: enter 2, enter 1, base, leave 1, leave 2 (one per line).

    if n <= 0:

        return
    print("enter", n)
    g(n - 1)
    print("leave", n)

Calls for fib(6)

The naive recursive Fibonacci program below counts its calls. How many calls does fib(6) make?

calls = 0

def fib(n):
    global calls
    calls += 1
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

fib(6)
print(calls)

How to think about it

  1. What is asked. The number of calls, which is the printed value of calls.
  2. Which idea applies. C(n) = 1 + C(n - 1) + C(n - 2), with C(0) = C(1) = 1.
  3. Work it out. C(0) = 1 and C(1) = 1. C(2) = 1 + 1 + 1 = 3. C(3) = 1 + 3 + 1 = 5. C(4) = 1 + 5 + 3 = 9. C(5) = 1 + 9 + 5 = 15. C(6) = 1 + 15 + 9 = 25.
  4. Check. The code below prints the count, which should match 25.

Answer: 25 calls.

Disk 1 in a three-disk puzzle

In the optimal solution for 3 disks, moving all disks from A to C, how many times does the smallest disk (disk 1) move?

How to think about it

  1. What is asked. The count of moves made by the smallest disk.
  2. Which idea applies. The smallest disk moves on every other move, so it moves 2n-1 times.
  3. Work it out. For n = 3, 23-1 = 22 = 4. The moves are 1, 3, 5 and 7 in the list shown on this page, and the moves listed at those positions are the ones that move disk 1.
  4. Check. Seven moves in total, with the smallest disk moving at 1, 3, 5 and 7, is four times.

Depth of the call stack

The program below counts the frames on the call stack while computing fact(5). What are the printed values of the factorial and the maximum depth?

depth = 0
max_depth = 0

def fact(n):
    global depth, max_depth
    depth += 1
    max_depth = max(max_depth, depth)
    if n == 0:
        depth -= 1
        return 1
    r = n * fact(n - 1)
    depth -= 1
    return r

print(fact(5), max_depth)

How to think about it

  1. What is asked. Two printed numbers: fact(5) and the maximum depth.
  2. Which idea applies. Each call adds a frame. The calls for fact(5) are fact(5), fact(4), fact(3), fact(2), fact(1) and fact(0), which is 6 calls in a chain.
  3. Work it out. 5 x 4 x 3 x 2 x 1 = 120. The deepest point is when fact(0) is active, and all six frames are on the stack, so the maximum depth is 6.
  4. Check. The depth is n + 1 = 6 for n = 5, which matches the formula on this page.

Answer: 120 and 6.

depth = 0
max_depth = 0

def fact(n):
    global depth, max_depth
    depth += 1
    max_depth = max(max_depth, depth)

        depth -= 1
        return 1

    depth -= 1
    return r

Exam-level 3: Recursion depth (NAT, 2 marks)

def g(n): return 1 if n <= 1 else g(n // 2) + 1. What is g(1000)?

How to think about it

  1. What is asked. The number of halvings plus one.
  2. Which idea applies. g(n) = ⌊log2 n⌋ + 1 for n ≥ 1.
  3. Work it out. 1000 → 500 → 250 → 125 → 62 → 31 → 15 → 7 → 3 → 1 is 9 halvings. g = 10.
