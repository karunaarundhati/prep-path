Hierarchical clustering (single/multi linkage)

Hierarchical clustering builds a family tree of groups instead of picking one split in advance. You start with every point alone and join the closest groups step by step, or split everything apart from the top. The result is a dendrogram, and the way you measure distance between groups (the linkage) changes the answer. GATE Data Science and AI often asks for a dendrogram built from a distance matrix.

The idea in plain words

Think about a family tree. At the bottom are individual people. Each step up joins two people, or two smaller families, into a bigger one. At the top is one big family that contains everyone. A family tree shows the whole history of joins, so you can stop at any level and see the groups.

Hierarchical clustering makes a tree like this for data points. It does not need you to decide the number of clusters in advance, as K-means does. Instead it produces every possible grouping, from one cluster per point up to one cluster for everything. You then decide where to stop.

There are two directions:

  • Agglomerative (bottom-up): start with each point as its own cluster, then repeatedly join the two closest clusters. This is the common version.
  • Divisive (top-down): start with all points in one cluster, then repeatedly split one cluster into two. It is less common, and we describe it briefly.

The key question is: what does "closest" mean for two clusters, each holding several points? That choice is called the linkage, and it decides the shape of the tree. GATE loves questions that ask you to build the merges for a given linkage, so this topic works through exact examples.

Key terms

Cluster
A group of points. Precise: at the start each point is a cluster of size 1.
Agglomerative clustering
Bottom-up merging. Precise: repeatedly merge the two closest clusters until one remains.
Divisive clustering
Top-down splitting. Precise: repeatedly split a cluster into two until every point stands alone.
Linkage
The rule for the distance between two clusters. Precise: a function of the distances between their member points.
Single linkage
Cluster distance is the closest pair of points. Precise: the minimum distance between a point in one cluster and a point in the other.
Complete linkage
Cluster distance is the farthest pair of points. Precise: the maximum distance between the two clusters' points.
Average linkage
Cluster distance is the average over all pairs. Precise: the mean of every pairwise distance between the two clusters.
Ward's method
Merge the pair that increases total spread the least. Precise: merges the two clusters whose union gives the smallest increase in within-cluster sum of squares.
Distance matrix
A table of all pairwise distances. Precise: entry (i, j) is the distance between point i and point j.
Dendrogram
A tree diagram of the merges. Precise: each join is drawn as a horizontal bar at the height of its merge distance.
Merge height
The distance at which two clusters join. Precise: the linkage value used for that merge.
Cutting a dendrogram
Choosing a height and reading off the clusters below it. Precise: every merge at or below the cut is kept, and the result is the set of clusters at that level.
Chaining
Clusters that stretch out in a long line. Precise: single linkage tends to join clusters through a chain of close neighbours, even when the ends are far apart.

Concept 1: Agglomerative and divisive hierarchical clustering

The agglomerative steps

  1. Start with n clusters, one per point.
  2. Compute the distance between every pair of clusters, using the chosen linkage.
  3. Find the closest pair, and merge them into one cluster. Record the merge height.
  4. Repeat steps 2 and 3 until only one cluster remains.

With n points there are always exactly n − 1 merges. Each merge reduces the number of clusters by one, from n down to 1. So five points give four merges. This is a quick check you can use in an exam.

The divisive steps

Divisive clustering goes the other way. It starts with one cluster containing everything, splits it into two groups, then splits the groups further. A common idea is to split off the most different point at each step. Divisive methods are harder to compute exactly, so agglomerative methods are the standard choice in most courses and exams.

Key ideaAgglomerative clustering with n points always makes exactly n − 1 merges, ending in one cluster. The linkage decides which pair merges at each step.

TrapStudents sometimes say divisive clustering starts with each point alone. That is the agglomerative start. Divisive starts with everything in one cluster.

How many merges are needed to join 8 points into one cluster?

7. Each merge reduces the number of clusters by one, from 8 to 1, so 8 − 1 = 7 merges.

What is the first merge in an agglomerative algorithm?

The two single points with the smallest distance between them. Every cluster is still a single point at that stage, so every linkage gives the same first merge.

Concept 2: Distance between clusters, single, complete and average linkage

Why we need a rule

Once a cluster contains two or more points, we need one number that stands for the distance between two clusters. Different rules give different trees. Three standard rules are below. Let A and B be two clusters.

LinkageCluster distanceIn words
Singlemin of d(a, b) over a in A and b in BThe closest pair, one from each cluster
Completemax of d(a, b) over a in A and b in BThe farthest pair, one from each cluster
Averagemean of d(a, b) over all pairsThe average of all pairwise distances

Here d(a, b) is the ordinary distance between points a and b. In one dimension it is simply the gap |a − b|, where the vertical bars mean "size of the difference, ignoring the sign".

Comparing the three rules on a small example

Take three points on a line: 1, 2 and 4. Suppose we have already merged 1 and 2 into cluster {1, 2}. Now we want the distance from {1, 2} to the single point {4}. The gaps are: from 1 to 4 is 3, and from 2 to 4 is 2.

  • Single linkage: the minimum is 2.
  • Complete linkage: the maximum is 3.
  • Average linkage: the mean of 3 and 2 is 5/2 = 2.5.

The same two clusters have three different distances, depending on the rule. This is why the rule must always be stated in a question.

TipRemember the names as the job they do: single takes the nearest pair (minimum), complete takes the farthest pair (maximum), and average takes the middle road (mean).

GATE loves thisSingle linkage tends to create long chains of points, because one close neighbour is enough to join clusters. Complete linkage tends to make compact, round groups. Average linkage sits in between.

Which linkage would join two clusters whose closest points are very close, even if their farthest points are very far apart?

Single linkage. It looks only at the closest pair, so one near neighbour is enough.

Why is complete linkage sensitive to outliers?

Because it uses the farthest pair. One far-away point can make the distance to a cluster large, which delays or changes the merge, even when most points are close.

Concept 3: Ward's method

The idea

Ward's method does not measure a distance between two clusters directly. Instead it asks: if we join clusters A and B, how much does the total within-cluster spread grow? The spread is the within-cluster sum of squares (WCSS), which we met in the K-means topic. Ward's method joins the pair that makes this growth smallest. It tends to produce compact clusters of similar size.

The formula

Cost(A, B) = (nA × nB) / (nA + nB) × (meanA − meanB)²
  • nA and nB are the numbers of points in each cluster.
  • meanA and meanB are the averages of the points in each cluster.
  • The fraction gets bigger when both clusters are large, and the squared gap between means gets bigger when the clusters are far apart.

A worked example

Use the five points 1, 2, 4, 9 and 15. Ward's method starts with single points. Compute a few costs, with exact fractions. For two single points, the cost is (1 × 1)/(1 + 1) × (gap)² = gap²/2.

  1. Join {1} and {2}: gap 1, cost 1/2.
  2. Join {9} and {15}: gap 6, cost 36/2 = 18.
  3. After joining {1} and {2}, the cluster {1, 2} has mean 3/2. Join {1, 2} with {4}: cost (2 × 1)/(2 + 1) × (4 − 3/2)² = (2/3) × (5/2)² = 25/6.

Python can confirm each cost with exact fractions:

from fractions import Fraction as F

def ward_cost(A, B):
    nA, nB = len(A), len(B)
    cA = F(sum(A), nA)
    cB = F(sum(B), nB)
    return F(nA * nB, nA + nB) * (cA - cB) ** 2

print("cost of {1} with {2}:", ward_cost([1], [2]))
print("cost of {1, 2} with {4}:", ward_cost([1, 2], [4]))
print("cost of {9} with {15}:", ward_cost([9], [15]))
print("cost of {1, 2, 4} with {9}:", ward_cost([1, 2, 4], [9]))
cost of {1} with {2}: 1/2
cost of {1, 2} with {4}: 25/6
cost of {9} with {15}: 18
cost of {1, 2, 4} with {9}: 100/3

At each step Ward's method takes the cheapest join. The costs 1/2 and 25/6 are small, so {1, 2} and then {4} join first. The later choice is between {9} with {15}, costing 18, and {1, 2, 4} with {9}, costing 100/3, which is about 33. The cheaper one, 18, wins. So {9, 15} forms next.

TrapWard's cost is not a plain distance. Do not compare it with the single, complete or average distances on the same scale. Only compare Ward costs with other Ward costs.

What does Ward's method try to keep small at each merge?

The increase in the within-cluster sum of squares, which is the spread of the points around their cluster means.

Using the formula, what is the Ward cost of joining two single points at distance 4 apart?

(1 × 1)/(1 + 1) × 4² = 16/2 = 8.

Concept 4: Building a dendrogram and cutting it

How to draw the tree

Every merge is drawn as a bar joining two branches. The bar sits at the height equal to the merge distance (for Ward's method, the merge cost or a function of it, depending on the convention). Read the diagram from the bottom up: the leaves are the original points, and the top bar is the final join.

Cutting the tree

To get a flat set of clusters, draw a horizontal line across the dendrogram at a chosen height. Each branch that the line crosses is one cluster. Equivalently, keep every merge whose height is at or below the cut. A low cut gives many small clusters, and a high cut gives few large ones.

For the five points 1, 2, 4, 9 and 15, the merge heights are listed in Concept 5. Cutting at height 4 keeps only the merges at or below 4, which is a simple count.

Key ideaThe dendrogram stores every grouping at once. Cutting at a height picks one level of the tree.

TipIn a GATE question, a cut at height h keeps every merge with height at most h. Count those merges to find the number of clusters left, which is n minus the number of merges kept.

Five points, and the first three merges all have height at most 4. How many clusters remain at a cut of 4?

5 − 3 = 2 clusters. Each merge reduces the count by one.

Why do the dendrogram heights never decrease as you go up the tree?

For the linkages in this topic, a merge joins clusters that are at least as far apart as the previous merges, so the heights rise (or stay level) as you move up. This is why the tree can be cut cleanly at any height.

Concept 5: Distance matrix updates after each merge

Starting from the distance matrix

Hierarchical clustering in an exam is usually done from a distance matrix, a table of all pairwise distances. For the points 1, 2, 4, 9 and 15, the matrix is below. The code prints it, and then runs all three linkages from start to finish.

How the matrix changes after a merge

After merging two clusters, we delete their two rows and two columns, and add one row and column for the new cluster. Each new entry is the linkage distance from the new cluster to an old cluster. For example, after merging 1 and 2 under complete linkage, the new cluster {1, 2} has distance to point 4 equal to the larger of d(1, 4) = 3 and d(2, 4) = 2, which is 3. Its distance to point 9 is the larger of 8 and 7, which is 8.

The code below runs the full agglomerative algorithm for each linkage. At each step it looks for the smallest entry in the current matrix, merges that pair, and prints the merge.

from fractions import Fraction as F

pts = [1, 2, 4, 9, 15]

print("distance matrix")
for a in pts:
    print(" ".join(f"{abs(a - b):>3}" for b in pts))

def link_dist(A, B, kind):
    ds = [abs(a - b) for a in A for b in B]
    if kind == "single":
        return min(ds)
    if kind == "complete":
        return max(ds)
    return F(sum(ds), len(ds))   # average linkage

for kind in ["single", "complete", "average"]:
    clusters = [[p] for p in pts]
    print(kind + " linkage:")
    while len(clusters) > 1:
        best = None
        for i in range(len(clusters)):
            for j in range(i + 1, len(clusters)):
                h = link_dist(clusters[i], clusters[j], kind)
                if best is None or h < best[0]:
                    best = (h, i, j)
        h, i, j = best
        merged = clusters[i] + clusters[j]
        print("  merge", clusters[i], "and", clusters[j], "at height", h)
        clusters = [c for k, c in enumerate(clusters) if k not in (i, j)] + [merged]

for kind in ["single", "complete"]:
    clusters = [[p] for p in pts]
    while len(clusters) > 1:
        best = None
        for i in range(len(clusters)):
            for j in range(i + 1, len(clusters)):
                h = link_dist(clusters[i], clusters[j], kind)
                if best is None or h < best[0]:
                    best = (h, i, j)
        h, i, j = best
        if h > 4:
            break
        merged = clusters[i] + clusters[j]
        clusters = [c for k, c in enumerate(clusters) if k not in (i, j)] + [merged]
    print("cut at height 4 with", kind, "linkage:", sorted(clusters))

Read the single linkage output. The merges are 1, 2, 5 and 6, with four merges for five points. The cut at height 4 keeps the first two merges, so the clusters are {1, 2, 4}, {9} and {15}. The complete linkage run has merge heights 1, 3, 6 and 14. The cut at 4 gives the same three clusters, because only the first two merges fall at or below 4.

Compare the final merges. Single linkage joins everything at height 6, because the chain {1, 2, 4} to 9 is only 5 wide, and 15 is 6 from 9. Complete linkage needs height 14, because the farthest pair between {1, 2, 4} and {9, 15} is 14 apart (from 1 to 15).

Key ideaEach row of the matrix update uses the linkage rule. Single takes the minimum, complete takes the maximum, and average takes the mean of the old entries weighted by cluster size.

TrapWhen two merges have the same smallest distance, the answer depends on the tie-break rule. Good exam questions avoid ties, but if you see one, state which pair you chose.

After merging 1 and 2 with single linkage, what is the distance from {1, 2} to point 4?

The smaller of d(1, 4) = 3 and d(2, 4) = 2, which is 2.

Why do single and complete linkage give different final merge heights for the same data?

Single takes the closest pair across the two clusters, while complete takes the farthest. The farthest pair is always at least as far as the closest, so complete linkage merges at a height that is never smaller.

Which linkage uses the farthest pair

Which linkage defines the distance between two clusters as the largest distance between a point in one and a point in the other? (MCQ, select one)

(A) Single
(B) Complete
(C) Average
(D) Ward

How to think about it

  1. What is asked. The linkage that uses the largest pairwise distance.
  2. Which idea applies. Single takes the minimum, complete takes the maximum, average takes the mean.
  3. Work it out. Largest means maximum, which is the complete linkage rule. Ward uses a cost formula, not a plain maximum.
  4. Check. The table in Concept 2 shows complete as the maximum.

Answer: (B).

Single linkage between a pair and a point

Points are 1, 2 and 4. Cluster {1, 2} is formed first. Using single linkage, what is the distance from {1, 2} to the point 4? (NAT)

How to think about it

  1. What is asked. The single-linkage distance from {1, 2} to {4}.
  2. Which idea applies. Single linkage takes the minimum over pairs.
  3. Work it out. d(1, 4) = 3 and d(2, 4) = 2. The minimum is 2.
  4. Check. The matrix row for point 2 shows 2 in the column for point 4, which is the minimum.

Facts about dendrograms and linkages

Select all statements that are correct. (MSQ)

(A) The height of a merge bar is the distance at which two clusters join.
(B) A cut at a lower height gives more clusters than a cut at a higher height.
(C) Single linkage can produce long chains of points.
(D) Ward's method merges the pair that maximises the within-cluster sum of squares.

How to think about it

  1. What is asked. Which statements about dendrograms and linkages are correct.
  2. Which idea applies. Merge heights, cutting, chaining, and Ward's objective.
  3. Work it out. (A) is true by definition. (B) is true: fewer merges are kept at a lower cut, so more clusters remain. (C) is true: chaining is the known weakness of single linkage. (D) is false: Ward's method merges the pair that minimises the increase in spread.
  4. Check. Statement (D) reverses "minimise" into "maximise", which is the usual trap.

Answer: (A), (B) and (C). Statement (D) is false.

Average linkage between two clusters

Points are 1, 2 and 4. Clusters {1, 2} and {4} are compared using average linkage. What is the average linkage distance between them? (NAT, give a decimal)

How to think about it

  1. What is asked. The mean of all pairwise distances between the two clusters.
  2. Which idea applies. Average linkage takes the mean over all pairs, one point from each cluster.
  3. Work it out. Pairs: (1, 4) gives 3, and (2, 4) gives 2. Mean: (3 + 2)/2 = 2.5.
  4. Check. The Python run in Concept 5 prints the average merge height 5/2 for these clusters, which is 2.5.

Answer: 2.5

Final merge under complete linkage

Points are 1, 2, 4, 9 and 15. Using complete linkage and the agglomerative algorithm, what is the height of the final merge, when all points become one cluster? (NAT)

How to think about it

  1. What is asked. The last merge height under complete linkage.
  2. Which idea applies. Run the merges, then read the last height.
  3. Work it out. Merges: {1} with {2} at 1, then {4} with {1, 2} at 3, then {9} with {15} at 6. The last merge joins {1, 2, 4} with {9, 15}. Its complete distance is the largest pair, which is 15 − 1 = 14.
  4. Check. The Python run in Concept 5 prints height 14 for this final merge.

Answer: 14

Clusters left after a cut

Points are 1, 2, 4, 9 and 15. A single-linkage dendrogram is cut at height 4. How many clusters remain? (NAT)

How to think about it

  1. What is asked. The number of clusters at the cut.
  2. Which idea applies. Keep merges at or below the cut, then count clusters as n minus merges kept.
  3. Work it out. Single-linkage merge heights are 1, 2, 5 and 6. Those at or below 4 are 1 and 2, so two merges are kept. Clusters: 5 − 2 = 3, namely {1, 2, 4}, {9} and {15}.
  4. Check. Count the clusters in the Python output: [4, 1, 2], [9] and [15], which is three.

Ward cost of a merge

Points are 1, 2, 4, 9 and 15, and Ward's method is used. What is the Ward cost of joining the cluster {1, 2} with the cluster {4}? Give the exact fraction. (NAT)

How to think about it

  1. What is asked. The exact Ward cost for one specific merge.
  2. Which idea applies. The Ward cost formula with nA, nB, and the cluster means.
  3. Work it out. nA = 2 and nB = 1. Mean of {1, 2} is 3/2, and the mean of {4} is 4. The gap is 4 − 3/2 = 5/2. Cost = (2 × 1)/(2 + 1) × (5/2)² = (2/3) × (25/4) = 50/12 = 25/6.
  4. Check. The Python run in Concept 3 printed 25/6 for this same merge.

Answer: 25/6

Exam-level 1: Single linkage merge height (NAT, 2 marks)

Points on a line: 0, 1, 4, 9, 11. Using single linkage, at what distance does the last merge happen?

How to think about it

  1. What is asked. The height of the root of the dendrogram.
  2. Which idea applies. Single linkage merges by the closest pair between clusters.
  3. Work it out. Merges: {0, 1} at 1, {9, 11} at 2, {0, 1, 4} at 3, then the two clusters at 9 − 4 = 5.
  4. Check. The code runs agglomerative clustering.
pts = [0, 1, 4, 9, 11]
C = [[p] for p in pts]
while len(C) > 1:
    d, i, j = min((min(abs(a - b) for a in C[i] for b in C[j]), i, j) for i in range(len(C)) for j in range(i + 1, len(C)))
    print("merge", C[i], C[j], "at", d)
    C[i] = C[i] + C[j]; del C[j]
