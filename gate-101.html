Naive Bayes classifier

The Naive Bayes classifier decides a class by combining how common each class is with how likely each clue is under that class. You will learn Bayes theorem from a frequency table, the independence assumption that makes the method simple, Laplace smoothing for unseen clues, and the Gaussian and multinomial versions for numbers and word counts.

The idea in plain words

Imagine a detective who sees a wet umbrella by the door. The detective asks two questions. How common are rainy days in general? And how often do people carry wet umbrellas on rainy days, compared with sunny days? Combining the common-ness of each explanation with how well each explanation fits the clue gives a verdict. The detective does not need certainty. A verdict is simply the explanation with the best combined score.

Naive Bayes works the same way. Given the features of a new item, it asks for each class: how common is this class, and how well does this item's feature pattern fit this class? It then picks the class with the highest combined score. The word naive refers to a simplifying assumption. We pretend that the clues are independent of each other once the class is known. In real life this is rarely exactly true, yet the method works surprisingly well.

For GATE, Naive Bayes is a standard classifier in the Machine Learning part of the Data Science and AI paper (DA). Questions ask you to apply Bayes theorem, compute a posterior score for each class, apply Laplace smoothing, and recognise the Gaussian and multinomial versions. The arithmetic is simple, but each step must be done carefully.

Key terms

Read these first. Each term returns later on the page.

Class C
One of the possible answers, such as spam or ham (not spam).
Feature vector x
The list of measured clues for one item, such as the words in an email.
Prior P(C)
How common class C is before looking at the clues. Estimated as the share of training items in class C.
Likelihood P(x | C)
How probable the clues are if the class is C.
Evidence P(x)
How probable the clues are overall, across all classes.
Posterior P(C | x)
How probable class C is after seeing the clues. This is what we want.
Bayes theorem
The rule P(C | x) = P(x | C) P(C) / P(x), which turns the likelihood into the posterior.
Conditional independence
Two clues are independent given the class if knowing one tells you nothing more about the other once the class is fixed.
Naive assumption
The assumption that all features are conditionally independent given the class.
Zero-frequency problem
A clue never seen with a class in training gives a likelihood of zero, which wipes out the whole product.
Laplace smoothing
Adding a small pseudo-count, usually 1, to every count so that no probability is exactly zero.
Gaussian distribution
The bell-shaped distribution with a mean μ and a variance σ², used for continuous features.
Multinomial model
A model for counts, such as how many times each word appears in a document.

Bayes theorem with a small example

Why Bayes theorem is needed

We usually know how the clues look for each class, because we have seen examples of each class. What we need is the reverse: given the clues, what is the class? Bayes theorem flips the question around.

P(C | x) = P(x | C) × P(C) / P(x)

Read it symbol by symbol. P(C | x) is the posterior, the probability of class C given the clues. P(x | C) is the likelihood, the probability of the clues given class C. P(C) is the prior, how common class C is. P(x) is the evidence, the probability of the clues overall. The vertical bar | means "given".

A frequency table makes it concrete

Suppose a clinic tests 1000 people for a disease. Imagine the numbers as a table, which is easier to follow than fractions alone.

GroupNumber of peopleTest positiveTest negative
Has the disease1091
Does not have it99050940
Total100059941

Question: a person tests positive. What is the chance they have the disease? Count the positives. There are 59 positive tests in total, and 9 of them are real cases. So the answer is 9/59, about 0.153.

Now see how Bayes theorem gives the same answer. The prior P(disease) = 10/1000 = 0.01. The likelihood P(positive | disease) = 9/10 = 0.9. The evidence P(positive) = 59/1000 = 0.059. So the posterior is (0.9 × 0.01)/0.059 = 0.009/0.059, which is about 0.153. The numbers agree.

Key ideaA positive result raises the probability from 1 percent to about 15 percent. It does not make the disease certain, because the disease is rare and many healthy people also test positive.

Worked example with numbers

Let P(A) = 0.3, P(B | A) = 0.5 and P(B) = 0.25. Find P(A | B).

  1. Write the formula. P(A | B) = P(B | A) × P(A) / P(B).
  2. Multiply the top. 0.5 × 0.3 = 0.15.
  3. Divide by the evidence. 0.15 / 0.25 = 0.6.
  4. Check. A probability must be between 0 and 1. 0.6 is valid.
Question: if P(B | A) were 1, what would P(A | B) be?

P(A | B) = 1 × 0.3/0.25 = 1.2, which is impossible. This means the inputs in that case would be inconsistent. Real probabilities always produce a value between 0 and 1.

Question: why can we skip P(x) when we only want to choose between classes?

P(x) is the same number for every class, because it is the overall probability of the clues. Dividing every score by the same number does not change which score is largest.

The naive independence assumption

The problem with many clues

Suppose an email has many words. To compute P(x | C) exactly, we would need the probability of the whole combination of words in each class. With even 20 words, the number of combinations is huge, and most combinations never appear in the training data. We cannot estimate them reliably.

The shortcut

The naive assumption says: once we know the class, each word is independent of the others. Then the probability of the whole combination is just the product of the individual probabilities.

P(x | C) = P(x1 | C) × P(x2 | C) × ... × P(xn | C)

Read it. Each factor is the probability of one clue given the class. The product gathers them all. Now we only need to estimate one probability per word per class, which is easy.

TrapThe independence is conditional on the class. Two words may be strongly related in general, for example "free" and "offer", but still be treated as independent once we know the email is spam. The model is a simplification, not a claim about the real world.

Why naive Bayes still works

Even if the probabilities are not accurate, the ranking of classes can still be right. The model only needs to put the correct class ahead of the others. This is why Naive Bayes is fast, needs little data, and is often a strong baseline for text.

Question: what does the naive assumption let us avoid?

It avoids estimating the joint probability of every combination of features in each class. Instead we estimate only one probability per feature per class and multiply them.

Question: is conditional independence the same as ordinary independence?

No. Conditional independence is measured given the class. Features can be dependent overall and still be conditionally independent once the class is known.

Scoring classes and picking the largest

The score for each class

Put Bayes theorem and the naive assumption together. The posterior for class C is proportional to the prior times the product of the likelihoods. The sign ∝ means "is proportional to", that is, equal up to a constant factor that is the same for all classes.

P(C | x) ∝ P(C) × Πi P(xi | C)

The symbol Π (capital pi) means "multiply over all i", just as Σ means "add over all i". The right-hand side is the score for class C. We compute it for each class and pick the class with the largest score. We do not need P(x), because it is the same for every class.

Worked example: spam or ham

Suppose 40 percent of past emails are spam, so the prior for spam is 0.4 and for ham is 0.6. Let the word "free" appear in 50 percent of spam and 10 percent of ham. Let the word "meeting" appear in 10 percent of spam and 40 percent of ham. A new email contains both "free" and "meeting". Which class is more likely?

  1. Score for spam. Prior 0.4, times P(free | spam) = 0.5, times P(meeting | spam) = 0.1. That is 0.4 × 0.5 × 0.1 = 0.020.
  2. Score for ham. Prior 0.6, times P(free | ham) = 0.1, times P(meeting | ham) = 0.4. That is 0.6 × 0.1 × 0.4 = 0.024.
  3. Pick the larger. 0.024 is larger than 0.020, so the model chooses ham.
  4. Get the true posterior if needed. Add the scores: 0.020 + 0.024 = 0.044. The posterior for spam is 0.020/0.044, about 0.455. For ham it is 0.545.

Key ideaThe word "free" favours spam, but "meeting" is more typical of ham and has a larger effect here. Naive Bayes multiplies all the evidence, so each word pushes the score up or down.

Use logarithms in practice

When there are hundreds of words, multiplying small probabilities gives a number so tiny that a computer rounds it to zero. The fix is to take logarithms. A product becomes a sum: log of the score = log P(C) + Σ log P(xi | C). Since the logarithm is increasing, the largest log-score is the same class as the largest score.

Question: in the example, why did we not divide by P(x) to choose the class?

Dividing both scores by the same total does not change which one is larger. The division is only needed when we want the actual posterior probability.

Question: what changes if the spam prior becomes 0.9 and the ham prior becomes 0.1?

The same two words now give spam the larger score: 0.9 × 0.5 × 0.1 = 0.045 for spam, against 0.1 × 0.1 × 0.4 = 0.004 for ham. Priors matter, and a strong enough prior can outweigh the clues.

Laplace smoothing for zero counts

The zero-frequency problem

Look at the spam example again. Suppose the word "lottery" never appears in any ham email in training. Then P(lottery | ham) = 0. The ham score is 0.6 × 0.1 × 0.4 × 0 = 0. One zero kills the whole product, even if all the other words strongly favour ham. This is clearly unfair, because the training data is only a sample. The word "lottery" might appear in ham tomorrow.

Laplace smoothing

The fix is to add a small pseudo-count to every count before dividing. The usual choice is 1, which is called Laplace smoothing or add-one smoothing.

P(word | C) = (count of word in C + 1) / (total count in C + V)

Read it. The count is how often the word appears in class C in training. The total is the number of all word occurrences in class C. V is the vocabulary size, the number of distinct words in the whole training data. Adding 1 to the top and V to the bottom keeps the probabilities adding to 1 over all words.

Worked example

In ham emails there are 20 word occurrences in total. The vocabulary has 4 distinct words, so V = 4. The word "lottery" appears 0 times in ham. With smoothing:

  1. Top. 0 + 1 = 1.
  2. Bottom. 20 + 4 = 24.
  3. Result. P(lottery | ham) = 1/24, about 0.042. It is small, but not zero.

TrapSmoothing must be applied to every class and every word using the same vocabulary size. Forgetting V in the denominator breaks the probabilities.

Question: a word appears 3 times in class C, which has 30 total words, and V = 10. What is its smoothed probability?

(3 + 1)/(30 + 10) = 4/40 = 0.1.

Question: does Laplace smoothing change the answer for a word that appears often in training?

Only slightly. The added 1 matters a lot for rare or unseen words and very little for common words, because the counts are large compared with the pseudo-count.

Gaussian and multinomial versions

Gaussian Naive Bayes for numbers

Word counts are not the only kind of clue. Suppose a feature is a measured number, such as the height of a person. We cannot count how often the exact height appears, because most heights appear only once. Instead we assume that, within each class, the feature follows a bell-shaped Gaussian distribution with mean μ and variance σ². We estimate μ and σ² for each class from the training data.

P(x | C) = (1 / √(2πσ²)) × e-(x minus μ)² / (2σ²)

Read it. The term (x minus μ)² measures how far the value is from the class centre. The exponential shrinks the likelihood as that distance grows. The term 1/√(2πσ²) is a normalising constant. Important: this is a density, not a probability, so its value can be larger than 1.

Worked example. A class has mean μ = 4 and variance σ² = 4, so σ = 2. Find the density at x = 4. The distance is 0, so the exponential is 1. The constant is 1/√(2π × 4) = 1/√(8π) = 1/5.013, about 0.1995. So the density is about 0.199.

Multinomial Naive Bayes for counts

When the features are counts, such as how many times each word appears in a document, we use the multinomial model. The likelihood of a word given the class is the smoothed share of that word among all words of that class.

P(wordi | C) = (counti,C + 1) / (total words in C + V)

This is the same smoothing as before. A document with several words multiplies these probabilities, once for each occurrence. Repeated words raise the power of their factor.

VersionFeature typeLikelihood comes from
GaussianContinuous numbersBell curve with class mean and variance
MultinomialCounts, such as word countsSmoothed share of each word in the class
BernoulliYes or no featuresProbability that each feature is present

GATE loves thisExpect a question that asks which version to use for a given feature type. Continuous features call for Gaussian NB. Word counts call for multinomial NB.

Question: can a Gaussian density be greater than 1?

Yes. A density is not a probability. When σ is small, the peak of the bell curve is tall, so the density can exceed 1.

Question: why does the multinomial model use the total words in the class in its denominator?

Because the probabilities of all words in one class must add to 1. The denominator is the total number of word slots for that class, adjusted by V for smoothing.

A single Bayes update (NAT)

P(A) = 0.3, P(B | A) = 0.5 and P(B) = 0.25. Find P(A | B). (NAT)

How to think about it

  1. What is asked. The posterior probability of A after seeing B.
  2. Which idea applies. Bayes theorem: P(A | B) = P(B | A)P(A)/P(B).

Facts about Naive Bayes (MSQ)

Which statements are true? Select all that apply.

(A) Naive Bayes assumes the features are independent given the class.

(B) When comparing classes for one item, the evidence P(x) can be ignored.

(C) Laplace smoothing can make a probability equal to zero.

(D) Gaussian Naive Bayes uses word counts as its features.

How to think about it

  1. What is asked. Which facts about Naive Bayes are correct.
  2. Which idea applies. The naive assumption, the role of the evidence, the purpose of smoothing, and which feature type each version uses.
  3. Work it out. (A) is true. (B) is true, because P(x) is the same for every class. (C) is false, smoothing exists to remove zeros. (D) is false, Gaussian NB is for continuous features, while word counts suit multinomial NB.
  4. Check. The two false statements mix up the purpose of smoothing and the feature type of Gaussian NB.

Answer: (A) and (B)

Spam or ham for an email with two words (NAT)

Priors are P(spam) = 0.3 and P(ham) = 0.7. The word "offer" has P(offer | spam) = 0.6 and P(offer | ham) = 0.2. The word "report" has P(report | spam) = 0.2 and P(report | ham) = 0.5. A new email contains both words. Using naive Bayes, find the posterior probability that the email is spam, to three decimal places. (NAT)

How to think about it

  1. What is asked. The posterior of spam, rounded.
  2. Which idea applies. Compute the score for each class, then divide by the sum of the scores.
  3. Work it out. Spam score = 0.3 × 0.6 × 0.2 = 0.036. Ham score = 0.7 × 0.2 × 0.5 = 0.070. Total = 0.106. Posterior spam = 0.036/0.106, about 0.340.
  4. Check. Ham has the larger score, so a posterior below 0.5 for spam is expected.

Answer: 0.340

In the ham class there are 20 word occurrences in total. The vocabulary has V = 4 distinct words. The word "lottery" appears 0 times in ham. With add-one Laplace smoothing, what is P(lottery | ham)? Select the single correct option.

(A) 0 (B) 1/24 (C) 1/20 (D) 1/4

  1. What is asked. The smoothed probability of an unseen word.
  2. Which idea applies. (count + 1)/(total + V).
  3. Work it out. (0 + 1)/(20 + 4) = 1/24.
  4. Check. Option (C) forgets the smoothing, and (A) is the unsmoothed zero that smoothing is meant to remove.

Gaussian density at the mean (NAT)

Within one class, a feature is modelled as Gaussian with mean 4 and variance 9. Find the Gaussian density at x = 4, to three decimal places. (NAT)

How to think about it

  1. What is asked. The density value at the mean.
  2. Which idea applies. P(x | C) = (1/√(2πσ²)) e-(x minus μ)²/(2σ²).
  3. Work it out. The variance is 9, so σ = 3. At x = μ the exponential is 1. The constant is 1/√(2π × 9) = 1/(3√(2π)) = 1/7.520, about 0.133.

Multinomial scores with smoothing (NAT)

Vocabulary has V = 3 words, a, b and c. Class Sports has 10 words in total, with counts a = 6, b = 3, c = 1. Class Politics has 8 words in total, with counts a = 1, b = 2, c = 5. The two priors are equal, 0.5 each. A new document contains the word a once and the word c once. Using add-one smoothing, find the posterior probability of Sports, to three decimal places. (NAT)

How to think about it

  1. What is asked. The posterior of Sports for this document.
  2. Which idea applies. Smoothed word probabilities for each class, product with the prior, then normalise over the two classes.
  3. Work it out. Sports: P(a) = (6 + 1)/(10 + 3) = 7/13 and P(c) = (1 + 1)/13 = 2/13. The product is 14/169, about 0.08284. Politics: P(a) = (1 + 1)/(8 + 3) = 2/11 and P(c) = (5 + 1)/11 = 6/11. The product is 12/121, about 0.09917. The priors cancel because they are equal. Posterior Sports = 0.08284/(0.08284 + 0.09917) = 0.08284/0.18201, about 0.455.
  4. Check. Politics has more weight on c, which the document uses, so Politics should be slightly ahead. The result 0.455 is below 0.5, which agrees.

Answer: 0.455

Which statements survive scrutiny? (MSQ)

Select all true statements about implementing and using Naive Bayes.

(A) Summing logarithms of probabilities avoids numerical underflow.

(B) Without smoothing, a word never seen with a class makes that class's score zero.

(C) Naive Bayes is a discriminative model that learns the boundary directly from the posterior.

(D) A Gaussian likelihood is a density and can exceed 1.

How to think about it

  1. What is asked. Recognise sound practical facts about Naive Bayes.
  2. Which idea applies. Logarithms turn products into sums. A zero factor kills a product. Naive Bayes models P(x | C) and P(C), so it is generative, not discriminative. Gaussian values are densities.
  3. Work it out. (A) is true. (B) is true. (C) is false, Naive Bayes is a generative model because it models how the features look in each class. (D) is true.
  4. Check. The false one contains the word discriminative. Logistic regression is the usual discriminative example.

Answer: (A), (B) and (D)

Exam-level 1: Naive Bayes posterior for two words (NAT, 2 marks)

An email filter uses Naive Bayes with two words. The prior probability that an email is spam is 0.4, so the prior for ham (good mail) is 0.6. The word free appears in 50 percent of spam emails and in 10 percent of ham emails. The word meeting appears in 10 percent of spam emails and in 40 percent of ham emails. Assume the two words are independent given the class. A new email contains both free and meeting. Find P(spam given both words) to three decimal places. (NAT)

How to think about it

  1. What is asked. The posterior probability of spam after seeing both words.
  2. Which idea applies. Multiply the prior by each word likelihood for each class, then divide by the sum of the two scores.
  3. Work it out. Spam score = 0.4 times 0.5 times 0.1 = 0.02. Ham score = 0.6 times 0.1 times 0.4 = 0.024. The posterior is 0.02 divided by (0.02 plus 0.024) = 0.02/0.044, which is about 0.455.
  4. Check. The spam score is smaller than the ham score, yet the answer is near one half. That is sensible, because free favours spam while meeting favours ham, so the evidence roughly cancels.

Answer: 0.455

Exam-level 2: Which Naive Bayes facts hold (MSQ, 2 marks)

A student compares Naive Bayes classifiers. Which of the following statements are correct? Select all that apply.

(A) Naive Bayes assumes that the features are independent of each other given the class.

(B) Gaussian Naive Bayes estimates a mean and a variance for each class and each continuous feature.

(C) Laplace smoothing adds a constant alpha to every count, so no class-conditional probability is exactly zero.

(D) The denominator P(x) must be computed separately for each class, so it cannot be dropped when choosing the largest posterior.

How to think about it

  1. What is asked. Which of four statements about Naive Bayes are true.
  2. Which idea applies. The independence assumption lets the likelihood factor into a product. Smoothing protects against zero counts. The denominator is shared by all classes.
  3. Work it out. (A) is true, which is the "naive" part of the name. (B) is true, because the Gaussian model needs those two numbers per class and feature. (C) is true, because adding alpha to each count keeps every probability above zero. (D) is false, because P(x) is the same number for every class, so it does not change which class has the largest posterior.
  4. Check. The code below shows smoothing on a word that never appears in spam. Its probability is 1/25, not zero, so one missing word cannot erase the whole product.

Answer: (A), (B) and (C). Option (D) is wrong because P(x) is the same for every class and can be dropped when comparing classes.

Exam-level 3: Smoothed word probabilities (NAT, 2 marks)

In a spam model, the spam class has 20 words in total after counting all training spam messages. The vocabulary has 5 distinct words. The word free never appears in spam, and the word win appears 6 times. Use Laplace smoothing with alpha = 1 for each word probability: P(word given spam) = (count plus alpha) divided by (total plus alpha times vocabulary size). For a message containing both free and win, assume the two words are independent given spam. Find P(free and win given spam). (NAT)

How to think about it

  1. What is asked. The joint likelihood of two words given the spam class.
  2. Which idea applies. Smoothed word probabilities, then multiply them because of the independence assumption.
  3. Work it out. The denominator is 20 plus 1 times 5 = 25. P(free given spam) = (0 plus 1)/25 = 1/25. P(win given spam) = (6 plus 1)/25 = 7/25. The product is 1/25 times 7/25 = 7/625, which equals 0.0112.
  4. Check. Without smoothing the free term would be 0 and the product would be 0. The smoothed answer 0.0112 is small but not zero, which is the whole purpose of smoothing.

Answer: 0.0112 (7/625)

Exam-level 4: Gaussian Naive Bayes posterior (NAT, 2 marks)

A Gaussian Naive Bayes classifier predicts a class from one continuous feature, height in cm. Class A has prior 0.3, mean 170 and standard deviation 5. Class B has prior 0.7, mean 180 and standard deviation 6. The Gaussian density is N(x; mu, sd) = exp(minus (x minus mu) squared divided by (2 sd squared)) divided by (sd times the square root of 2 pi). A new person has height 176. Find P(class A given height 176) to three decimal places. (NAT)

How to think about it

  1. What is asked. The posterior probability of class A for one height.
  2. Which idea applies. Multiply each prior by its Gaussian density at x, then divide by the sum over the two classes.
  3. Work it out. For class A, (176 minus 170) squared divided by (2 times 25) = 36/50 = 0.72, so the density is about 0.03884 after dividing by 5 times the square root of 2 pi. For class B, (176 minus 180) squared divided by (2 times 36) = 16/72, about 0.2222, so the density is about 0.05324. Weighted by priors: A gives 0.3 times 0.03883 = 0.01165 and B gives 0.7 times 0.05324 = 0.03727. The posterior is 0.01165 divided by 0.04892, about 0.238.
  4. Check. In units of each class's own spread, 176 sits 1.2 standard deviations above the mean of A and about 0.67 standard deviations below the mean of B, so the likelihood already favours B. A posterior of 0.238 for A, below one half, agrees with that.

Answer: 0.238

import math
from fractions import Fraction as F

# Exam-level 1: Naive Bayes posterior for two words
p_spam, p_ham = 0.4, 0.6
spam_score = p_spam * 0.5 * 0.1
ham_score = p_ham * 0.1 * 0.4
print("E1 spam score =", round(spam_score, 4), " ham score =", round(ham_score, 4), " P(spam | words) =", round(spam_score / (spam_score + ham_score), 3))

# Exam-level 2: Laplace smoothing gives no zero probability
counts = {"free": 0, "win": 6}
total, vocab, alpha = 20, 5, 1
for word, c in counts.items():
    print("E2", word, "smoothed P(word | spam) =", F(c + alpha, total + alpha * vocab))

# Exam-level 3: two smoothed word probabilities multiplied
p_free = F(0 + alpha, total + alpha * vocab)
p_win = F(6 + alpha, total + alpha * vocab)
print("E3 P(free | spam) =", p_free, " P(win | spam) =", p_win, " product =", p_free * p_win, "=", float(p_free * p_win))

# Exam-level 4: Gaussian Naive Bayes posterior
def gauss(x, mu, sd):
    return math.exp(-(x - mu) ** 2 / (2 * sd * sd)) / (sd * math.sqrt(2 * math.pi))
a = 0.3 * gauss(176, 170, 5)
b = 0.7 * gauss(176, 180, 6)
print("E4 density A =", round(gauss(176, 170, 5), 5), " density B =", round(gauss(176, 180, 6), 5))

Summary

Here is every key term in one line each.

Class
One of the possible answers the classifier can give.
Prior
How common a class is before looking at the clues.
Likelihood
How probable the clues are if the class is known.
Evidence
How probable the clues are overall. The same for all classes.
Posterior
How probable a class is after seeing the clues.
Bayes theorem
Posterior equals likelihood times prior divided by evidence.
Conditional independence
Features are independent once the class is known.
Naive assumption
The simplifying claim of conditional independence across all features.
Score
Prior times the product of likelihoods, compared across classes.
Zero-frequency problem
A zero likelihood that wipes out the whole product.
Laplace smoothing
Adding 1 to counts and V to totals so that no probability is zero.
Gaussian Naive Bayes
Naive Bayes for continuous features, using a bell curve per class.
Multinomial Naive Bayes
Naive Bayes for counts such as word frequencies.
Log-score
The sum of logarithms, used to avoid underflow.
Generative model
A model that describes how features look in each class, as Naive Bayes does.

Remember these

  • Bayes theorem turns how the clues look in each class into the probability of each class.
  • For classification, compare prior times the product of likelihoods. The evidence cancels.
  • The naive assumption treats features as independent once the class is known.
  • Always apply smoothing so that one unseen word does not zero out a class.
  • Use Gaussian Naive Bayes for continuous features and multinomial for counts.
  • A Gaussian value is a density and can be larger than 1.
