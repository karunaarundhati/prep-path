Semantic HTML and forms

HTML describes the structure and meaning of a page. A semantic element names what its content is, so that browsers, search engines and screen readers can use the structure without guessing. A div says nothing about its content. A nav says "this is the navigation", and a screen reader can offer the user a list of navigation regions. Choosing the right element is the cheapest accessibility and SEO improvement you can make.

The landmark elements

HTML5 introduced a set of structural elements. The most useful are header (introductory content, often with a logo and navigation), nav (a block of navigation links), main (the central content, one per page), article (self-contained content that could be reused on its own, such as a blog post), section (a thematic group with its own heading), aside (related but separate content, such as a sidebar), and footer (closing information). Use div and span only when no semantic element fits.

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Shop</title>
</head>
<body>
  <header>
    <nav aria-label="Main">
      <a href="/products">Products</a>
      <a href="/cart">Cart</a>
    </nav>
  </header>
  <main>
    <article>
      <h1>Wireless keyboard</h1>
      <p>Quiet keys and a two year battery.</p>
    </article>
  </main>
  <footer>Contact us</footer>
</body>
</html>

Three details in the skeleton matter. The lang attribute tells screen readers which language to use. The viewport meta tag tells phones to use the device width instead of a desktop width of about 980 pixels, which is needed for responsive layouts. The h1 appears once and the headings below it step down one level at a time.

Forms

A form collects input and sends it to a URL. Three rules cover most real forms. First, every input needs a label. A label connected with for (matching the input's id) gives the input its accessible name, and clicking the label focuses the input. Second, use the right input type, because browsers then show the right keyboard on phones and can validate for free: email, number, date, tel, url and password. Third, use the built-in validation attributes such as required, min, max and pattern.

<form action="/subscribe" method="post">
  <fieldset>
    <legend>Newsletter</legend>
    <label for="email">Email address</label>
    <input id="email" name="email" type="email" required autocomplete="email">
    <label>
      <input name="weekly" type="checkbox"> Send weekly digest
    </label>
  </fieldset>
  <button type="submit">Subscribe</button>
</form>

The method attribute decides how the data travels. GET puts the fields in the URL, which suits searches because the result can be bookmarked, but it must never carry passwords. POST sends them in the request body, which suits anything that changes data. The name attribute is the key the server receives, so an input without a name is not submitted at all. The fieldset and legend group related controls and give them a shared caption.

TrapRelying on client-side validation for security. A user, or a script, can send any request directly, so the server must validate every field again. Browser validation is a convenience for the user, not a control on the server.

Key ideaPrefer the native element before building your own. A real button, link, input or dialog already has keyboard handling, focus rules and screen reader roles.

Why does a label need a for attribute that matches the input's id?

The for attribute connects the label to the input, so the input gets the label text as its accessible name, and clicking the label focuses or toggles the input. Without the connection, a screen reader user hears only "edit text" with no name, and a mouse user cannot click the label to focus the field. Wrapping the input inside the label element is an alternative that also connects them.

Accessibility

Accessibility (often shortened to a11y) means that people using screen readers, keyboards, voice control or high-contrast settings can use the page. It is also a legal and quality requirement in many places, and it is a frequent interview topic because it tests whether you know the platform. The standard most teams follow is WCAG (Web Content Accessibility Guidelines), and its AA level is the usual target.

The core checks

  • Text alternatives. Every meaningful image needs an alt attribute that describes its purpose. A decorative image gets alt="" so screen readers skip it. Icons used as buttons need a name, for example aria-label="Close".
  • Colour contrast. Normal text needs a contrast ratio of at least 4.5 to 1 against its background, and large text (about 24 pixels, or 18.66 pixels in bold) needs 3 to 1. Colour alone must never carry meaning, such as a red field with no error text.
  • Keyboard access. Every action must work with the Tab, Enter, Space and arrow keys. Use real buttons and links, which are focusable by default. Never remove the focus outline without providing a visible replacement.
  • Heading structure. Headings describe the outline of the page. Use one h1, do not skip levels, and do not choose headings for their size, because CSS can handle size.
  • Labels and names. Every form control has a visible label, and every interactive element has an accessible name.
  • ARIA. ARIA (Accessible Rich Internet Applications) adds roles and states, such as aria-expanded="true" on a disclosure button. The first rule of ARIA is to use a native element if one exists. A div with role="button" still needs keyboard handling and focus, while a real button gets all of that for free.

A useful habit is to test with the keyboard alone. Press Tab through the page. If you cannot reach something, or you cannot tell where the focus is, a keyboard user is stuck too.

Interviewers askWhat is the first rule of ARIA? Answer: do not use ARIA if a native HTML element already does the job. ARIA changes what assistive technology announces, but it does not add behaviour, so a fake button still needs its own keyboard and focus code.

TrapUsing placeholder as the only label. The placeholder disappears when the user types, and many screen readers do not announce it reliably. Keep a visible label.

What contrast ratio does WCAG AA require for normal body text?

At least 4.5 to 1 for normal text, and 3 to 1 for large text. The ratio compares the relative luminance of the text and background colours. Colour is never the only signal, so an error needs an icon or text as well as red.

CSS: box model, specificity and positioning

CSS (Cascading Style Sheets) decides how elements look. Three ideas explain most surprises: the box model (how much space an element takes), specificity (which rule wins when two rules match), and positioning (where an element ends up relative to the normal flow of the page).

The box model

Every element is a rectangular box made of four layers, from inside to outside: the content (the text or image), the padding (space inside the border), the border, and the margin (space outside the border that separates the box from its neighbours). By default, width sets only the content width, so padding and border add to the total. The property box-sizing: border-box changes this so that width includes padding and border, which makes layouts easier to predict. Most modern projects set it on every element.

*,
*::before,
*::after {
  box-sizing: border-box;
}

.card {
  width: 300px;        /* total width, including padding and border */
  padding: 16px;
  border: 1px solid #ccc;
  margin: 0 auto;      /* centre a block element horizontally */
}

Adjacent vertical margins collapse. When two block boxes stack, the gap between them is the larger of the two margins, not their sum. Margins of a parent and its first or last child can also collapse into the parent. Keep this in mind when a gap looks smaller than the CSS says.

Specificity: which rule wins

When two rules set the same property on the same element, the browser uses specificity, then source order. Specificity is a score with three columns, usually written as (ids, classes, types). An ID selector adds to the first column. A class, attribute selector or pseudo-class such as :hover adds to the second. An element name or pseudo-element such as ::before adds to the third. The universal selector * and combinators such as > add nothing. An inline style attribute beats all of them, and !important beats even inline styles, but both are usually a sign of a design problem.

Selector(ids, classes, types)
p(0, 0, 1)
.card p(0, 1, 1)
#main .card p:first-child(1, 2, 1)
:where(#main) p(0, 0, 1), because :where() adds nothing

Compare the first two rows: .card p has one class and one element, so it beats a plain p wherever both match, even if the plain rule is written later. Scores compare column by column from left to right. One ID beats any number of classes, and one class beats any number of element names. Ten classes still lose to a single ID.

// Specificity as [ids, classes, types]. Sort the selectors from weakest to strongest.
const selectors = [
  ["#nav a", [1, 0, 1]],
  [".card .title", [0, 2, 0]],
  ["div p", [0, 0, 2]],
  ["#main .item:hover", [1, 2, 0]],
  ["ul li:first-child", [0, 1, 2]],
];

function compare(a, b) {
  for (let i = 0; i < 3; i++) {
    if (a[i] !== b[i]) return a[i] - b[i];
  }
  return 0;
}

const sorted = [...selectors].sort((x, y) => compare(x[1], y[1]));
for (const [name, spec] of sorted) {
  console.log(`${name.padEnd(20)} ${spec.join(",")}`);
}

TrapFighting specificity with more specific selectors until the stylesheet is unreadable. Prefer one class per component, and keep selectors short. A rule that needs !important usually means two components are competing for the same element.

Positioning

The position property decides how an element is placed. static (the default) keeps the element in the normal flow. relative keeps the space in the flow but shifts the box by top, left and similar offsets, and it becomes the reference for absolute children. absolute removes the element from the flow and places it relative to its nearest positioned ancestor, or to the page if none exists. fixed places it relative to the viewport, so it stays in place while the page scrolls. sticky behaves like relative until the element reaches a threshold such as top: 0, and then it sticks like fixed inside its parent.

The z-index property sets stacking order. It only has an effect on positioned elements, and on flex and grid items. A higher value draws on top, but only within the same stacking context.

Which has higher specificity, a class selector with two classes or an ID selector with no classes?

The ID selector. Specificity compares the ID column first, and one ID beats any number of classes. So #header, written as (1, 0, 0), beats .nav.menu, written as (0, 2, 0).

Layout: flexbox, grid and responsive design

Before flexbox and grid, page layout relied on floats and hacks. Both modern systems are built to lay out children inside a parent, and both are declared on the parent with display. Use flexbox for one-dimensional layout (a row or a column) and grid for two-dimensional layout (rows and columns together).

Flexbox

A flex container arranges its children along a main axis, which is a row by default (flex-direction: row), and a cross axis perpendicular to it. justify-content distributes the children along the main axis, and align-items aligns them on the cross axis. Each child can grow with flex-grow, shrink with flex-shrink, and start from a size given by flex-basis. The shorthand flex: 1 means grow equally and start from zero, so the children share the space.

.toolbar {
  display: flex;
  justify-content: space-between;   /* push the groups to both ends */
  align-items: center;              /* centre them vertically */
  gap: 12px;
}

.toolbar .search {
  flex: 1;                          /* the search box takes the free space */
}

Flexbox is the right tool for a navigation bar, a row of buttons, or centring one element inside another. It works along one axis at a time, so it is not the best tool for a whole page grid.

Grid

A grid container defines rows and columns, and children are placed into the cells. grid-template-columns defines the tracks, and repeat() saves typing. The function minmax(220px, 1fr) means a column is at least 220 pixels wide and grows to share free space, where fr is a fraction of the remaining space. Combined with auto-fit, the browser creates as many columns as fit, which gives a responsive card layout without a single media query.

.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
  gap: 16px;
}

Responsive design

Responsive design makes one page work across screen sizes. Three ingredients are standard. The viewport meta tag (shown earlier) stops phones from zooming out. Images scale down with max-width: 100% and height: auto, so they never overflow their container. Media queries change the layout at breakpoints. A mobile-first approach writes the small layout first and adds larger layouts with min-width queries, which keeps the default simple for phones.

img {
  max-width: 100%;
  height: auto;
}

.layout {
  display: block;                   /* one column on phones */
}

@media (min-width: 768px) {
  .layout {
    display: grid;
    grid-template-columns: 240px 1fr;  /* sidebar plus content on tablets and up */
  }
}

Key ideaFlexbox distributes space along one axis, grid places items on two axes, and media queries change which of them you use. Start from the content, not from a device list.

TrapSetting a fixed pixel width on a container and then wondering why it overflows on a phone. Use max-width so the container can shrink, and let the children wrap.

What does flex: 1 do, and what does the shorthand stand for?

It sets flex-grow to 1, flex-shrink to 1 and flex-basis to 0 percent. The item starts from no preferred size and takes an equal share of the free space with its siblings that also have flex: 1. It is the usual way to make a search box fill the remaining width of a toolbar.

How the browser renders a page, and how scripts load

When you ask for a page, the browser does far more than display text. Understanding the pipeline explains why some changes are cheap and others make the page stutter, and why a script in the wrong place delays everything.

From bytes to pixels

  1. Parse HTML into the DOM (Document Object Model), a tree of nodes that JavaScript can read and change.
  2. Parse CSS into the CSSOM (CSS Object Model), a tree of style rules with the computed styles for each node.
  3. Build the render tree by combining the two. Nodes with display: none are left out, while visibility: hidden nodes stay in the tree because they still take up space.
  4. Layout (also called reflow) computes the position and size of every box.
  5. Paint fills in pixels: colours, borders, text and images, usually into layers.
  6. Composite combines the layers in the right order, often on the GPU, and shows the frame.
HTML bytes ---> DOM ----+
                   +--> render tree ---> layout ---> paint ---> composite ---> screen
CSS bytes  ---> CSSOM --+

CSS is render-blocking: the browser will not paint content it might later restyle, so it waits for the stylesheets it has found. A script that reads a style value must also wait for the CSSOM, because the answer depends on the CSS.

Reflow versus repaint

A change that affects geometry, such as width, height, font size, or adding or removing an element, forces reflow: layout runs again for the affected part of the tree, and then paint runs. A change that affects appearance without moving anything, such as colour, background or visibility, causes only a repaint. Changing transform or opacity can skip both layout and paint in many browsers, which is why animations use those properties. Reading layout properties such as offsetHeight after a write forces the browser to lay out immediately, and a loop that alternates writes and reads causes layout thrashing.

TrapAnimating top or width for movement. Each frame then runs layout and paint. Animate transform: translateX() instead, which runs on the compositor.

Scripts: parser-blocking, async and defer

A plain script tag stops HTML parsing while the script downloads and runs, because the script might call document.write or read elements that are not yet parsed. That is why scripts used to sit at the bottom of the body. The two attributes below remove the block in different ways.

Core Web Vitals

Core Web Vitals are three metrics that Google uses to measure user experience. They are measured from real visits, and the score is the 75th percentile, which means three out of four visits must meet the target. The thresholds are the ones below.

MetricWhat it measuresGoodPoor
LCP (Largest Contentful Paint)Time until the largest visible element is painted2.5 seconds or lessOver 4 seconds
INP (Interaction to Next Paint)Delay from a click, tap or key press to the next paint200 milliseconds or lessOver 500 milliseconds

Good habits follow from the pipeline: reserve space for images and ads with width and height attributes to avoid layout shift, load the largest image early, and keep the main thread free so that input is answered quickly.

Interviewers askWhat is the difference between reflow and repaint? Answer: reflow recalculates geometry and then repaints, while repaint only redraws appearance, such as colour, and leaves the layout alone.

Why is a script without async or defer a problem for page speed?

The parser stops at the script tag while the script downloads and runs. If the script is large or slow to fetch, everything after it, including content the user is waiting for, is delayed. defer downloads in parallel and runs after parsing in document order, and async downloads in parallel and runs as soon as it is ready, which is right for scripts that do not depend on each other.

Same-origin policy, CORS and cookie flags

The browser is a sandbox for code from many websites that run in the same tab. Three security mechanisms keep one site from reading another site's data. They are the same-origin policy, CORS (Cross-Origin Resource Sharing) and the security attributes of cookies.

Origin

An origin is the combination of scheme (for example https), host (example.com) and port (443 for https by default). Two URLs have the same origin only if all three parts match. The path, query and fragment do not matter. The same-origin policy says that a script on one origin cannot read the responses or the DOM of a document from a different origin. Note the precise wording: the browser still sends many cross-origin requests (for example, a form submission or an image), but JavaScript is not allowed to read the response unless the server permits it.

function sameOrigin(a, b) {
  return new URL(a).origin === new URL(b).origin;
}

const pairs = [
  ["https://example.com/login", "https://example.com/profile"],
  ["https://example.com", "http://example.com"],
  ["https://example.com", "https://api.example.com"],
  ["https://example.com", "https://example.com:443"],
  ["http://localhost:3000", "http://localhost:8080"],
];

for (const [a, b] of pairs) {
  console.log(`${a} vs ${b}: ${sameOrigin(a, b)}`);
}
https://example.com/login vs https://example.com/profile: true
https://example.com vs http://example.com: false
https://example.com vs https://api.example.com: false
https://example.com vs https://example.com:443: true
http://localhost:3000 vs http://localhost:8080: false

Read the last two rows. Changing the port changes the origin, which is why a React app on port 3000 calling an API on port 8080 is cross-origin, even on the same machine. The URL class normalises the default port, so 443 on https is the same origin as no port at all.

CORS

CORS is the mechanism by which a server says that a different origin may read its responses. The browser adds an Origin header to cross-origin requests, and the server answers with Access-Control-Allow-Origin. If the header does not match the requesting origin, the browser hides the response from the script and reports a CORS error.

Some requests are "simple": GET, HEAD and POST with ordinary headers and a content type of text/plain, application/x-www-form-urlencoded or multipart/form-data. Anything else, such as a JSON body (application/json), a custom header, or methods like PUT and DELETE, first triggers a preflight. The browser sends an OPTIONS request asking whether the real request is allowed, and only sends the real request if the answer allows it.

Preflight request from the browser:
OPTIONS /api/orders HTTP/1.1
Origin: https://shop.example
Access-Control-Request-Method: POST
Access-Control-Request-Headers: content-type

Server answer:
HTTP/1.1 204 No Content
Access-Control-Allow-Origin: https://shop.example
Access-Control-Allow-Methods: POST
Access-Control-Allow-Headers: content-type
Access-Control-Max-Age: 600

When the request carries cookies (fetch with credentials: "include"), the rules tighten. The server must name the exact origin, because * is not allowed, and it must send Access-Control-Allow-Credentials: true.

TrapThinking CORS protects the server. It does not. CORS only controls what a browser script may read. Non-browser clients ignore it completely, and simple requests may still reach the server. The server must check authentication and authorisation on every request.

Cookies and their flags

A cookie is a small piece of data that the server sets with a Set-Cookie header and the browser sends back with later requests to the same site. Its attributes control how it is used. HttpOnly hides the cookie from JavaScript, which limits damage from cross-site scripting. Secure sends it only over HTTPS. SameSite controls whether the browser sends it with cross-site requests: Strict never sends it across sites, Lax sends it on top-level navigation such as following a link, and None sends it everywhere, but only together with Secure. Chrome treats a cookie without a SameSite attribute as Lax. Max-Age and Expires set the lifetime, and Path and Domain set where it applies.

Set-Cookie: session=abc123; Path=/; Secure; HttpOnly; SameSite=Lax; Max-Age=3600

SameSite is a major defence against cross-site request forgery (CSRF), where another site makes your browser send a state-changing request with your cookie. Lax already blocks most forged POST requests from other sites, and a CSRF token adds a second check for sensitive forms.

Key ideaOrigin decides what script can read. CORS lets a server opt in to sharing responses with other origins. Cookie flags decide when the browser attaches credentials. These three rules are separate, and a bug usually comes from mixing them up.

Why does a JSON POST from a page on one origin to an API on another origin trigger a preflight?

A JSON body uses the application/json content type, which is not one of the simple content types. Browsers therefore send an OPTIONS request first, asking the server whether that method, header and content type are allowed from this origin. The real POST is sent only after the server answers with the matching Access-Control headers.

Interview questions

Answer each one aloud first. The model answers name the rules you should be able to recite and explain.

What makes an element semantic, and why does it matter?

A semantic element describes what its content is, such as nav, main or article, while div and span describe nothing. Semantics help screen readers announce regions and help search engines understand the page. They also give default behaviour and styling, so the element does more of the work for you.

How do you connect a label to a text input?

Give the input an id and set the label's for attribute to the same value, or wrap the input inside the label. The label then supplies the accessible name and clicking it focuses the input. Use a visible label rather than a placeholder, because placeholders disappear and are not reliably announced.

What is the first rule of ARIA, and why?

Do not use ARIA when a native element does the job. ARIA only changes what assistive technology announces. It does not add keyboard support, focus or click behaviour, so a div with role="button" still needs code for Enter, Space and focus. A real button has all of that already.

A div with a class of card has an id selector on its parent. Which rule wins over a plain element selector on the same div?

Specificity decides. A class (0, 1, 0) beats an element selector (0, 0, 1), regardless of source order. An ID on an ancestor only matters if the rule targets the element through that ancestor, such as #main .card, which scores (1, 1, 0) and beats both.

What is the difference between flexbox and grid?

Flexbox lays items out along one axis, a row or a column, and distributes the remaining space among them. Grid defines rows and columns together and places items into cells. Use flexbox for a toolbar or a nav bar, and grid for a card gallery or a page layout with a sidebar.

What triggers a reflow, and what only triggers a repaint?

Reflow is triggered by changes to geometry, such as width, height, font size, or adding and removing elements, and it recalculates layout before painting. Repaint is triggered by visual-only changes such as colour and background, which skip layout. Animating transform or opacity avoids both on most browsers.

What is the difference between async and defer?

Both download in parallel with parsing. async runs the script as soon as the download finishes, which can interrupt parsing and does not guarantee order. defer waits until parsing is complete and runs scripts in document order. Use defer for application code that needs the DOM, and async for independent scripts such as analytics.

Which Core Web Vital replaced FID, and what does it measure?

INP, Interaction to Next Paint, replaced First Input Delay in March 2024. It measures the delay from a user interaction until the browser paints the next frame, across the whole visit, and the good threshold is 200 milliseconds or less.

Are http://example.com and https://example.com the same origin?

No. The scheme differs, so the origins differ even though the host is the same. The same is true when the port differs, such as localhost:3000 and localhost:8080.

Does CORS stop a malicious site from sending a request to your server?

No. CORS only controls whether browser JavaScript on another origin may read the response. Simple requests can still reach the server, and non-browser clients ignore CORS entirely. Protection against forged requests comes from SameSite cookies, CSRF tokens, and authorisation checks on the server.

What does the HttpOnly cookie flag protect against, and what does SameSite=Lax protect against?

HttpOnly hides the cookie from document.cookie and other JavaScript, so a cross-site scripting bug cannot steal it directly. SameSite=Lax stops the browser from sending the cookie on most cross-site requests, such as a forged POST from another site, which reduces cross-site request forgery.

DSA: string algorithms (KMP, Rabin-Karp)

Searching for a pattern inside a text is one of the most common string tasks. The naive method tries every starting position and compares characters one at a time, which costs O(n m) in the worst case, where n is the text length and m is the pattern length. Two algorithms remove most of that waste. KMP (Knuth, Morris and Pratt) never moves backward through the text, and it uses a table built from the pattern itself. Rabin-Karp compares a fingerprint, called a hash, of each window instead of the characters, and it can update that fingerprint in constant time as the window slides.

The pattern: a prefix table for KMP

The key object is the prefix function, written pi. For each position i of the pattern p, pi[i] is the length of the longest proper prefix of p[0..i] that is also a suffix of it. "Proper" means shorter than the whole piece. A prefix that is also a suffix is called a border. The table tells the search how much of the pattern can be reused after a mismatch. Here is the prefix function of "ababaca", computed by the code below.

def prefix_function(p):
    pi = [0] * len(p)
    k = 0                                  # length of the current border
    for i in range(1, len(p)):
        while k > 0 and p[i] != p[k]:
            k = pi[k - 1]                  # fall back to a shorter border
        if p[i] == p[k]:
            k += 1
        pi[i] = k
    return pi


print(prefix_function("ababaca"))
[0, 0, 1, 2, 3, 0, 1]

The table is built in one pass. Position 0 always gets 0, because one character has no proper prefix. At position 5 the character c does not extend the border of length 3 (the prefix "aba" is followed by b in the pattern, not c), so the loop falls back to shorter borders, first to 1 and then to 0, which gives 0. At position 6 the character a extends the border of length 0 to length 1. The fall-back step is the heart of the method: a border is always a border of a shorter border, so the search can jump from one candidate to the next without re-checking characters.

The pattern: KMP never moves backward in the text

The KMP search keeps k, the number of pattern characters matched so far. For each text character, if it matches needle[k], k grows. If it does not match, k falls back to pi[k - 1], the longest border of the matched part, and the text pointer stays where it is. The text is read once from left to right, so the whole search is O(n + m). The example below searches for "abcaby" in "abxabcabcaby", and the table after each text character shows the state.

The match ends at text index 11, so it starts at 11 - 6 + 1 = 6. The text pointer never went backward, and the characters "abc" at index 5 to 7 were reused after the mismatch at index 8.

The pattern: Rabin-Karp compares fingerprints

Rabin-Karp assigns each string a number, its hash, computed as a polynomial in a base (here 256, one per byte) modulo a large prime. The hash of a window can be updated in constant time when the window slides: remove the leftmost character's contribution, multiply by the base, and add the new character. Equal hashes are only a hint, because different strings can share a hash (a collision), so every hit must be confirmed by comparing the characters. The code below uses the fixed base and modulus, so the output is the same on every run.

def rabin_karp(text, pattern):
    n, m = len(text), len(pattern)
    if m == 0 or m > n:
        return []
    base, mod = 256, 1_000_000_007
    high = pow(base, m - 1, mod)           # weight of the leftmost character
    p_hash = t_hash = 0
    for k in range(m):
        p_hash = (p_hash * base + ord(pattern[k])) % mod
        t_hash = (t_hash * base + ord(text[k])) % mod
    matches = []
    for i in range(n - m + 1):
        # equal hashes are only a hint, so confirm the characters
        if p_hash == t_hash and text[i:i + m] == pattern:
            matches.append(i)
        if i + m < n:
            # slide the window: drop text[i], add text[i + m]
            t_hash = ((t_hash - ord(text[i]) * high) * base + ord(text[i + m])) % mod
    return matches


print(rabin_karp("banana anaconda", "ana"))
print(rabin_karp("aaaaa", "aa"))
print(rabin_karp("abc", "d"))
[1, 3, 7]
[0, 1, 2, 3]
[]

The first call finds "ana" at positions 1, 3 and 7 (the windows overlap, which is allowed). Rabin-Karp is the right tool when you must compare many windows against one another, as in the repeated-substring problem below. For a single pattern, KMP gives a guaranteed linear bound, while Rabin-Karp is linear on average and can degrade on adversarial input.

Pattern to rememberUse the prefix function (KMP) when you search one pattern in a text, or when you need the borders of a string. Use a rolling hash (Rabin-Karp) when you slide a fixed-size window and need to compare many windows quickly. Always verify a hash hit by comparing the characters.

Find the Index of the First Occurrence in a String (LeetCode 28)

Given two strings, haystack and needle, return the index of the first occurrence of needle in haystack, or -1 if needle is not part of haystack. For example, "sadbutsad" with needle "sad" gives 0, because "sad" first appears at index 0.

How to think about it

  1. Understand. Return the leftmost starting index of a full match. An empty needle returns 0 by convention, the same as Python's str.find.
  2. Brute force. For each start i in the haystack, compare needle with haystack[i:i+m] character by character. The worst case is O(n m), for example searching "aaaa...ab" in "aaaa...a".
  3. Find the waste. After a mismatch at needle position k, the naive method restarts at the next start position and re-reads characters it has already matched. Those characters are known, so their information should be reused.
  4. Optimise. Build the prefix function of the needle. On a mismatch at needle position k, fall back to pi[k - 1] instead of restarting, because that is the longest part of the matched text that could still begin a match. The haystack pointer never moves backward, so the search is O(n + m).
  5. Dry run. The prefix function and the traces are shown in the explanation above. For "sadbutsad" with "sad", the match of "sad" ends at index 2, so the function returns 2 - 3 + 1 = 0.

Code

def prefix_function(p):
    pi = [0] * len(p)
    k = 0
    for i in range(1, len(p)):
        while k > 0 and p[i] != p[k]:
            k = pi[k - 1]
        if p[i] == p[k]:
            k += 1
        pi[i] = k
    return pi


def str_str(haystack, needle):
    if not needle:
        return 0
    pi = prefix_function(needle)
    k = 0                                  # characters of needle matched so far
    for i, ch in enumerate(haystack):
        while k > 0 and ch != needle[k]:
            k = pi[k - 1]                  # reuse the matched part
        if ch == needle[k]:
            k += 1
        if k == len(needle):
            return i - len(needle) + 1     # the match ends at i
    return -1


print(str_str("sadbutsad", "sad"))
print(str_str("leetcode", "leeto"))
print(str_str("hello", "ll"))
0
-1
2

Time O(n + m) · Space O(m)

Pattern to rememberWhen a naive scan restarts after a mismatch, ask: what do I already know about the text? The prefix function encodes exactly that knowledge about the pattern.

Repeated DNA Sequences (LeetCode 187)

A DNA string is made of the letters A, C, G and T. Return every substring of length 10 that occurs more than once in the string. For example, the 32-letter string used below contains two such substrings: "AAAAACCCCC" and "CCCCCAAAAA".

How to think about it

  1. Understand. Only substrings of length exactly 10 count, and each repeated one is reported once. Any order is accepted, and the code below reports them in the order their second occurrence appears.
  2. Brute force. Put every length-10 substring into a dictionary of counts, then keep the ones with a count above one. This is O(10 n) time and memory, which is fine, but it stores many long strings.
  3. Find the waste. Each window is a string of 10 letters, and comparing or hashing strings costs time proportional to their length. The windows overlap, so we can update a window from the previous one instead of rebuilding it.
  4. Optimise. Encode each letter in two bits: A is 00, C is 01, G is 10, T is 11. Ten letters need 20 bits, which fit in one integer. Sliding the window is one shift, one OR and one mask: value = ((value shifted left by 2) OR code) AND mask, where the mask keeps the last 20 bits. Two windows are equal if and only if their integers are equal, so there are no collisions, and integers are cheap to store in a set.
  5. Dry run. In "AAAAACCCCCAAAAACCCCCCAAAAAGGGTTT", the window starting at index 0 and the window starting at index 10 both spell "AAAAACCCCC". Their integers match, so the second sighting (when the window ends at index 19) adds the substring to the result. The window starting at index 5, "CCCCCAAAAA", is first seen when it ends at index 14. It repeats at index 16, so the second sighting (when it ends at index 25) adds it after the first. The result is in that order.

Code

def find_repeated_dna(s):
    code = {"A": 0, "C": 1, "G": 2, "T": 3}
    mask = (1 << 20) - 1                  # keep the last 10 letters, 2 bits each
    seen, repeated = set(), set()
    result = []
    value = 0
    for i, ch in enumerate(s):
        value = ((value << 2) | code[ch]) & mask
        if i < 9:
            continue                        # the first full window ends at index 9
        if value in seen:
            if value not in repeated:
                repeated.add(value)
                result.append(s[i - 9:i + 1])
        else:
            seen.add(value)
    return result


print(find_repeated_dna("AAAAACCCCCAAAAACCCCCCAAAAAGGGTTT"))
print(find_repeated_dna("AAAAAAAAAAAAA"))
print(find_repeated_dna("ACGTACGTACGTACGT"))
['AAAAACCCCC', 'CCCCCAAAAA']
['AAAAAAAAAA']
['ACGTACGTAC', 'CGTACGTACG', 'GTACGTACGT']

Time O(n) · Space O(n)

TrapForgetting to report each repeated window only once. In "AAAAAAAAAAAAA" the window "AAAAAAAAAA" appears four times, but it must appear once in the result. The repeated set stops duplicates.

Pattern to rememberWhen the alphabet is small and the window is short, pack the window into an integer with bit shifts. The integer is an exact fingerprint, so it needs no collision check.

Longest Happy Prefix (LeetCode 1392)

A happy prefix is a non-empty prefix of a string that is also a suffix, and is not the whole string. Return the longest happy prefix of s. For example, "level" has the happy prefix "l" (the first and last letters), and "ababab" has the happy prefix "abab".

How to think about it

  1. Understand. We need the longest proper border of s. A border is a prefix that is also a suffix, and "proper" means it is not the whole string.
  2. Brute force. For each length L from n - 1 down to 1, compare s[:L] with s[n - L:]. The first match is the answer. This is O(n^2) character comparisons in the worst case.
  3. Find the waste. Comparing a prefix with a suffix is exactly what the prefix function computes. The prefix function already records the longest border of every prefix of s, so one pass answers the question for all lengths at once.
  4. Optimise. The last entry of the prefix function, pi[n - 1], is the length of the longest proper border of the whole string. Return s[:pi[-1]].
  5. Dry run. For "ababab" the prefix function is computed as follows.

The last value is 4, so the answer is "abab". The border "abab" is both the first four letters and the last four letters.

Shortest Palindrome (LeetCode 214)

You may add characters only at the front of string s. Return the shortest palindrome you can make this way. For example, "aacecaaa" becomes "aaacecaaa" by adding one "a" at the front, and "abcd" becomes "dcbabcd" by adding "dcb".

How to think about it

  1. Understand. Adding characters at the front is the only freedom. The characters that can stay are a palindromic prefix of s, so the goal is the longest palindromic prefix. Whatever is left after it must be reversed and placed in front.
  2. Brute force. For end from len(s) down to 0, check whether s[:end] is a palindrome. The first palindrome found gives the answer as reverse(s[end:]) + s. The checks cost O(n^2) or worse with slicing.
  3. Find the waste. Checking whether a prefix is a palindrome is the same as checking whether the prefix equals the reverse of that prefix. A prefix of s equals the reversed version of the same prefix exactly when it matches a suffix of reverse(s). That is again a border question, which the prefix function answers in one pass.
  4. Optimise. Build t = s + "#" + reverse(s). The separator "#" does not occur in s, so no border can run past the middle. The last value of the prefix function of t is the length L of the longest palindromic prefix of s. Then the answer is reverse(s[L:]) + s. For lowercase letters the separator is safe; for other alphabets, choose a character that s does not contain.
  5. Dry run. For "aacecaaa", t is "aacecaaa#aaacecaa", and its last prefix-function value is 7. The palindromic prefix is "aacecaa", so s[7:] is "a". Reversed, "a" is still "a", and the answer is "a" + "aacecaaa" = "aaacecaaa".

Code

def prefix_function(p):
    pi = [0] * len(p)
    k = 0
    for i in range(1, len(p)):
        while k > 0 and p[i] != p[k]:
            k = pi[k - 1]
        if p[i] == p[k]:
            k += 1
        pi[i] = k
    return pi


def shortest_palindrome(s):
    t = s + "#" + s[::-1]                 # the separator stops matches from crossing it
    longest_pal_prefix = prefix_function(t)[-1]
    return s[longest_pal_prefix:][::-1] + s


def shortest_palindrome_slow(s):
    # O(n^2): try the longest prefix first and check it directly
    for end in range(len(s), -1, -1):
        if s[:end] == s[:end][::-1]:
            return s[end:][::-1] + s

print(shortest_palindrome("abcd"))
print(shortest_palindrome("a"))
print(shortest_palindrome_slow("aacecaaa") == shortest_palindrome("aacecaaa"))
