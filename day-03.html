Types, sizes and integer behaviour

C is a statically typed, compiled language. Every variable has a fixed type that is known at compile time, and that type decides how many bytes the variable occupies and how its bits are read. Unlike Python, C does not check types for you at runtime. A wrong type is simply a wrong interpretation of the same bytes, so you must know the rules.

The sizes in this unit are the ones on a typical 64-bit Linux system, which is the system the examples were run on. The C standard only guarantees minimum sizes, so the exact values can differ on other platforms. Use sizeof in real code instead of assuming a size.

The basic types

TypeTypical sizeNotes
char1 byteHolds a character code or a small integer. Whether it is signed is platform-defined.
short2 bytesAt least 16 bits.
int4 bytesThe default integer type. At least 16 bits by the standard, but 32 bits in practice here.
long8 bytes on 64-bit Linux4 bytes on Windows, which is why portable code uses fixed-width types from stdint.h.
long long8 bytesAt least 64 bits.
float, double4 and 8 bytesFloating point. double is the default for literals such as 3.5.
pointers8 bytesThe size of an address on a 64-bit system, whatever the pointed-to type is.

Each integer type can be signed (the default for int) or unsigned. A signed type uses one bit for the sign, so it holds values from negative to positive. An unsigned type holds only zero and positive numbers, and its range starts at zero.

Printing values with the right format

printf needs a format specifier that matches the type. A mismatch compiles with a warning and then prints garbage. The most common ones are %d for int, %u for unsigned int, %zu for sizeof results, %f or %.2f for double, %c for a single character and %s for a string.

#include <stdio.h>

int main(void) {
    printf("char=%zu short=%zu int=%zu long=%zu\n",
           sizeof(char), sizeof(short), sizeof(int), sizeof(long));
    printf("double=%zu\n", sizeof(double));

    char c = 'A';
    printf("%c %d\n", c, c);          /* the same byte, shown as a letter and as a number */
    return 0;
}
char=1 short=2 int=4 long=8
double=8
A 65

The character 'A' is stored as the number 65, which is its ASCII code. Printing it with %c shows the letter, and printing it with %d shows the number. There is no separate character type in memory, only a small integer that the format string interprets.

Integer division, remainder and wraparound

Dividing two integers gives an integer result. The fraction is thrown away, which means the result is truncated toward zero. Since C99, the remainder operator % has the sign of the dividend, so -7 % 3 is -1. Unsigned arithmetic wraps around modulo 2 to the power of the number of bits, which gives a predictable result.

#include <stdio.h>
#include <limits.h>

int main(void) {
    printf("%d %d\n", 7 / 2, -7 / 2);
    printf("%d %d\n", -7 % 3, 7 % -3);
    printf("%.2f\n", 7 / 2.0);

    unsigned int u = 0;
    u = u - 1;                        /* wraps around to the largest unsigned int */
    printf("%u\n", u);
    printf("%d\n", INT_MAX);
    return 0;
}
3 -3
-1 1
3.50
4294967295
2147483647

The line 7 / 2.0 divides by a double, so the arithmetic happens in floating point and gives 3.5. Dividing by the integer 2 instead would give 3. The unsigned subtraction 0 - 1 gives 4294967295, which is 2 to the power 32 minus 1, because an unsigned int has 32 bits here.

TrapSigned integer overflow, such as adding one to INT_MAX, is undefined behaviour in C. The program may do anything, including appear to work. Unsigned overflow is defined to wrap, but it can still hide bugs, such as a loop that counts down past zero and never ends.

Interviewers askWhat is the size of an int and of a pointer? An int is typically 4 bytes and a pointer is 8 bytes on a 64-bit system. Pointer size depends on the architecture, not on the type being pointed to.

What is the result of -7 / 2 and -7 % 2 in C?

The division truncates toward zero, so the result is -3. The remainder takes the sign of the dividend, so it is -1. Together they satisfy (a / b) * b + a % b = a, which is -3 times 2 plus -1, giving -7.

Storage classes and scope

Every variable in C has a storage class, which decides three things: where the variable is stored in memory, how long it lives, and which parts of the program can name it. You set the storage class with a keyword in the declaration, or it is implied by where the declaration appears.

KeywordWhere it livesLifetimeTypical use
auto (default for locals)The stackFrom the start of its block until the block endsOrdinary local variables
static inside a functionStatic storageThe whole program run, initialised onceA counter that keeps its value between calls
static at file levelStatic storageThe whole program runA helper variable hidden from other files
file-level variable (no keyword)Static storageThe whole program runShared state, visible to other files through extern
externDeclared here, defined elsewhereAs the definitionTelling this file about a variable defined in another file
registerA hint to keep it in a CPU registerBlockRarely needed; modern compilers decide this well

Scope is where a name can be used. Lifetime is when the memory exists. They are different. A static local variable has a lifetime of the whole program but a scope of only its function. A file-level static variable has the whole program as its lifetime, but its scope is only the file where it is written.

Static locals: state that survives a call

#include <stdio.h>

int global_count = 0;             /* file-level: static storage, visible to other files */
static int file_only = 5;         /* file-level static: visible only in this file */

void tick(void) {
    static int calls = 0;         /* initialised once, keeps its value between calls */
    int local = 0;                /* automatic: created fresh on every call */
    calls++;
    local++;
    global_count++;
    printf("calls=%d local=%d\n", calls, local);
}

int main(void) {
    tick();
    tick();
    tick();
    printf("global_count=%d file_only=%d\n", global_count, file_only);
    return 0;
}
calls=1 local=1
calls=2 local=1
calls=3 local=1
global_count=3 file_only=5

The output shows the difference clearly. calls grows from 1 to 3 because it is a static local, so the same memory is used on every call. local is 1 each time because a fresh automatic variable is created and set to 0 on each call, then incremented to 1. A static local initialiser runs once, before main starts, so the line static int calls = 0 does not reset it on later calls.

TrapUninitialised automatic variables hold garbage, not zero. Only static and file-level variables are zeroed before the program starts. Always initialise your locals.

Key ideaAutomatic variables live on the stack and vanish when their block ends. Static variables live for the whole program. A pointer to an automatic variable is dangerous once that variable is gone.

What is the difference between scope and lifetime, using a static local as the example?

Scope is where the name can be used, which for a static local is only inside its function. Lifetime is how long the memory exists, which for a static local is the whole program. The variable keeps its value between calls, even though no other function can name it.

const and volatile

const tells the compiler and other programmers that a value must not be changed through a particular name. The compiler enforces it, so an attempt to assign to a const variable is an error. volatile says the opposite kind of thing: the value may change at any time, from outside the normal flow of the program, so every read must really go to memory.

Reading a const declaration

The position of const relative to the * decides what is constant. Read the declaration from the name outward, toward the left.

DeclarationMeaning
const int *pPointer to const int. You cannot change the int through p, but you can point p somewhere else.
int *const pConst pointer to int. p must always point to the same place, but you can change the int it points to.
const int *const pConst pointer to const int. Neither the pointer nor the int can change.
#include <stdio.h>

int main(void) {
    int a = 1, b = 2;
    const int *p1 = &a;           /* pointer to const: *p1 cannot be assigned */
    int *const p2 = &a;          /* const pointer: p2 cannot be moved */
    const int *const p3 = &b;    /* both are fixed */

    p1 = &b;                      /* allowed: the pointer itself is not const */
    /* *p1 = 5;   would not compile: the int is const through p1 */
    /* p2 = &b;   would not compile: p2 is a const pointer */
    *p2 = 10;                       /* allowed: the int a is not const */

    printf("%d %d %d\n", *p1, *p2, *p3);
    return 0;
}
2 10 2

Trace the program. After p1 = &b, *p1 reads b, which is still 2. *p2 = 10 changes a to 10, because p2 points to a non-const int. *p3 reads b, which is 2. The two commented lines show what the compiler rejects.

volatile is used for memory-mapped hardware registers, variables changed by a signal handler, and values changed by another thread without proper synchronisation. It stops the compiler from caching the value in a register or optimising away repeated reads. It does not make operations atomic or thread-safe. For threads, use the synchronisation tools of the language instead.

Interviewers askWhat is the difference between const int *p and int *const p? The first protects the value and lets the pointer move. The second protects the pointer and lets the value change.

Why would you declare a hardware status register as volatile?

The hardware can change the register at any moment, outside the program's visible writes. Declaring it volatile forces every read to load from memory, so the program sees the current value rather than a copy the compiler kept in a register.

Functions and call by value

A C function has a return type, a name and a parameter list. Before you call a function, the compiler must know its signature, either from a prototype (a declaration such as int add(int a, int b);) or from the definition itself. Since C99, calling an undeclared function is an error, which catches a whole class of mistakes at compile time.

Arguments are copied: call by value

C always passes arguments by value. The function receives a copy of each argument. Changing the copy inside the function does not change the caller's variable. To let a function change a caller's variable, pass its address and let the function write through a pointer. This is the only way to get "call by reference" behaviour in C.

#include <stdio.h>

void swap_wrong(int x, int y) {
    int t = x;
    x = y;
    y = t;                       /* swaps the local copies only */
}

void swap_right(int *x, int *y) {
    int t = *x;
    *x = *y;                     /* writes through the pointers, into the caller's variables */
    *y = t;
}

int main(void) {
    int a = 1, b = 2;
    swap_wrong(a, b);
    printf("after wrong: %d %d\n", a, b);
    swap_right(&a, &b);
    printf("after right: %d %d\n", a, b);
    return 0;
}
after wrong: 1 2
after right: 2 1

In swap_wrong, the names x and y are fresh copies, so swapping them is invisible to main. In swap_right, the function receives the addresses of a and b, and *x is the caller's a. The & operator takes an address, and * follows an address to the value stored there.

Function pointers

A function has an address too, and you can store it in a pointer. The declaration reads: a pointer named op to a function that takes two ints and returns an int. The parentheses are essential. Without them, int *op(int, int) would declare a function returning a pointer.

#include <stdio.h>

int add(int a, int b) { return a + b; }
int mul(int a, int b) { return a * b; }

int apply(int (*op)(int, int), int a, int b) {
    return op(a, b);             /* calls whichever function was passed in */
}

int main(void) {
    int (*fp)(int, int) = add;   /* a function name decays to its address */
    printf("%d %d\n", fp(3, 4), apply(mul, 3, 4));
    return 0;
}
7 12

Function pointers are how C implements callbacks, such as the comparison function passed to qsort, and simple dispatch tables. The call fp(3, 4) and the call op(a, b) inside apply use the same syntax as a normal call, because calling through a pointer and calling a name are the same operation.

TipUse a typedef to make function pointer types readable, for example typedef int (*binop)(int, int);, and then declare binop op.

Why does swapping two ints through copies fail, and what is the fix?

Arguments are copied, so the function swaps its own copies, and the caller never sees the change. The fix is to pass the addresses of the variables and write through the pointers, so the function changes the caller's objects.

Pointers of every kind

A pointer is a variable that stores the address of another object. The unary & operator produces an address, and the unary * operator reads or writes the object at an address. Pointers are the most important and most error-prone part of C, so this unit goes slowly through each kind you must recognise.

Address-of and dereference

#include <stdio.h>

int main(void) {
    int x = 42;
    int *p = &x;                 /* p holds the address of x */
    int **pp = &p;               /* pp holds the address of the pointer p */

    printf("%d %d\n", *p, **pp);   /* two dereferences reach x */
    *p = 7;                        /* writes into x through p */
    printf("%d\n", x);
    return 0;
}
42 42
7

The variable pp is a pointer to a pointer. It is used in C for things like changing a caller's pointer, for example when a function allocates memory and must return the new address through a parameter. Each * removes one level of pointer, so **pp is the int at the end of the chain.

Pointer arithmetic and arrays

Adding an integer to a pointer moves it by that many elements, not that many bytes. If p points to an int, p + 1 points to the next int, which is four bytes further on. Subtracting two pointers into the same array gives the number of elements between them. An array name, used without brackets, decays to a pointer to its first element.

#include <stdio.h>
#include <stddef.h>

int main(void) {
    int arr[4] = {10, 20, 30, 40};
    int *q = arr;                          /* the array name decays to &arr[0] */

    printf("%d %d\n", *(q + 2), q[3]);     /* q[i] is the same as *(q + i) */
    printf("%td\n", (q + 3) - q);          /* elements between the two pointers */
    return 0;
}
30 40
3

q[3] is defined as *(q + 3), so the bracket notation and pointer arithmetic are two spellings of one thing. The difference of two pointers has the type ptrdiff_t, which is printed with %td. Pointer arithmetic is only defined while the pointer stays inside the same array, or one element past its end.

The null pointer and the void pointer

A null pointer holds the special value that means "points to nothing". Dereferencing it is undefined behaviour, which usually crashes the program. Always check a pointer for null before you use it, especially after malloc. A void pointer, declared void *, can hold the address of any object, but it cannot be dereferenced or used in arithmetic until it is cast back to a real pointer type.

#include <stdio.h>
#include <stddef.h>

int main(void) {
    int x = 7;
    int *np = NULL;
    if (np == NULL) {
        printf("np is null\n");
    }

    void *vp = &x;                 /* any object address fits in a void pointer */
    printf("%d\n", *(int *)vp);     /* cast back to int * before reading */
    return 0;
}
np is null
7

Pointer to array, array of pointers

The two are easy to confuse. An array of pointers is an array whose elements are pointers, written int *table[2]. A pointer to an array points to a whole array, written int (*pa)[4]. Read the parentheses first: (*pa) is a pointer, and [4] says what it points to.

#include <stdio.h>

int main(void) {
    int arr[4] = {10, 20, 30, 40};

    int *table[2] = {&arr[0], &arr[3]};     /* array of pointers */
    printf("%d %d\n", *table[0], *table[1]);

    int (*pa)[4] = &arr;                     /* pointer to the whole array */
    printf("%d\n", (*pa)[1]);
    return 0;
}
10 40
20

Dangling, wild and function pointers

A dangling pointer still holds the address of memory that no longer belongs to the object, for example after free(p), or after returning the address of a local variable from a function. Using it is undefined behaviour. A wild pointer is one that was never initialised, so it holds an arbitrary address. Initialise every pointer when you declare it, set it to NULL after freeing it, and never return the address of a local variable.

TrapReturning &local from a function gives the caller a pointer to memory that the function's return has already released. It may appear to work for a while, which makes the bug harder to find. Return values, or allocate with malloc, or use a static object.

Function pointers were covered in the functions unit. They are the third kind of pointer to know by heart, alongside data pointers and void pointers.

Interviewers askWhat is the difference between int *p[10] and int (*p)[10]? The first is an array of ten int pointers. The second is a single pointer to an array of ten ints.

If p points to an int, what does p + 1 point to, and how far away is it in bytes?

It points to the next int in memory, which is sizeof(int) bytes further on, typically 4. The arithmetic is in elements, so the compiler scales by the size of the pointed-to type.

Arrays and strings

An array in C is a fixed block of consecutive elements of one type. The size is part of the declaration and must be known at compile time, or use dynamic memory, which comes later in this page. C does not store the length of an array anywhere. Code that wants the length must track it, or use sizeof on an array that is still in scope.

sizeof on arrays versus pointers

sizeof is computed at compile time. For a true array it gives the total number of bytes, so dividing by the size of one element gives the element count. Once an array is passed to a function, it has decayed to a pointer, and sizeof then gives the size of the pointer. This is one of the most common interview traps.

#include <stdio.h>
#include <string.h>

void show_size(int a[]) {
    /* here a is really an int *, so sizeof reports the size of a pointer */
    printf("inside: sizeof(a)=%zu\n", sizeof(a));
}

int main(void) {
    char word[] = "hello";          /* 5 letters plus the terminating '\0' */
    printf("sizeof(word)=%zu strlen(word)=%zu\n", sizeof(word), strlen(word));

    int nums[5] = {1, 2, 3, 4, 5};
    printf("sizeof(nums)=%zu count=%zu\n", sizeof(nums), sizeof(nums) / sizeof(nums[0]));
    show_size(nums);

    char dest[10];
    strcpy(dest, word);             /* copies the characters and the terminating '\0' */
    printf("%s %d\n", dest, strcmp(dest, "hello") == 0);
    dest[0] = 'J';
    printf("%s\n", dest);
    return 0;
}
sizeof(word)=6 strlen(word)=5
sizeof(nums)=20 count=5
inside: sizeof(a)=8
hello 1
Jello

The difference between sizeof(word) (6) and strlen(word) (5) is the whole story of C strings. sizeof counts the array's bytes, including the terminator. strlen counts characters up to, but not including, the first '\0'. The show_size line prints 8 because a pointer is 8 bytes on this 64-bit system, not the 20 bytes of the array.

C strings are character arrays with a terminator

A C string is an array of char that ends with the byte '\0', called the null terminator. Every standard string function, such as strlen, strcpy and strcmp, relies on that byte to know where the string ends. The literal "hello" therefore takes six bytes.

  • strlen(s) counts characters before the terminator. It scans the string, so it is O(n) each time you call it.
  • strcpy(dest, src) copies src, including the terminator, into dest. It does not check the size of dest, so a long source overflows dest and corrupts memory.
  • strcmp(a, b) returns 0 when the strings are equal, a negative number when a sorts before b, and a positive number otherwise. Never compare strings with ==, because that compares the addresses.
  • strncpy and snprintf take a size limit, which is safer. Even strncpy does not always add the terminator, so check it yourself.

TrapWriting char *s = "hi"; s[0] = 'H'; is undefined behaviour, because string literals are not meant to be changed. Copy the literal into an array first: char s[] = "hi";.

TrapForgetting room for the terminator is the classic off-by-one. A string of 5 letters needs an array of at least 6 chars.

Why is sizeof(word) 6 for char word[] = "hello" while strlen(word) is 5?

sizeof counts all the bytes of the array, which are five letters plus the terminating '\0'. strlen counts the characters before the terminator, which are five.

Passing arrays to functions

An array parameter is really a pointer parameter, so the function receives the address of the first element and cannot see the length. That is why C functions that take arrays almost always take a length too. The caller passes the array name, which decays to its address.

Interviewers askWhy does sizeof of an array parameter give the pointer size? Because the parameter is adjusted to a pointer when the function is declared. The array's size information is lost at that point.

Dynamic memory: malloc, calloc, realloc and free

Automatic variables disappear when their block ends, and their size must be fixed at compile time. When the size is known only at runtime, or the data must outlive the function that creates it, you ask for memory from the heap with the functions in stdlib.h. You own that memory. It stays valid until you call free, and you must free it exactly once.

The four functions

FunctionWhat it doesReturns
malloc(bytes)Allocates a block of the given number of bytes. The contents are uninitialised, meaning garbage.A pointer to the block, or NULL on failure
calloc(count, size)Allocates count elements of size bytes each, and sets every byte to zero.A pointer, or NULL
realloc(p, bytes)Resizes a block to the new size. It may move the data to a new location, copying the old contents as far as they fit.A pointer to the new block, or NULL on failure. The old pointer is then still valid.
free(p)Releases a block that malloc, calloc or realloc returned.Nothing

Write the size as n * sizeof *p, not as a literal number. The expression is then correct for any element type, and if the type changes, the size changes with it. Always check the result of an allocation for NULL before using it.

#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int n = 5;
    int *a = malloc(n * sizeof *a);        /* uninitialised: contents are garbage */
    if (a == NULL) {
        return 1;
    }
    for (int i = 0; i < n; i++) {
        a[i] = i * i;
    }

    int *z = calloc(n, sizeof *z);         /* every element starts at zero */
    printf("%d %d\n", a[4], z[4]);

    int *bigger = realloc(a, 2 * n * sizeof *bigger);
    if (bigger == NULL) {                   /* the old block a is still valid here */
        free(a);
        free(z);
        return 1;
    }
    a = bigger;                             /* the old pointer must not be used any more */
    for (int i = n; i < 2 * n; i++) {
        a[i] = -1;
    }
    printf("%d %d %d\n", a[0], a[4], a[9]);

    free(a);
    free(z);
    a = NULL;                               /* a dangling pointer is avoided by clearing it */
    z = NULL;
    return 0;
}
16 0
0 16 -1

Read the program in order. malloc gives five ints, which the loop fills with 0, 1, 4, 9 and 16. calloc gives five zeroed ints, so z[4] is 0. realloc grows the first block to ten ints and keeps the first five values. The loop fills the new half with -1. Finally both blocks are freed, and the pointers are set to NULL so that a later accidental use fails cleanly.

TrapAfter realloc succeeds, the old pointer may be invalid because the block moved. Assign the result to a new variable, check it, and only then overwrite the original pointer. Writing a = realloc(a, ...) loses the old block if the allocation fails.

TrapFreeing the same block twice is a double free, and using a block after freeing it is a use-after-free. Both are undefined behaviour and are common sources of security bugs. Setting the pointer to NULL after free makes the second free harmless, because free(NULL) does nothing.

Memory leaks

A memory leak happens when a block is allocated and the program loses every pointer to it without freeing it. The memory stays reserved until the process exits, and in a long-running program it grows until the system runs out. The function below leaks its block: it returns without freeing p, so nothing can free it later.

#include <stdlib.h>

void leaky(void) {
    int *p = malloc(100 * sizeof *p);
    if (p == NULL) {
        return;
    }
    p[0] = 1;
    /* missing free(p): the 400 bytes stay reserved after this function returns */
}

Tools such as valgrind report leaks and invalid accesses when you run a program. In an interview, the expected habit is simple: every malloc has a matching free on every path out of the function, including the error paths.

Interviewers askWhat is the difference between malloc and calloc? calloc takes two arguments and zeroes the memory. malloc takes one argument and leaves the contents uninitialised. Both return NULL on failure.

Why is realloc dangerous when written as a = realloc(a, size)?

If realloc fails, it returns NULL, and the assignment overwrites the only pointer to the original block, leaking it. Store the result in a temporary pointer, check it, and only then assign it to the original variable.

Memory layout of a C program

When a C program runs, the operating system gives it one address space divided into regions. Knowing where each variable lives explains the storage classes, the lifetime rules and the bugs in this page. The diagram below shows the usual layout from the high addresses at the top to the low addresses at the bottom. Exact placement varies by system, so treat it as the standard model.

high addresses
  stack   grows downward: local (automatic) variables, function call frames
  (free space between the stack and the heap)
  heap    grows upward: memory from malloc, calloc and realloc
  bss     global and static variables with no initialiser, zeroed at start
  data    global and static variables with an initialiser
  text    the program's machine code, usually read-only
low addresses

The stack is managed automatically. Each function call pushes a frame holding its parameters and locals, and the return pops it. The heap is managed by you, through malloc and free. Global and static variables live in the data or bss segments for the whole run. The next program shows the two static segments.

#include <stdio.h>
#include <stdlib.h>

int initialised = 10;         /* data segment: starts with this value */
int zeroed;                   /* bss segment: zero until the program sets it */

int *make_on_heap(int v) {
    int *p = malloc(sizeof *p);
    if (p != NULL) {
        *p = v;               /* lives until free(), not until this function returns */
    }
    return p;
}

int main(void) {
    printf("%d %d\n", initialised, zeroed);
    int *h = make_on_heap(99);
    if (h != NULL) {
        printf("%d\n", *h);
        free(h);
    }
    return 0;
}
10 0
99

The value zeroed is 0 without any assignment, because bss memory is cleared before main starts. initialised is 10 because its value is stored in the data segment. The block returned by make_on_heap survives the function's return, which is impossible for a local variable, and it is freed explicitly in main.

Key ideaAutomatic variables are on the stack and end with their block. Static and global variables last for the whole program. Heap memory lasts until you free it. Matching each allocation to a free is the whole discipline of manual memory management.

Interviewers askWhere does each kind of variable live? Locals on the stack, malloc'd blocks on the heap, initialised globals and statics in the data segment, uninitialised globals and statics in bss, and code in text.

A function returns a pointer to a local array. Why is that a bug, and what are two correct alternatives?

The local array lives on the stack and is released when the function returns, so the pointer dangles. Two correct alternatives are to allocate the array with malloc and return that pointer, so the caller frees it later, or to have the caller pass in a buffer to fill.

Interview questions

Answer each question aloud before opening the answer. The model answers name the points to cover, so practise saying them in your own words, and try to write a small program for the trickier ones.

What is the output of printf("%d", -7 / 2);, and why?

It prints -3. Integer division in C truncates toward zero, so the fraction -3.5 is dropped in the direction of zero.

Why does a function that swaps two int parameters leave the caller unchanged?

C passes arguments by value, so the function works on copies. To change the caller's variables, pass their addresses and write through the pointers.

What is the difference between const int *p and int *const p?

The first is a pointer to a constant int: the int cannot be changed through p, but p can point elsewhere. The second is a constant pointer to an int: p must keep its address, but the int it points to can change.

What is a dangling pointer? Give one way to create one.

A dangling pointer holds the address of memory that has been freed or has gone out of scope. Returning the address of a local variable from a function, or using a pointer after free, creates one. Using it is undefined behaviour.

What is the difference between malloc and calloc?

malloc takes one size argument and leaves the memory uninitialised. calloc takes a count and an element size, and zeroes the memory. Both return NULL on failure.

What does volatile mean, and what does it not guarantee?

volatile tells the compiler the value may change outside the visible program flow, so each read must load from memory. It does not make operations atomic, and it does not provide thread synchronisation.

Where does a local variable without a storage class keyword live, and how long does it last?

It is an automatic variable. It lives on the stack, is created when its block is entered, and is destroyed when the block ends. Its initial value is indeterminate unless you initialise it.

What is the difference between strlen and sizeof on a char array?

sizeof is the compile-time size of the array in bytes, including the terminator. strlen scans at runtime for the terminator and returns the number of characters before it.

What is a memory leak, and how do you prevent one?

A leak is memory that was allocated and can no longer be reached, so it is never freed. Prevent it by pairing every allocation with a free on every exit path, including error paths, and by checking tools such as valgrind.

Why does the declaration of a function pointer need parentheses around the star?

In int (*fp)(int, int), the parentheses make fp a pointer to a function. Without them, int *fp(int, int) declares a function named fp that returns an int pointer.

DSA: Hashing

A hash table stores keys and values so that lookup, insertion and deletion take O(1) time on average. A hash function turns each key into a number, the hash, and the number chooses a slot. Python's dict and set are hash tables, and most hashing problems are solved by choosing what to store as the key and what to store as the value.

The three patterns in this lesson are: remember what you have seen (a set), count occurrences (a dict of counts), and record a running value so that a range becomes a difference (a prefix sum stored in a dict). The fourth problem, which is hard, uses the same idea with a normalised slope as the key.

  • Seen before? A set answers "have I seen this value" in O(1). Use it to detect duplicates in one pass.
  • How often? A dict or Counter maps each value to its count, which makes frequency questions simple.
  • How many earlier prefixes match? Store each prefix sum with its count, so that a subarray ending here with sum k corresponds to an earlier prefix equal to current minus k.
  • Group by a canonical key. Pick a key that two things share exactly when they belong together, then count or group by that key.

Contains Duplicate (LeetCode 217)

Given an integer array nums, return True if any value appears at least twice in the array, and False if every element is distinct. For [1, 2, 3, 1], the answer is True.

How to think about it

  1. Understand. We only need a yes or no. The array can be unsorted, and negative numbers are allowed. An empty array has no duplicates.
  2. Brute force. Compare every pair of elements. With n elements that is about n squared over two comparisons, so O(n squared) time and O(1) space.
  3. Find the waste. Each comparison asks whether this value has appeared before. The brute force answers that by scanning the whole array again each time.
  4. Optimise. Walk the array once and keep a set of the values seen so far. The first value already in the set is a duplicate, so return True immediately. Each membership test is O(1) on average, so the whole job is O(n).

def contains_duplicate(nums):
    seen = set()
    for x in nums:
        if x in seen:              # this value has appeared before
            return True
        seen.add(x)
    return False

Subarray Sum Equals K (LeetCode 560)

Given an array of integers nums and an integer k, return the number of contiguous subarrays whose elements sum to k. The array may contain negative numbers. For [1, 1, 1] and k = 2, the answer is 2, from the subarrays at positions 0 to 1 and 1 to 2.

How to think about it

  1. Understand. A subarray is contiguous, so we count windows, not arbitrary subsets. Negative numbers rule out the simple sliding window that works for positive numbers, because a longer window can have a smaller sum.
  2. Brute force. Try every start and every end, and add up each subarray. That is O(n squared) pairs, and summing each one adds another factor of n, so O(n cubed) in the simplest form. A running sum for each start gives O(n squared).
  3. Find the waste. The sum of the subarray from i to j is the prefix sum at j minus the prefix sum at i-1. So the question becomes: how many earlier prefix sums equal the current prefix sum minus k?
  4. Optimise. Walk the array while keeping a running prefix sum. Keep a dict that counts how many times each earlier prefix sum has occurred, starting with the empty prefix 0 counted once. At each position, add the count of prefix - k to the answer, then record the current prefix. Each step is O(1) on average, so the total is O(n).
  5. Dry run. The table follows [1, 1, 1] with k = 2. The prefix sums are 1, 2 and 3.
xprefix after xlook up prefix - kmatches foundanswer so farseen after the step
111 - 2 = -100{0: 1, 1: 1}
122 - 2 = 01 (the empty prefix)1{0: 1, 1: 1, 2: 1}
133 - 2 = 11 (prefix 1 at the start)2{0: 1, 1: 1, 2: 1, 3: 1}

Code

def subarray_sum(nums, k):
    count = 0
    prefix = 0
    seen = {0: 1}                          # the empty prefix sum 0 occurs once
    for x in nums:
        prefix += x
        count += seen.get(prefix - k, 0)   # earlier prefixes that leave exactly k
        seen[prefix] = seen.get(prefix, 0) + 1
    return count

print(subarray_sum([1, 1, 1], 2))
print(subarray_sum([1, 2, 3], 3))
print(subarray_sum([1, -1, 0], 0))

The third test shows why the approach works with negative numbers. The subarrays with sum 0 are [1, -1], [0], and [1, -1, 0]. The prefix sums are 0, 1, 0, 0, and the dict holds the earlier 0 values, which gives the three matches.

Time O(n) · Space O(n) for the dict

TrapDo not use a sliding window here when the array can contain negative numbers. Growing the window can lower the sum, so shrinking rules break. The prefix sum with a dict handles any sign.

Pattern to rememberFor counting subarrays with a target sum, combine running prefix sums with a dict of how often each prefix has appeared.

Top K Frequent Elements (LeetCode 347)

Given an integer array nums and an integer k, return the k most frequent elements. The answer may be in any order, and the problem guarantees a unique answer. For [1, 1, 1, 2, 2, 3] and k = 2, the answer is [1, 2].

How to think about it

  1. Understand. Count each value, then pick the k highest counts. Values with the same count are a tie, but the problem guarantees that the top k can be chosen unambiguously.
  2. Brute force. For each distinct value, count its occurrences by scanning the array, then sort the values by count. Counting costs O(n) per value, so the total is O(n squared) with a sort on top.
  3. Find the waste. Counting by scanning repeats work that a single dict can record in one pass. Sorting all values by count is also more than we need, because we only want the top k.
  4. Optimise. Count everything in one pass with a Counter. Then use bucket sort: a count can be at most n, so make n + 1 buckets, put each value into the bucket for its count, and read the buckets from the highest count down until k values are collected. This is O(n).
  5. Dry run. The table follows [1, 1, 1, 2, 2, 3]. The counts are 1 to 3, 2 to 2 and 3 to 1, so bucket 3 holds 1, bucket 2 holds 2 and bucket 1 holds 3.
Bucket (count)Values in the bucketCollected after reading this bucket
3[1][1]
2[2][1, 2], which has k = 2 values, so stop
1[3]not reached

Code

from collections import Counter

def top_k_frequent(nums, k):
    counts = Counter(nums)
    buckets = [[] for _ in range(len(nums) + 1)]   # bucket i holds the values seen i times
    for value, c in counts.items():
        buckets[c].append(value)
    result = []
    for c in range(len(buckets) - 1, 0, -1):       # read from the highest count down
        for value in buckets[c]:
            result.append(value)
            if len(result) == k:
                return result
    return result

print(top_k_frequent([1, 1, 1, 2, 2, 3], 2))
print(top_k_frequent([1], 1))
print(top_k_frequent([4, 4, 4, 5, 5, 6, 6, 6, 6], 2))
[1, 2]
[1]
[6, 4]

The third test shows the bucket order at work. Value 6 appears four times, so it sits in the highest bucket and comes out first. Value 4 appears three times and comes next. The buckets are read from index len(nums) down to 1, so the highest possible count is checked first.

Time O(n) · Space O(n)

TipIn an interview, first offer the heap approach, which is O(n log k) with heapq.nlargest(k, counts, key=counts.get). Then improve it to bucket sort when the interviewer asks for O(n).

Pattern to rememberWhen counts are bounded by n, bucket sort by count gives the top k in linear time.

Max Points on a Line (LeetCode 149)

Given an array points, where each element [x, y] is a point on the plane, return the largest number of points that lie on one straight line. For [[1, 1], [2, 2], [3, 3]], the answer is 3, because all three points are on the line y = x. For [[1, 1], [3, 2], [5, 3], [4, 1], [2, 3], [1, 4]], the answer is 4, from the points (3, 2), (4, 1), (2, 3) and (1, 4), which all lie on x + y = 5.

How to think about it

  1. Understand. Any two distinct points define exactly one line, so an answer of at least 2 exists when there are two or more points. Points can repeat, and a repeated point lies on every line through its twin. The coordinates can be negative, and a vertical line has no slope in the usual sense.
  2. Brute force. Take every pair of points to define a line. For each line, test every other point with a cross product: three points are collinear when the cross product of the two difference vectors is zero. That is O(n cubed) work. The code below assumes the points are distinct, because a repeated pair would define a degenerate line that every point lies on.
  3. Find the waste. Many pairs define the same line, and each one retests all the points. A better plan is to fix one point, called the anchor, and find all the lines through it at once.
  4. Optimise. For each anchor, compare it with every later point and compute the direction from the anchor. Two points lie on the same line through the anchor exactly when they have the same direction. Store the direction in a dict as a key, so every point on the same line shares one key. Use the difference (dx, dy) divided by its gcd, with a fixed sign, so that equal directions give equal keys without floating-point error. Points that equal the anchor are counted separately, because they fit on every line. The answer is the best direction count plus the duplicates plus the anchor. This is O(n squared) with a dict per anchor.
  5. Dry run. The table follows the anchor (3, 2) in the second example. Each other point gives one direction key, and the points that share a key lie on one line through the anchor.

The best count for this anchor is 3, so the line through (3, 2), (4, 1), (2, 3) and (1, 4) contains 3 other points plus the anchor, giving 4.

Code

The brute force version comes first. It is simple to check and useful to describe in an interview. It assumes distinct points, which the examples below satisfy.

def max_points_brute(points):
    n = len(points)
    if n < 3:
        return n
    best = 2                               # any two distinct points lie on a line
    for i in range(n):
        for j in range(i + 1, n):
            (x1, y1), (x2, y2) = points[i], points[j]
            count = 0
            for x, y in points:
                # collinear when the cross product of (p2 - p1) and (p - p1) is zero
                if (x2 - x1) * (y - y1) == (y2 - y1) * (x - x1):
                    count += 1
            best = max(best, count)
    return best

print(max_points_brute([[1, 1], [2, 2], [3, 3]]))
print(max_points_brute([[1, 1], [3, 2], [5, 3], [4, 1], [2, 3], [1, 4]]))

Now the optimised version. It handles repeated points and uses integer directions, so no floating-point numbers are involved.

from collections import defaultdict
from math import gcd

def max_points(points):
    n = len(points)
    if n < 3:
        return n
    best = 0
    for i in range(n):                     # each point takes a turn as the anchor
        slopes = defaultdict(int)
        duplicates = 0
        most_on_one_line = 0
        x1, y1 = points[i]
        for j in range(i + 1, n):
            x2, y2 = points[j]
            dx, dy = x2 - x1, y2 - y1
            if dx == 0 and dy == 0:        # the same point as the anchor
                duplicates += 1
                continue
            g = gcd(abs(dx), abs(dy))      # reduce the direction to its simplest form
            dx //= g
            dy //= g
            if dx < 0 or (dx == 0 and dy < 0):   # fix the sign so opposite directions match
                dx, dy = -dx, -dy
            slopes[(dx, dy)] += 1
            most_on_one_line = max(most_on_one_line, slopes[(dx, dy)])
        best = max(best, most_on_one_line + duplicates + 1)
    return best

print(max_points([[1, 1], [2, 2], [3, 3]]))
print(max_points([[1, 1], [3, 2], [5, 3], [4, 1], [2, 3], [1, 4]]))
print(max_points([[1, 1], [1, 1], [2, 2]]))
3
4
3

The third test has a repeated point. The anchor (1, 1) finds the duplicate (1, 1), which is counted separately, and the point (2, 2) on one direction. The total is 1 + 1 + 1 = 3. Without the separate duplicate count, the answer would be wrong, because a repeated point would then be treated as a direction of zero length.

Time O(n squared) with a dict per anchor · Space O(n)

TrapUsing floating-point slopes such as dy / dx risks precision errors, and division by zero for vertical lines. Reduce the direction with gcd and fix its sign, so the key is exact.

TrapForgetting that repeated points lie on every line through the anchor. Count them separately and add them at the end.

Pattern to rememberTo group points by the line they share with an anchor, use a dict keyed by the reduced, sign-normalised direction. Equal keys mean collinear.
