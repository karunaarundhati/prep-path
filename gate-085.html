Stack & queue (recap)

A stack and a queue are two simple ways to line up data, and each one follows one fixed rule for who leaves first. This quick recap covers the stack (last in, first out), the queue (first in, first out), the circular queue, and the common uses that GATE questions test.

The idea in plain words

Picture two ways of waiting. In the first, you pile plates on a table. You put each new plate on the top, and you take the top plate when you need one. The plate you put on last is the first one you take off. That is a stack.

In the second, people wait at a bus stop. The person who arrived first gets on the bus first. New people join at the back, and people leave from the front. That is a queue.

The real difference is which end is used for leaving. A stack has one open end, so it is last in, first out. A queue has two ends, one for joining and one for leaving, so it is first in, first out.

Why this matters for GATE: stacks and queues appear in questions about evaluating expressions, checking brackets, function calls, breadth first search, and scheduling. Many questions show a sequence of operations and ask for the final contents, so be precise about the order.

Key terms

Stack
A list where items are added and removed at one end, called the top. Precisely: a last in, first out (LIFO) structure.
push
Add an item to the top of a stack.
pop
Remove and return the item at the top of a stack.
top (peek)
Look at the item on the top without removing it.
Queue
A list where items join at the rear and leave from the front. Precisely: a first in, first out (FIFO) structure.
enqueue
Add an item at the rear of a queue.
dequeue
Remove and return the item at the front of a queue.
Overflow
Trying to add to a full, fixed-size structure.
Underflow
Trying to remove from an empty structure.
Circular queue
A fixed-size queue whose ends wrap around to the start of the array, so space freed at the front can be reused.
Postfix expression
An arithmetic expression where each operator comes after its two operands, such as 3 4 + for 3 + 4.

The stack and LIFO

A stack supports three basic operations: push, pop and top. Start with an empty stack and follow each step:

  1. Push 10. The stack is 10, with 10 on top.
  2. Push 20. The stack is 10, 20, with 20 on top.
  3. Push 30. The stack is 10, 20, 30, with 30 on top.
  4. Pop. The item 30 is removed and returned. The stack is 10, 20.

In Python, a plain list works as a stack if you use append to push and pop() with no argument to pop from the end. The end of the list is the top. The code below runs these steps.

stack = []
stack.append(10)
stack.append(20)
stack.append(30)
print("top:", stack[-1])
print("pop:", stack.pop())
print("stack now:", stack)
top: 30
pop: 30
stack now: [10, 20]

The top is read with stack[-1], which means the last item. Reading the top does not remove anything.

TrapA pop from an empty stack is underflow. In Python it raises an error. In a GATE question it usually means the sequence of operations is wrong, so check the order first.

After push 1, push 2, pop, push 3, what is on top?

3. The pop removed 2, leaving 1 at the bottom. Then 3 was pushed on top of 1.

Why is the stack called last in, first out?

Because the item pushed last is the first one popped. The top is the only item that can be removed.

Applications of stacks

Stacks appear whenever you need to return to the most recent unfinished thing. Three common uses matter for GATE.

Evaluating postfix expressions

Ordinary (infix) arithmetic such as 3 + 4 × 2 needs brackets and rules of precedence. A postfix expression, such as 3 4 + 2 ×, needs neither. Read the tokens from left to right. Push each number. When you meet an operator, pop two numbers, apply the operator, and push the result.

Take the postfix expression 5 6 2 + * 12 4 / -. Push 5, push 6, push 2. The + pops 2 and 6, and pushes 8. The * pops 8 and 5, and pushes 40. Push 12, push 4. The / pops 4 and 12, and pushes 3. The - pops 3 and 40, and pushes 37. The answer is 37.

def eval_postfix(tokens):
    stack = []
    for t in tokens:
        if t in "+-*/":
            b = stack.pop()
            a = stack.pop()
            if t == "+":
                stack.append(a + b)
            elif t == "-":
                stack.append(a - b)
            elif t == "*":
                stack.append(a * b)
            else:
                stack.append(a // b)
        else:
            stack.append(int(t))
    return stack.pop()

print(eval_postfix("5 6 2 + * 12 4 / -".split()))
print(eval_postfix("3 4 + 2 *".split()))
37
14

TipThe first popped value is the right operand. For subtraction, the answer is the second popped value minus the first popped value. Getting this order wrong is the most common mistake.

Checking balanced brackets

Brackets are balanced when every opening bracket has a matching closing bracket, in the right nesting order. Push each opening bracket. When you meet a closing bracket, pop the top. If the popped bracket does not match, the text is not balanced. At the end, the stack must be empty.

def balanced(text):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in text:
        if ch in "([{":
            stack.append(ch)
        elif ch in ")]}":
            if not stack or stack.pop() != pairs[ch]:
                return False
    return len(stack) == 0

for s in ["(a[b]{c})", "(a]", "((())"]:
    print(s, balanced(s))
(a[b]{c}) True
(a] False
((()) False

The first text is balanced. The second fails because the closing ] meets an opening (. The third has three openings and only two closings, so one bracket is left on the stack at the end.

Evaluate the postfix expression 2 3 4 * +.

14. Push 2, 3, 4. The * pops 4 and 3 and pushes 12. The + pops 12 and 2 and pushes 14.

Why does a balanced-bracket check need a stack and not just a counter?

A counter cannot tell whether the brackets are nested in the right order. For example, "(]" has equal counts of opening and closing brackets but is not balanced. The stack remembers which opening bracket is the most recent one.

The queue and FIFO

A queue has two ends. Items join at the rear through enqueue, and leave from the front through dequeue. The first item to join is the first to leave, so a queue is first in, first out.

Here is a worked example. Enqueue a, then b, then c. The front is a and the rear is c. Dequeue returns a, and the queue is now b, c. Enqueue d, and the queue is b, c, d.

In Python, use collections.deque. Its append adds at the rear and its popleft removes from the front. A plain list also works, but pop(0) is slow for long lists because every other item must shift.

from collections import deque
q = deque()
q.append("a")
q.append("b")
q.append("c")
print("front:", q[0])
print("dequeue:", q.popleft())
print("queue now:", list(q))
front: a
dequeue: a
queue now: ['b', 'c']

Queues are used when items must be served in arrival order. Breadth first search from the graph recap uses a queue for exactly this reason. Printer jobs and call centre waiting lines also work this way.

TrapStudents often mix up the two ends. In a queue, the new item goes to the rear, and the removed item comes from the front. In a stack, both actions use the top.

Enqueue 1, enqueue 2, dequeue, enqueue 3. Which item is at the front?

2. The dequeue removed 1. Then 2 is at the front, and 3 joined at the rear.

Which structure is used by breadth first search?

A queue, because vertices must be handled in the order they were found.

Circular queue

A simple queue built in a fixed array has a problem. After many dequeues, the front moves toward the end of the array, and the space at the start is wasted. A circular queue fixes this. When an index passes the last slot, it wraps back to slot 0. We use the remainder operator % to do this, because (index + 1) % size goes from size minus 1 back to 0.

The code below keeps a front index and a count of items. The rear position is worked out as (front + count) % size.

class CircularQueue:
    def __init__(self, size):
        self.size = size
        self.items = [None] * size
        self.front = 0
        self.count = 0

    def enqueue(self, x):
        if self.count == self.size:
            return False
        rear = (self.front + self.count) % self.size
        self.items[rear] = x
        self.count = self.count + 1
        return True

    def dequeue(self):
        if self.count == 0:
            return None
        x = self.items[self.front]
        self.front = (self.front + 1) % self.size
        self.count = self.count - 1
        return x

q = CircularQueue(3)
print(q.enqueue(1), q.enqueue(2), q.enqueue(3), q.enqueue(4))
print(q.dequeue())
print(q.enqueue(5))
print(q.items)
True True True False
1
True
[5, 2, 3]

The fourth enqueue fails, because the array of size 3 is full. Then one dequeue frees slot 0. The new item 5 is placed in slot 0, because the rear wraps around. The array now reads 5, 2, 3, and the front points to slot 1, which holds 2.

Key ideaA circular queue of size n holds at most n items. Every slot can be reused once it has been dequeued.

In a circular queue of size 3 with front at slot 2 and count 2, where does the next enqueue go?

Slot 1, because (2 + 2) % 3 = 1. The rear wraps around past the end of the array.

What does the % operator do in the rear formula?

It gives the remainder after dividing by the size, so the index always stays between 0 and size minus 1.

Comparing the two

Both structures are often built on an array or a linked list, and both can be implemented in O(1) time per push, pop, enqueue and dequeue when the structure is designed well. The difference lies in the order of removal, and this decides which problem each one solves.

FeatureStackQueue
Order of removalLast in, first outFirst in, first out
Where items are addedTopRear
Where items are removedTopFront
Typical useUndo, function calls, postfix evaluation, bracket checksScheduling, breadth first search, buffers
Fixed-size array problemFull when top reaches the endWasted space unless made circular

GATE loves thisWhen a question describes "the most recent" item or a "reverse order", think stack. When it describes "the earliest" or "order of arrival", think queue.

Which structure would reverse the order of the letters A, B, C?

A stack. Pushing A, B, C and popping gives C, B, A.

Solved GATE-style problems

Final stack contents

An empty stack receives these operations in order: push 1, push 2, push 3, pop, push 4. Which item is on the top at the end?

How to think about it

  1. What is asked. The top item after all operations.
  2. Which idea applies. Push adds to the top, and pop removes the top.
  3. Work it out. After the three pushes the stack is 1, 2, 3. The pop removes 3, leaving 1, 2. Then 4 is pushed, so the stack is 1, 2, 4 with 4 on top.
  4. Check. Run the code below.
stack = []
stack.append(1)
stack.append(2)
stack.append(3)
stack.pop()
stack.append(4)
print(stack)
[1, 2, 4]

Answer: 4.

Front of a queue

An empty queue receives these operations in order: enqueue a, enqueue b, enqueue c, dequeue, enqueue d. What is the content of the queue from front to rear?

How to think about it

  1. What is asked. The items in order from the front.
  2. Which idea applies. Enqueue adds at the rear and dequeue removes from the front.
  3. Work it out. After three enqueues the queue is a, b, c. The dequeue removes a, leaving b, c. Then d joins at the rear, giving b, c, d.
  4. Check. Run the code below.
from collections import deque
q = deque(["a", "b", "c"])
q.popleft()
q.append("d")
print(list(q))
['b', 'c', 'd']

Answer: b, c, d.

Value of a postfix expression

Evaluate the postfix expression 7 2 3 * - using a stack. What is the value? This is a NAT question.

How to think about it

  1. What is asked. The numerical value of the expression.
  2. Which idea applies. Push numbers. When an operator comes, pop two numbers and push the result.
  3. Work it out. Push 7, push 2, push 3. The * pops 3 and 2 and pushes 6. The - pops 6 and 7. The right operand is the first popped value, so the calculation is 7 - 6 = 1.
  4. Check. Run the code below.
print(7 - 2 * 3)
1

Answer: 1.

Is the bracket string balanced?

Using the stack method for brackets, is the string {[()]} balanced? Give True or False.

How to think about it

  1. What is asked. Whether every bracket is matched in nesting order.
  2. Which idea applies. Push openings. Each closing must match the top.
  3. Work it out. Push {, then [, then (. The ) matches the top (, so pop it. The ] matches the top [, so pop it. The } matches the top {, so pop it. The stack is empty at the end, so the string is balanced.
  4. Check. Run the code below.
def balanced(text):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in text:
        if ch in "([{":
            stack.append(ch)
        elif ch in ")]}":
            if not stack or stack.pop() != pairs[ch]:
                return False
    return len(stack) == 0

print(balanced("{[()]}"))
True

Answer: True.

Overflow count in a circular queue

A circular queue has size 4 and starts empty. The operations are, in order: enqueue, enqueue, enqueue, enqueue, dequeue, dequeue, enqueue, enqueue, enqueue, enqueue. Each enqueue adds the next number from 1 onward, so the enqueues are the values 1, 2, 3, 4, 5, 6, 7, 8 in order. How many enqueue operations fail because the queue is full? This is a NAT question.

How to think about it

  1. What is asked. The number of failed enqueues.
  2. Which idea applies. A full circular queue of size 4 holds 4 items. A dequeue frees one slot.
  3. Work it out. The first four enqueues (1 to 4) fill the queue. Two dequeues remove 1 and 2, leaving 3 and 4, so there are 2 free slots. Enqueue 5 and enqueue 6 succeed and fill the queue. Enqueue 7 fails, and enqueue 8 also fails. That is 2 failures.
  4. Check. Run the code below, which uses the circular queue class from this page.
class CircularQueue:
    def __init__(self, size):
        self.size = size
        self.items = [None] * size
        self.front = 0
        self.count = 0

    def enqueue(self, x):
        if self.count == self.size:
            return False
        rear = (self.front + self.count) % self.size
        self.items[rear] = x
        self.count = self.count + 1
        return True

    def dequeue(self):
        if self.count == 0:
            return None
        x = self.items[self.front]
        self.front = (self.front + 1) % self.size
        self.count = self.count - 1
        return x

q = CircularQueue(4)
fails = 0
ops = ["E1", "E2", "E3", "E4", "D", "D", "E5", "E6", "E7", "E8"]
for op in ops:
    if op == "D":
        q.dequeue()
    else:
        ok = q.enqueue(op)
        if not ok:
            fails = fails + 1
print(fails)
2

Answer: 2.

Select all that apply.

  • (A) Using pop(0) on a Python list to dequeue is slow for long lists, because the other items must shift.
  • (B) A circular queue reuses slots freed at the front.
  • (C) A circular queue built with only front and rear indices, where empty means front equals rear, holds at most n minus 1 items in an array of size n.
  • (D) Push and pop on a stack implemented with an array always take O(n) time.

How to think about it

  1. What is asked. Which statements are true.
  2. Which idea applies. The cost of shifting, the reuse of slots, and the full and empty tests.
  3. Work it out. (A) True. Removing index 0 moves every other item one place. (B) True, that is the purpose of the wrap. (C) True. If front equals rear means empty, the array can never be completely full, so one slot is always left unused. (D) False. Push and pop at the top of an array-based stack take O(1) time.
  4. Check. The reasoning above is enough. No code is needed.

Exam-level practice

Exam-level 1: Circular queue size (NAT, 2 marks)

A circular queue uses an array of size 8, with front = 6 and rear = 2, where rear points to the next free slot. How many elements are in it?

How to think about it

  1. What is asked. The current count.
  2. Which idea applies. count = (rear − front + size) mod size.
  3. Work it out. (2 − 6 + 8) mod 8 = 4.
  4. Check. Occupied slots are 6, 7, 0, 1.

Answer: 4.

Exam-level 2: Balanced brackets (MCQ, 2 marks)

Which string is balanced? (A) ([)] (B) {[()()]} (C) ((()) (D) )(

How to think about it

  1. What is asked. The one a stack accepts.
  2. Which idea applies. Push openers, and each closer must match the top.
  3. Work it out. Only (B) matches at every step and ends empty.
  4. Check. The code checks each.
def ok(s):
    st = []; pair = {')': '(', ']': '[', '}': '{'}
    for c in s:
        if c in "([{": st.append(c)
        elif not st or st.pop() != pair[c]: return False
    return not st
for s in ("([)]", "{[()()]}", "((())", ")("): print(s, ok(s))

([)] False
{[()()]} True
((()) False
)( False

Answer: (B).

Exam-level 3: Max stack depth (NAT, 2 marks)

Converting the infix expression a + b * (c − d) / e − f to postfix with the usual stack algorithm, what is the maximum number of symbols on the operator stack at any time (counting parentheses)?

How to think about it

  1. What is asked. The peak operator stack size.
  2. Which idea applies. The stack holds pending operators of lower precedence and open brackets.
  3. Work it out. After reading a, +, b, *, (, c, −: the stack holds + * ( − which is 4.
  4. Check. Then ) pops − and (, and later operators pop the rest.

Answer: 4.

Summary

Stack
A last in, first out structure with one open end, the top.
push
Add an item to the top of a stack.
pop
Remove the top item of a stack.
Queue
A first in, first out structure with a rear for joining and a front for leaving.
enqueue
Add an item at the rear of a queue.
dequeue
Remove the front item of a queue.
Underflow
Removing from an empty structure.
Overflow
Adding to a full fixed-size structure.
Circular queue
A fixed-size queue whose indices wrap around with the % operator.
Postfix expression
An expression with operators after their operands, evaluated with a stack.
Bracket check
Push openings, pop on closings, and require an empty stack at the end.
Breadth first search
Uses a queue, so vertices are handled in the order found.

Remember these

  • A stack is last in, first out. A queue is first in, first out.
  • Postfix expressions are evaluated left to right with one stack.
  • When popping two values for an operator, the first popped is the right operand.
  • A circular queue uses (front + count) % size for the rear position.
  • A full circular queue of size n has exactly n items and rejects the next enqueue.
  • Trace every operation in order, and write the contents after each step.
