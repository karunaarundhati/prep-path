JDK, JRE, JVM and JVM memory

Java programs do not run directly on the hardware. The Java compiler, javac, turns source files into bytecode, a compact instruction set stored in .class files. Bytecode runs on the Java Virtual Machine (JVM), a program that loads classes, checks them, runs them, and manages memory. The same bytecode runs on any operating system that has a JVM, which is the origin of the phrase "write once, run anywhere".

Three names appear constantly, and they nest like boxes. The JVM executes bytecode. The JRE (Java Runtime Environment) is the JVM plus the standard libraries needed to run programs. The JDK (Java Development Kit) is the JRE plus development tools, such as javac, the debugger and the documentation generator. If you install the JDK, you have everything. Modern releases ship only the JDK, because the separate JRE download was dropped.

Key ideaJDK contains JRE, JRE contains JVM. Write code with the JDK, run it on the JVM.

How the JVM uses memory

Interviewers often ask where objects live. The JVM divides its memory into areas. Each thread has its own stack, which holds method call frames and local variables of primitive types, plus references to objects. All objects live in the shared heap, which the garbage collector cleans up when objects are no longer reachable. The method area (called Metaspace in modern HotSpot JVMs) holds class metadata, such as the structure of each class and its static fields. String literals live in a special part of the heap called the string pool, covered in the next section.

A small example shows how the parts cooperate. When main calls makeGreeting, a new frame goes on the current thread's stack. The local variable name holds a reference, which is the address of a String object on the heap. When makeGreeting returns, its frame is removed, and the String object becomes garbage once nothing else refers to it.

TrapJava has no stack-allocated objects. A variable of a class type is a reference, and the object it names always lives on the heap. Passing an object to a method passes a copy of the reference, not a copy of the object.

What is the difference between the JDK, the JRE and the JVM?

The JVM runs bytecode. The JRE is the JVM plus the standard libraries needed to run a program. The JDK is the JRE plus the development tools, such as the compiler javac. A developer installs the JDK, and a machine that only runs programs needs the JRE, or in modern releases the JVM and libraries.

String immutability, the string pool and StringBuilder

A String in Java is immutable: once created, its characters never change. Methods such as toUpperCase do not change the string they are called on. They return a new string. Immutability makes strings safe to share between threads and safe to use as keys in a hash map, because their value cannot change under you.

Because many strings are the same text, the JVM keeps a string pool. When your code writes a literal such as "hello", the JVM reuses one pooled object for every occurrence of that literal. A string created with new String("hello") is a separate object on the heap, even though its text is the same. The == operator compares object identity, which is the question "are these the same object?", so the two cases behave differently.

public class Strings {
    public static void main(String[] args) {
        String a = "hello";
        String b = "hello";                 // the same pooled object as a
        String c = new String("hello");     // a new object on the heap
        System.out.println(a == b);
        System.out.println(a == c);
        System.out.println(a.equals(c));    // equals compares the text
        System.out.println(a == c.intern()); // intern returns the pooled instance

        String s = "java";
        s.toUpperCase();                    // returns a new string, s is unchanged
        System.out.println(s);
        s = s.toUpperCase();                // assign the new string to s
        System.out.println(s);

        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < 3; i++) {
            sb.append(i).append(',');
        }
        sb.setLength(sb.length() - 1);      // remove the trailing comma
        System.out.println(sb);
        System.out.println(sb.reverse());   // reverse changes sb in place
    }
}

Read the output with two rules in mind. For a == b, both names refer to the same pooled object, so the answer is true. For a == c, the names refer to different objects, so the answer is false, even though the text matches. equals asks the question people usually mean, "same text?", and returns true. intern looks the text up in the pool and returns the pooled instance, which is why the last comparison is true.

The toUpperCase lines show immutability. Calling it on s and ignoring the result leaves s as "java". Only assigning the result changes what s refers to. Forgetting this is a common beginner mistake.

Building a string in a loop with + creates a new string each time, so it costs time proportional to the total length on every step. StringBuilder is a mutable buffer. Its append adds to the existing buffer, and toString makes a final string at the end. The example uses setLength to drop the last comma, and reverse to flip the characters in place.

TrapNever compare strings with == to check their text. Strings from user input, from new String or from concatenation at run time are usually different objects. Use equals.

TipUse StringBuilder when you combine strings inside a loop. A single + outside a loop is fine, and the compiler optimizes simple cases.

Why does a == c print false when both hold the text hello?

The literal "hello" is one pooled object, and a is a reference to it. new String("hello") creates a new object on the heap. The == operator compares references, so the two references differ. equals compares the characters, so it returns true.

equals, hashCode and the == operator

In Java, == compares references for objects and values for primitives. The equals method is what a class uses to define when two different objects count as the same value. The class Object provides a default equals that behaves like ==, so a class that wants value equality must override it.

hashCode returns an int summary of an object's value. Hash-based collections such as HashSet and HashMap use it to decide which bucket to search. The two methods must agree through a rule called the equals and hashCode contract: if a.equals(b) is true, then a.hashCode() must equal b.hashCode(). Equal objects must produce equal hashes. The reverse is not required, because two unequal objects may share a hash.

import java.util.HashSet;
import java.util.Objects;
import java.util.Set;

class Point {
    private final int x;
    private final int y;

    Point(int x, int y) {
        this.x = x;
        this.y = y;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Point)) return false;
        Point p = (Point) o;
        return x == p.x && y == p.y;
    }

    @Override
    public int hashCode() {
        return Objects.hash(x, y);
    }

    @Override
    public String toString() {
        return "(" + x + ", " + y + ")";
    }
}

public class EqualsDemo {
    public static void main(String[] args) {
        Point a = new Point(1, 2);
        Point b = new Point(1, 2);
        System.out.println(a == b);
        System.out.println(a.equals(b));
        System.out.println(a.hashCode());
        System.out.println(a.hashCode() == b.hashCode());

        Set<Point> set = new HashSet<>();
        set.add(a);
        System.out.println(set.contains(b));
        System.out.println(set.add(b));
        System.out.println(set.size());
    }
}

Walk through the output. a == b is false because they are two objects. a.equals(b) is true because the coordinates match. hashCode is 994 here. Objects.hash(1, 2) computes a hash from the array of values with the formula 31 times (31 plus the hash of the first value) plus the hash of the second value, which is 31 times 32 plus 2, or 994. You do not need to memorize the formula, but knowing that equal inputs give equal hashes is essential.

The HashSet check shows why both methods matter. set.contains(b) is true because b has the same hash as a and equals a. set.add(b) returns false, because the set already holds an equal element, and so the size stays 1.

TrapOverriding equals without hashCode breaks hash collections. Two equal objects then land in different buckets, and contains returns false even though an equal object is stored. Always override both together.

Interviewers askWhy must equal objects have equal hash codes? Answer: hash collections find an object by first looking in the bucket for its hash, so an equal object with a different hash would be looked for in the wrong place.

If two objects are not equal, must their hash codes differ?

No. Unequal objects may share a hash code, which is called a collision. Hash collections handle collisions by comparing with equals inside the bucket. The contract only requires that equal objects share a hash.

Interfaces versus abstract classes

Java has two ways to declare a shared contract. An interface lists methods that a class promises to provide, and a class can implement any number of interfaces. An abstract class can hold fields and constructors and can provide code, but a class can extend only one of them. Since Java 8, an interface may also contain default methods with a body, and static methods. Interfaces still hold no instance state, because their fields are always public, static and final constants.

Use an interface to describe a capability that unrelated classes can share, such as "can be drawn" or "can be compared". Use an abstract class when several related classes share state and common code, such as a shape with a name field and a shared toString. The program below uses both. The interface Drawable is a capability, and the abstract class Shape is the shared base of a family.

interface Drawable {
    String draw();                          // abstract by default

    default String describe() {             // default method, Java 8 and later
        return "I am drawable: " + draw();
    }
}

abstract class Shape implements Drawable {
    protected final String name;            // shared state

    Shape(String name) {
        this.name = name;
    }

    abstract double area();                 // each subclass must provide this

    @Override
    public String draw() {
        return "shape " + name;
    }

    @Override
    public String toString() {
        return name + " area=" + area();
    }
}

class Circle extends Shape {
    private final double r;

    Circle(double r) {
        super("circle");
        this.r = r;
    }

    @Override
    double area() {
        return Math.PI * r * r;
    }
}

class Rect extends Shape {
    private final double w;
    private final double h;

    Rect(double w, double h) {
        super("rect");
        this.w = w;
        this.h = h;
    }

    @Override
    double area() {
        return w * h;
    }
}

public class Hierarchy {
    public static void main(String[] args) {
        Shape[] shapes = { new Circle(1), new Rect(3, 4) };
        for (Shape s : shapes) {
            System.out.println(s);
            System.out.println(s.describe());
        }
        Drawable d = shapes[1];             // a Rect is a Shape, and a Shape is a Drawable
        System.out.println(d instanceof Shape);
    }
}

Why can a class implement several interfaces but extend only one class?

Java avoids the ambiguity of multiple inheritance of state and code, the diamond problem. Interfaces carry no instance state, so a class can take many contracts without inheriting conflicting fields. Default methods were added with rules that resolve conflicts between interfaces.

Collections: lists, maps, queues and ordering

The java.util package holds collections, which are containers for groups of objects. Most collections are described by an interface (List, Map, Queue), and you choose a class that implements it. The choice decides speed. Interviewers want you to know the costs, not just the names.

Lists: ArrayList versus LinkedList

ArrayList stores its elements in an array. Reading element i is fast, O(1), because the position is computed directly. Inserting at the end is usually O(1), but inserting in the middle shifts later elements, which is O(n). LinkedList stores each element in a node that points to the next and previous nodes. Adding or removing at either end is O(1), but reading element i means walking the nodes, which is O(n). In practice ArrayList is faster for most work because of memory layout, so use LinkedList only when you add and remove at the ends constantly.

Maps: HashMap, TreeMap and how HashMap works inside

A HashMap stores key and value pairs. Internally it is an array of buckets. To store a key, Java computes its hashCode, spreads the high bits into the low bits to reduce clustering, and uses the result to pick a bucket. If the bucket is empty, the entry goes there. If the bucket already has entries (a collision), the entries are compared with equals and either replaced or added to the bucket's chain. When a bucket reaches eight entries and the table has at least 64 buckets, the chain is converted to a balanced tree, so lookups stay fast in the worst case. The table starts with 16 buckets and doubles when it is more than 75 percent full, which is the default load factor of 0.75.

The result is O(1) average time for get, put and containsKey, assuming a good hash function. The order of entries is not defined, and it can change when the table resizes. Never rely on the iteration order of a HashMap.

TreeMap keeps keys in sorted order, using their natural order or a comparator. Each operation takes O(log n) time, because the map is a balanced tree. Use it when you need the keys in order, or the smallest or largest key quickly. It has methods such as firstKey and headMap that HashMap does not have.

Queues: PriorityQueue

PriorityQueue is a heap. poll always removes the smallest element, by natural order by default, and offer adds an element in O(log n). The iteration order of a priority queue is not sorted, only the head is guaranteed to be the minimum. Repeated poll calls return the elements in sorted order, which is how the example below prints them.

Ordering: Comparable versus Comparator

To sort objects, Java needs a way to compare them. Comparable is an interface a class implements to give its natural order, through one method, compareTo. Comparator is a separate object that compares two values, and you pass it to a sort. A class can have only one natural order, but many comparators, so comparators are the way to sort the same objects in different ways.

import java.util.*;

class Student implements Comparable<Student> {
    final String name;
    final int score;

    Student(String name, int score) {
        this.name = name;
        this.score = score;
    }

    @Override
    public int compareTo(Student other) {
        return Integer.compare(score, other.score);   // natural order: by score
    }

    @Override
    public String toString() {
        return name + ":" + score;
    }
}

public class CollectionsTour {
    public static void main(String[] args) {
        List<Integer> arrayList = new ArrayList<>(List.of(10, 20, 30));
        arrayList.add(1, 15);
        System.out.println(arrayList);

        LinkedList<Integer> linked = new LinkedList<>(List.of(10, 20, 30));
        linked.addFirst(5);
        System.out.println(linked);
        System.out.println(linked.getFirst());

        Map<String, Integer> hash = new HashMap<>();
        hash.put("pear", 3);
        hash.put("apple", 5);
        hash.put("fig", 1);
        TreeMap<String, Integer> sorted = new TreeMap<>(hash);
        System.out.println(sorted);
        System.out.println(sorted.firstKey());
        System.out.println(sorted.headMap("g"));
        System.out.println(hash.get("kiwi"));

        PriorityQueue<Integer> pq = new PriorityQueue<>();
        for (int x : new int[]{5, 1, 4, 2}) {
            pq.offer(x);
        }
        StringBuilder order = new StringBuilder();
        while (!pq.isEmpty()) {
            order.append(pq.poll()).append(' ');
        }
        System.out.println(order.toString().trim());

        List<Student> students = new ArrayList<>(List.of(
                new Student("Ravi", 82), new Student("Mei", 95), new Student("Ola", 70)));
        Collections.sort(students);                      // uses compareTo (Comparable)
        System.out.println(students);
        students.sort(Comparator.comparing((Student s) -> s.name));  // a comparator: by name
        System.out.println(students);
    }
}

TrapA HashMap key must have a good hashCode, and it must not change while it is in the map. If a mutable key changes, its hash no longer matches its bucket, and the entry becomes hard to find.

Interviewers askHow does HashMap find a key? Answer: it computes the key's hash, uses it to pick a bucket, and compares keys with equals inside that bucket. Average O(1), worst case slower when many keys collide.

When would you choose TreeMap over HashMap?

When you need the keys in sorted order, or operations based on order such as the smallest key, the largest key, or a range of keys. The price is O(log n) per operation instead of O(1) on average.

Checked and unchecked exceptions, and generics

An exception is an object that describes an error, and Java's throw statement starts unwinding the call stack until a matching catch handles it. All exceptions extend Throwable. Two families matter for interviews. A checked exception extends Exception but not RuntimeException. The compiler forces the caller to catch it or declare it with throws, because the failure is expected, such as a missing file. An unchecked exception extends RuntimeException, such as NullPointerException or NumberFormatException. It signals a bug or a bad argument, and the compiler does not require handling it.

A finally block runs whether or not an exception happened, which makes it the place for cleanup. It runs even when the try block returns a value, and it runs after the return value is computed but before the method returns to its caller. The example below shows the order.

Generics: one class for many types

Generics let a class or method work with a type chosen by the caller, such as List<String>. The type is checked at compile time, so you avoid casts and the errors they hide. A bounded type parameter, written T extends Comparable<T>, restricts the types allowed, here to types that can be compared with themselves.

Java generics use type erasure. The compiler checks the types, then removes them from the compiled code, so at run time List<String> and List<Integer> are the same class. That is why new ArrayList<String>().getClass() and new ArrayList<Integer>().getClass() return the same object, and it is a common interview question.

import java.io.IOException;
import java.util.ArrayList;
import java.util.List;

class Box<T extends Comparable<T>> {
    private final T value;

    Box(T value) {
        this.value = value;
    }

    T get() {
        return value;
    }

    boolean isBigger(Box<T> other) {
        return value.compareTo(other.value) > 0;
    }
}

public class ErrorsAndGenerics {
    static int parse(String s) {
        try {
            return Integer.parseInt(s);         // throws an unchecked NumberFormatException on bad input
        } catch (NumberFormatException e) {
            return -1;
        } finally {
            System.out.println("parsed " + s);  // runs on every path
        }
    }

    static void readFile() throws IOException {  // a checked exception must be declared
        throw new IOException("disk gone");
    }

    public static void main(String[] args) {
        Box<Integer> a = new Box<>(5);
        Box<Integer> b = new Box<>(3);
        System.out.println(a.isBigger(b));
        System.out.println(parse("42"));
        System.out.println(parse("x"));

        try {
            readFile();
        } catch (IOException e) {
            System.out.println("caught: " + e.getMessage());
        }

        List<String> names = new ArrayList<>();
        List<Integer> numbers = new ArrayList<>();
        System.out.println(names.getClass() == numbers.getClass());   // erasure: same runtime class
    }
}

Key ideaChecked exceptions are for failures a caller can reasonably recover from. Unchecked exceptions usually mean the code has a bug, so fix the code rather than catching them everywhere.

What is the difference between a checked and an unchecked exception?

A checked exception extends Exception and must be caught or declared with throws, because the failure is expected. An unchecked exception extends RuntimeException and does not need to be declared. It usually signals a programming error, such as a null reference or a bad argument.

Lambdas and streams

A lambda is a short anonymous function, written with an arrow: (x, y) -> x + y. Lambdas implement functional interfaces, which are interfaces with exactly one abstract method, such as Runnable, Comparator and Function. A lambda is shorter than an anonymous class and captures the surrounding variables, which must be effectively final, meaning they are never reassigned after they get their value.

A stream is a pipeline of operations on a sequence of values. The pipeline has three parts: a source (here a list), zero or more intermediate operations that return a new stream (such as filter, map and sorted), and one terminal operation that produces a result (such as collect, sum or findFirst). Nothing runs until the terminal operation is called, which is called lazy evaluation.

import java.util.List;
import java.util.Map;
import java.util.Optional;
import java.util.TreeMap;
import java.util.stream.Collectors;
import java.util.stream.IntStream;

public class StreamsDemo {
    public static void main(String[] args) {
        List<String> words = List.of("java", "is", "fun", "and", "fast");

        List<String> result = words.stream()
                .filter(w -> w.length() > 2)          // keep words longer than 2 letters
                .map(String::toUpperCase)            // change each word to uppercase
                .sorted()                            // sort alphabetically
                .collect(Collectors.toList());       // terminal operation: gather into a list
        System.out.println(result);

        int total = IntStream.rangeClosed(1, 5).map(x -> x * x).sum();
        System.out.println(total);

        Optional<String> first = words.stream().filter(w -> w.startsWith("f")).findFirst();
        System.out.println(first.orElse("none"));

        Runnable r = () -> System.out.println("lambda run");
        r.run();

        Map<Integer, Long> byLength = words.stream()
                .collect(Collectors.groupingBy(String::length, TreeMap::new, Collectors.counting()));
        System.out.println(byLength);
    }
}

The first pipeline keeps "java", "fun", "and" and "fast", uppercases them, sorts them and collects the result. IntStream.rangeClosed(1, 5) produces 1 to 5, squares each value, and sums them: 1 + 4 + 9 + 16 + 25 = 55. findFirst returns an Optional, a container that may or may not hold a value, and orElse supplies a default. The last collector counts words by length into a TreeMap, so the keys print in order.

TipUse map to transform each element, filter to keep some, and collect or a reduction such as sum to finish. If a loop only builds a new list, a stream is usually clearer.

Why must a variable captured by a lambda be effectively final?

The lambda copies the value of the variable when it is created. If the variable could change afterward, the lambda and the surrounding code would see different values, which Java forbids. Requiring the variable to be effectively final keeps the copy and the original in agreement.

Threads basics

A thread is an independent path of execution inside one program. Several threads can run at the same time on a multi-core machine, or take turns on one core. In Java you create a thread from an object that implements Runnable, a functional interface with one method, run. Calling start creates the new thread and runs run on it. Calling run directly does not create a thread, which is a common mistake. join makes the current thread wait until another thread finishes.

The danger of threads is the race condition. Two threads that update the same variable can interleave their steps, so one update is lost. counter++ looks like one step, but it reads, adds and writes. The fix is to make the update exclusive, with the synchronized keyword. Only one thread at a time can enter a block synchronized on the same lock object.

public class ThreadsDemo {
    private static int counter = 0;
    private static final Object lock = new Object();

    static void increment() {
        for (int i = 0; i < 1000; i++) {
            synchronized (lock) {        // only one thread at a time runs this block
                counter++;
            }
        }
    }

    public static void main(String[] args) throws InterruptedException {
        Thread t1 = new Thread(ThreadsDemo::increment);
        Thread t2 = new Thread(() -> increment());
        t1.start();
        t2.start();
        t1.join();                       // wait for t1 to finish
        t2.join();                       // wait for t2 to finish
        System.out.println("counter = " + counter);
    }
}
counter = 2000

Each thread adds 1000 to the counter, so the total is 2000 only because every increment is protected by the lock. Without synchronized, the two threads could read the same old value and write back the same new value, and the final count could be less than 2000. The result is unpredictable, which is what makes race conditions hard to test for.

The join calls matter too. Without them, main could print the counter before the threads finished. Always wait for threads before reading their results, or use higher-level tools such as ExecutorService, which manages a pool of threads for you.

TrapCalling run() instead of start() runs the code on the current thread, so no concurrency happens. Use start() to create a new thread.

Interviewers askWhat does synchronized do? Answer: it gives mutual exclusion on a lock object, so only one thread runs the block at a time, and it makes changes made inside the block visible to the next thread that takes the same lock.

Why does counter++ need protection when two threads run it?

The increment is not a single indivisible action. It reads the value, adds one, and writes the result back. Two threads can read the same value before either writes, and one increment is then lost. A synchronized block makes the whole read-add-write sequence happen without interference.

Putting it together: a HashMap word count

A word count is the classic exercise that combines strings, a map and sorting. The program below splits a text into words, counts each word with a HashMap, and then prints the counts in alphabetical order and the top three words. Two details deserve attention. merge is a single call that inserts 1 for a new word or adds 1 to the existing count. Because HashMap order is undefined, the program sorts the keys before printing.

import java.util.ArrayList;
import java.util.Collections;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

public class WordCount {
    public static void main(String[] args) {
        String text = "the quick brown fox jumps over the lazy dog. The dog sleeps; the fox runs!";

        Map<String, Integer> counts = new HashMap<>();
        for (String raw : text.toLowerCase().split("[^a-z]+")) {   // split on anything that is not a letter
            if (raw.isEmpty()) {
                continue;
            }
            counts.merge(raw, 1, Integer::sum);   // new word: 1, existing word: old value plus 1
        }

        // HashMap order is undefined, so sort the keys before printing.
        List<String> keys = new ArrayList<>(counts.keySet());
        Collections.sort(keys);
        for (String k : keys) {
            System.out.println(k + " " + counts.get(k));
        }

        System.out.println("top three:");
        counts.entrySet().stream()
                .sorted(Map.Entry.<String, Integer>comparingByValue().reversed()
                        .thenComparing(Map.Entry.<String, Integer>comparingByKey()))
                .limit(3)
                .forEach(e -> System.out.println(e.getKey() + " " + e.getValue()));
    }

Trace the split first. Lowercasing the text makes "The" and "the" the same key. The regular expression [^a-z]+ means one or more characters that are not lowercase letters, so punctuation and spaces separate the words. TipRebuilding a list of keys and sorting it is the simplest way to print a HashMap in order. Use a TreeMap instead when the sorted order is needed all the time.

Why does the program call merge rather than get followed by put?

merge does both steps in one call: if the key is absent, it stores the value 1, and if the key is present, it combines the old value with 1 using Integer::sum. Writing get and put separately works too, but merge is shorter and avoids a second lookup.

Interview questions

Say each answer aloud in two or three sentences before you open it. The model answers give the reason as well as the fact, because interviewers ask why.

What are the JDK, the JRE and the JVM?

The JVM executes Java bytecode and manages memory. The JRE is the JVM plus the standard libraries needed to run programs. The JDK is the JRE plus development tools such as the compiler javac.

Why are Java strings immutable, and what does that buy you?

Once created, a String never changes, so methods return new strings. This makes strings safe to share between threads, safe as hash keys, and lets the JVM keep one pooled copy of each literal.

What is the difference between == and equals?

== compares references for objects, so it asks whether two names refer to the same object. equals compares values, and a class defines it. For strings, equals is what you usually want, because two equal strings can be different objects.

What is the equals and hashCode contract?

If two objects are equal under equals, they must return the same hashCode. Hash collections rely on this, because they look for an object in the bucket of its hash. Override both methods together, using the same fields.

What is the difference between an interface and an abstract class?

A class can implement many interfaces but extend only one class. An interface describes a capability and holds no instance state. An abstract class can hold state, constructors and shared code for related classes.

How does HashMap store and find a key?

It computes the key's hashCode, spreads the bits, and uses the result to choose a bucket in an array. Within the bucket, it compares keys with equals. Average time is O(1), and buckets with many entries become trees, so the worst case is O(log n).

When would you use TreeMap, and what does it cost?

Use TreeMap when keys must stay sorted or you need the smallest or largest key, or a range of keys. Each operation takes O(log n), because the keys are kept in a balanced tree.

What is the difference between Comparable and Comparator?

Comparable is implemented by the class itself and defines its natural order through compareTo. A Comparator is a separate object that defines an order, and you pass it to a sort. A class has one natural order but can have many comparators.

What is the difference between a checked and an unchecked exception?

A checked exception extends Exception and must be caught or declared, because the failure is expected and recoverable. An unchecked exception extends RuntimeException and is not required to be declared. It usually signals a programming error.

What is type erasure?

The compiler checks generic types and then removes them from the compiled code. At run time, List of String and List of Integer are the same class. This is why generics cannot be used with primitive types directly, and why new ArrayList of String and new ArrayList of Integer have the same getClass result.

What does a lambda capture, and what is required of captured variables?

A lambda captures the variables it uses from the enclosing scope. Those variables must be effectively final, so the captured value cannot change after the lambda is created.

Why does a stream pipeline do nothing until a terminal operation runs?

Intermediate operations such as filter and map are lazy: they only describe the work. The terminal operation, such as collect or sum, pulls elements through the pipeline. This lets Java process one element at a time and stop early, for example with findFirst.

What happens if two threads increment the same counter without synchronization?

Updates can be lost, because the read, add and write steps interleave. The final count can be less than expected and can change from run to run. A synchronized block or an atomic type makes each update exclusive.

DSA: prefix sums and difference arrays

A prefix sum array stores running totals. If nums is [3, 1, 4], the prefix array p has one more entry than nums, starts at 0, and p[i] is the sum of the first i numbers: p = [0, 3, 4, 8]. Building it takes one pass. Then the sum of any range nums[left..right] (both ends included) is p[right + 1] minus p[left], which takes O(1). The idea is to pay O(n) once to answer many range queries quickly.

A difference array works in the other direction. To add a value to a whole range of positions, you change only two entries of an array d, one at the start and one just after the end. A final running sum of d gives the added amounts. Many range updates then cost O(1) each, plus one O(n) pass at the end. Prefix sums and difference arrays are inverses of each other, and interviewers like to test both.

Pattern to rememberMany range queries on a fixed array: build a prefix sum. Many range updates followed by one read of all values: use a difference array and take a running sum at the end.

Range Sum Query - Immutable (LeetCode 303)

Given an integer array that never changes, answer many queries of the form "what is the sum of the elements from index left to index right, both included?" For [-2, 0, 3, -5, 2, -1], the sum from index 0 to 2 is 1.

How to think about it

  1. Understand. The array is fixed, and there can be many queries. Left and right are valid indexes with left at most right.
  2. Brute force. Loop from left to right and add each value. Each query costs O(n), so q queries cost O(n * q).
  3. Find the waste. Each query repeats the additions of the earlier queries. The sum of the first k values is reused by every query that needs it.
  4. Optimise. Build a prefix array once, where prefix[i] holds the sum of the first i values and prefix[0] is 0. The sum from left to right is prefix[right + 1] minus prefix[left], which is the sum of the values between them. Each query becomes O(1).
  5. Dry run. nums = [-2, 0, 3, -5, 2, -1] gives prefix = [0, -2, -2, 1, -4, -2, -3]. The query (0, 2) is prefix[3] minus prefix[0], which is 1 minus 0, so 1. The query (2, 5) is prefix[6] minus prefix[2], which is -3 minus -2, so -1.

Code

class NumArray:
    def __init__(self, nums):
        self.prefix = [0]                     # prefix[i] is the sum of the first i values
        for x in nums:
            self.prefix.append(self.prefix[-1] + x)

    def sumRange(self, left, right):
        return self.prefix[right + 1] - self.prefix[left]

na = NumArray([-2, 0, 3, -5, 2, -1])
print(na.sumRange(0, 2))
print(na.sumRange(2, 5))
print(na.sumRange(0, 5))
1
-1
-3

Build O(n) · Each query O(1) · Space O(n)

TrapOff-by-one errors are the main risk. The prefix array has length n + 1, so the right end is prefix[right + 1], not prefix[right]. Test a range that starts at index 0, because that is where the leading zero matters.

Continuous Subarray Sum (LeetCode 523)

Given a list of non-negative integers and an integer k, return True if the list has a subarray of length at least 2 whose sum is a multiple of k. Zero counts as a multiple of every k. For [23, 2, 4, 6, 7] and k = 6, the subarray [2, 4] sums to 6, so the answer is True.

How to think about it

  1. Understand. The subarray must be contiguous and have at least two elements. Only the remainder of the sum matters, so the question is about multiples of k.
  2. Brute force. Try every start and end pair, add the values, and check the remainder. That is O(n^2) pairs, each summed in O(n) without extra work, or O(n^2) with a running sum.
  3. Find the waste. Subarray sums are differences of prefix sums. The sum from index i to j-1 equals prefix[j] minus prefix[i]. That difference is a multiple of k exactly when prefix[j] and prefix[i] have the same remainder when divided by k.
  4. Optimise. Walk through the prefix sums and store, for each remainder, the first index where it appeared. When a remainder appears again at index j, check that the earlier index is at least two positions before j. That gives a subarray of length at least 2 whose sum is a multiple of k. Start with remainder 0 at index 0, which handles subarrays that begin at the first element. This is O(n) time.
  5. Dry run. nums = [23, 2, 4, 6, 7], k = 6. Remainders of the prefix sums (0, 23, 25, 29, 35, 42) are 0, 5, 1, 5, 5, 0. Remainder 0 is first seen at index 0. Remainder 5 is first seen at index 1, then appears at index 3. Index 3 minus index 1 is 2, so the subarray nums[1:3] = [2, 4] qualifies, and the answer is True.
def check_subarray_sum(nums, k):
    first_seen = {0: 0}                       # remainder -> first prefix index with it
    prefix = 0
    for j in range(1, len(nums) + 1):
        prefix += nums[j - 1]
        r = prefix if k == 0 else prefix % k  # with k = 0, equal prefix sums mean a zero-sum subarray
        if r not in first_seen:
            first_seen[r] = j
        elif j - first_seen[r] >= 2:           # the subarray nums[first:j] has length at least 2
            return True
    return False

print(check_subarray_sum([23, 2, 4, 6, 7], 6))
print(check_subarray_sum([23, 2, 6, 4, 7], 13))
print(check_subarray_sum([1, 0], 2))

False

Pattern to rememberWhen a question asks whether some range has a sum that is a multiple of k, look at prefix sums modulo k. Equal remainders mark ranges whose sums are multiples of k.

Corporate Flight Bookings (LeetCode 1109)

There are n flights numbered 1 to n. You are given bookings, where each booking [first, last, seats] reserves that many seats on every flight from first to last, both included. Return the total number of seats reserved on each flight. For n = 5 and the bookings [[1, 2, 10], [2, 3, 20], [2, 5, 25]], the answer is [10, 55, 45, 25, 25].

How to think about it

  1. Understand. Each booking adds seats to a whole range of flights. There can be many bookings, and the output is one total per flight.
  2. Brute force. For each booking, loop from first to last and add the seats. That costs O(length of range) per booking, which can be O(n) each, so O(n * bookings) in the worst case.
  3. Find the waste. Each booking touches a whole range, but the only places where the added amount changes are the start and the position after the end. Everything in between gets the same change.
  4. Optimise. Use a difference array d of length n + 1. For a booking [first, last, seats], add seats at index first - 1 and subtract seats at index last. After all bookings, take the running sum of d for positions 0 to n - 1. The running sum carries the added seats across the range and removes them just after its end. This is O(n + bookings) time.
  5. Dry run. n = 5, bookings [1, 2, 10] and [2, 3, 20]. The first booking gives d[0] += 10 and d[2] -= 10. The second gives d[1] += 20 and d[3] -= 20. The array is now [10, 20, -10, -20, 0]. Running sums: 10, 30, 20, 0, 0. These are the totals from these two bookings alone, and the third booking adds 25 to positions 1 to 4, which gives 10, 55, 45, 25, 25.
def corp_flight_bookings(bookings, n):
    diff = [0] * (n + 1)                      # one extra slot for the position after the last flight
    for first, last, seats in bookings:
        diff[first - 1] += seats              # the seats start at flight first (index first - 1)
        diff[last] -= seats                   # and stop after flight last (index last)
    answer = []
    running = 0
    for i in range(n):
        running += diff[i]                    # the running sum is the seats on flight i + 1
        answer.append(running)
    return answer

print(corp_flight_bookings([[1, 2, 10], [2, 3, 20], [2, 5, 25]], 5))
print(corp_flight_bookings([[1, 2, 10], [2, 2, 15]], 2))
[10, 55, 45, 25, 25]
[10, 25]

Time O(n + bookings) · Space O(n)

TipUse 1-based booking numbers carefully. Flight 1 is index 0, so the start of a booking is shifted by one, and the subtraction at index last already points to the flight after the end.

Pattern to rememberTo add a value to a whole range, change two entries of a difference array and take a running sum at the end.

Maximum Sum of 3 Non-Overlapping Subarrays (LeetCode 689)

Given an array nums and an integer k, find three non-overlapping subarrays, each of length k, whose total sum is as large as possible. Return the starting indexes of the three subarrays as a list. If several answers have the same total, return the one that is smallest in lexicographic order, which means the first index is as small as possible, then the second, and so on. For nums = [1, 2, 1, 2, 6, 7, 5, 1] and k = 2, the answer is [0, 3, 5], with total 3 + 8 + 12 = 23.

How to think about it

  1. Understand. Each subarray has exactly k elements, and the three must not share an element. The output is three start indexes, and ties must be broken toward the smallest indexes.
  2. Brute force. Try every triple of start indexes a, b and c with b at least a + k and c at least b + k. Compute each sum from prefix sums. That is O(n^3) triples, which is too slow for large inputs.
  3. Find the waste. Compute the sum of every window of length k once, into an array W. Then the problem is to choose three indexes in W that are at least k apart and have the largest total. For a middle window starting at j, the best choice on its left is the best window that ends before j, and the best on its right is the best window that starts after j + k - 1.
  4. Optimise. Build two helper arrays. left[i] is the index of the best window in W from 0 to i. right[i] is the index of the best window in W from i to the end. Keep the leftmost index on ties. Then try each middle start j from k to len(W) - 1 - k. The candidate is left[j - k], j and right[j + k]. Keep the candidate with the largest total, and change only on a strictly larger total so the earliest candidate wins. This is O(n) time.
  5. Dry run. nums = [1, 2, 1, 2, 6, 7, 5, 1], k = 2. The window sums W are [3, 3, 3, 8, 13, 12, 6]. The left helper becomes [0, 0, 0, 3, 4, 4, 4], because index 3 (sum 8) is the best window so far from index 3 on and index 4 (sum 13) takes over from there. The right helper becomes [4, 4, 4, 4, 4, 5, 6]. For middle start j = 2, the candidate is left[0] = 0, j = 2 and right[4] = 4, total 3 + 3 + 13 = 19. For j = 3, the candidate is left[1] = 0, 3 and right[5] = 5, total 3 + 8 + 12 = 23, which is larger, so it wins. For j = 4, the candidate is left[2] = 0, 4 and right[6] = 6, total 3 + 13 + 6 = 22, which is smaller. The answer is [0, 3, 5].
def max_sum_of_three(nums, k):
    n = len(nums)
    prefix = [0]
    for x in nums:
        prefix.append(prefix[-1] + x)
    # W[i] is the sum of the window nums[i : i + k], for every valid start i
    W = [prefix[i + k] - prefix[i] for i in range(n - k + 1)]
    m = len(W)

    left = [0] * m                            # left[i]: leftmost best window start in W[0..i]
    best = 0
    for i in range(m):
        if W[i] > W[best]:
            best = i
        left[i] = best

    right = [0] * m                           # right[i]: leftmost best window start in W[i..m-1]
    best = m - 1
    for i in range(m - 1, -1, -1):
        if W[i] >= W[best]:
            best = i
        right[i] = best

    answer = None
    best_total = -1
    for j in range(k, m - k):                 # the middle window starts at j
        a = left[j - k]                       # best window that ends before j starts
        b = right[j + k]                      # best window that starts after j + k - 1
        total = W[a] + W[j] + W[b]
        if total > best_total:                 # strictly greater keeps the earliest answer
            best_total = total
            answer = [a, j, b]
    return answer

print(max_sum_of_three([1, 2, 1, 2, 6, 7, 5, 1], 2))
print(max_sum_of_three([1, 2, 1, 2, 1, 2, 1, 2, 1], 2))
[0, 3, 5]
[0, 2, 4]

Time O(n) · Space O(n) for the prefix sums and helper arrays

TrapThe tie rules decide which of several correct answers is returned. Using greater-or-equal in the wrong direction returns a later index on ties, which fails the lexicographic requirement. Test a case where all windows are equal, as in the second example, where the answer is [0, 2, 4].

Pattern to rememberPick a middle block, then choose the best block on each side using two helper arrays built in one pass each. This turns a three-way search into a single loop over the middle.

For interviews, state the three approaches in order: brute force, prefix sums for each query, and the difference array or the helper arrays for each update or three-way choice. Explain that prefix sums turn a range sum into a subtraction, and a difference array turns a range update into two point updates.
