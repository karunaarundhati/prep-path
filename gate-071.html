Linked Lists

A linked list is a chain of small boxes, where each box holds one value and a pointer to the next box. It is the main alternative to an array, and GATE questions often ask you to follow the pointer changes needed to insert, delete or reverse a node.

The idea in plain words

Imagine a treasure hunt. Each clue is written on a card, and each card tells you where the next card is hidden. You do not know where the 50th card is until you have found the first 49. To reach the end, you must follow the chain one card at a time. A linked list works the same way. Each node holds a value and a pointer, which is a reference that says where the next node is. The last node points to nothing.

An array, by contrast, is like a row of numbered lockers. You can open locker number 50 directly, without opening lockers 1 to 49. But if you want to put a new item between two lockers, the whole row must shift. A linked list is the opposite: adding or removing a node in the middle is easy, because you only change a few pointers, but finding the 50th node means following 49 pointers.

Knowing this trade-off is the heart of the topic. Each GATE question on linked lists asks you, in some form, to count pointer changes or to follow pointers in the right order.

Why this matters for GATE. Questions include the time complexity of insertion and deletion, the number of nodes after a sequence of operations, the correct order of pointer updates, and the final state of a list after reversal. Draw the nodes as boxes with arrows, and update the arrows one line at a time.

Key terms

Linked list
A chain of nodes, where each node points to the next. Plain meaning: a treasure hunt of cards. Precise definition: a linear data structure whose elements are nodes connected by pointers.
Node
One element of a linked list. It holds data and one or more pointers.
Data
The value stored in a node.
Pointer (or reference)
A stored address that says which node comes next. In Python, a variable that holds a node object acts as a pointer to it.
Head
The variable or first node that starts the list. It is the entry point to the whole chain.
Tail
The last node of the list. Its next pointer is empty.
None
The empty pointer. It means "no next node". Python uses None for this.
Singly linked list
A list in which each node has one pointer, to the next node.
Doubly linked list
A list in which each node has two pointers, one to the next node and one to the previous node.
Circular linked list
A list in which the last node points back to the first node, so there is no empty pointer.
Traversal
Visiting every node in order, by following the pointers from the head.
Insertion
Adding a new node at a chosen place, by changing pointers.
Deletion
Removing a node from the list, by changing the pointer that reaches it.
Reversal
Changing the list so that its nodes point in the opposite direction, so the old tail becomes the new head.
Class
A blueprint for an object that holds named values. A Node class groups data and next together.
is None
A test that checks whether a variable holds the empty pointer. It is written with the word is, not with ==.

Nodes and the singly linked list

What a node looks like

A node has two parts: the value and the pointer to the next node. In Python we describe a node with a class. A class is a blueprint. Calling Node(5) builds one node that holds 5, with its next pointer set to None. The word self refers to the node being built, so self.data is the data of that node.

A list is then just a chain of these nodes, and we keep a variable called head that points to the first node.

class Node:
    def __init__(self, data):
        self.data = data
        self.next = None

a = Node(10)
b = Node(20)
a.next = b
print(a.data, a.next.data)
print(b.next)
10 20
None

The first print shows the data of a, which is 10, and the data of the node that a points to, which is 20. The second print shows that b points to nothing, so its next pointer is None. The line a.next = b is a pointer change: it links two nodes together.

Traversal

To visit every node, start at the head and follow next until the pointer is None. This is called traversal. The variable that moves along the list is often called cur, for current.

Key ideaNever lose the head. If you move the head variable while you traverse, you lose the start of the list. Always move a second variable, like cur, and keep head where it is.

If the list is 10 to 20 to 30, what is head.next.next.data?

30. head.next is the node 20, and its next is the node 30.

What does traversal do when the head is None?

It visits nothing. The loop condition cur is not None is False from the start, so the list is empty.

Insertion and deletion at head, tail and middle

Inserting at the head

Inserting at the head is the cheapest operation. Create the new node, point its next to the old head, and make the new node the head. Only two pointers change, so the time is O(1), whatever the list length.

Inserting at the tail

To insert at the tail, you must first reach the last node. Without a tail pointer, this means traversing the whole list, which takes O(n) time. Once you reach the last node, set its next to the new node. If you keep a separate tail pointer, the insertion is O(1).

Inserting in the middle

To insert a new node after a given node P, do two pointer changes, in the right order:

  1. Set the new node's next to P.next. Now the new node points to the old successor.
  2. Set P.next to the new node.

If you reverse these two steps, the old successor is lost. The first change must happen first, because it saves the link before the second change overwrites it. The time is O(1) once you hold a pointer to P. Finding P in the first place takes O(n) by traversal.

Deleting a node

To delete a node after a given node P, set P.next to P.next.next. The node in between is no longer reachable from the list, so it is dropped. The following code deletes the first node with a given value. It has three cases: an empty list, a match at the head, and a match further along.

class Node:
    def __init__(self, data):
        self.data = data
        self.next = None

def insert_head(head, value):
    node = Node(value)
    node.next = head
    return node

def insert_tail(head, value):
    node = Node(value)
    if head is None:
        return node
    cur = head
    while cur.next is not None:
        cur = cur.next
    cur.next = node
    return head

def delete_value(head, target):
    if head is None:
        return None
    if head.data == target:
        return head.next
    cur = head
    while cur.next is not None and cur.next.data != target:
        cur = cur.next
    if cur.next is not None:
        cur.next = cur.next.next
    return head

def to_list(head):
    items = []
    cur = head
    while cur is not None:
        items.append(cur.data)
        cur = cur.next
    return items

head = None
head = insert_tail(head, 10)
head = insert_tail(head, 20)
head = insert_tail(head, 30)
head = insert_head(head, 5)
print(to_list(head))
head = delete_value(head, 20)
print(to_list(head))
head = delete_value(head, 99)
print(to_list(head))
[5, 10, 20, 30]
[5, 10, 30]
[5, 10, 30]

The list is built as 10, 20, 30 with tail insertions, then 5 is added at the head. The deletion of 20 changes only the pointer of 10, which now points to 30. Deleting 99 finds nothing, so the loop stops at the last node and the list is unchanged.

TrapIn the code, head = insert_head(head, 5) is needed because the new node becomes the new head. A question that forgets to update the head variable will print the old list. Always update head when the first node changes.

What is the time to insert at the head of a singly linked list of 1000 nodes?

O(1). Only two pointers change, and no traversal is needed.

To insert X after node P, why must X.next = P.next come before P.next = X?

Because the first line saves the link to the old successor. If P.next is changed first, the old successor cannot be reached any more.

Reversing a linked list

The idea

Reversing a list turns every arrow around. The old tail becomes the new head. The standard method walks down the list, one node at a time, and turns each arrow to point at the node behind it. Three variables are used:

  • prev: the node that has already been reversed, which starts as None.
  • cur: the node being processed now, which starts at the head.
  • nxt: the next node, saved before the arrow is changed.

Each step does four things, in this order: save the next node, turn the arrow of cur to point at prev, move prev forward to cur, and move cur forward to the saved next node.

class Node:
    def __init__(self, data):
        self.data = data
        self.next = None

def reverse(head):
    prev = None
    cur = head
    while cur is not None:
        nxt = cur.next
        cur.next = prev
        prev = cur
        cur = nxt
    return prev

def to_list(head):
    items = []
    cur = head
    while cur is not None:
        items.append(cur.data)
        cur = cur.next
    return items

head = None
for v in [1, 2, 3, 4]:
    node = Node(v)
    node.next = head
    head = node
print(to_list(head))
head = reverse(head)
print(to_list(head))
[4, 3, 2, 1]
[1, 2, 3, 4]

The list is built by inserting each value at the head, so the first print shows 4, 3, 2, 1. The reverse function then turns every arrow, and the second print shows 1, 2, 3, 4.

Key ideaThe saved pointer nxt is what makes reversal possible. Without it, changing cur.next would lose the rest of the list.

How many loop passes does reverse make on a list with 5 nodes?

5. There is one pass for each node, and the loop stops when cur becomes None.

What is the time complexity of reversing a singly linked list?

O(n). Each node is visited exactly once, and the pointer changes are constant work per node.

Doubly and circular linked lists

Doubly linked lists

A doubly linked list node has two pointers: next to the following node and prev to the node before it. This costs extra memory, but it allows backward traversal and makes deletion easier, because you can reach the previous node directly.

To delete a node X that is in the middle, two pointers change:

  1. X.prev.next = X.next, so the node before X skips over it.
  2. X.next.prev = X.prev, so the node after X skips back over it.

Given the node X itself, deletion takes O(1) time. In a singly linked list, you would need to find the node before X first, which takes O(n).

Circular linked lists

In a circular list, the last node points back to the first node instead of to None. There is no empty pointer, so a traversal must stop after a fixed count or when it returns to the start. The code below builds a circle of three nodes and walks around it five times.

class Node:
    def __init__(self, data):
        self.data = data
        self.next = None

a = Node("A")
b = Node("B")
c = Node("C")
a.next = b
b.next = c
c.next = a
cur = a
visited = []
for k in range(5):
    visited.append(cur.data)
    cur = cur.next
print(visited)
['A', 'B', 'C', 'A', 'B']

After C, the pointer goes back to A, so the walk wraps around. A common use of circular lists is round-robin scheduling, where each process gets a turn and then the turn returns to the first process.

TrapA loop written as "while cur is not None" never ends on a circular list, because no pointer is ever None. Always use a counter or compare with the starting node.

In a circular list of 4 nodes starting at A, which node is reached after 4 steps?

A again. After 4 steps around a cycle of 4 nodes, the walk returns to the start.

Which list type allows deleting a given node in O(1) time without a traversal?

The doubly linked list, because each node knows its previous node.

Linked list versus array

The comparison

Arrays and linked lists are the two main ways to store a sequence. Their costs differ, and GATE asks you to choose or compare them.

OperationArraySingly linked list
Access the k-th itemO(1), direct indexO(k), follow k pointers
Search for a valueO(n)O(n)
Insert at the headO(n), shift everythingO(1)
Insert after a known nodeO(n), shift the restO(1)
Delete after a known nodeO(n), shift the restO(1)
Extra memory per itemNone beyond the valueOne pointer per node
SizeFixed, or costly to resizeGrows one node at a time

The rule of thumb is simple. Use an array when you need fast access by position and the size is known. Use a linked list when you insert and delete often at known places, and you do not need quick access by position. The memory cost of pointers is the price of that flexibility.

GATE loves thisA common question asks for the best data structure for a given set of operations. Count the operations: frequent random access points to an array, and frequent insertion at a known node points to a linked list.

Which is faster to find the 500th item, an array or a singly linked list?

The array, which is O(1). The linked list needs about 500 pointer follows, which is O(k) with k = 500.

Does a linked list need the items to be next to each other in memory?

No. Each node can be stored anywhere, because the pointer says where the next node is.

Pointer tracing questions

A method for pointer questions

Pointer questions look hard because the arrows are easy to lose. Use this method:

  1. Draw the nodes as boxes with their values, and draw an arrow for each next pointer. Mark None where a pointer is empty.
  2. Write the variables such as head, cur and prev, and point each one at its box.
  3. Apply one line at a time. Redraw the arrows after each assignment that changes a pointer.
  4. Check the final picture by following the arrows from the head.

Worked trace

Start with the list 3 to 7 to 9. Run q = head.next and then head.next = q.next. After the first line, q points to node 7. After the second line, the node 3 points to 9. The node 7 is no longer reachable from head. The list is now 3 to 9, and node 7 is dropped. This is the middle deletion pattern from the earlier section, written as two lines.

TipWhen a question changes a pointer, ask two questions: which node is being changed, and what did its pointer point to before. If the old target is not saved in a variable, it may be lost forever.

Counting pointer changes

Many questions ask for the number of pointer changes. In the reversal method, each node has its next changed exactly once, so reversing n nodes changes n pointers. In a middle insertion, two pointers change. In a doubly linked middle deletion, two pointers change.

In the worked trace above, is node 7 still in the list after the two lines?

No. Nothing points to node 7 any more, so it is unreachable from head.

How many pointer assignments does inserting at the head of a singly linked list make?

Two: node.next = head and then head = node. The second line changes the head variable, which is the entry point to the list.

Exam-level 1: delete, append, reverse (NAT, 2 marks)

A singly linked list holds the values 5, 8, 2, 9, 4, 7 in this order from head to tail. An algorithm makes one pass from head to tail and deletes every node whose value is greater than 6. It then adds a new node with value 10 at the tail. Finally it reverses the whole list in place, so that the old tail becomes the head. After these steps the list is read from head to tail. Let a be the value at the second position and b the value at the third position. Find a + b. Give the answer as an integer.

How to think about it

  1. What is asked. The sum of the values at positions 2 and 3, after the deletion, the append and the reversal.
  2. Which idea applies. Deleting nodes while walking the list, adding at the tail, and reversing by flipping pointers. Each step changes the list, so track the values after each one.
  3. Work it out. Deleting values above 6 removes 8, 9 and 7, leaving 5, 2, 4. Appending 10 gives 5, 2, 4, 10. Reversing gives 10, 4, 2, 5. The second value is 4 and the third is 2, so a + b = 4 + 2 = 6.
  4. Check. The list has 4 values after the deletion and append, which matches 6 nodes minus 3 deletions plus 1 addition. The Python block below repeats the same steps.
vals = [5, 8, 2, 9, 4, 7]
vals = [v for v in vals if v <= 6]
vals.append(10)
vals = vals[::-1]
print(vals)
print(vals[1] + vals[2])
[10, 4, 2, 5]
6

Answer: 6

Exam-level 2: operations on a list with head and tail pointers (MSQ, 2 marks)

A queue is built with a singly linked list. The structure keeps a head pointer and a tail pointer, but no previous pointers, so each node points only forward. Consider the following operations on a list with n nodes. (A) Adding a new node after the tail takes O(1) time. (B) Deleting the last node takes O(1) time. (C) Reversing the whole list in place takes O(n) time and O(1) extra space. (D) Finding the middle node takes O(1) time. Select all that apply.

How to think about it

  1. What is asked. Every option that is true for this structure.
  2. Which idea applies. In a singly linked list you can only move forward, so reaching the node before a given node needs a walk from the head.
  3. Work it out. (A) New node: set tail.next to the new node, then move tail to it. Two changes, no walk, so O(1). True. (B) Deleting the last node needs the node before the tail, and only a walk from the head finds it, which is O(n). False. (C) Reversal uses three pointers (previous, current, next) and visits each node once. O(n) time, O(1) extra space. True. (D) Finding the middle needs about n/2 forward steps, so O(n). False.
  4. Check. Options B and D look constant time because the tail pointer and the length are sometimes known. Neither gives a way back, so both need a walk.

Answer: (A) and (C). Option (B) is wrong because the node before the tail is not reachable in O(1) without previous pointers. Option (D) is wrong because the middle needs a walk of about n/2 steps.

Exam-level 3: circle elimination (NAT, 2 marks)

Forty-one people stand in a circle, numbered 1 to 41 in clockwise order. The circle is stored as a circular singly linked list in which each node points to the next person clockwise. Counting starts at person 1. The rule is: skip the next surviving person, then remove the person after that one. Counting then continues from the next surviving person after the removed one, and the process repeats until only one person remains. Give the number of the last survivor as an integer.

How to think about it

  1. What is asked. The number of the single person left at the end.
  2. Which idea applies. This is the Josephus elimination for step 2. For n people, write n = 2m + L with L smaller than 2m, remove the first L people (the even numbers 2, 4, ..., 2L), then the survivor is person 2L + 1.
  3. Work it out. 41 = 32 + 9, so m = 5 and L = 9. Removing the 9 people 2, 4, 6, ..., 18 leaves 32 people, and counting restarts at person 19. With 32 people, a power of two, the person who starts the count survives. So the survivor is 19, which is 2 x 9 + 1.
  4. Check. The Python block simulates the removals one by one and gives the same answer, 19.
def survivor(n):
    people = list(range(1, n + 1))
    i = 0
    while len(people) > 1:
        i = (i + 1) % len(people)
        people.pop(i)
        i = i % len(people)
    return people[0]
print(survivor(41))
19

Answer: 19

Exam-level 4: memory of a sensor log (NAT, 2 marks)

A sensor logger stores 1000 readings. Each reading is a 4-byte value. The logger can keep the readings either in a singly linked list, where each node holds the value and one 8-byte pointer to the next node, or in a doubly linked list, where each node holds the value and two 8-byte pointers, one to the next node and one to the previous node. Ignore any memory for the head pointer and any other overhead. Find the ratio of the total memory used by the doubly linked list to the total memory used by the singly linked list. Give the answer correct to 2 decimal places.

How to think about it

  1. What is asked. A ratio of two totals, rounded to 2 decimal places.
  2. Which idea applies. Memory per node is the value size plus the pointer sizes. The number of nodes is the same in both lists.
  3. Work it out. Singly node: 4 + 8 = 12 bytes, so 1000 nodes use 12000 bytes. Doubly node: 4 + 8 + 8 = 20 bytes, so 1000 nodes use 20000 bytes. Ratio: 20000 / 12000 = 1.6667, which is 1.67 to 2 decimal places.
  4. Check. The ratio is above 1, as expected, because the doubly list has extra pointers. The Python block computes the same values.
value_bytes = 4
pointer_bytes = 8
n = 1000
singly = n * (value_bytes + pointer_bytes)
doubly = n * (value_bytes + 2 * pointer_bytes)
print(singly, doubly)
print(round(doubly / singly, 2))
12000 20000
1.67

Answer: 1.67

Exam-level 5: slow and fast pointers (NAT, 2 marks)

A singly linked list has 11 nodes, numbered 1 to 11 from head to tail. Two pointers start together at node 1. In each step, the slow pointer moves forward one node and the fast pointer moves forward two nodes. The steps continue until the fast pointer reaches node 11, the last node. At that moment, which node number does the slow pointer point to? Give the answer as an integer.

How to think about it

  1. What is asked. The node number of the slow pointer when the fast pointer is at node 11.
  2. Which idea applies. After t steps, the slow pointer is at node 1 + t and the fast pointer is at node 1 + 2t.
  3. Work it out. The fast pointer reaches node 11 when 1 + 2t = 11, so 2t = 10 and t = 5. After 5 steps the slow pointer is at node 1 + 5 = 6.
  4. Check. In 5 steps the fast pointer covered 10 links and the slow pointer covered 5 links. Node 11 is 10 links after node 1, so the numbers agree. The Python block simulates it.
nodes = list(range(1, 12))
slow = 0
fast = 0
while True:
    if fast + 1 >= len(nodes):
        break
    fast = fast + 2
    slow = slow + 1
    if fast >= len(nodes) - 1:
        break
print(nodes[slow], nodes[fast])
6 11

Answer: 6

Exam-level 6: where a cycle is detected (NAT, 2 marks)

Ten nodes numbered 1 to 10 form a singly linked list in which node i points to node i + 1 for i from 1 to 9. The last node, node 10, is then changed to point back to node 4, so the list now contains a cycle. Two pointers both start at node 1. In each step the slow pointer moves forward one node and the fast pointer moves forward two nodes. The procedure stops at the first step in which both pointers point to the same node. Give the number of that node as an integer.

How to think about it

  1. What is asked. The node where the two pointers first meet.
  2. Which idea applies. The fast pointer goes around the cycle and catches the slow pointer. Count where each pointer is after each step.
  3. Work it out. The path 1 to 10 has 9 links. Node 10 points to node 4, so the cycle is 4, 5, 6, 7, 8, 9, 10, with length 7. After t steps the slow pointer is at node t + 1 while t is at most 9. After h fast hops the fast pointer is at node h + 1 for h up to 9, and at node h - 6 for h from 10 on. At step 7 the slow pointer is at node 8. The fast pointer has made 14 hops, and 14 - 6 = 8, so it is also at node 8. No earlier step matches, so they first meet at node 8.
  4. Check. The Python block repeats the simulation and reports step 7 and node 8.
nxt = {i: i + 1 for i in range(1, 10)}
nxt[10] = 4
slow = 1
fast = 1
step = 0
while True:
    step += 1
    slow = nxt[slow]
    fast = nxt[nxt[fast]]
    if slow == fast:
        break
print(step, slow)
7 8

Answer: 8

Summary

Linked list
A chain of nodes where each node points to the next.
Node
A value plus one or more pointers.
Head
The variable that starts the list. Never lose it.
Tail
The last node, whose next pointer is None.
None
The empty pointer, tested with is None.
Singly linked list
Each node has one pointer, forward.
Doubly linked list
Each node has next and prev pointers.
Circular linked list
The last node points back to the first.
Traversal
Visiting nodes in order by following next.
Insertion after P
Save P.next in the new node first, then set P.next.
Deletion after P
Set P.next to P.next.next.
Reversal
Turns every arrow around, using prev, cur and nxt.
Access by position
O(1) in an array, O(k) in a linked list.
Pointer trace
Draw boxes and arrows, and update one line at a time.

Remember these

  1. Insertion at the head of a singly linked list is O(1).
  2. Save the old link before you overwrite a pointer.
  3. Reversal changes one next pointer per node, so n nodes mean n changes.
  4. A doubly linked list can delete a given node in O(1), but needs more memory.
  5. A circular list never reaches None, so use a counter in loops.
  6. Arrays give fast access by position. Linked lists give cheap insertion at known places.
