Bias-variance tradeoff

Every learning model can go wrong in two different ways at once. It can be too stiff to notice the real pattern (bias), or too jumpy and easily fooled by the particular data it saw (variance). This topic shows how these two errors trade off against each other, and why GATE Data Science and AI asks about them so often.

The idea in plain words

Imagine three throwers playing darts, each throwing ten darts at a bullseye:

  • Thrower A's darts all land in one spot, far from the bullseye. Their aim is consistently wrong.
  • Thrower B's darts land all over the board. Their aim is unreliable, but the darts are roughly around the bullseye on average.
  • Thrower C's darts are tightly grouped on the bullseye. This is the goal.

Machine learning has the same two problems. A learning algorithm looks at a training set (examples with known answers) and builds a model (a rule that makes predictions). A slightly different training set gives a slightly different model, so each model is like one dart throw. Two things can go wrong:

  • The model rests on a wrong assumption, so it is consistently off target, like Thrower A. This error is bias.
  • The model changes a lot depending on which examples happened to be in the training set, so its predictions scatter, like Thrower B. This error is variance.

The bias-variance tradeoff says these two errors are often linked. Making a model more flexible usually lowers bias but raises variance. Making it more rigid does the opposite. The skill is finding the setting where the total error is smallest.

Why does this matter for GATE? The Data Science and AI paper has a machine learning unit. Questions often ask you to spot underfitting (high bias) or overfitting (high variance), or to compute an expected error from its parts.

Concept 1: Bias, the error from wrong assumptions

What it means in plain words

Bias is the part of the error that comes from building on a wrong idea. Suppose the true pattern is a curve, but you insist the model must be a straight line. Even the best straight line misses the curve, and collecting more data does not fix that. The miss is bias. It is like a bent ruler: every measurement is off in the same direction.

The formal definition

Imagine drawing many training sets from the same world, training a model on each, and asking every model to predict at the same input x. Let f(x) be the true value at x.

Bias(x) = E[f̂(x)] − f(x)
  • f(x) is the true value at input x, the answer we want to hit.
  • f̂(x) (read "f hat of x") is the prediction of one trained model at x. It changes from one training set to another.
  • E[f̂(x)] is the average of those predictions over all the training sets. It is the model's "typical" answer.

A small number example

  1. The true value is f(x) = 2.
  2. Across training sets, the model predicts 3 on average: E[f̂(x)] = 3.
  3. Bias = 3 − 2 = 1.

The model is consistently one unit too high. Bias can be negative too, but squaring removes the sign when we measure error.

Key ideaHigh bias means the model is consistently wrong in one direction. It usually comes from a model that is too simple, such as a straight line for curved data.

TrapBias is not "how wrong one prediction is". One prediction can be far off by chance. Bias is about the average prediction over many training sets.

If a model has zero bias at every input, does it make no errors?

No. Zero bias means the average prediction is exactly right, but individual predictions can still scatter (variance), and the noise adds more error.

A straight line is fitted to data that clearly follows a curve. Is the bias high or low?

High. The straight-line assumption is wrong, so even the average line misses the curve systematically. This is underfitting.

Concept 2: Variance, the error from sensitivity to the training data

What it means in plain words

Variance is the part of the error that comes from the model changing too much when the training data changes a little. A very flexible model that tries to pass through every training point can swing wildly if one point moves. Its predictions then depend on luck: which examples you happened to collect. Think of a sensitive weighing scale that jumps when someone breathes on it. Its readings are not wrong on average, but each reading is unreliable.

The formal definition

Variance(x) = E[(f̂(x) − E[f̂(x)])²]
  • f̂(x) − E[f̂(x)] is how far one model's prediction is from the typical prediction.
  • ( … )² squares this distance, so wobbles up and down both count as positive.
  • E[ … ] averages the squared wobbles over all the training sets.

A small number example

Three equally likely training sets lead to predictions of 1, 3 and 5 at the same input.

  1. Average prediction: (1 + 3 + 5) / 3 = 3.
  2. Distances from the average: 1 − 3 = −2, 3 − 3 = 0, 5 − 3 = 2.
  3. Squared distances: 4, 0 and 4.
  4. Average of the squared distances: (4 + 0 + 4) / 3 = 8/3.

So the variance is 8/3, about 2.67.

TipAlways square before you average. Averaging the raw distances gives −2 + 0 + 2 = 0, which wrongly suggests there is no spread at all.

TrapVariance is the spread of predictions across different training sets. It is not the spread of the answers y inside one training set.

GATE loves thisA model with near-zero training error but a large gap to test error has high variance. That gap is the signature of overfitting.

If variance is 0, do predictions change when the training data changes?

No. Zero variance means every training set gives the same prediction at that input. The model is stable, though it might still be biased.

Concept 3: Splitting the error into parts

Why we want a split

A third source of error is the noise in the answers. Two houses of the same size may sell for different prices, so the observed answer is never exactly the true value. We write:

y = f(x) + ε
  • y is the observed answer.
  • f(x) is the true pattern, the same for every sample.
  • ε (epsilon) is random noise with average zero and variance σ². It is independent of the model's predictions.

The key result

For a new input x, with squared error averaged over training sets and noise, the expected error splits into three parts:

E[(y − f̂(x))²] = Bias² + Variance + σ²
  • Bias² is the squared bias from Concept 1.
  • Variance is the variance from Concept 2.
  • σ² is the irreducible noise. It sets a floor under the error.

Why it works, step by step

Write p for the prediction f̂(x) and m = E[p] for its average. The average of (p − m) is zero, and the noise averages to zero and is independent of p.

  1. The error is (y − p)² = ((f − p) + ε)².
  2. Expand: (f − p)² + 2(f − p)ε + ε².
  3. Average. The middle term averages to zero, since ε averages to zero and is independent of p. The last term averages to σ². So the expected error is E[(f − p)²] + σ².
  4. Split f − p = (f − m) + (m − p) and square: (f − m)² + 2(f − m)(m − p) + (m − p)².
  5. Average again. The middle term is zero because E[m − p] = 0. The first term is the squared bias, and the last term is the variance.

A worked numeric example

At one input the true value is f = 2. Three equally likely models predict 1, 3 and 5. The noise is +1 or −1 with equal chance, so σ² = 1. We compute the expected error two ways. If the formula is right, both agree.

from fractions import Fraction as F

preds = [F(1), F(3), F(5)]           # three possible predictions
probs = [F(1, 3), F(1, 3), F(1, 3)]  # each equally likely
f = F(2)                             # true value at x
noise_var = F(1)                     # noise is +1 or -1, so variance is 1

mean_pred = sum(p * q for p, q in zip(preds, probs))
bias_sq = (mean_pred - f) ** 2
variance = sum(q * (p - mean_pred) ** 2 for p, q in zip(preds, probs))
three_part = bias_sq + variance + noise_var

# direct: noise plus the average squared gap to the true value
direct = noise_var + sum(q * (f - p) ** 2 for p, q in zip(preds, probs))

print("mean prediction:", mean_pred)
print("bias squared:", bias_sq)
print("variance:", variance)
print("bias^2 + variance + noise:", three_part)
print("direct expected error:", direct)
print("they agree:", three_part == direct)
mean prediction: 3
bias squared: 1
variance: 8/3
bias^2 + variance + noise: 14/3
direct expected error: 14/3
they agree: True

The mean prediction is 3, so the bias is 1 and the squared bias is 1. The variance is 8/3. The total is 1 + 8/3 + 1 = 14/3, and the direct calculation also gives 14/3.

Key ideaOnly bias and variance depend on the model, so only they can be improved by changing the model. The noise part is a floor no model can go below.

TrapThe formula uses Bias², not bias. A bias of −2 contributes 4, not −2. The noise σ² is always added, even when bias and variance are zero.

A model has squared bias 4, variance 3 and noise 2. What is its expected squared error?

4 + 3 + 2 = 9. Squared bias is already squared, so we do not square it again.

Why can we never reach zero expected error on noisy data?

Because the noise σ² is random and appears in every answer. Even a perfect model equal to f(x) still differs from y by ε, so the error is at least σ².

Concept 4: Model complexity and the U-shaped curve

An everyday analogy

A student who learns one rule, "always answer B", does badly on the real questions. That is underfitting. A student who memorises last year's practice sheet word for word scores perfectly on that sheet but badly on the real exam. That is overfitting. The best student learns the real patterns and ignores the accidents of the practice sheet.

Complexity controls the tradeoff

Model complexity is how flexible a model is. For polynomial curves, a degree-1 line is simple and a degree-10 curve is very flexible. The usual pattern is:

ModelBiasVarianceTraining errorTest errorSituation
Very simple (a constant guess)HighLowHighHighUnderfitting
Medium (right flexibility)Low enoughLow enoughModerateLowestGood fit
Very complex (passes through every point)LowHighNear zeroHighOverfitting

Why the test error is U-shaped

As complexity rises, bias falls, because the model can represent the true pattern more closely. Variance rises, because the model reacts more to the particular training points. Test error is the sum of these effects plus noise, so plotted against complexity it falls, reaches a lowest point, then rises. This is the U-shape.

Training error keeps falling as complexity rises, because a flexible model can always fit the training points better. A low training error alone does not prove a model is good.

TipLook at the two errors. Both high means underfitting (high bias). Training low but test high means overfitting (high variance). Both low means you are near the sweet spot.

Trap"More complex models are always more accurate" is false. They fit the training data better, but they can be much worse on new data.

GATE loves thisQuestions often describe a table of training and test errors and ask you to name the problem. The table above answers them quickly.

A model has 98 percent training accuracy and 60 percent test accuracy. High bias or high variance?

High variance, which is overfitting. A high-bias model would be poor on both sets.

As complexity grows, does the bias go up or down?

Down. A more flexible model can represent the true pattern more closely. The variance goes up at the same time, which is the tradeoff.

Concept 5: Taming the tradeoff with regularization and validation

Regularization in plain words

Regularization tells the model: "Prefer small, simple answers unless the data clearly demands otherwise." You add a penalty to the quantity the model minimises, so large parameters cost extra. This shrinks the parameters towards zero. Shrinking makes the model less sensitive to noise, so variance goes down, but it pulls the model away from the exact fit, so bias goes up. It is a deliberate trade: a little more bias for a lot less variance.

The penalty, written out

Suppose we estimate a single number θ (theta) from data x1, …, xn. Without regularization we minimise:

Σ (xi − θ)²

With a ridge penalty of strength λ we minimise:

Σ (xi − θ)² + λθ²
  • Σ (capital sigma) means add up over all data points, from i = 1 to n.
  • λθ² is the penalty. The bigger λ is, the more a large θ costs.

The best θ for this problem is:

θ̂ = Σ xi / (n + λ)

Solving it with a small example

Take the data 2, 4, 6, so n = 3 and the sum is 12.

  1. No penalty, λ = 0: θ̂ = 12 / (3 + 0) = 4. This is the ordinary average.
  2. Penalty λ = 3: θ̂ = 12 / (3 + 3) = 12/6 = 2. The estimate moved halfway from 4 to 0.

Here is the same calculation in Python, using exact fractions.

from fractions import Fraction as F

data = [2, 4, 6]
n = len(data)
s = sum(data)
lam_none = 0
lam_pen = 3

plain = F(s, n + lam_none)
ridge = F(s, n + lam_pen)

print("sum of data:", s)
print("no penalty:", plain)
print("with penalty 3:", ridge)
sum of data: 12
no penalty: 4
with penalty 3: 2

The output matches the hand calculation.

How cross-validation helps choose the setting

You cannot choose λ or complexity by training error, because it always favours the most flexible model. Instead, cross-validation splits the training data into equal parts called folds, holds one fold out in turn, trains on the rest, measures the error on the held-out fold, and averages these errors. The setting with the lowest average is chosen. Each error is measured on data the model did not train on, so the estimate is honest.

Key ideaRegularization lowers variance by paying with a little bias. Cross-validation picks the best setting by measuring error on data the model did not train on.

GATE loves thisLearn the direction of each knob. A larger penalty λ raises bias and lowers variance. More model complexity lowers bias and raises variance.

Does a larger penalty make the model more or less likely to overfit?

Less likely. The parameters stay small, so the model cannot chase noise as hard. Variance falls, though bias may rise.

Why use held-out error instead of training error?

Training error always shrinks as the model gets more flexible, so it would always pick the most complex model. Held-out error penalises overfitting, because memorised training data does badly on new points.

Solved GATE-style problems

These problems are original, written in the style of GATE questions. They are not past exam questions. Try each one before reading the answer.

Reading the pattern in the errors

A linear regression model is fitted to data that clearly follows a curve. Its training error and test error are both large and close to each other. Which statement is correct? (MCQ, select one)

(A) The model has high variance and is overfitting.
(B) The model has high bias and is underfitting.
(C) The noise in the data is zero.
(D) Collecting more data will remove the error.

How to think about it

  1. What is asked. The option that describes both errors high and close together.
  2. Which idea applies. A model too simple for the pattern has high bias. Overfitting shows a large gap between training and test error, which is not the case here.
  3. Work it out. Both errors are large, so the model misses the pattern everywhere. That is underfitting, so (B). Option (A) needs a big gap. Option (C) is false because real data is noisy. Option (D) is false because a straight line cannot fit a curve however much data you add.
  4. Check. This matches the table in Concept 4: high bias gives high errors on both sets.

Answer: (B).

Adding up the three parts

A model has squared bias 2.5, variance 1.5 and noise variance σ² = 0.5. Find its expected squared error at a point. (NAT, give a decimal)

How to think about it

  1. What is asked. The total expected squared error.
  2. Which idea applies. Expected error = Bias² + Variance + σ².
  3. Work it out. Bias² is already squared, so use 2.5 as is. 2.5 + 1.5 = 4.0, then 4.0 + 0.5 = 4.5.
  4. Check. The total must be bigger than each part. 4.5 is bigger than 2.5, 1.5 and 0.5.

Answer: 4.5

Which statements about the tradeoff are true

Select all that apply. Consider a model family in which a complexity setting can be increased. (MSQ)

(A) Increasing model complexity usually lowers bias.
(B) Increasing model complexity usually raises variance.
(C) Ridge regularization with a larger penalty usually raises bias and lowers variance.
(D) Adding more training data usually increases variance.

How to think about it

  1. What is asked. Which of the four statements are true in general.
  2. Which idea applies. Complexity and penalty strength move bias and variance in opposite directions. More data makes estimates more stable.
  3. Work it out. (A) is true: a flexible model matches the pattern more closely. (B) is true: it reacts more to the training points. (C) is true: shrinking adds bias and removes variance. (D) is false: more data usually reduces variance.
  4. Check. Each true statement matches the rules in this topic. The false one contradicts the fact that more data stabilises estimates.

Answer: (A), (B) and (C). Statement (D) is false.

Expected error from a list of predictions

At one input the true value is f = 1. Three equally likely training sets give predictions 0, 2 and 4. The noise variance is σ² = 4. Find the expected squared error at this input as an exact fraction. (NAT)

How to think about it

  1. What is asked. The expected squared error, as a fraction.
  2. Which idea applies. Find the average prediction, the bias, the variance, then add the noise.
  3. Work it out. Average prediction: (0 + 2 + 4)/3 = 2. Bias = 2 − 1 = 1, so Bias² = 1. Distances from the average: −2, 0, 2. Squares: 4, 0, 4. Variance = 8/3. Total = 4 + 1 + 8/3 = 23/3, about 7.67.
  4. Check. Directly: 4 + average of (1 − p)². The gaps are 1, −1 and −3, with squares 1, 1, 9 averaging to 11/3. Then 4 + 11/3 = 23/3, which agrees.
from fractions import Fraction as F

preds = [F(0), F(2), F(4)]
probs = [F(1, 3)] * 3
f = F(1)
noise_var = F(4)

m = sum(p * q for p, q in zip(preds, probs))
bias_sq = (m - f) ** 2
var = sum(q * (p - m) ** 2 for p, q in zip(preds, probs))
total = noise_var + bias_sq + var
direct = noise_var + sum(q * (f - p) ** 2 for p, q in zip(preds, probs))

print("bias squared:", bias_sq)
print("variance:", var)
print("total:", total)
print("direct:", direct)
print("decimal:", round(float(total), 2))
bias squared: 1
variance: 8/3
total: 23/3
direct: 23/3
decimal: 7.67

Answer: 23/3, about 7.67.

Ridge estimate of a mean

The data points are 1, 2, 3 and 6. A ridge penalty with λ = 2 estimates a single value θ using θ̂ = Σxi / (n + λ). Find θ̂. (NAT)

How to think about it

  1. What is asked. The regularized estimate θ̂.
  2. Which idea applies. The formula from Concept 5.
  3. Work it out. Sum: 1 + 2 + 3 + 6 = 12. Number of points n = 4. Denominator: 4 + 2 = 6. Estimate: 12/6 = 2.
  4. Check. The plain mean is 12/4 = 3. The penalty pulled the estimate down to 2, towards zero.
from fractions import Fraction as F

data = [1, 2, 3, 6]
n = len(data)
lam = 2

theta = F(sum(data), n + lam)
print("sum:", sum(data))
print("ridge estimate:", theta)
print("plain mean:", F(sum(data), n))
sum: 12
ridge estimate: 2
plain mean: 3

Answer: 2

Training size inside cross-validation

A training set has 10 points. 5-fold cross-validation splits them into 5 equal folds. In each round one fold is held out and the model trains on the others. How many points does the model train on in each round? (NAT)

How to think about it

  1. What is asked. The number of training points per round.
  2. Which idea applies. One fold is held out each round; the rest are used for training.
  3. Work it out. Fold size: 10 / 5 = 2. Held out per round: 2. Training points: 10 − 2 = 8.
  4. Check. Five folds of 2 make 10 points, so each point is held out once over the five rounds.

Answer: 8

How a larger penalty changes the errors

A ridge regression model is trained on one fixed training set. The penalty λ is increased from 0 to a very large value. Select all statements that are generally true. (MSQ)

(A) The bias of the model increases as λ grows.
(B) The variance of the model decreases as λ grows.
(C) The training error increases as λ grows.
(D) The lowest test error is always reached at λ = 0.

How to think about it

  1. What is asked. Which statements about ridge regression on one training set are generally true.
  2. Which idea applies. A larger penalty shrinks the parameters. Shrinking adds bias, removes variance, and makes the fit follow the training points less closely.
  3. Work it out. In θ̂ = Σxi/(n + λ), a larger λ makes the denominator larger, so θ̂ moves towards zero and away from the data average. More bias: (A) is true. The estimate depends less on the data: (B) is true. The fit is pulled away from the training points, so the training error rises: (C) is true. Statement (D) is false, because a moderate penalty often lowers test error by reducing variance.
  4. Check. Each true statement matches the direction of the knobs. The false statement says the penalty never helps, which contradicts the purpose of regularization.

Answer: (A), (B) and (C). Statement (D) is false.

Unequal chances in the predictions

At one input the true value is f = 2 and the noise variance is σ² = 1. Across training sets, the model predicts 0 with probability 1/4 and 4 with probability 3/4. Find the expected squared error at this input. (NAT)

How to think about it

  1. What is asked. The total expected squared error, with unequal probabilities.
  2. Which idea applies. Each average must weight every prediction by its probability.
  3. Work it out. Average prediction: 0 × 1/4 + 4 × 3/4 = 3. Bias = 3 − 2 = 1, so Bias² = 1. Distances from 3: −3 and 1. Squares: 9 and 1. Weighted variance: 9 × 1/4 + 1 × 3/4 = 3. Total = 1 + 3 + 1 = 5.
  4. Check. Directly: 1 + weighted average of (2 − p)². The gaps are 2 and −2, squares 4 and 4, so the average is 4, giving 1 + 4 = 5.
from fractions import Fraction as F

preds = [F(0), F(4)]
probs = [F(1, 4), F(3, 4)]
f = F(2)
noise_var = F(1)

m = sum(p * q for p, q in zip(preds, probs))
bias_sq = (m - f) ** 2
var = sum(q * (p - m) ** 2 for p, q in zip(preds, probs))
direct = noise_var + sum(q * (f - p) ** 2 for p, q in zip(preds, probs))

print("mean prediction:", m)
print("bias squared:", bias_sq)
print("variance:", var)
print("expected error:", noise_var + bias_sq + var)
print("direct check:", direct)
mean prediction: 3
bias squared: 1
variance: 3
expected error: 5
direct check: 5

Answer: 5

Exam-level practice

Exam-level 1: Decomposing expected error (NAT, 2 marks)

For a regression model at a fixed input, the expected squared error is 2.5, the noise variance is 0.4 and the variance of the prediction across training sets is 0.6. Find the squared bias.

How to think about it

  1. What is asked. The bias² term of the decomposition.
  2. Which idea applies. Expected error = bias² + variance + irreducible noise.
  3. Work it out. bias² = 2.5 − 0.6 − 0.4 = 1.5.
  4. Check. All three parts are nonnegative, as they must be.

Answer: 1.5.

Exam-level 2: Effect of model complexity (MSQ, 2 marks)

As the degree of a polynomial regression model rises (with fixed data), which usually happen? (A) Training error falls. (B) Bias falls. (C) Variance rises. (D) Test error always falls.

How to think about it

  1. What is asked. Typical trends as flexibility increases.
  2. Which idea applies. More flexible models fit training data better but react more to noise.
  3. Work it out. (A) True. (B) True. (C) True. (D) Test error is U-shaped: it falls then rises. False.
  4. Check. The best degree sits at the bottom of the test error curve.

Answer: (A), (B) and (C).

Exam-level 3: Bias of a shrunk estimator (NAT, 2 marks)

X1, ..., Xn are independent with mean μ = 10 and variance σ² = 25, and n = 25. The estimator is T = 0.8 X̄. Find the mean squared error of T.

How to think about it

  1. What is asked. MSE = bias² + variance.
  2. Which idea applies. E[T] = 0.8μ and Var(T) = 0.64 σ²/n.
  3. Work it out. Bias = 8 − 10 = −2, bias² = 4. Var = 0.64 · 1 = 0.64. MSE = 4.64.
  4. Check. The plain mean X̄ has MSE 1, so this shrinkage hurts here because μ is large.
mu, s2, n, c = 10, 25, 25, 0.8
print("MSE = %.2f" % ((c * mu - mu) ** 2 + c * c * s2 / n))

MSE = 4.64

Answer: 4.64.

Remember these

  1. Bias is about the average prediction. Variance is about how much predictions wobble between training sets.
  2. Expected squared error = Bias² + Variance + σ². Only the first two depend on the model.
  3. High bias means underfitting. High variance means overfitting.
  4. Raising complexity lowers bias and raises variance. Raising the penalty does the reverse.
  5. Training error alone cannot tell you whether a model is good. Use held-out data.
  6. In the ridge estimate the denominator is n + λ, so a larger λ pulls the answer towards zero.
