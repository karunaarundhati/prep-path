Python functions & recursion

A function is a named, reusable block of code, and recursion is a function that calls itself. Both appear often in the code-tracing questions of the Data Science and AI paper, so this page teaches you to follow them one call at a time.

The idea in plain words

Think of a recipe card for making tea. The card has a name, "make tea", and a list of steps. Whenever you want tea, you read the card. You do not write the steps again each time. A function in Python is a recipe card for code. You give the block a name, write its steps once, and then call it by name whenever you need it.

Some recipes need ingredients. The ingredients you hand to a function are called arguments. Some recipes give something back, such as a cup of tea. What a function gives back is its return value.

Now imagine a recipe card that says "to make a stack of pancakes, make one pancake, then make a stack of one fewer pancakes". The card refers to itself. This is recursion. It sounds strange, but it is the natural way to describe many problems, such as factorials, number puzzles and tree structures. Recursion also needs a stop rule, or the cooking never ends. That stop rule is called the base case.

Why this matters for GATE. Questions often show a small function, sometimes recursive, and ask for the printed value or the number of calls. The method is always the same: write down each call, follow the code in order, and keep a careful count. You will practise this method on this page.

Key terms

Function
A named block of code that does one job. Defined with def. Plain meaning: a recipe card. Precise definition: a callable object whose body runs when it is called.
Definition
The code that creates a function, starting with def name(...):. Writing the definition does not run the body.
Call
Running a function by writing its name followed by brackets, such as add(2, 3).
Parameter
A name listed in the definition, such as a in def add(a, b). It is a placeholder.
Argument
The actual value passed in a call, such as 2 in add(2, 3).
Default argument
A value given to a parameter in the definition, such as greeting="Hello". It is used when the caller leaves that argument out.
Keyword argument
An argument passed by name in a call, such as greeting="Hi". Its position does not matter.
Return value
The value a function sends back, given by return. If a function has no return, it gives back None.
None
Python's special "no value" object. You will see it printed when a function does not return anything.
Scope
The part of a program where a name can be used. Plain meaning: where a label is visible. Precise definition: the region of code in which a name binding is accessible.
Local variable
A variable created inside a function. It exists only while that function runs.
Global variable
A variable created outside all functions, at the top level of the file.
Recursion
A function that calls itself, directly or through other calls, to solve a smaller version of the same problem.
Base case
The simplest input, where the function answers directly without calling itself. It stops the recursion.
Recursive case
The part of the function that calls itself on a smaller input.
Call stack
The list of calls that are currently active. The most recent call is on top. When a call returns, it is removed from the top.
Recursion tree
A diagram where each box is one call and each child box is a call made by its parent.
Factorial
The product of all whole numbers from 1 up to n, written n!. For example, 5! = 1 * 2 * 3 * 4 * 5 = 120.
Fibonacci number
The sequence 0, 1, 1, 2, 3, 5, 8, 13, ... where each number is the sum of the two before it.
GCD
Greatest common divisor: the largest number that divides two given numbers exactly.
Iteration
Repeating work with a loop, rather than with a function calling itself.

Defining and calling functions

Why functions exist

Suppose a program needs to add two numbers in ten places. You could copy the addition ten times, but if you later want to change it, you must change ten copies. A function solves this. You write the logic once and call it ten times. This idea is called reuse.

The shape of a function

A function has three parts: the def line with its name and parameters, a body indented underneath, and usually a return line.

def add(a, b):        # name is add, parameters are a and b
    return a + b      # body: work out the result and send it back

Read the call add(2, 3) like this. Python puts 2 into the parameter a and 3 into the parameter b. It runs the body, which computes 2 + 3. The return sends 5 back to the place where the call was written.

Default and keyword arguments

A default argument gives a parameter a starting value. The caller may leave it out. A keyword argument names the parameter in the call, so the order of the arguments can change.

def add(a, b):
    return a + b

def greet(name, greeting="Hello"):
    return greeting + ", " + name

print(add(2, 3))
print(greet("Asha"))
print(greet("Ravi", greeting="Namaste"))
print(greet(greeting="Hi", name="Meena"))
5
Hello, Asha
Namaste, Ravi
Hi, Meena

In the first greet call, the second parameter is left out, so it uses its default "Hello". In the last call, both arguments are named, so their order is free.

TrapA function with no return still runs its body, but it gives back None. A common exam mistake is to think a function "gives" the value of its last line. It does not. Only return sends a value back. The example def sq(n): n * n followed by print(sq(4)) prints None.

What does print(greet("Ravi")) print, using the definition above?

It prints Hello, Ravi. The missing greeting argument takes its default value "Hello".

Is a positional argument allowed after a keyword argument in a call?

No. Positional arguments must come first. greet(name="Ravi", "Hi") is a syntax error. greet("Ravi", greeting="Hi") is fine.

Scope: local and global variables

Where can a name be seen?

Scope answers the question "where is this label visible?". Imagine a school with a notice board in the main hall, which everyone can read, and a note on one teacher's desk, which only that teacher can see. A global variable is the notice board. A local variable is the note on the desk.

In Python:

  • A variable assigned inside a function is local. It is created when the function runs and disappears when the function returns.
  • A variable assigned at the top level of the file is global.
  • A function can read a global variable. But an assignment inside the function creates a new local variable with the same name. The global one is not changed.
  • To change a global variable inside a function, write global name first.

Key ideaAn assignment inside a function makes that name local for the whole function. The name is not looked up outside. This is the reason for many errors in exam questions.

A runnable example

x = 10
def f():
    x = 20
    print("inside f:", x)
f()
print("outside f:", x)

def g():
    global x
    x = 30
g()
print("after g:", x)

def h(v):
    v = v + 1
    return v
y = 5
print(h(y), y)
inside f: 20
outside f: 10
after g: 30
6 5

Step through it. In f, the assignment x = 20 makes a new local x. The global x stays 10, as the next print shows. In g, the line global x tells Python to use the global x, so the value becomes 30. In h, the parameter v is a copy of the number 5. Changing v does not change y. The function returns 6, and y is still 5.

TrapNumbers, strings and tuples are passed in as values, so a function cannot change the caller's variable by reassigning its parameter. Lists are different. If a function changes a list in place, for example with append, the caller sees the change. This is covered with aliasing on the previous page.

What is printed by def k(): z = 1 then k() then print(z), if z was never defined at the top level?

Python prints an error, a NameError. The z inside k was local and disappeared when k returned, so no z exists at the top level.

Why does h(y) leave y unchanged?

Because v is a new name bound to the value 5. The line v = v + 1 moves the label v to 6. The label y still points to 5.

Recursion: base case and recursive case

The big idea

A recursive function solves a problem by solving a smaller copy of the same problem. It must do two things:

  1. Have a base case: an input so small that the answer is given directly, with no further call.
  2. Have a recursive case: a step that calls the same function on a smaller input, and then uses the answer.

If the base case is missing, or if the calls never move towards it, the calls go on forever. Python then stops the program with a RecursionError.

What happens on the call stack

Each call gets its own set of local variables. Python keeps a list of the active calls, called the call stack. A new call is placed on top. When the call finishes, it is removed, and its return value goes to the call below it.

The next example prints a message when each call starts and when it ends. Follow the order carefully. Calls go down first, then the messages come back up.

def countdown(n):
    print("enter", n)
    if n == 0:
        print("base case")
        return
    countdown(n - 1)
    print("leave", n)

countdown(2)
enter 2
enter 1
enter 0
base case
leave 1
leave 2

Here is the call stack at the moment "base case" is printed. The top of the stack is the newest call.

top     countdown(0)   waiting for nothing, it returns now
        countdown(1)   waiting for countdown(0) to finish
bottom  countdown(2)   waiting for countdown(1) to finish

When countdown(0) returns, the top call is removed, and countdown(1) continues with the line print("leave", 1). Then it returns, and countdown(2) prints "leave 2". This "down then back up" order is the most important thing to see when you trace recursion.

Key ideaEvery recursive call waits for the call it made. So the lines written after a recursive call run only on the way back up. In countdown, the line print("leave", n) runs after the deeper calls are finished.

A recursion tree

When a function calls itself twice, the picture becomes a tree. Each node is one call. The tree for fib(4) is in the next section. Counting the nodes gives you the total number of calls, which is often what a GATE question asks.

In countdown(3), how many lines does the function print in total?

There are 4 calls (3, 2, 1, 0). Each call prints "enter", and the base case prints one more line. Each call except the base case prints "leave" on the way back, so there are 3 "leave" lines. The total is 4 + 1 + 3 = 8 lines.

What would happen if the base case in countdown were removed?

The calls would never stop. The number would go to 0, then -1, then -2, and so on. Python would end the program with a RecursionError.

Classic recursive problems

Factorial

The factorial of n, written n!, is the product of the numbers 1 up to n. For example, 4! = 4 * 3 * 2 * 1 = 24. A useful fact is that n! = n * (n-1)!. So you can define it by a smaller copy of itself:

fact(0) = 1 (base case), fact(n) = n * fact(n-1) for n > 0 (recursive case)

Trace fact(3) by hand. The call fact(3) needs fact(2), which needs fact(1), which needs fact(0). The base case gives 1. Now the answers come back up: fact(1) = 1 * 1 = 1, fact(2) = 2 * 1 = 2, fact(3) = 3 * 2 = 6.

Fibonacci

The Fibonacci numbers start with 0 and 1, and each later number is the sum of the two before it: 0, 1, 1, 2, 3, 5, 8, 13. The recursive rule is:

fib(0) = 0, fib(1) = 1, fib(n) = fib(n-1) + fib(n-2) for n >= 2

The Fibonacci definition has two base cases, not one. The reason is that the recursive case looks back two steps, so both starting values must be known.

Greatest common divisor by Euclid's method

The GCD of two numbers can be found with a neat rule. If the second number is 0, the GCD is the first number. Otherwise, replace the pair (a, b) by (b, a % b), and try again. This is Euclid's algorithm, and it is one of the oldest algorithms known.

gcd(a, 0) = a, gcd(a, b) = gcd(b, a % b) for b > 0

Here are all three problems in one runnable program.

def fact(n):
    if n == 0:
        return 1
    return n * fact(n - 1)

def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

def gcd(a, b):
    if b == 0:
        return a
    return gcd(b, a % b)

print(fact(5))
print(fib(0), fib(1), fib(2), fib(3), fib(4), fib(5), fib(6), fib(7))
print(gcd(48, 18))
print(gcd(17, 5))
120
0 1 1 2 3 5 8 13
6
1

Check the GCD by hand. gcd(48, 18) becomes gcd(18, 12), since 48 % 18 is 12. Then gcd(12, 6), since 18 % 12 is 6. Then gcd(6, 0), since 12 % 6 is 0. The base case returns 6. The numbers 17 and 5 have no common factor, so the answer is 1.

Counting calls in Fibonacci

The recursive Fibonacci function repeats a lot of work. Look at the recursion tree for fib(4):

                 fib(4)
              /          \
          fib(3)          fib(2)
          /     \         /    \
      fib(2)   fib(1)  fib(1)  fib(0)
      /    \
  fib(1)  fib(0)

Count the boxes. There are 9 calls. Two of them are fib(2), and fib(1) appears three times. The same answer is computed again and again. Techniques such as memoization (saving answers already computed) remove this repeated work, but for this topic you only need to count the calls.

GATE loves thisA common question asks how many calls fib(n) makes in total. For this naive version, the count is 2 * fib(n+1) - 1, where fib(n+1) is the next Fibonacci number. Check it with fib(4): fib(5) is 5, and 2 * 5 - 1 = 9, which matches the tree above.

What is fact(0)?

It is 1. This is the base case, and it returns directly without a call.

What is gcd(12, 0)?

It is 12. The second number is 0, so the base case returns the first number.

Recursion versus iteration

Two ways to repeat work

Every recursive function can be rewritten with a loop, and every loop can be rewritten as recursion. This is called iteration when it uses a loop. Here is the factorial written with a loop:

def fact_loop(n):
    result = 1
    for i in range(1, n + 1):
        result = result * i
    return result

print(fact_loop(5))
120

Both versions print the same answer. Which one should you use?

PointRecursionIteration (loop)
Natural forTrees, nested problems, divide and conquerSimple counting and accumulating
MemoryEach call adds a frame to the call stackUsually a fixed number of variables
RiskMissing base case gives RecursionErrorMissing change to the loop variable gives an endless loop
SpeedExtra cost for every callUsually a little faster in Python

Use recursion when the problem itself has a self-similar shape, such as a folder inside a folder. Use a loop when a simple repeat is all you need. In exams, read the question carefully. If it says "recursive function" you must trace calls. If it asks for a loop, you must trace iterations.

A small trace with several results

def f(n):
    if n <= 1:
        return 1
    return f(n - 1) + f(n - 2)

print(f(4))
5

Draw the tree. f(4) calls f(3) and f(2). f(3) returns f(2) + f(1), which is 2 + 1 = 3. f(2) returns f(1) + f(0), which is 1 + 1 = 2. So f(4) is 3 + 2 = 5. The base case here is "n is 1 or less", so both f(1) and f(0) return 1.

Which is more likely to crash for a very large input, a loop or a recursive function with no base case?

The recursive function. A missing base case makes the calls pile up on the call stack until Python raises a RecursionError.

Does fact_loop(0) return 1 or 0?

It returns 1. The range(1, 1) is empty, so the loop never runs, and result stays at its starting value of 1.

Solved GATE-style problems

These problems are original, written in the GATE style, and are not taken from any past paper. Trace each one on paper before you read the steps.

Default argument

What is printed by the following code? Write both numbers, separated by one space.

def f(x, y=3):
    return x * 10 + y
print(f(2), f(2, 5))

How to think about it

  1. What is asked. Two numbers, one from each call.
  2. Which idea applies. The first call leaves y out, so it uses the default 3. The second call passes 5.
  3. Work it out. f(2) is 2 * 10 + 3 = 23. f(2, 5) is 2 * 10 + 5 = 25.
  4. Check. The second value is 5 more than the first, which matches the change from 3 to 5 in y.

Answer: 23 25

Functions with no return

Consider the code def sq(n): followed by an indented line n * n. Select all statements that are true. (A) Calling sq(4) gives 16. (B) Calling sq(4) gives None. (C) print(sq(4)) prints None. (D) sq cannot be called.

How to think about it

  1. What is asked. Every true statement about a function that has no return.
  2. Which idea applies. Only return sends a value back. Without it the function gives None.
  3. Work it out. (A) is false, because the value 16 is computed but thrown away. (B) is true. (C) is true, since print shows the returned None. (D) is false, because the function can be called as normal.
  4. Check. Adding return in front of n * n would make A and not B or C true, which confirms the reasoning.

Answer: (B) and (C)

Factorial quotient

Give the number printed by this code.

def fact(n):
    if n == 0:
        return 1
    return n * fact(n - 1)
print(fact(4) // fact(2))

How to think about it

  1. What is asked. The floor division of two factorials.
  2. Which idea applies. Each call of fact returns a factorial, and // is floor division.
  3. Work it out. fact(4) = 4 * 3 * 2 * 1 = 24. fact(2) = 2 * 1 = 2. Then 24 // 2 = 12.
  4. Check. 4! / 2! is 3 * 4 = 12, which is the same as the tree result.

Answer: 12

Parameter is a copy

What two numbers are printed? Give them in order, separated by one space.

total = 100
def spend(total):
    total = total - 30
    return total
print(spend(total), total)

How to think about it

  1. What is asked. The return value of spend, and the value of the global total after the call.
  2. Which idea applies. The parameter total is a local name. Its assignment does not touch the global name.
  3. Work it out. Inside spend, the parameter starts as 100. The line total = total - 30 makes it 70, and that is returned. The global total was never assigned, so it is still 100.
  4. Check. The printed pair is 70 then 100, showing that the two names are separate.

Answer: 70 100

Counting calls in naive Fibonacci

Give the two numbers printed, separated by one space. The variable calls counts how many times fib starts running.

calls = 0
def fib(n):
    global calls
    calls = calls + 1
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)
print(fib(6), calls)

How to think about it

  1. What is asked. The value of fib(6) and the total number of calls made.
  2. Which idea applies. The Fibonacci values, and the count formula 2 * fib(n+1) - 1 for naive calls.
  3. Work it out. The Fibonacci sequence is 0, 1, 1, 2, 3, 5, 8, so fib(6) is 8. For the number of calls, fib(6) needs 2 * fib(7) - 1. fib(7) is 13, so 2 * 13 - 1 = 25.
  4. Check. For fib(4) the formula gave 9, which matched the tree. The same method works here, so 25 is consistent.

Answer: 8 25

Tracing a walk

List the lines printed by this code, in order.

def walk(n):
    if n == 0:
        return
    print("down", n)
    walk(n - 1)
    print("up", n)
walk(3)

How to think about it

  1. What is asked. Every printed line, in the exact order.
  2. Which idea applies. A recursive call stops the current pass until it returns. The line after the call runs on the way back up.
  3. Work it out. Start with walk(3). It prints "down 3" and calls walk(2), which prints "down 2" and calls walk(1). That prints "down 1" and calls walk(0). walk(0) returns with no output. Back in walk(1), it prints "up 1". Back in walk(2), it prints "up 2". Back in walk(3), it prints "up 3".
  4. Check. There are three "down" lines and three "up" lines, one pair for each non-zero call. The "up" lines come in reverse order, which is the mark of a call stack.

Answer: down 3, down 2, down 1, up 1, up 2, up 3 (one per line)

Digit sum by recursion

Give the number printed by this code.

def mystery(n, acc=0):
    if n == 0:
        return acc
    return mystery(n // 10, acc + n % 10)
print(mystery(4721))

How to think about it

  1. What is asked. The value returned for the input 4721.
  2. Which idea applies. n % 10 gives the last digit. n // 10 removes the last digit. The parameter acc collects a running total.
  3. Work it out. Step 1: n = 4721, last digit 1, acc = 0 + 1 = 1, next n = 472. Step 2: last digit 2, acc = 3, next n = 47. Step 3: last digit 7, acc = 10, next n = 4. Step 4: last digit 4, acc = 14, next n = 0. The base case returns acc = 14.
  4. Check. The digits of 4721 are 4, 7, 2 and 1, and 4 + 7 + 2 + 1 = 14.

Answer: 14

Two recursive calls

Give the number printed by this code.

def f(n):
    if n <= 1:
        return 1
    return f(n - 1) + f(n - 2)
print(f(4))

How to think about it

  1. What is asked. The return value of f(4).
  2. Which idea applies. Both base cases, n = 0 and n = 1, return 1. Each other call adds two smaller calls.
  3. Work it out. f(0) = 1 and f(1) = 1. f(2) = f(1) + f(0) = 2. f(3) = f(2) + f(1) = 2 + 1 = 3. f(4) = f(3) + f(2) = 3 + 2 = 5.
  4. Check. The values 1, 1, 2, 3, 5 are the Fibonacci numbers, shifted because this version starts with 1 and 1 instead of 0 and 1.

Answer: 5

Exam-level practice

Exam-level 1: Recursion count (NAT, 2 marks)

def f(n): return 1 if n <= 1 else f(n − 1) + f(n − 2). How many calls to f are made in total when f(6) is evaluated (including the first call)?

How to think about it

  1. What is asked. The size of the recursion tree.
  2. Which idea applies. Let C(n) be the number of calls. C(0) = C(1) = 1 and C(n) = 1 + C(n − 1) + C(n − 2).
  3. Work it out. C(2) = 3, C(3) = 5, C(4) = 9, C(5) = 15, C(6) = 25.
  4. Check. The code counts with a global counter.
calls = 0
def f(n):
    global calls
    calls += 1
    return 1 if n <= 1 else f(n - 1) + f(n - 2)
f(6)
print(calls)

25

Answer: 25.

Exam-level 2: Closures (MCQ, 2 marks)

What does this print? fs = [lambda: i for i in range(3)]; print([g() for g in fs]) (A) [0, 1, 2] (B) [2, 2, 2] (C) [0, 0, 0] (D) Error

How to think about it

  1. What is asked. Late binding of loop variables in closures.
  2. Which idea applies. Each lambda looks up i when it is called, not when it is created.
  3. Work it out. After the comprehension, i is 2 in that scope, so every call returns 2.
  4. Check. Writing lambda i=i: i would capture each value.
fs = [lambda: i for i in range(3)]
print([g() for g in fs])

[2, 2, 2]

Answer: (B).

Exam-level 3: Recursive sum of digits (NAT, 2 marks)

def g(n): return n if n < 10 else g(sum(int(d) for d in str(n))). Find g(987654321).

How to think about it

  1. What is asked. The repeated digit sum.
  2. Which idea applies. The digital root equals 1 + (n − 1) mod 9 for n > 0.
  3. Work it out. Digit sum = 45, then 4 + 5 = 9. g = 9.
  4. Check. 987654321 is divisible by 9, so the root is 9.
def g(n):
    return n if n < 10 else g(sum(int(d) for d in str(n)))
print(g(987654321))

9

Answer: 9.
