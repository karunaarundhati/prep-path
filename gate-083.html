Linked list (recap)

A linked list is a chain of small boxes, where each box stores a value and a pointer to the next box. This quick recap covers singly and doubly linked lists, how to insert and delete, how to walk the list, and how their costs compare with arrays, which GATE asks about often.

The idea in plain words

Think of a train. Each carriage holds some passengers, and it is hitched to the next carriage. To visit every carriage you start at the engine and walk from one to the next. You cannot jump straight to carriage 7. You must pass carriages 1 to 6 first.

A linked list works the same way. Each box, called a node, stores a value and a pointer, which is a reference that says where the next node is. The list itself is remembered by one pointer, called the head, which points to the first node.

Why this matters for GATE: linked lists appear in questions about the cost of insertion and deletion, about how many pointers change, and about comparing lists with arrays. The key fact is simple. Changing a link is cheap. Finding the place to change is often the expensive part.

Key terms

Node
A box holding a value and one or more pointers.
Pointer (link)
A stored address that tells you where another node is.
Head
The pointer to the first node of the list. If the list is empty, the head is empty (None in Python).
Singly linked list
A list where each node has one pointer, to the next node.
Doubly linked list
A list where each node has two pointers, one to the next node and one to the previous node.
Traversal
Visiting every node in order, by following the pointers from the head.
Predecessor
The node just before a given node.
Time complexity
How the number of steps grows as the list gets longer. O(1) means a fixed number of steps. O(n) means about n steps for n nodes.

Singly linked lists

A singly linked list stores the values 10, 20 and 30 like this. Each arrow is a pointer.

head → [10 | ●] → [20 | ●] → [30 | None]

The last node points to nothing, so you know the list has ended. To read the whole list you start at the head and follow each arrow. This is traversal. Finding the node at position k needs k steps, so reading the k-th value costs O(k), and in the worst case O(n).

Here is a small Python version. The class Node holds one value and one pointer. The class LinkedList holds the head and offers the operations we will use.

class Node:
    def __init__(self, data):
        self.data = data
        self.next = None

class LinkedList:
    def __init__(self):
        self.head = None

    def insert_front(self, data):
        node = Node(data)
        node.next = self.head
        self.head = node

    def insert_end(self, data):
        node = Node(data)
        if self.head is None:
            self.head = node
            return
        cur = self.head
        while cur.next is not None:
            cur = cur.next
        cur.next = node

    def delete(self, data):
        if self.head is None:
            return False
        if self.head.data == data:
            self.head = self.head.next
            return True
        prev = self.head
        while prev.next is not None:
            if prev.next.data == data:
                prev.next = prev.next.next
                return True
            prev = prev.next
        return False

    def to_list(self):
        items = []
        cur = self.head
        while cur is not None:
            items.append(cur.data)
            cur = cur.next
        return items

lst = LinkedList()
lst.insert_end(10)
lst.insert_end(20)
lst.insert_front(5)
print(lst.to_list())
lst.delete(20)
print(lst.to_list())
print(len(lst.to_list()))
print(lst.delete(99))
[5, 10, 20]
[5, 10]
2
False

Read the output line by line. The insert at the front gave 5 in the first place. The delete of 20 removed the last node by changing one pointer, the pointer of node 10, so it now points to None. The search for 99 found nothing, so the method returned False.

TrapAlways check for an empty list before you touch head.next. Trying to read a field of None is an error, not a zero.

In the code above, which pointer changes when 20 is deleted?

The next pointer of the node holding 10. It is changed from pointing to 20 to pointing to None.

Can you reach the third node of a singly linked list without visiting the first two?

No. You must follow the pointers from the head, one node at a time.

Insertion and deletion

Insertion and deletion are cheap only when you already hold the right pointer. The cost depends on where you act.

  • Insert at the front. Make the new node point to the old head, then move the head to the new node. Two pointer changes, no walking. This is O(1).
  • Insert at the end. With only a head pointer, you must walk to the last node first. That takes n steps for n nodes, so this is O(n). If the list also keeps a tail pointer, this becomes O(1).
  • Insert after a given node. If you already hold a pointer to that node, change two pointers. This is O(1).
  • Delete the first node. Move the head to the second node. This is O(1).
  • Delete a node by value. You must find its predecessor first, so this is O(n) in the worst case.

Here is a worked example. The list is 10, 20, 30, 40. We delete 30. The predecessor of 30 is 20. We set the pointer of 20 to point to 40, skipping 30. Nothing else changes. The node 30 is now unreachable, and the language removes it.

Before: 10 → 20 → 30 → 40 → None
After: 10 → 20 → 40 → None

Key ideaDeleting a node needs the pointer to the node before it. In a singly linked list you usually find that by walking from the head, which is why deleting by value is O(n).

What is the cost of inserting at the front of a singly linked list with only a head pointer?

O(1). Two pointers change and nothing is walked.

Why does deleting the node 30 need the node 20?

Because the pointer that must be changed belongs to 20. Only 20 can be redirected from 30 to 40.

Doubly linked lists

A doubly linked list gives each node two pointers: next for the node after it, and prev for the node before it. It is like a train where each carriage has a hook at both ends.

None ← [10] ⇄ [20] ⇄ [30] → None

The extra pointer costs memory, because each node stores one more reference. In return, you can walk in both directions, and you can delete a node when you already hold a pointer to it, without walking from the head.

To delete a node x in a doubly linked list, set x.prev.next to x.next, and set x.next.prev to x.prev. Take care with the first and last nodes, where one of these pointers is None. The whole change takes a fixed number of steps, so it is O(1).

TrapA doubly linked list does not make search faster. Finding a value still walks the list, which is O(n). The gain is only in insertion and deletion once you hold a pointer to the place.

What does a doubly linked list gain compared with a singly linked list?

It can move backward, and it can delete a node in O(1) when a pointer to that node is given. It costs one extra pointer per node.

How many pointers change when a middle node is deleted from a doubly linked list?

Two: the next pointer of its predecessor and the prev pointer of its successor.

Comparing with arrays

An array stores its items side by side in memory, so you can jump directly to item k. A linked list stores each item in a separate node, and you must walk to it. This difference drives most GATE comparisons.

OperationSingly linked list (head only)Doubly linked list (head and tail)Array
Access the k-th itemO(k)O(k)O(1)
Insert at the frontO(1)O(1)O(n)
Insert at the endO(n)O(1)O(1) amortised
Delete the frontO(1)O(1)O(n)
Delete a given nodeO(n)O(1)O(n) to find, then shift
Search by valueO(n)O(n)O(n) unsorted

The table says: use an array when you read by position often. Use a linked list when you insert or delete at the front or at a known place often, and you do not need fast access by position.

GATE loves thisRead the question for the phrase "given a pointer to the node" or "at the beginning". These phrases change the answer from O(n) to O(1).

Which is faster for reading the 1000th item: an array or a singly linked list?

An array. Its access is O(1). The linked list needs 1000 steps from the head.

What does "amortised" mean in the table?

It means the average cost over a long run of operations is constant, even though a single operation may occasionally be slow, for example when an array must be resized.

Solved GATE-style problems

These problems are original, written in the GATE style. They are not real past questions. Trace the pointers on paper before you check with code.

Order of values after three insertions

An empty singly linked list receives 10 at the end, then 20 at the end, then 5 at the front. In what order are the values read from the head?

How to think about it

  1. What is asked. The order of the values from the head.
  2. Which idea applies. Insert at the end adds after the last node. Insert at the front puts the new node first.
  3. Work it out. After the first two steps the list is 10, 20. The front insertion puts 5 first, so the list is 5, 10, 20.
  4. Check. Run the code below. A Python list stands in for the order of values.
items = []
items.append(10)
items.append(20)
items.insert(0, 5)
print(items)
[5, 10, 20]

Answer: 5, 10, 20.

Cheapest insertion

A singly linked list has only a head pointer. Which operation costs O(1): insert at the front, or insert at the end? Give one word.

How to think about it

  1. What is asked. The cheaper of two insertions.
  2. Which idea applies. Insert at the end needs a walk to the last node, but insert at the front does not.
  3. Work it out. Insert at the front changes two pointers and walks nothing. So it is O(1).
  4. Check. A walk over n nodes takes n steps, so insert at the end is O(n). The front wins.

Answer: front.

Select all true statements about list costs

Select all that apply.

  • (A) In a singly linked list, deleting a node when only its pointer is given takes O(n) time in the worst case.
  • (B) In a doubly linked list, deleting a node when its pointer is given takes O(1) time.
  • (C) An array gives O(1) access to its k-th item, but a singly linked list needs k steps.
  • (D) A singly linked list can be read backward in O(1) time per node.

How to think about it

  1. What is asked. Which statements are true.
  2. Which idea applies. Deletion needs the predecessor, and only doubly linked nodes can reach it directly.
  3. Work it out. (A) With only the pointer to the node, you cannot reach its predecessor without walking from the head, so O(n). True. (B) The node holds prev, so two pointers change directly. True. (C) Array access is O(1), and reaching the k-th node costs k steps. True. (D) A singly linked list has no backward pointer, so reading backward needs a walk from the head. False.
  4. Check. The statements are checked by the reasoning above. No code is needed.

Answer: (A), (B) and (C).

Visits to reach the end

A singly linked list has 5 nodes, and the head points to the first. To insert a new node at the end, the algorithm walks from the head until it reaches the last node. How many nodes does the walk visit, counting the last node? This is a NAT question.

How to think about it

  1. What is asked. The number of node visits in the walk.
  2. Which idea applies. Each step visits one node, and the walk stops at the last node.
  3. Work it out. The walk visits node 1, node 2, node 3, node 4, and node 5. That is 5 visits.
  4. Check. Run the code below. It follows the next pointers and counts each visit.
nxt = {"a": "b", "b": "c", "c": "d", "d": "e", "e": None}
cur = "a"
steps = 0
while cur is not None:
    steps = steps + 1
    cur = nxt[cur]
print(steps)
5

Answer: 5.

Deleting from the middle

The list 10, 20, 30, 40 is stored with a next pointer for each node. The node 30 is deleted by changing one pointer. Which values are read from the head after the deletion?

How to think about it

  1. What is asked. The values read from the head after the change.
  2. Which idea applies. The predecessor of 30 is 20. Its pointer must skip over 30.
  3. Work it out. Set the next pointer of 20 to 40. The list is now 10, 20, 40.
  4. Check. Run the code below.
nxt = {10: 20, 20: 30, 30: 40, 40: None}
nxt[20] = nxt[30]
del nxt[30]
out = []
cur = 10
while cur is not None:
    out.append(cur)
    cur = nxt[cur]
print(out)
[10, 20, 40]

Answer: 10, 20, 40.

Reversing a singly linked list

The list 1, 2, 3, 4 is reversed by changing the next pointers, one node at a time. Which values are read from the new head? Give the list in order.

How to think about it

  1. What is asked. The order of values after reversal.
  2. Which idea applies. For each node, save its old next pointer, point it backward to the previous node, then move both markers forward.
  3. Work it out. Start with prev = None and cur = 1. Each step makes cur point back to prev. After node 1 points to None, node 2 points to 1, node 3 points to 2, and node 4 points to 3. The last node, 4, becomes the new head. Reading from 4 gives 4, 3, 2, 1.
  4. Check. Run the code below.
nxt = {1: 2, 2: 3, 3: 4, 4: None}
head = 1
prev = None
cur = head
while cur is not None:
    after = nxt[cur]
    nxt[cur] = prev
    prev = cur
    cur = after
head = prev
out = []
cur = head
while cur is not None:
    out.append(cur)
    cur = nxt[cur]
print(out)
[4, 3, 2, 1]

Answer: 4, 3, 2, 1.

Select all true statements about a doubly linked list

A doubly linked list keeps a head pointer and a tail pointer. Select all that apply.

  • (A) Inserting a new node at the tail takes O(1) time.
  • (B) Deleting the last node takes O(1) time.
  • (C) Deleting a middle node changes the prev pointer of its successor and the next pointer of its predecessor.
  • (D) Each node uses less memory than in a singly linked list holding the same values.

How to think about it

  1. What is asked. Which statements are true.
  2. Which idea applies. The tail pointer gives direct access to the end. Each node stores two pointers.
  3. Work it out. (A) The tail is known, so a new node is linked after it in O(1). True. (B) The tail's prev pointer leads to the new last node, so the removal is O(1). True. (C) This is exactly the two-pointer change described earlier. True. (D) A doubly linked node stores one extra pointer, so it uses more memory. False.
  4. Check. The reasoning above covers each statement. No code is needed.

Answer: (A), (B) and (C).

Exam-level practice

Exam-level 1: Reverse a linked list (NAT, 2 marks)

Iterative reversal of a singly linked list with n = 1000 nodes changes how many next pointers?

How to think about it

  1. What is asked. The number of pointer reassignments.
  2. Which idea applies. Each node's next is reassigned exactly once.
  3. Work it out. 1000.
  4. Check. The old head's next becomes None, which also counts as a change.

Answer: 1000.

Exam-level 2: Floyd cycle detection (NAT, 2 marks)

A list has a tail of 3 nodes before a cycle of 5 nodes. Slow moves 1, fast moves 2, both from the head. After how many steps do they first meet?

How to think about it

  1. What is asked. The first meeting time.
  2. Which idea applies. Simulate positions; nodes 0, 1, 2 are the tail and 3 to 7 form the cycle.
  3. Work it out. Number the tail nodes 0, 1, 2 and the cycle nodes 3 to 7. After t steps (t ≥ 3) both pointers are on the cycle and the gap between them is t. They meet when t is a multiple of 5, and the first such t ≥ 3 is 5.
  4. Check. The code simulates both pointers.
def nxt(i): return i + 1 if i < 7 else 3
s = f = 0; t = 0
while True:
    s = nxt(s); f = nxt(nxt(f)); t += 1
    if s == f: break
print("meet after", t, "steps at node", s)

meet after 5 steps at node 5

Answer: 5.

Exam-level 3: List operations (MSQ, 2 marks)

Which are O(1) on a singly linked list with only a head pointer? (A) Insert at head (B) Delete the last node (C) Access the k-th node (D) Delete the head

How to think about it

  1. What is asked. Constant-time operations.
  2. Which idea applies. Anything near the tail needs a walk without a tail pointer.
  3. Work it out. (A) True. (B) Needs the second last node. O(n). (C) O(k). (D) True.
  4. Check. A doubly linked list with a tail pointer makes (B) O(1).

Answer: (A) and (D).

Summary

Node
A box with a value and pointers.
Pointer
A stored reference to another node.
Head
The pointer to the first node.
Singly linked list
Each node has one pointer, to the next node.
Doubly linked list
Each node has a next and a prev pointer.
Traversal
Visiting every node by following pointers from the head.
Predecessor
The node just before the given node.
Insert at front
O(1) in both list types.
Insert at end
O(n) with head only, O(1) with a tail pointer.
Delete given node
O(1) in a doubly linked list, O(n) in a singly linked list.
Access by position
O(k) in a linked list, O(1) in an array.
Reversal
Redirect each next pointer to the previous node, one node at a time.

Remember these

  • Linked lists are fast to change and slow to search or index.
  • Insertion at the front is always O(1).
  • Deletion needs the predecessor, so it is O(n) in a singly linked list.
  • A doubly linked list costs one extra pointer per node.
  • Arrays give O(1) access by position, linked lists do not.
