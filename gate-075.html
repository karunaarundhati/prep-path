Graph theory intro + BFS/DFS traversals

A graph is a set of points (vertices) joined by lines (edges), such as cities and roads or people and friendships. Breadth-first search (BFS) and depth-first search (DFS) are two ways to visit every vertex. They power connectivity checks, cycle detection and many shortest-path ideas, and GATE often asks you to write their visiting order.

The idea in plain words

Picture a city map. Each junction is a point, and each road is a line between two points. If you want to visit every junction, you need a plan. Should you visit all the neighbours of your start first, then the neighbours of those neighbours? Or should you follow one road as far as it goes, then come back and try the next one? These two plans are exactly BFS and DFS.

Graphs are everywhere in computing. Social networks are graphs (people are vertices, friendships are edges). The web is a graph (pages are vertices, links are edges). A robot's map of a building is a graph (rooms are vertices, doorways are edges). Once you can describe a problem as a graph, these two searches let you answer questions like "can I get from here to there?" and "does this network have a loop?"

In GATE DA, graph questions usually give you a small graph, ask for the BFS or DFS order from a start vertex, or ask about the number of edges, the degree of a vertex, or the time complexity. The rules below will let you answer all of them.

Key ideaBFS explores the graph in rings around the start, using a queue (first in, first out). DFS dives as deep as it can along one path, using a stack (last in, first out) or recursion.

Key terms

Every term used on this page is listed here. Read the plain meaning first, then the precise definition.

Vertex (node)
A point in the graph. Precisely: an element of the vertex set V. The number of vertices is written |V| or simply V.
Edge
A line joining two vertices. Precisely: a pair of vertices, written as (u, v). The number of edges is written |E| or E.
Undirected graph
Edges have no direction, like two-way roads. Precisely: the edge (u, v) is the same as (v, u).
Directed graph
Edges have a direction, like one-way streets. Precisely: the edge u to v is different from v to u.
Weighted graph
Each edge carries a number, such as a distance or a cost. Precisely: a weight function gives a value to each edge. An unweighted graph is the special case where every weight is the same.
Neighbour
A vertex directly joined to another by an edge. Precisely: w is a neighbour of v if (v, w) is an edge.
Degree
How many edges touch a vertex. Precisely: the number of neighbours of an undirected vertex. For directed graphs, out-degree counts outgoing edges and in-degree counts incoming ones.
Path
A sequence of vertices where each consecutive pair is joined by an edge.
Connected graph
Every vertex can be reached from every other vertex by some path. Precisely: an undirected graph with one connected component.
Connected component
A maximal group of vertices that can all reach one another. Precisely: a piece of the graph that is connected inside, with no edges to the rest.
Cycle
A path that starts and ends at the same vertex, using at least three edges in an undirected simple graph. Precisely: a closed loop.
Adjacency matrix
A V by V table of 0s and 1s (or weights). Precisely: entry (i, j) is 1 when there is an edge from vertex i to vertex j.
Adjacency list
For each vertex, a list of its neighbours. Precisely: an array of lists with one list per vertex.
BFS (breadth-first search)
Visit by levels: all vertices at distance 1, then distance 2, and so on. Precisely: uses a queue.
DFS (depth-first search)
Go as deep as possible before backtracking. Precisely: uses a stack or recursion.
Queue
A line where the first item in is the first item out. Precisely: enqueue adds at the back, dequeue removes at the front.
Stack
A pile where the last item in is the first item out. Precisely: push adds to the top, pop removes from the top.

Graphs and how to store them

Here is the running example for this page. Call it graph G. It has six vertices, A to F, and six undirected edges: A-B, A-C, B-D, C-E, D-E and D-F.

      A ---- B
      |      |
      C      D ---- F
      |     /
      E ---+          (E is joined to C and D)

The diagram shows the edges, but a computer needs a structure it can read quickly. There are two common choices.

Adjacency list. For each vertex, write down its neighbours. This is the most common choice for sparse graphs, meaning graphs with few edges. For G, the lists are: A: B, C; B: A, D; C: A, E; D: B, E, F; E: C, D; F: D.

Adjacency matrix. Make a 6 by 6 table of 0s and 1s, with rows and columns in the order A, B, C, D, E, F. Put a 1 wherever two vertices are joined. Because G is undirected, the table is symmetric: entry (A, B) and entry (B, A) are both 1.

The Python program below builds the matrix from the list and checks the degrees. It uses the same graph G, and the lists are sorted alphabetically, which matters for the traversal examples later.

graph = {
    "A": ["B", "C"],
    "B": ["A", "D"],
    "C": ["A", "E"],
    "D": ["B", "E", "F"],
    "E": ["C", "D"],
    "F": ["D"],
}

vertices = list(graph)
matrix = [[0] * len(vertices) for _ in vertices]
for v in vertices:
    for w in graph[v]:
        matrix[vertices.index(v)][vertices.index(w)] = 1

for row in matrix:
    print(row)
print("sum of degrees:", sum(len(graph[v]) for v in graph))

Read the output carefully. Row A has 1s in columns B and C, which matches the edges A-B and A-C. The sum of the degrees is 12, and that is twice the number of edges, which is 6. This is always true for an undirected graph, because each edge is counted once at each of its two ends.

Choosing a representation

A matrix uses V x V cells, whatever the number of edges. So for G it uses 36 cells even though there are only 6 edges. An adjacency list uses space in proportion to V + E. Checking whether one specific edge exists is fast with a matrix (one lookup) and slower with a list (scan one list). Use a matrix for dense graphs (many edges), and a list for sparse graphs (few edges).

TrapIn a directed graph, the edge from A to B does not give an edge from B to A. The matrix is then not symmetric, and the degree splits into out-degree and in-degree. Do not double count.

What is the degree of vertex D in graph G?

3. D is joined to B, E and F, so three edges touch D.

A simple undirected graph has 5 vertices and 4 edges. What is the sum of all the degrees?

8. Each edge adds 1 to the degree of each of its two ends, so the sum is 2 x 4 = 8.

Breadth-first search (BFS): ring by ring

Imagine dropping a stone in a pond. The first ring of ripples reaches the vertices one edge away from the start. The next ring reaches vertices two edges away. BFS works the same way. It finishes every vertex at distance 1 before it looks at any vertex at distance 2.

BFS needs a queue. The steps are:

  1. Mark the start vertex as visited and put it in the queue.
  2. Take the vertex at the front of the queue. Call it v.
  3. For each neighbour w of v, in the order listed, if w is not yet visited, mark w as visited and add it to the back of the queue.
  4. Repeat from step 2 until the queue is empty.

Notice that we mark a vertex when we add it to the queue, not when we remove it. This prevents the same vertex from entering the queue twice.

Worked trace on graph G from A

StepTake from frontNew neighbours addedQueue after the step
0 (start)-A is added[A]
1AB and C (both unvisited)[B, C]
2BD (A is already visited)[C, D]
3CE (A is already visited)[D, E]
4DF (B and E are already visited or queued)[E, F]
5Enothing (C and D are visited)[F]
6Fnothing (D is visited)[]

The BFS order is A, B, C, D, E, F. Each vertex's distance from A is the ring it was added in: B and C are at distance 1, D and E at distance 2, and F at distance 3. Note that E is reached through C at distance 2, not through D.

Key ideaIn an unweighted graph, BFS gives the shortest number of edges from the start to every reachable vertex. This is why BFS is the standard tool for "fewest hops" questions.

Cost: every vertex enters and leaves the queue once, which takes O(V) work. Every adjacency list is read once in full, and the total length of all the lists is 2E for an undirected graph. So BFS costs O(V + E) with adjacency lists. With an adjacency matrix, each vertex scans a full row of V entries, so the cost is O(V2).

In BFS, which vertices are at distance 2 from A in graph G?

D and E. D is reached from B, and E is reached from C. Both B and C are one edge from A.

Why do we mark a vertex when it is queued rather than when it is dequeued?

If we waited, the same vertex could be added to the queue several times by different neighbours, wasting time and possibly giving a wrong order.

Depth-first search (DFS): follow one road to the end

DFS is the explorer who keeps walking down one road until it stops, then comes back to the last junction and tries the next road. The "come back" step is called backtracking. A recursive function does this naturally, because each call waits for its children to finish before returning.

The rules for recursive DFS from a vertex v are:

  1. Mark v as visited and record it.
  2. For each neighbour w of v, in the order listed, if w is not visited, run DFS from w.
  3. When every neighbour is done, return. The caller then continues with its next neighbour.

Worked trace on graph G from A

  • Visit A. Its first neighbour is B, which is unvisited, so go to B.
  • At B: neighbour A is visited. Next neighbour D is unvisited, so go to D.
  • At D: neighbour B is visited. Next neighbour E is unvisited, so go to E.
  • At E: neighbour C is unvisited, so go to C.
  • At C: neighbours A and E are both visited. Dead end. Backtrack to E.
  • At E: neighbour D is visited. Backtrack to D.
  • At D: next neighbour F is unvisited, so go to F.
  • At F: neighbour D is visited. Dead end. Backtrack all the way to A. Its neighbour C is already visited, so DFS finishes.

The DFS order is A, B, D, E, C, F. Compare it with the BFS order A, B, C, D, E, F. Same vertices, different order. This is why a question must always say which order to use.

DFS can also be written with an explicit stack. The stack version below pushes all unvisited neighbours at once. It gives a different but still valid order, which is a common source of mistakes. The program prints all three results so you can compare them.

from collections import deque

graph = {
    "A": ["B", "C"],
    "B": ["A", "D"],
    "C": ["A", "E"],
    "D": ["B", "E", "F"],
    "E": ["C", "D"],
    "F": ["D"],
}

def bfs(graph, start):
    visited = {start}
    order = []
    queue = deque([start])
    while queue:
        v = queue.popleft()
        order.append(v)
        for w in graph[v]:
            if w not in visited:
                visited.add(w)
                queue.append(w)
    return order

def dfs(graph, v, visited, order):
    visited.add(v)
    order.append(v)
    for w in graph[v]:
        if w not in visited:
            dfs(graph, w, visited, order)

def dfs_stack(graph, start):
    visited = set()
    order = []
    stack = [start]
    while stack:
        v = stack.pop()
        if v in visited:
            continue
        visited.add(v)
        order.append(v)
        for w in graph[v]:
            if w not in visited:
                stack.append(w)
    return order

order = []
dfs(graph, "A", set(), order)
print("BFS from A:", " ".join(bfs(graph, "A")))
print("DFS from A (recursive):", " ".join(order))
print("DFS from A (stack):", " ".join(dfs_stack(graph, "A")))
BFS from A: A B C D E F
DFS from A (recursive): A B D E C F
DFS from A (stack): A C E D F B

TrapThe stack version pops the last neighbour pushed, so it visits C before B. Two methods, two orders. In a GATE question, use the method and the neighbour order the question states. If none is stated, use the recursive version with neighbours in alphabetical order.

In DFS on G from A, why is C visited after E?

DFS goes from A to B, then D, then E, and only then to C, because C is reached from E before the search backtracks to A.

What data structure does DFS use in place of a queue?

A stack, either explicit or the call stack of recursion (last in, first out).

Connectivity, cycle detection and complexity

Both searches answer a yes or no question about the whole graph. Here are the two most common uses.

Connectivity and components. Start a search from one vertex. Everything it visits forms one connected component. If some vertices are still unvisited, start a new search from one of them and count another component. The number of searches you start is the number of connected components. A graph is connected exactly when one search covers every vertex.

Cycle detection in an undirected graph. Run DFS, remembering the parent of each vertex (the vertex from which you arrived). If you meet a neighbour that is already visited and is not the parent, you have found a cycle. Graph G has one: A, B, D, E, C, A uses the edges A-B, B-D, D-E, E-C and C-A. The walk returns to A, so the graph contains a cycle.

A useful fact follows from this. A connected undirected graph with V vertices is a tree (no cycles) exactly when it has V - 1 edges. G has 6 vertices and 6 edges, so it is not a tree.

GATE loves thisFor an undirected graph, the sum of the degrees is 2E. A graph with V vertices, where every vertex has degree 2, has E = V edges, so it must contain a cycle.

Time complexity. Both BFS and DFS visit each vertex once and look at each adjacency list once. With adjacency lists the total time is O(V + E). With an adjacency matrix the time is O(V2), because each vertex scans V entries. The space is O(V) for the visited marks and queue or stack, plus the graph itself.

BFS and DFS with adjacency lists: O(V + E)
BFS and DFS with adjacency matrix: O(V2)
How many connected components does a graph have if a search from one vertex visits 4 of its 7 vertices, and a second search from an unvisited vertex covers the other 3?

Two. The first search gives one component, and the second search (started from an unvisited vertex) gives the other.

Is graph G connected?

Yes. One search from A reaches all six vertices, so G is a connected graph with one component.

Edges and the degree of vertex 2

An undirected graph has vertices 1 to 5 and the edges 1-2, 2-3, 3-4, 4-1 and 2-5. How many edges does it have, and what is the degree of vertex 2?

How to think about it

  1. What is asked. The number of edges, and the degree of one vertex.
  2. Which idea applies. Each listed pair is one edge. The degree of a vertex counts the edges that touch it.
  3. Work it out. The list has 5 pairs, so E = 5. Vertex 2 appears in the pairs 1-2, 2-3 and 2-5, so its degree is 3.
  4. Check. Degrees are 2, 3, 2, 2 and 1 for vertices 1 to 5. Their sum is 10, which is 2 x 5, as the handshake rule says.

Answer: 5 edges, and vertex 2 has degree 3.

Ones in an adjacency matrix

An undirected simple graph has 4 vertices and 3 edges. How many entries of its adjacency matrix equal 1?

How to think about it

  1. What is asked. Count the 1s in the matrix.
  2. Which idea applies. In an undirected matrix, each edge sets two entries, one for each direction.
  3. Work it out. 3 edges, each setting 2 entries, gives 3 x 2 = 6 ones. The diagonal is all 0s in a simple graph (no self-loops), so no extra 1s appear there.
  4. Check. The matrix is symmetric, so the number of ones must be even. 6 is even.

Answer: 6.

Which statements about BFS and DFS are true?

Select all that apply.

  • (A) BFS uses a queue.
  • (B) DFS can be written with an explicit stack.
  • (C) In an unweighted graph, BFS from a source reaches each vertex at the smallest number of edges from the source.
  • (D) DFS on an adjacency list always takes O(V2) time.
  • (E) On a tree, BFS from the root visits the vertices level by level.

How to think about it

  1. What is asked. Which claims are true.
  2. Which idea applies. BFS uses a queue and visits by levels. DFS uses a stack or recursion. With adjacency lists, both cost O(V + E).
  3. Work it out. (A) True. (B) True. (C) True, since BFS adds vertices in rings of increasing distance. (D) False, the cost with lists is O(V + E). (E) True, a tree has no cycles, so BFS from the root gives its levels.

Connected components after two edges are removed

Graph H has vertices 1 to 6 and the edges 1-2, 1-3, 2-4, 3-5, 4-6 and 5-6. Remove the edges 1-2 and 5-6. How many connected components remain?

How to think about it

  1. What is asked. The number of connected components after the removal.
  2. Which idea applies. Count the groups of vertices that can still reach each other.
  3. Work it out. The remaining edges are 1-3, 3-5, 2-4 and 4-6. Vertices 1, 3 and 5 are joined together. Vertices 2, 4 and 6 are joined together. No edge links the two groups, so there are two components.
  4. Check. Run a search from vertex 1 (it reaches 3 and 5 only) and from vertex 2 (it reaches 4 and 6 only). Two searches means two components. The code below counts this.

Answer: 2.

graph = {1: [3], 2: [4], 3: [1, 5], 4: [2, 6], 5: [3], 6: [4]}
seen = set()
count = 0
for start in graph:
    if start in seen:
        continue
    count += 1
    stack = [start]
    while stack:
        v = stack.pop()
        if v in seen:
            continue
        seen.add(v)
        stack.extend(graph[v])
print(count)

Order of visits with neighbours in listed order

Use graph H from the previous problem, but with the original edges 1-2, 1-3, 2-4, 3-5, 4-6 and 5-6. Each neighbour list is sorted in increasing order. Write the DFS visiting order from vertex 1, using the recursive method.

  2. Which idea applies. Recursive DFS: visit, then go to the first unvisited neighbour, recursively, and backtrack when stuck.

Which representation fits which graph?

Select all that apply.

  • (A) An adjacency matrix is the better choice for a dense graph, where E is close to V2.
  • (B) An adjacency list uses O(V + E) space.
  • (C) Checking whether edge (u, v) exists takes O(1) with a matrix and O(degree of u) with a list.
  • (D) BFS on a graph stored as a matrix takes O(V2) time.
  • (E) BFS on a graph stored as a list always takes O(V2) time.

How to think about it

  1. What is asked. Which claims about storage and cost are true.
  2. Which idea applies. Matrix: V2 space and O(1) edge lookup. List: V + E space, and scanning a list costs its length.
  3. Work it out. (A) True, because a dense graph wastes little space in a matrix. (B) True. (C) True. (D) True, each vertex scans a row of V cells. (E) False, with lists BFS costs O(V + E), which is much less than V2 for a sparse graph.
  4. Check. Take V = 1,000 and E = 2,000. A list costs about 3,000 steps, while a matrix costs 1,000,000. So (E) is clearly false.

Answer: (A), (B), (C) and (D).

Edges in a forest

A forest is an undirected graph with no cycles. A forest has 10 vertices and exactly 3 connected components. How many edges does it have?

How to think about it

  1. What is asked. The number of edges in a forest with given vertices and components.
  2. Which idea applies. Each component with k vertices and no cycles is a tree, and a tree on k vertices has k - 1 edges.
  3. Work it out. Let the components have k1, k2 and k3 vertices, with k1 + k2 + k3 = 10. The edges are (k1 - 1) + (k2 - 1) + (k3 - 1) = 10 - 3 = 7. The sizes do not matter, only the total and the count of components.
  4. Check. A single tree (1 component) on 10 vertices has 9 edges, which is 10 - 1. Each extra component removes one edge, so 9 - 2 = 7.

Answer: 7 edges.

Exam-level 1: BFS order (MCQ, 2 marks)

An undirected graph has edges A-B, A-C, B-D, C-D, C-E, D-F, E-F. BFS starts at A and visits neighbours in alphabetical order. What is the visit order? (A) A B C D E F (B) A B D C E F (C) A C B E D F (D) A B C E D F

How to think about it

  1. What is asked. The BFS order.
  2. Which idea applies. BFS processes vertices level by level using a queue.
  3. Work it out. Level 1: B, C. From B: D. From C: E (D seen). Then F. Order A B C D E F.
  4. Check. The code runs BFS.
from collections import deque
E = ["AB", "AC", "BD", "CD", "CE", "DF", "EF"]
G = {}
for u, v in E: G.setdefault(u, []).append(v); G.setdefault(v, []).append(u)
seen, q, out = {"A"}, deque("A"), []
while q:
    u = q.popleft(); out.append(u)
    for v in sorted(G[u]):
        if v not in seen: seen.add(v); q.append(v)
print(" ".join(out))

Summary

Vertex
A point in a graph.
Edge
A line joining two vertices, possibly with a direction or a weight.
Undirected graph
Edges have no direction.
Directed graph
Edges go one way only.
Weighted graph
Each edge has a number attached, such as a distance.
Degree
The number of edges touching a vertex.
Adjacency matrix
A V by V table with 1 where an edge exists. Space V2.
Adjacency list
One list of neighbours per vertex. Space V + E.
Connected component
A group of vertices that can all reach each other.
BFS
Breadth-first search. Visits by levels using a queue.
DFS
Depth-first search. Goes deep, then backtracks, using a stack or recursion.
Queue
First in, first out. Used by BFS.
Stack
Last in, first out. Used by DFS.
Backtracking
Returning to the last junction when a path has no new vertices.
Cycle
A closed loop of edges that returns to its starting vertex.
Time of BFS and DFS
O(V + E) with adjacency lists, O(V2) with a matrix.
Handshake rule
The sum of the degrees in an undirected graph is 2E.

Remember these

  1. BFS uses a queue and gives shortest hop counts in unweighted graphs.
  2. DFS uses a stack or recursion and backtracks when stuck.
  3. The visiting order depends on the neighbour order, so always read the question's rule.
  4. Mark a vertex when you first add it, not when you remove it.
  5. Each search costs O(V + E) with adjacency lists.
