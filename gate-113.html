Adversarial search: Minimax & Alpha-Beta pruning

Minimax is a rule for choosing the best move when two players compete over a game tree, and alpha-beta pruning reaches the same answer while skipping work that cannot change it.

The idea in plain words

Imagine you are playing a board game against a friend. Before you move, you think ahead: "If I make this move, what will my friend do? And then what can I do?" A computer does the same thing. It writes the possible futures down as a tree. Each position is a box, and each legal move is a line to the next box.

The computer then uses one simple rule: assume both players always play the best move they can. This rule is called minimax. The tree grows very fast, so looking at every branch is slow. Alpha-beta pruning is a shortcut. It notices when a branch cannot change the final decision and skips it. The answer is exactly the same as minimax, but the work is much smaller.

Everyday analogy: you want the cheapest laptop in five shops. In shop one you find a price of 500. In shop two, the first laptop already costs 900. You stop comparing shop two, because nothing there can beat 500. Alpha-beta pruning works the same way.

Why it matters for GATE. In the Data Science and AI (DA) paper, you may get a small game tree drawn as a diagram. You may be asked for the minimax value at the root, or which branches are pruned when alpha-beta runs from left to right.

Key terms

Game tree
Plain: all the possible futures, drawn as a tree. Precise: nodes are game positions and edges are legal moves.
Root
Plain: the top of the tree, where the decision is made now. Precise: the node for the current position.
Leaf
Plain: an end of the game. Precise: a node with no children, which has a utility (score) attached.
MAX node
Plain: a position where the computer chooses. Precise: a node where the player to move wants the largest utility.
MIN node
Plain: a position where the opponent chooses. Precise: a node where the other player wants the smallest utility.
Minimax value
Plain: what the game is worth if both play perfectly. Precise: the value obtained by backing up leaf utilities with max at MAX nodes and min at MIN nodes.
Alpha (α)
Plain: the best score MAX is already sure to get. Precise: a lower bound for MAX, starting at minus infinity.
Beta (β)
Plain: the best score MIN is already sure to hold MAX to. Precise: an upper bound for MIN, starting at plus infinity.
Pruning
Plain: cutting off a branch that cannot matter. Precise: stopping the search of a node's remaining children because they cannot change the root decision.
Branching factor (b)
The average number of children of a node.
Depth (d)
The number of moves on the longest path from the root to a leaf.
Move ordering
The order in which children are examined. Trying good moves first allows more pruning.

Concept 1: Game trees and the two players

Take the simplest game. Two players take turns. The first player is MAX, who wants a big score. The second player is MIN, who wants a small score. The score at each leaf is its utility.

The root is the position where MAX must choose now. Its children are the positions after each MAX move. Those positions are MIN nodes, because MIN moves next. The levels alternate: MAX, MIN, MAX, and so on, down to the leaves.

                 MAX (root)
             /          |          \
         MIN A        MIN B        MIN C
         /   \        /   \        /   \
        3     5      6     9      1     2

MAX picks one of the three MIN nodes. Then MIN picks one leaf. MIN wants the smaller number, so MAX has to think about what MIN will do.

TipWrite MAX or MIN next to each level before you start. Count from the root: root is MAX, next level MIN, then MAX, and so on.

If every node has b children and the depth is d, the number of leaves is bd. Each level multiplies the count by b. With b = 3 and d = 2, there are 32 = 9 leaves.

Question: A tree has branching factor 2 and depth 3. How many leaves does it have?

2 x 2 x 2 = 8 leaves. Each level doubles the count.

Question: The root is a MAX node. Is the level below it MAX or MIN?

MIN. The players alternate.

Concept 2: Backing up values with minimax

To find the root value, start at the leaves, where values are known. Move one level up at a time. This is called backing up the values.

  • At a MAX node, the value is the largest child value.
  • At a MIN node, the value is the smallest child value.
V(n) = max(V(c1), ..., V(ck)) if n is a MAX node
V(n) = min(V(c1), ..., V(ck)) if n is a MIN node

Here V(n) is the minimax value of node n, and c1 to ck are its children. Read max as "the largest of" and min as "the smallest of".

Worked example on the tree from Concept 1

  1. MIN A has leaves 3 and 5. The smaller is 3. So V(MIN A) = 3.
  2. MIN B has leaves 6 and 9. The smaller is 6. So V(MIN B) = 6.
  3. MIN C has leaves 1 and 2. The smaller is 1. So V(MIN C) = 1.
  4. Root is MAX with children 3, 6 and 1. The largest is 6. So V(root) = 6.

The game is worth 6 to MAX, and MAX should move to MIN B.

def minimax(node, maximizing):
    if isinstance(node, int):          # a leaf: its value is the number itself
        return node
    values = [minimax(child, not maximizing) for child in node]
    if maximizing:
        return max(values)             # MAX node: take the largest child value
    return min(values)                 # MIN node: take the smallest child value

tree = [[3, 5], [6, 9], [1, 2]]        # root (MAX) with three MIN children
print("Minimax value of the root:", minimax(tree, True))
Minimax value of the root: 6

TrapThe most common slip is taking the max at a MIN level, or the min at a MAX level. At each node ask "who is choosing here?"

Question: A MIN node has leaves 4 and 8. What is its value?

MIN takes the smaller leaf, so the value is 4.

Question: A MAX root has children with values 2 and 7. What is the root value?

MAX takes the larger value, so the root value is 7.

Concept 3: Alpha-beta pruning

Alpha-beta looks at the same tree but skips leaves that cannot change the answer. It keeps two numbers while it walks from left to right.

  • Alpha (α) is the best value MAX is sure of so far. It starts at minus infinity and can only go up.
  • Beta (β) is the best value MIN is sure to hold MAX to. It starts at plus infinity and can only go down.
Stop at a MIN node when alpha is at least beta.
Stop at a MAX node when alpha is at least beta.

Why is this safe? If a MIN node already has a value no bigger than something MAX can already get elsewhere, MAX will never choose that MIN node. So its remaining children do not matter.

Key ideaAlpha-beta always returns the same root value as minimax, so the chosen move stays the same. It only saves work.

Trace on the same tree

  1. MIN A (alpha = minus infinity, beta = plus infinity). Leaf 3 makes beta = 3. Leaf 5 does not change it. MIN A = 3. At the root, alpha becomes 3.
  2. MIN B (alpha = 3). Leaf 6 makes beta = 6. Is alpha at least beta? 3 is not at least 6, so continue. Leaf 9 does not change it. MIN B = 6. At the root, alpha becomes 6.
  3. MIN C (alpha = 6). Leaf 1 makes beta = 1. Is alpha at least beta? 6 is at least 1, yes. Stop. Leaf 2 is pruned. MIN C returns 1.
  4. Root. The best child value is 6, the same as minimax.

Minimax looks at six leaves. Alpha-beta looks at five.

def alphabeta(node, maximizing, alpha, beta, seen):
    if isinstance(node, int):
        seen.append(node)              # record every leaf we actually look at
        return node
    if maximizing:
        value = -10**9
        for child in node:
            value = max(value, alphabeta(child, False, alpha, beta, seen))
            alpha = max(alpha, value)
            if alpha >= beta:           # MAX cut: the rest cannot matter
                break
        return value
    value = 10**9
    for child in node:
        value = min(value, alphabeta(child, True, alpha, beta, seen))
        beta = min(beta, value)
        if alpha >= beta:               # MIN cut: the rest cannot matter
            break
    return value

tree = [[3, 5], [6, 9], [1, 2]]
leaves = [3, 5, 6, 9, 1, 2]
seen = []
value = alphabeta(tree, True, -10**9, 10**9, seen)
print("Alpha-beta value of the root:", value)
print("Leaves evaluated, left to right:", seen)
print("Leaves skipped:", [x for x in leaves if x not in seen])
Alpha-beta value of the root: 6
Leaves evaluated, left to right: [3, 5, 6, 9, 1]
Leaves skipped: [2]

TrapA pruned node's value is only a bound. MIN C returned 1, but its exact value does not matter for the root. Do not write a pruned value down as if it were exact.

Question: At a MIN node, alpha is 5 and the first leaf is 4. Do we look at the other leaves?

No. Beta becomes 4, alpha (5) is at least beta (4), so we stop.

Question: Which bound starts at plus infinity and only goes down?

Beta.

Concept 4: Counting the work saved

GATE questions often ask how many leaves are examined. Plain minimax examines every leaf: bd of them. Alpha-beta with the best move ordering, where the best move is always examined first, examines the fewest leaves it can. The exact best-case count is:

best-case leaves = b⌈d/2⌉ + b⌊d/2⌋ - 1

Here ⌈d/2⌉ means d divided by 2, rounded up, and ⌊d/2⌋ means d divided by 2, rounded down.

def best_case_leaves(b, d):
    up = (d + 1) // 2                  # ceiling of d / 2
    down = d // 2                      # floor of d / 2
    return b ** up + b ** down - 1

print("b = 3, d = 2:", best_case_leaves(3, 2))
print("b = 2, d = 4:", best_case_leaves(2, 4))
print("b = 3, d = 4:", best_case_leaves(3, 4))
print("Plain minimax for b = 3, d = 4:", 3 ** 4)
b = 3, d = 2: 5
b = 2, d = 4: 7
b = 3, d = 4: 17
Plain minimax for b = 3, d = 4: 81

Check the first line by hand. With b = 3 and d = 2, the first MIN node needs all 3 of its leaves. Each of the other two MIN nodes needs only 1 leaf before it is cut. The total is 3 + 1 + 1 = 5.

GATE loves thisFor a given tree, work left to right. Write alpha and beta at each step, mark each leaf "evaluated" or "pruned", then count.

Question: Branching factor 2, depth 4. What is the best-case number of leaves for alpha-beta?

22 + 22 - 1 = 4 + 4 - 1 = 7. Plain minimax would examine 16.

Question: Can alpha-beta give a different root value from minimax?

No. It only skips branches that cannot change the root value.

Solved GATE-style problems

These problems are original, written in the style of GATE. They are not past exam questions. Try each one on paper before reading the answer.

Minimax of a small tree

A MAX root has two MIN children, A and B. Node A has leaves 4 and 7. Node B has leaves 2 and 9. What is the minimax value of the root?

How to think about it

  1. What is asked. The minimax value of the MAX root.
  2. Which idea applies. MIN takes the smallest leaf, MAX takes the largest child.
  3. Work it out. A = min(4, 7) = 4. B = min(2, 9) = 2. Root = max(4, 2) = 4.
  4. Check. The root value must equal one of the child values. It equals A's value, 4.

Answer: 4.

True statements about alpha-beta (select all that apply)

Which statements about alpha-beta pruning are true? Select all that apply.

(A) It returns the same root value as plain minimax.
(B) It always examines more leaves than plain minimax.
(C) It can skip subtrees that cannot change the root decision.
(D) It changes the minimax value of the root.

How to think about it

  1. What is asked. Which statements are true.
  2. Which idea applies. Alpha-beta is safe. It only prunes what cannot matter.
  3. Work it out. (A) is true. (B) is false, alpha-beta never examines more leaves. (C) is true, which is the purpose of pruning. (D) is false.
  4. Check. In the trace above, leaf 2 was skipped, yet the root value 6 matched minimax.

Answer: (A) and (C).

Alpha-beta trace on three MIN children

A MAX root has three MIN children, visited left to right. The leaves are: first child [5, 6], second child [7, 4, 5], third child [3]. Using alpha-beta, which leaf is not evaluated? What is the root value?

How to think about it

  1. What is asked. The skipped leaf and the root value.
  2. Which idea applies. Alpha-beta trace with the cut rules.
  3. Work it out. First child: visit 5 and 6, value 5, so alpha = 5 at the root. Second child (alpha = 5): visit 7, beta = 7. Visit 4, beta = 4. Now alpha = 5 is at least beta = 4, so stop. The last leaf, 5, is skipped. The child returns 4. Third child: visit 3. Root = max(5, 4, 3) = 5.
  4. Check. Minimax gives 5, 4 and 3 for the three MIN nodes, and the largest is 5.

Answer: The skipped leaf is the last leaf (value 5) of the second child. The root value is 5.

Best-case leaves for a bigger tree

A uniform game tree has branching factor 3 and depth 4. With the best move ordering, how many leaves does alpha-beta examine? Give a whole number.

How to think about it

  1. What is asked. The best-case leaf count, as a whole number.
  2. Which idea applies. b⌈d/2⌉ + b⌊d/2⌋ - 1.
  3. Work it out. b = 3, d = 4, so ⌈4/2⌉ = 2 and ⌊4/2⌋ = 2. The count is 32 + 32 - 1 = 9 + 9 - 1 = 17.
  4. Check. Plain minimax examines 81 leaves, and 17 is much smaller. The Python check above also printed 17.

Answer: 17.

Inherited alpha causes an early cut

Inside a MIN node B, alpha = 5 has been passed down from the root, because the root already has 5 from another branch. Node B has leaves 4, 9 and 1, visited left to right. How many of B's leaves are evaluated, and what does B return?

How to think about it

  1. What is asked. The number of evaluated leaves and the value returned.
  2. Which idea applies. The MIN cut rule.
  3. Work it out. Visit leaf 4. Beta becomes 4. Alpha = 5 is at least beta = 4, so stop. Leaves 9 and 1 are skipped. B returns at most 4.
  4. Check. The root already has 5, and B can give at most 4, so B cannot change the root decision.

Answer: One leaf is evaluated (the leaf 4). B returns a value of at most 4.

Full trace on a three-level tree

A MAX root has two MIN children, X and Y. Each MIN node has two MAX children. The leaves, drawn below, are visited left to right with alpha-beta. Find the root value and the leaves that are not evaluated.

                 MAX (root)
                /           \
           MIN X             MIN Y
           /     \           /     \
        MAX      MAX      MAX      MAX
       /   \    /   \    /   \    /   \
      3     5  6     9  1     2  0     7

How to think about it

  1. What is asked. The root value and the skipped leaves.
  2. Which idea applies. Alpha-beta carried through three levels.
  3. Work it out. Start with alpha = minus infinity, beta = plus infinity. MIN X: its first MAX child [3, 5] gives 5, so beta = 5. Its second MAX child [6, 9]: visit 6, which is at least beta = 5, so cut. Leaf 9 is skipped. MIN X = 5, so root alpha = 5. MIN Y (alpha = 5): its first MAX child [1, 2] gives 2, so beta = 2. Alpha = 5 is at least beta = 2, so cut. The second MAX child [0, 7] is never visited. Root = max(5, 2) = 5.
  4. Check. Minimax also gives 5: X = min(5, 9) = 5 and Y = min(2, 7) = 2.

Answer: The root value is 5. The leaves not evaluated are 9, 0 and 7.

Exam-level practice

Exam-level 1: Minimax value (NAT, 2 marks)

A depth-2 game tree: MAX root with three MIN children. Leaves (left to right): [3, 12, 8], [2, 4, 6], [14, 5, 2]. Find the minimax value at the root.

How to think about it

  1. What is asked. The value MAX can guarantee.
  2. Which idea applies. Each MIN node takes the smallest leaf. MAX takes the largest of those.
  3. Work it out. MIN values: 3, 2, 2. Root = 3.
  4. Check. The code evaluates it.
T = [[3, 12, 8], [2, 4, 6], [14, 5, 2]]
print(max(min(c) for c in T))

3

Answer: 3.

Exam-level 2: Leaves pruned (NAT, 2 marks)

In the same tree, with alpha-beta pruning and left to right order, how many leaves are evaluated?

How to think about it

  1. What is asked. Leaves that alpha-beta actually visits.
  2. Which idea applies. Once a MIN node's value falls to or below α, its remaining children are pruned.
  3. Work it out. First child: all 3 leaves, α = 3. Second: leaf 2 ≤ 3, prune the other two. Third: 14, then 5, then 2 (still above 3 until the last leaf). Total 3 + 1 + 3 = 7.
  4. Check. The code counts visited leaves.
T = [[3, 12, 8], [2, 4, 6], [14, 5, 2]]
seen = 0; alpha = -1e9
for c in T:
    v = 1e9
    for x in c:
        seen += 1; v = min(v, x)
        if v <= alpha: break
    alpha = max(alpha, v)
print("root", alpha, "leaves visited", seen)

root 3 leaves visited 7

Answer: 7.

Exam-level 3: Alpha-beta facts (MSQ, 2 marks)

Which are TRUE? (A) Alpha-beta returns the same root value as minimax. (B) With perfect ordering it examines about bd/2 leaves. (C) Pruning depends on move ordering. (D) Alpha-beta can be used in games of chance without change.

How to think about it

  1. What is asked. Facts about alpha-beta.
  2. Which idea applies. Pruning removes only branches that cannot change the decision.
  3. Work it out. (A) True. (B) True. (C) True. (D) Chance nodes need expectiminimax and different bounds. False.
  4. Check. Perfect ordering doubles the searchable depth for the same effort.

Answer: (A), (B) and (C).

Remember these

  1. MAX takes the largest child. MIN takes the smallest child.
  2. Work from the leaves up to the root.
  3. Alpha only goes up. Beta only goes down.
  4. Cut when alpha is at least beta.
  5. Alpha-beta always gives the same root value as minimax.
  6. A pruned node's value is only a bound.
