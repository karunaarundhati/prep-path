Stacks and Queues

A stack and a queue are two simple ways to hold a line of items. A stack gives back the newest item first, and a queue gives back the oldest item first. Both appear in compilers, operating systems and many GATE questions, usually as trace problems.

The idea in plain words

Picture a pile of plates in a kitchen. You add a clean plate to the top, and when you need a plate you take the top one. The last plate placed is the first plate removed. That is a stack, and the rule is called LIFO, which stands for last in, first out.

Now picture a queue at a bus stop. The person who arrived first gets on the bus first. New people join at the back, and the bus takes people from the front. That is a queue, and the rule is called FIFO, which stands for first in, first out.

Both structures hold items in a line, and both have two main operations: put an item in, and take an item out. The only difference is which end the item leaves from. That single difference changes everything about how a trace works, so practise it until it feels automatic.

Why this matters for GATE. Stacks are used to check brackets, to evaluate expressions, and to run recursion. Queues are used to schedule jobs and to process requests in order. Exam questions often give a sequence of operations and ask for the final contents, the output order, or the number of items left. The method is to draw the structure after each operation.

Key terms

Stack
A list of items where items are added and removed at one end, called the top. Plain meaning: a pile of plates. Precise definition: an abstract data type with LIFO ordering.
LIFO
Last in, first out. The most recently added item is removed first.
push
Add an item to the top of a stack.
pop
Remove and return the item at the top of a stack.
peek (or top)
Look at the top item without removing it.
Queue
A list of items where items are added at the back, called the rear, and removed at the front. Precise definition: an abstract data type with FIFO ordering.
FIFO
First in, first out. The oldest item is removed first.
enqueue
Add an item at the rear of a queue.
dequeue
Remove and return the item at the front of a queue.
Circular queue
A queue stored in a fixed array where the end of the array wraps around to the start, so space is reused.
Overflow
An attempt to push or enqueue when the structure is full.
Underflow
An attempt to pop or dequeue when the structure is empty.
Deque
A double-ended queue. Items can be added and removed at both ends.
Priority queue
A collection where each removal returns the item with the highest priority, usually the smallest number.
Postfix notation
A way to write arithmetic where each operator comes after its two operands, such as 3 4 + for 3 + 4.
Infix notation
The usual way of writing arithmetic, with the operator between its operands, such as 3 + 4.
Modulo (%)
The remainder after division. Used to wrap an index around a circular array.

Stack: last in, first out

The three operations

  • push(x): put x on the top.
  • pop(): take the top item off and return it.
  • peek(): return the top item but leave it in place.

In Python, a list already acts as a stack. append is push, and pop() with no argument removes the last item, which is the top. The last item of the list is written stack[-1], and that is the peek.

stack = []
stack.append(10)
stack.append(20)
stack.append(30)
print(stack)
print(stack.pop())
print(stack[-1])
print(stack)
print(len(stack))
[10, 20, 30]
30
20
[10, 20]
2

Trace the code step by step. After three pushes the list is [10, 20, 30], with 30 on top. pop() removes 30 and returns it, so the first print of the pop is 30. Now the top is 20, which stack[-1] shows. The list has two items left.

Underflow and overflow

Popping from an empty stack is an error, called underflow. In Python this raises an exception. In a fixed-size array implementation, pushing into a full array is an overflow. A GATE question may ask you to say which of these occurs for a given sequence of operations, so always check the size and the number of items before each operation.

TrapIn a stack, peek shows the top, which is the last item pushed. Students often read the first item of the list by mistake. In [10, 20, 30] the top is 30, not 10.

After push 5, push 7, pop, push 9, what is the top of the stack?

9. The pop removed 7, and then 9 was pushed on top of 5.

What does pop return from an empty stack?

Nothing useful. It is an underflow error. A correct algorithm checks that the stack is not empty before a pop.

Stack applications: brackets and postfix expressions

Matching brackets

An expression such as (a[b]{c}) is balanced when every opening bracket has a matching closing bracket, and the pairs are properly nested. A stack solves this neatly. Push every opening bracket. When you meet a closing bracket, pop the top. The popped bracket must be the matching opening bracket. If it is not, or if the stack is empty at that moment, the expression is not balanced. At the end, the stack must be empty.

def balanced(s):
    stack = []
    pairs = {")": "(", "]": "[", "}": "{"}
    for ch in s:
        if ch in "([{":
            stack.append(ch)
        elif ch in ")]}":
            if len(stack) == 0:
                return False
            if stack.pop() != pairs[ch]:
                return False
    return len(stack) == 0

print(balanced("(a[b]{c})"))
print(balanced("(a[b)]"))
print(balanced("(("))
True
False
False

The first string is balanced. Each closing bracket meets the most recent opening bracket. The second string fails at the ), because the top of the stack is [, not (. The third string ends with two open brackets still on the stack, so the final check len(stack) == 0 is False.

Postfix expressions

Humans write 3 + 4, with the operator between the numbers. This is infix notation. It needs brackets and precedence rules to avoid confusion. Postfix notation puts each operator after its operands: 3 4 +. There are no brackets, and the order is always clear. For this reason, postfix form is often used as an intermediate form inside programming language tools.

To evaluate postfix with a stack, read the tokens from left to right. A number is pushed. An operator pops two numbers, applies the operator, and pushes the result. At the end the stack holds the answer.

def eval_postfix(tokens):
    stack = []
    for t in tokens:
        if t in "+-*/":
            b = stack.pop()
            a = stack.pop()
            if t == "+":
                stack.append(a + b)
            elif t == "-":
                stack.append(a - b)
            elif t == "*":
                stack.append(a * b)
            else:
                stack.append(a // b)
        else:
            stack.append(int(t))
    return stack.pop()

print(eval_postfix(["5", "1", "2", "+", "4", "*", "+", "3", "-"]))
print(eval_postfix(["6", "2", "3", "+", "*", "4", "-"]))
14
26

The function int(t) turns the text "12" into the number 12. The first example works like this. Push 5 and 1, then 2. The + pops 2 and 1, pushes 3, so the stack is 5, 3. Then 4 is pushed, and * pops 4 and 3, pushes 12. Then + pops 12 and 5, pushes 17. Finally 3 is pushed and - pops 3 and 17, giving 14. Notice that the operands are popped in reverse, so b is the top and a is the one below it. That is why subtraction and division use a - b and a // b.

Key ideaIn postfix evaluation, the first number popped is the right operand, and the second number popped is the left operand. Getting this order wrong gives a wrong answer for - and /, which exam questions like to test.

The call stack

Recursion, from the recursion topic, uses a stack without you seeing it. Each function call is pushed onto the call stack, and when it returns, it is popped. That is why the "leave" lines of the countdown example appeared in reverse order. The most recent call is the first to finish.

What is the value of the postfix expression 4 2 -?

2. The - pops 2 as b and 4 as a, then computes 4 - 2.

Is (] balanced according to the bracket code?

No. The closing ] pops the (, which is not its matching [, so the function returns False.

Queue: first in, first out

The operations

  • enqueue(x): add x at the rear.
  • dequeue(): remove and return the front item.
  • front: look at the front item without removing it.

A Python list can act as a queue, but pop(0) removes the first item and shifts every other item one place left, which costs time. The standard library class deque from the collections module removes from the front in constant time, so it is the correct choice for a queue.

from collections import deque
q = deque()
q.append("A")
q.append("B")
q.append("C")
print(q.popleft())
q.append("D")
print(list(q))
print(q[0])
A
['B', 'C', 'D']
B

In this program, append adds at the rear, and popleft removes from the front. The first dequeue returns "A", because it arrived first. After adding "D", the queue holds B, C, D in that order. The front is now "B".

Hand trace of a queue

Start with an empty queue. Enqueue 3, enqueue 8, dequeue, enqueue 1. The queue is first [3], then [3, 8]. The dequeue returns 3, leaving [8]. Then 1 joins the rear, giving [8, 1]. The front is 8.

TrapStudents often remove from the rear by mistake, because the last item added is the one they see first. In a queue, the item that leaves is always the one that arrived first. Write the queue as a row, with the front on the left, and move only the left end.

Enqueue 4, enqueue 5, dequeue, dequeue. What is the queue now?

Empty. The first dequeue removes 4, and the second removes 5.

Which end is used for enqueue in a queue?

The rear, which is the back end.

Circular queue

Why a circular queue is needed

Suppose a queue is stored in a fixed array of 4 cells, and we always add at the end of the array and remove from the start. After four enqueues and two dequeues, the front has moved to cell 2, and the rear is at the end of the array. The two freed cells at the start are wasted, because the rear cannot go back to them. A circular queue fixes this. When the rear or front reaches the end of the array, it wraps around to position 0.

The wrap is done with the remainder operator. The next position is (pos + 1) % size. For size 4, position 3 goes to (3 + 1) % 4, which is 0. Position 2 goes to 3, as usual.

A runnable example

The program below stores a circular queue of size 4 in a list. It uses a count variable to know how many items are present. This is the usual way to tell a full queue from an empty one, because front and rear are equal in both cases.

size = 4
buf = [None] * size
front = 0
rear = 0
count = 0

def enqueue(x):
    global rear, count
    buf[rear] = x
    rear = (rear + 1) % size
    count = count + 1

def dequeue():
    global front, count
    x = buf[front]
    front = (front + 1) % size
    count = count - 1
    return x

enqueue(10)
enqueue(20)
enqueue(30)
print(dequeue())
enqueue(40)
enqueue(50)
print(buf, front, rear, count)
10
[50, 20, 30, 40] 1 1 4

Trace it carefully. The three enqueues fill cells 0, 1 and 2, and rear becomes 3. The dequeue returns 10 from cell 0, and front becomes 1. Enqueue 40 goes into cell 3, and rear wraps to 0. Enqueue 50 goes into cell 0, which was freed by the dequeue, so rear becomes 1. Now count is 4, and the queue is full. The front is 1 and the rear is 1 again, which is why the count is needed.

Key ideaIn a circular queue of size n, the number of items is count. If you do not keep a count, you must leave one cell empty to tell full from empty. Exam questions often ask for the number of items when front and rear are given, so learn the formula in the formula sheet.

In a circular queue of size 4, what is (0 - 3) % 4?

1. In Python, -3 % 4 is 1, because -3 = 4 * (-1) + 1. This is how the wrap works when subtracting.

What is the new rear after enqueue when rear is 3 and size is 4?

0. The rear moves to (3 + 1) % 4, which is 0.

Priority queue and deque

Priority queue

A priority queue is a queue where the item with the highest priority leaves first, not the oldest item. Think of a hospital emergency room. A patient with a serious injury is treated before a patient who arrived earlier with a minor problem. In code, the priority is often a number, and the smallest number is treated as the highest priority.

Python provides this in the heapq module. The function heappush adds an item, and heappop removes the smallest item. The details of how the heap works are beyond this page, but the behaviour is what matters for tracing.

import heapq
pq = []
heapq.heappush(pq, 5)
heapq.heappush(pq, 1)
heapq.heappush(pq, 3)
print(heapq.heappop(pq))
print(heapq.heappop(pq))
print(len(pq))
1
3
1

The values 5, 1 and 3 went in, but 1 came out first, then 3. The 5 is still waiting. The priority queue always returns the smallest remaining value, regardless of insertion order.

Deque

A deque, short for double-ended queue, lets you add and remove at both ends. It is useful when you need both a stack and a queue behaviour in one structure. Adding at the front uses appendleft, and removing from the front uses popleft. Removing from the rear uses pop. Each of these takes constant time.

Push 9, push 2, pop (heap). What does the heap pop return?

2, the smaller value. A priority queue returns the smallest item, not the newest or the oldest.

Which deque method removes from the front of the deque?

popleft. The method pop without an argument removes from the rear.

Queue dequeue on a plain Python list with pop(0)O(n)Every other item shifts left

Implementation with arrays or linked lists

Both stacks and queues can be built on an array, which has a fixed size, or on a linked list, which grows one node at a time. The array version of a stack keeps a top index. The linked version keeps a pointer to the head node, and push and pop add or remove that head. The linked version never overflows except when memory runs out. The array version can overflow, and a circular array is needed to reuse space in a queue.

Tracing with a table

For a stack, draw a column with the top at the upper end. For a queue, draw a row with the front on the left. Update the picture after every operation, and write the output of every dequeue or pop as you go. The table is the most reliable way to answer trace questions.

GATE loves thisWhen a question says "after these operations, what is the output sequence?", draw the stack or queue as a picture, and write each removed item as it leaves. A question that asks for a possible output order for a stack is a common favourite.

Why is deque.popleft() preferred over list.pop(0) for a queue?

Because popleft takes constant time, while pop(0) must shift every remaining item one place left, which takes time proportional to the number of items.

Is a stack or a queue better for checking brackets?

A stack. The most recent opening bracket must match the next closing bracket, which is LIFO behaviour.

Solved GATE-style problems

These problems are original, written in the GATE style, and are not taken from any past paper. Trace each one on paper before you read the steps.

Stack size after operations

An empty stack receives these operations in order: push 5, push 7, pop, push 9, push 2, pop. How many items are in the stack at the end?

How to think about it

  1. What is asked. The number of items left after all six operations.
  2. Which idea applies. Each push adds one item, and each pop removes one item.
  3. Work it out. Count: 1 after push 5, 2 after push 7, 1 after pop, 2 after push 9, 3 after push 2, and 2 after the last pop. The contents are 5, 9.
  4. Check. Four pushes and two pops give 4 - 2 = 2 items, which matches.

Answer: 2

True statements about stacks and queues

Select all true statements. (A) A stack removes the oldest item first. (B) A queue removes the oldest item first. (C) A stack implemented with a Python list does push and pop in constant time. (D) A stack can be used to check whether brackets are balanced.

How to think about it

  1. What is asked. Every true statement.
  2. Which idea applies. LIFO for stacks, FIFO for queues, and the bracket method from this page.
  3. Work it out. (A) is false, since a stack removes the newest item. (B) is true, which is FIFO. (C) is true, because append and pop at the end of a list take constant time. (D) is true, as shown with the balanced function.
  4. Check. Statement A describes a queue by mistake, which is the most common error on this topic.

Answer: (B), (C) and (D)

Evaluate a postfix expression

Evaluate the postfix expression 6 2 3 + * 4 -. Give the single number left on the stack.

How to think about it

  1. What is asked. The value of the expression.
  2. Which idea applies. Push numbers, and let each operator pop two numbers and push one result.
  3. Work it out. Push 6, push 2, push 3. The + pops 3 and 2, and pushes 5. The stack is 6, 5. The * pops 5 and 6, and pushes 30. The stack is 30. Push 4. The - pops 4 and 30, and computes 30 - 4 = 26.
  4. Check. In infix form this is 6 * (2 + 3) - 4 = 6 * 5 - 4 = 30 - 4 = 26, which matches.

Answer: 26

Front after a mixed sequence

An empty queue receives these operations in order: enqueue A, enqueue B, enqueue C, dequeue, enqueue D, dequeue. Which item is now at the front? Give the letter.

How to think about it

  1. What is asked. The front item after the sequence.
  2. Which idea applies. Dequeue removes the oldest item, and enqueue adds at the rear.
  3. Work it out. After three enqueues the queue is A, B, C. The first dequeue removes A, leaving B, C. Enqueue D gives B, C, D. The second dequeue removes B, leaving C, D.
  4. Check. Two items were removed from the front in order, A and then B, so C is the next to leave.

Answer: C

Circular queue state

A circular queue of size 4 starts empty with front = 0 and rear = 0. The operations are: enqueue 10, enqueue 20, enqueue 30, enqueue 40, dequeue, dequeue, enqueue 50. Give the final front, rear and count, separated by spaces.

How to think about it

  1. What is asked. Three numbers after the operations.
  2. Which idea applies. Enqueue writes at rear and moves rear by (rear + 1) % 4. Dequeue reads at front and moves front by (front + 1) % 4.
  3. Work it out. The four enqueues fill cells 0 to 3, so rear wraps to 0 and count is 4. Each dequeue moves front: after the first it is 1 with count 3, and after the second it is 2 with count 2. Enqueue 50 writes to cell rear = 0, moves rear to 1, and count becomes 3.
  4. Check. Items in the queue are cells 2, 3 and 0, which is 3 items, matching count = 3.

Answer: 2 1 3

Which bracket strings are balanced?

Select all strings that are balanced by the rule of this topic. (A) {[()]} (B) {[(])} (C) (() (D) []{}()

How to think about it

  1. What is asked. Every balanced string.
  2. Which idea applies. Push openers, and each closer must match the top.
  3. Work it out. (A): push {, [, (. The ) pops (, the ] pops [, the } pops {. Balanced. (B): push {, [, (. The ] meets the top (, which does not match. Not balanced. (C): two pushes and one pop, so one ( is left. Not balanced. (D): each pair closes at once, and the stack is empty. Balanced.
  4. Check. The two balanced strings are the ones where the pairs are nested or side by side, with no crossing.

Answer: (A) and (D)

Impossible stack outputs

The numbers 1, 2, 3 are pushed onto an empty stack in this order. Pops may happen at any time, and each number must be pushed before it can be popped. Select all output orders that are impossible. (A) 1 2 3 (B) 3 1 2 (C) 3 2 1 (D) 2 3 1

How to think about it

  1. What is asked. The output orders that no sequence of pushes and pops can produce.
  2. Which idea applies. Because of LIFO, a number deeper in the stack cannot leave before the numbers above it.
  3. Work it out. (A): push 1, pop 1, push 2, pop 2, push 3, pop 3. Possible. (C): push 1, 2, 3, then pop 3, 2, 1. Possible. (D): push 1, push 2, pop 2, push 3, pop 3, pop 1. Possible. (B): to get 3 first, all three must be pushed, so the stack is 1, 2, 3 with 3 on top. The next pop gives 2, not 1. So 1 cannot come next. Impossible.
  4. Check. Of the 6 possible orders of three numbers, a stack can produce 5. The one it cannot produce is 3 1 2, which is the answer.

Answer: (B)

Items in a circular queue

A circular queue has size 5. Its front is at index 3 and its rear is at index 1. Here the rear points to the next free cell. How many items are in the queue? Give one number.

How to think about it

  1. What is asked. The count of items, given front and rear.
  2. Which idea applies. Items = (rear - front) % size, when the queue is not full.
  3. Work it out. (1 - 3) % 5 = (-2) % 5 = 3, because -2 = 5 * (-1) + 3. The items are in cells 3, 4 and 0.
  4. Check. Counting cells from 3 up to but not including 1, with wrap-around, gives cells 3, 4 and 0, which is 3 cells.

Answer: 3

Exam-level practice

Exam-level 1: Stack permutations (MCQ, 2 marks)

The numbers 1, 2, 3, 4 are pushed in that order and pops may happen at any time. Which output order is impossible? (A) 2, 1, 4, 3 (B) 3, 2, 4, 1 (C) 4, 1, 2, 3 (D) 1, 2, 3, 4

How to think about it

  1. What is asked. The order no stack can produce.
  2. Which idea applies. Once 4 is popped first, 3, 2, 1 are still stacked and must come out as 3, 2, 1.
  3. Work it out. (C) needs 1 right after 4, but 3 is on top. Impossible.
  4. Check. The code simulates each order.
def ok(out):
    st, nxt = [], 1
    for x in out:
        while nxt <= x:
            st.append(nxt); nxt += 1
        if st[-1] != x:
            return False
        st.pop()
    return True
for o in ([2, 1, 4, 3], [3, 2, 4, 1], [4, 1, 2, 3], [1, 2, 3, 4]):
    print(o, ok(o))

[2, 1, 4, 3] True
[3, 2, 4, 1] True
[4, 1, 2, 3] False
[1, 2, 3, 4] True

Answer: (C).

Exam-level 2: Postfix evaluation (NAT, 2 marks)

Evaluate the postfix expression 6 2 3 + − 3 8 2 / + * using a stack.

How to think about it

  1. What is asked. The value of the expression.
  2. Which idea applies. Push numbers. On an operator, pop b then a and push a op b.
  3. Work it out. 2 + 3 = 5, 6 − 5 = 1. 8/2 = 4, 3 + 4 = 7. 1 * 7 = 7.
  4. Check. The code evaluates it.
st = []
for t in "6 2 3 + - 3 8 2 / + *".split():
    if t in "+-*/":
        b, a = st.pop(), st.pop()
        st.append({'+': a + b, '-': a - b, '*': a * b, '/': a / b}[t])
    else:
        st.append(int(t))
print(st)

[7.0]

Answer: 7.

Exam-level 3: Queue with two stacks (NAT, 2 marks)

A queue is built from two stacks: enqueue pushes onto S1. Dequeue pops from S2, and if S2 is empty it first moves everything from S1 to S2. For enqueue 1, 2, 3, dequeue, enqueue 4, dequeue, dequeue, dequeue, how many single element moves from S1 to S2 happen?

How to think about it

  1. What is asked. The total transfer count.
  2. Which idea applies. Transfers happen only when S2 is empty at a dequeue.
  3. Work it out. First dequeue moves 1, 2, 3 (3 moves). Then 2 and 3 are dequeued from S2. Last dequeue finds S2 empty and moves 4 (1 move). Total 4.
  4. Check. Each element is moved exactly once, which is why the amortized cost is O(1).

Answer: 4.

Remember these

  1. A stack is LIFO and a queue is FIFO. Never mix them up in a trace.
  2. Peek on a stack shows the top, which is the newest item.
  3. Bracket matching uses a stack, with an empty-stack check at the end.
  4. In postfix evaluation, the first popped number is the right operand.
  5. In a circular queue, the next index is (pos + 1) % size.
  6. Use a count, or leave one cell empty, to tell full from empty in a circular queue.
