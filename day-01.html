Core language: names, objects and mutability

Python is dynamically typed. You do not declare a variable's type. Instead, a variable is a name that points to an object, and the object is what carries a type. In x = 10, the name x is attached to an int object holding 10. Writing x = "ten" afterwards does not change the int object. It simply attaches the name x to a new str object. The name is cheap and easy to move; the object is where the data lives.

x = 10
print(type(x))
x = "ten"
print(type(x), x)
<class 'int'>
<class 'str'> ten

Objects are either mutable or immutable

Every object is either mutable (its contents can change in place) or immutable (it can never change after it is created). This one idea explains most surprising Python behaviour, so learn it well.

Immutable (cannot change in place)Mutable (can change in place)
int, float, complex, bool, str, tuple, frozenset, bytes, Nonelist, dict, set, bytearray, and most instances of your own classes

Look at what happens when a string and a list are changed.

s = "hi"
t = s                # t and s now name the same str object
s += "!"             # str cannot change, so Python builds a NEW string for s
print(s, t)

a = [1, 2]
b = a                # b and a name the same list object
a += [3]             # the list changes IN PLACE, so b sees the change too
print(a, b)
hi! hi
[1, 2, 3] [1, 2, 3]

The string case rebinds the name s to a brand new object, so t keeps the old value. The list case mutates the one shared object, so both names show the change. Only hashable objects can be dictionary keys or set members, because an object's hash must never change while it sits in the table. In practice that means immutable objects such as strings, numbers and tuples.

Trapa += [3] and a = a + [3] look almost the same but are not. The first mutates the list in place. The second builds a new list and rebinds a. For a list shared by two names, only the first one changes what both names see.

Operators that surprise people

The / operator always returns a float in Python 3, even for 6 / 2. Floor division // rounds down toward negative infinity, not toward zero. This matters with negative numbers. The modulo operator % is defined so that (a // b) * b + a % b always equals a, which is why -7 % 2 is 1 and not -1.

print(7 / 2, 7 // 2, -7 // 2, -7 % 2, 2 ** 10)
print(0.1 + 0.2 == 0.3, round(0.1 + 0.2, 10) == 0.3)
print(1 < 3 < 5, 1 < 3 > 5)
3.5 3 -4 1 1024
False True
True False

Three lessons are in that output. First, -7 // 2 is -4 because -3.5 rounds down to -4. Second, floating point numbers cannot store 0.1 and 0.2 exactly, so their sum is slightly off from 0.3. Compare floats with a rounding step or with math.isclose, never with a bare ==. Third, comparisons chain: 1 < 3 > 5 means 1 < 3 and 3 > 5, which is False.

Truthiness: what counts as False

Python uses the same rule in if, while, and and or. An object is falsy when it is None, False, a numeric zero, or an empty collection or string. Everything else is truthy. The string "0" is truthy because it is a non-empty string, and the list [0] is truthy because it has one element.

for v in [0, 0.0, "", [], {}, set(), None, "0", [0], " "]:
    print(repr(v), bool(v))
0 False
0.0 False
'' False
[] False
{} False
set() False
None False
'0' True
[0] True
' ' True

A common habit is writing if len(items) == 0. The idiomatic form is if not items, which works for any container. Both are correct, but the second is shorter and says what you mean.

Interviewers askIs Python compiled or interpreted? The honest answer is both. CPython compiles source code to bytecode, which is a compact set of low-level instructions, and then a virtual machine interprets that bytecode one instruction at a time.

What is the difference between a mutable and an immutable object? Give one example of each.

An immutable object cannot change after it is created, for example an int or a str. A mutable object can change in place, for example a list or a dict. Changing a shared mutable object is visible through every name that refers to it. Changing an immutable one always produces a new object and leaves the old one untouched.

Built-in data structures and their costs

Python ships with four core containers that you will use in almost every solution: list (an ordered, growable sequence), tuple (an ordered, fixed sequence), dict (a mapping from keys to values) and set (an unordered collection of unique values). Knowing what each operation costs is what separates a quick, correct answer from a slow one.

The cost table to memorise

Big O notation (explained in the DSA section below) describes how the cost of an operation grows as the container grows. We write the size as n. The table gives the typical costs in CPython, the standard implementation.

Two words in that table need explaining. Average is the typical case for dicts and sets, which use hash tables. A hash table turns a key into a number (its hash) and jumps straight to the slot where that key should live, so a lookup does not depend on how many keys there are. In the rare worst case, many keys land in the same slot and the cost degrades toward O(n). Amortized means an operation is occasionally expensive but cheap on average over many operations. Appending to a list is the classic example. Most appends simply write into spare room. The rare append that finds no room copies the whole array into a bigger one, but because the new array is much bigger, those copies are spread thin over many appends.

Since Python 3.7, dicts also keep their keys in insertion order. This is a guaranteed part of the language, so you can rely on it.

list: the workhorse

A list is a dynamic array. Its items sit side by side in memory, so reading by index is instant. Adding at the end is cheap. Adding or removing at the front is slow, because every other item must move one place to make room or close the gap.

nums = [5, 3, 8]
nums.append(1)
nums.insert(0, 9)
print(nums, nums[-1], nums[1:3], nums[::-1])
print(sorted(nums), nums.pop(), nums)
squares = [x * x for x in range(6) if x % 2 == 0]
print(squares)
[9, 5, 3, 8, 1] 1 [5, 3] [1, 8, 3, 5, 9]
[1, 3, 5, 8, 9] 1 [9, 5, 3, 8]
[0, 4, 16]

Read the first line carefully. nums[-1] is the last item. nums[1:3] is a slice that takes indexes 1 and 2, because the end index is excluded. nums[::-1] is a reversed copy. The second line shows that sorted returns a new list and leaves nums alone, while pop() removes the last item and returns it. Arguments are evaluated from left to right, so sorted(nums) runs before pop() removes the 1. The last line is a list comprehension, a compact loop that builds a list. Here it produces the squares of the even numbers from 0 to 5.

TrapCalling list.pop(0) or list.insert(0, x) inside a loop turns an O(n) job into O(n squared). When you need a fast queue, use collections.deque, which is covered below.

tuple: fixed and hashable

A tuple cannot be changed after creation. That makes it smaller and a little faster than a list, and it lets it be used as a dictionary key. Packing and unpacking are the everyday uses.

point = (3, 4)
x, y = point
first, *rest = (1, 2, 3, 4)
print(x, y, first, rest, (5,) == 5, type((5,)))
3 4 1 [2, 3, 4] False <class 'tuple'>

The star in first, *rest collects all the leftover items into a list. A one-element tuple needs a trailing comma. (5,) is a tuple, but (5) is only the integer 5 in parentheses. That is why (5,) == 5 is False.

dict: keys to values

ages = {"asha": 21, "ravi": 23}
ages["meena"] = 22
print(ages.get("john"), ages.get("john", 0), "ravi" in ages)
for name, age in ages.items():
    print(name, age)
print({k: v for k, v in ages.items() if v > 21})
None 0 True
asha 21
ravi 23
meena 22
{'ravi': 23, 'meena': 22}

Reading ages["john"] directly would raise a KeyError, because John is not a key. The get method returns None when a key is missing, or the default value you pass as the second argument. The in operator checks keys, not values. The items() method gives key and value pairs, which the loop header unpacks into two names.

TipA dict comprehension such as {k: v for k, v in ...} builds a dict the same way a list comprehension builds a list. The trailing if keeps only the pairs that match.

set: unique values and fast membership

A set stores each value once and answers "is this value present?" in O(1) on average. It also supports the mathematical operations of union, intersection, difference and symmetric difference.

a, b = {1, 2, 3}, {3, 4}
print(a | b, a & b, a - b, a ^ b)
print(list(set([3, 1, 3, 2, 1])))
{1, 2, 3, 4} {3} {1, 2} {1, 2, 4}
[1, 2, 3]

The operators are | for union (everything in either set), & for intersection (only what both sets share), - for difference (in the left set but not the right), and ^ for symmetric difference (in exactly one of the two). The second line removes duplicates from a list. A set has no order guarantee, so convert it back to a sorted list when the order matters.

Interviewers askWhy does a set lookup take O(1) average time and a list lookup take O(n)? A set uses hashing to jump to the slot for a value. A list has no such shortcut, so it must compare with each item in turn.

Why is x in some_list slow for a large list, and what should you use instead?

The membership test scans the list from the start until it finds x or runs out of items, which is O(n). If you need to test membership many times, build a set once from the list (O(n)) and then test with in on the set, which is O(1) on average for each test.

The standard library helpers: collections, heapq and bisect

The standard library contains specialised containers that remove a lot of boilerplate. Interviewers expect you to know them, because they make solutions shorter and faster. Each example below is complete, so you can copy it into a file and run it.

Counter: count things

A Counter is a dict subclass that counts hashable items. Missing keys return 0 instead of raising an error, and most_common returns the most frequent items first. When two items have the same count, they appear in the order they were first seen.

from collections import Counter

c = Counter("mississippi")
print(c)
print(c.most_common(2), c["z"])
Counter({'i': 4, 's': 4, 'p': 2, 'm': 1})
[('i', 4), ('s', 4)] 0

defaultdict: no KeyError for new keys

A defaultdict is a dict that creates a default value the first time you touch a missing key. You pass it a factory function such as list, which is called with no arguments to make each new value. This removes the common "if key not in dict, create the list first" code.

from collections import defaultdict

groups = defaultdict(list)
for word in ["apple", "avocado", "banana", "blueberry", "cherry"]:
    groups[word[0]].append(word)
print(dict(groups))
{'a': ['apple', 'avocado'], 'b': ['banana', 'blueberry'], 'c': ['cherry']}

When groups["a"] is first read, the dict has no such key, so list() is called to create an empty list, which is stored and returned. The append then works on that stored list.

deque: fast at both ends

A deque (pronounced "deck", short for double-ended queue) is a list-like container that is O(1) to add or remove at either end. It is the right tool for queues, for breadth-first search and for sliding windows. It also accepts a maxlen, which silently drops the oldest item when full.

from collections import deque

d = deque([1, 2, 3])
d.appendleft(0)
d.append(4)
print(d.popleft(), d)
d.rotate(1)
print(d)
recent = deque(maxlen=3)
for i in range(5):
    recent.append(i)
print(recent)
0 deque([1, 2, 3, 4])
deque([4, 1, 2, 3])
deque([2, 3, 4], maxlen=3)

rotate(1) moves every item one step to the right, so the last item wraps around to the front. The maxlen=3 deque keeps only the three most recent values, which is handy for "last N events" questions.

TrapDo not use a plain list as a queue with pop(0). Each call shifts the whole list. Use deque.popleft() instead.

namedtuple: a tuple with names

A namedtuple creates a small immutable class whose instances are tuples, but whose fields can also be read by name. It is lighter than writing a class by hand, and it still unpacks like any tuple.

from collections import namedtuple

Point = namedtuple("Point", ["x", "y"])
p = Point(3, 4)
print(p, p.x, p[1])
Point(x=3, y=4) 3 4

heapq: a min-heap built on a plain list

A heap is a tree-shaped structure stored in a list in which the smallest item is always at index 0. The heapq module offers functions that keep this order. heappush and heappop each take O(log n). heapify turns an existing list into a heap in O(n). Python provides only a min-heap, so for a max-heap you store negated values.

import heapq

nums = [5, 1, 8, 3, 2]
heapq.heapify(nums)
heapq.heappush(nums, 0)
print([heapq.heappop(nums) for _ in range(len(nums))])
print(heapq.nlargest(2, [5, 1, 8, 3, 2]), heapq.nsmallest(3, [5, 1, 8, 3, 2]))

maxheap = []
for x in [5, 1, 8]:
    heapq.heappush(maxheap, -x)
print(-heapq.heappop(maxheap))
[0, 1, 2, 3, 5, 8]
[8, 5] [1, 2, 3]
8

Popping repeatedly returns the items in ascending order, which is a simple heap sort. For a max-heap, negation is the trick: the most negative stored number is the largest original number, so the heap's minimum is the original maximum. Use a heap for "top k" questions, "k-th largest" questions, merging several sorted lists, and shortest-path algorithms such as Dijkstra.

bisect: binary search on a sorted list

bisect_left(a, x) returns the index where x would be inserted to keep a sorted, placing x before any equal values. bisect_right (also called bisect) places x after equal values. insort inserts x at that position. All of these take O(log n) to find the position, but inserting into a list still shifts items, so the insert itself is O(n).

import bisect

a = [1, 3, 3, 5, 8]
print(bisect.bisect_left(a, 3), bisect.bisect_right(a, 3), bisect.bisect_left(a, 4))
bisect.insort(a, 4)
print(a)

def grade(score, cutoffs=(60, 70, 80, 90), letters="FDCBA"):
    return letters[bisect.bisect(cutoffs, score)]

print([grade(s) for s in [59, 60, 85, 90, 100]])
1 3 3
[1, 3, 3, 4, 5, 8]
['F', 'D', 'B', 'A', 'A']

The grade function is a clean use of bisect. The cutoffs are sorted, so bisect returns how many cutoffs the score has reached. Score 59 reaches none and gets index 0, which is F. Score 60 reaches one cutoff, so it gets D. The cutoffs are a tuple here, which avoids the mutable default trap explained later in this page.

Key ideabisect only works on a list that is already sorted. It does not sort for you, and on an unsorted list its answer is meaningless.

When would you choose a heap over sorting the whole list?

When you need only some of the items. Keeping the k largest items seen so far in a min-heap of size k costs O(n log k), which beats the O(n log n) of a full sort when k is small. Sorting is simpler when you need every item in order anyway.

Functions: parameters, arguments and first-class functions

A function is a named block of code that takes inputs (parameters) and returns a result. When you call it, the values you pass are the arguments. Python's rules for matching arguments to parameters are richer than most languages, and interviewers like to probe them.

Every parameter kind in one signature

Read the signature below from left to right. The / and * markers are separators that control how callers may pass each parameter.

def f(a, /, b, c=3, *args, d, e=5, **kwargs):
    print(a, b, c, args, d, e, kwargs)

f(1, 2, 30, 40, 50, d=4, z=9)
1 2 30 (40, 50) 4 5 {'z': 9}
Part of the signatureMeaning
a, /Positional-only. The caller must pass a by position, so a=1 is an error.
b, c=3Normal parameters. They can be passed by position or by name. c has a default of 3.
*argsCollects any extra positional arguments into a tuple. Here it receives 40 and 50.
d, e=5 after the starKeyword-only. These must be passed by name, as d=4.
**kwargsCollects any extra keyword arguments into a dict. Here it receives z=9.

Working through the call f(1, 2, 30, 40, 50, d=4, z=9) step by step: 1 goes to a because it is first. 2 goes to b. 30 goes to c. The next two positional values, 40 and 50, do not fit any named positional parameter, so they fill args. d=4 matches the keyword-only d. Nothing supplied e, so it keeps its default of 5. z=9 matches no named parameter, so it lands in kwargs.

TipYou will write *args and **kwargs when you wrap another function and want to pass everything through unchanged. The decorator lesson in day 2 relies on exactly this pattern.

How arguments are passed: object references

Python does not have "pass by value" or "pass by reference" in the C or Java sense. Each argument is passed as a reference to an object. The function gets its own new name for the same object. That leads to a rule with two halves. If the function mutates the object, the caller sees the change. If the function reassigns its name, the caller does not.

def modify(lst):
    lst.append(4)      # mutates the caller's list, which is the same object
    lst = [99]         # rebinds only the local name lst

nums = [1, 2, 3]
modify(nums)
print(nums)
[1, 2, 3, 4]

Trace it: the name nums and the parameter lst both point at one list object. append changes that object, so nums shows the 4. Then lst = [99] makes the local name point at a different list, and that new list disappears when the function ends. The caller's nums is untouched by that line.

Functions are objects

A function is a value like any other. You can store it in a variable, pass it to another function, return it, and put it in a list. Functions that take or return functions are called higher-order. The built-in functions sorted, map and filter are all higher-order.

def shout(s):
    return s.upper()

def apply(func, value):
    return func(value)

print(apply(shout, "hi"), apply(lambda s: s[::-1], "hi"))

words = ["kiwi", "Banana", "apple"]
print(sorted(words))
print(sorted(words, key=str.lower))
print(sorted(words, key=len))
print(list(map(len, words)), list(filter(lambda w: "a" in w, words)))
HI ih
['Banana', 'apple', 'kiwi']
['apple', 'Banana', 'kiwi']
['kiwi', 'apple', 'Banana']
[4, 6, 5] ['Banana', 'apple']

lambda s: s[::-1] is an anonymous one-expression function. key= tells sorted what to compare by. The plain sort puts "Banana" first because uppercase letters have smaller codes than lowercase ones: 'B' is 66 and 'a' is 97. Sorting with key=str.lower ignores case. Sorting with key=len orders by length, and Python's sort is stable, so items with equal keys keep their original order.

Interviewers askWhat is the difference between *args and **kwargs? *args collects extra positional arguments as a tuple. **kwargs collects extra keyword arguments as a dict. The names are only conventions; the star is what matters.

Given def f(a, *args, b=2, **kw), what are a, args, b and kw after f(1, 2, 3, b=4, c=5)?

a is 1. args is the tuple (2, 3). b is 4 because it was passed by keyword. kw is the dict {'c': 5}, which collected the keyword that matched no named parameter.

Scope (LEGB) and closures

Scope is the part of a program where a name is visible. When Python meets a name, it looks it up in a fixed order called LEGB: Local (inside the current function), Enclosing (in any function that contains the current one), Global (at the top level of the module), and Built-in (names such as len and print). The first match wins.

x = "global"
def outer():
    x = "enclosing"
    def inner():
        x = "local"
        print(x)
    inner()
    print(x)

outer()
print(x)
local
enclosing
global

Each print finds the nearest x. Inside inner, the local assignment wins. Back in outer, the enclosing assignment is found. At the module level, only the global one exists.

global and nonlocal: changing a name from outside its function

Reading a name from an outer scope is automatic. Assigning to it is not. Writing x = 5 inside a function creates a new local x instead of changing the global one. Two keywords fix this. global x means "this name refers to the module-level x". nonlocal x means "this name refers to the nearest enclosing function's x".

count = 0

def bump():
    global count        # assign to the module-level name
    count += 1

bump()
bump()
print(count)
2

TrapAny assignment to a name anywhere in a function makes that name local for the whole function. So total += 1 inside a function fails if total is a global you never declared with global. Python reads the name as local before it has a value.

total = 0

def add():
    total += 1

try:
    add()
except UnboundLocalError as e:
    print("UnboundLocalError:", e)
UnboundLocalError: cannot access local variable 'total' where it is not associated with a value

The fix is to add global total at the top of add, or to pass total in and return the new value. Passing values in and returning results is usually the cleaner design.

TrapShadowing a built-in name. If you write list = [1, 2], the global name list now hides the built-in type for the rest of the module, and calling list(...) breaks.

list = [1, 2]
try:
    list("ab")
except TypeError as e:
    print("TypeError:", e)
TypeError: 'list' object is not callable

Never use the names of built-ins such as list, dict, str, id, sum or max as variable names. Choose items, mapping, text, ident, total or best instead.

Closures: functions that remember their surroundings

A closure is an inner function that keeps access to variables from the enclosing function, even after that enclosing function has returned. Python attaches the captured variables to the inner function. You can inspect them through the __closure__ attribute. Closures are the mechanism behind decorators, which you will see on day 2.

def make_multiplier(n):
    def multiply(x):
        return x * n          # n comes from the enclosing scope
    return multiply

double = make_multiplier(2)
triple = make_multiplier(3)
print(double(5), triple(5))
print(double.__closure__[0].cell_contents)
10 15
2

make_multiplier finished running long before double(5) was called, yet double still knows n is 2. Each call to make_multiplier creates a separate n, which is why double and triple do not interfere.

A counter with state, using nonlocal

A closure can also change the variable it captured, as long as it declares that variable with nonlocal. This gives you a small piece of private state without writing a class.

def make_counter():
    count = 0
    def increment():
        nonlocal count        # modify the enclosing variable, not a new local
        count += 1
        return count
    return increment

c = make_counter()
print(c(), c(), c())
1 2 3

Late binding: a classic interview trap

A closure looks up its captured variable when it is called, not when it is created. Loops make this visible. The lambdas below all share the same i, and by the time they run, the loop has finished with i equal to 2.

TrapClosures created in a loop all see the final value of the loop variable. Fix it by capturing the current value as a default argument.

funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])
[2, 2, 2]
[0, 1, 2]

The default argument i=i is evaluated once, at the moment each lambda is created, so each lambda keeps its own copy of the current value. This works, but a helper function with an explicit parameter is often clearer in production code.

Interviewers askWhat is a closure? An inner function that remembers variables from its enclosing scope after that scope has finished, usually created by a function that returns the inner function.

What does nonlocal do that a plain assignment inside a closure does not?

A plain assignment creates a new local name in the inner function, so the enclosing variable is left alone. nonlocal tells Python to find the nearest enclosing variable with that name and assign to it, which is how the closure can update state shared with the outer function.

The mutable default argument trap

Python evaluates a default argument value once, when the def statement runs, not each time the function is called. The default object is then stored on the function and reused. If that default is a mutable object such as a list, every call that uses the default shares the same list. This is one of the most common bugs in Python code, and interviewers use it to check whether you understand evaluation time.

def add_item(item, bucket=[]):
    bucket.append(item)
    return bucket

print(add_item(1))
print(add_item(2))
[1]
[1, 2]

The second call did not start with a fresh empty list. It received the same list that the first call built, and appended to it. The default list lives on the function object, in the attribute add_item.__defaults__. Each call that leaves bucket out gets that one shared object.

The standard fix is to use None as the default, a sentinel meaning "not given", and create the list inside the function when it is needed.

def add_item(item, bucket=None):
    if bucket is None:
        bucket = []          # a fresh list on every call
    bucket.append(item)
    return bucket

print(add_item(1), add_item(2))
[1] [2]

TrapThe same problem appears with dicts and sets as defaults, and with any mutable object. Immutable defaults such as numbers, strings, and tuples are safe, because you cannot change them in place.

Mutable defaults are not always a bug. A deliberate cache can use one, although functools.lru_cache is clearer and safer. The point is that the choice should be deliberate.

Key ideaDefault values are evaluated at definition time, once. Use None as the default for any mutable argument, and create the object inside the function.

When exactly is the default value of a parameter evaluated?

When the def statement runs, which is normally when the module is imported. It is not evaluated on each call. That is why a mutable default is shared between calls.

Interview questions

Answer each question aloud before you open the answer. The model answers are short, so use them as a checklist of points rather than a script.

What is the difference between a name and an object in Python?

An object is the value in memory, with a type and contents. A name is a label that refers to an object. Assigning a name does not copy the object, and two names can refer to the same object.

Why can a list not be a dictionary key, while a tuple can?

A dictionary key must have a hash that never changes. A list can be modified in place, which could change its contents and break the table. A tuple can only hold immutable items, so it is safe to hash. Note that a tuple holding a list is not hashable, because it contains something mutable.

What is the time complexity of in for a list, a set and a dict?

For a list it is O(n), because the search scans items. For a set and a dict it is O(1) on average, because the hash table jumps directly to the slot. The worst case for sets and dicts is O(n) when many keys collide.

What does -7 // 2 give, and why?

It gives -4. Floor division rounds toward negative infinity, and -3.5 rounds down to -4. Truncation toward zero would give -3, which is a different operation.

Why is list.pop(0) slow, and what do you use for a queue?

Removing the first item forces every other item to shift one place, which is O(n). Use collections.deque and call popleft(), which is O(1).

What is amortized O(1) time, and why does append have it?

Amortized O(1) means the average cost per operation over a long sequence is constant, even though some single operations are expensive. Appending usually writes into spare capacity. When the array is full, it copies everything into a larger array, but the capacity doubles, so the total copying over n appends is at most about 2n.

What is the difference between *args and a regular parameter?

A regular parameter binds exactly one argument by name or position. *args collects any number of extra positional arguments into a tuple, so the function can accept a variable number of values.

What does LEGB stand for, and in what order does Python search?

Local, Enclosing, Global, Built-in. Python searches the innermost scope first and moves outward, stopping at the first match.

What is a closure, and what does nonlocal add?

A closure is an inner function that keeps references to variables of its enclosing function, even after that function returns. nonlocal lets the inner function assign to one of those variables rather than creating a new local.

Explain why def f(x, items=[]) behaves strangely when called twice without items.

The default list is created once when def runs and is shared by every call that omits the argument. Calls that append to it see each other's items. Use items=None and create the list inside the function.

What is the difference between heapq.nlargest(k, data) and sorted(data)[-k:]?

Both give the k largest items. nlargest works in O(n log k) with a heap of size k, while sorting costs O(n log n). For small k and large n, the heap is faster. Sorting is simpler and fine when n is small.

DSA: Big O and the array patterns

A data structure stores data. An algorithm is a step-by-step procedure that works on it. Interviewers want to see that you can describe how much time and memory your solution needs as the input grows. The language for that is Big O notation.

What Big O measures

Big O describes how the number of steps (time) or the amount of extra memory (space) grows as the input size n grows. It ignores constant factors and smaller terms, because they matter less as n gets large. A machine twice as fast is still the same Big O class; a solution that does n squared steps will eventually lose to one that does n steps, however fast the machine is.

The rules for counting

  • Drop constants: O(3n + 5) is O(n).
  • Keep only the biggest term: O(n2 + n) is O(n2).
  • Steps in sequence add up. A loop followed by another loop is O(a + b) for lengths a and b.
  • Nested loops multiply. A loop inside another loop, both over n, is O(n2).

Count the steps directly to see these rules at work. The two functions below count how many times the inner statement runs.

def steps_nested(n):
    count = 0
    for i in range(n):
        for j in range(i, n):
            count += 1
    return count

def steps_halving(n):
    count = 0
    while n > 1:
        n //= 2
        count += 1
    return count

for n in [8, 1000]:
    print(n, steps_nested(n), steps_halving(n))
8 36 3
1000 500500 9

The nested loop runs 1 + 2 + ... + n times, which is n(n + 1) / 2, so it grows with n squared. For n = 1000 that is 500,500 steps. The halving loop divides n by 2 each time, so it needs about log2(n) steps. For n = 1000 that is 9 steps, because 2 to the power 9 is 512 and 2 to the power 10 is 1024.

Amortized O(1): why append is fast

The Big O of a single append is not always O(1). When the internal array is full, Python allocates a bigger one and copies every item. The trick is that the new array is much bigger, so such copies are rare. The function below simulates a dynamic array that doubles its capacity, and counts how many item copies happen over n appends.

def copies_for_appends(n):
    capacity, size, copies = 1, 0, 0
    for _ in range(n):
        if size == capacity:          # the array is full: copy into a bigger one
            copies += size
            capacity *= 2
        size += 1
    return copies

for n in [10, 100, 1000]:
    c = copies_for_appends(n)
    print(n, c, round(c / n, 2))
10 15 1.5
100 127 1.27
1000 1023 1.02

The amortized argument is easy to check with the output. Ten appends cost 15 copies, 100 appends cost 127, and 1000 appends cost 1023. The copies per append settle near 1, which is constant. Each append costs O(1) amortized, while any single append in the middle of a growth step may cost O(n). Interviewers often ask the difference between worst case and amortized cost, so keep this example in mind.

The array patterns you will use all week

Most array questions reduce to one of a few patterns. Recognising the pattern is half of the solution.

  • Hash map lookup. When a question asks for a pair, a count or a "seen before" check, store what you have seen in a dict or set, so each check is O(1).
  • Running values. Keep the best, smallest or largest value seen so far while you scan once.
  • Prefix sums. Precompute running totals once, so any range sum becomes a subtraction.
  • Two pointers. Use two indexes that move through the array together, often to rearrange items in place.
  • Index as a hash. When values are bounded by the array length, the array itself can record what has been seen.

Two Sum (LeetCode 1)

Given an array nums and an integer target, return the indices of two different elements whose values add up to target. Exactly one answer exists, and you may not use the same element twice. For nums = [2, 7, 11, 15] and target = 9, the answer is [0, 1], because 2 + 7 = 9.

How to think about it

  1. Understand. We need indices, not values. The two indices must be different. Negative numbers and duplicate values are allowed.
  2. Brute force. Try every pair with two nested loops. That is O(n squared) time and O(1) extra space.
  3. Find the waste. The inner loop searches the whole array for target - x, which is a lookup. A lookup is what a dict is good at, but the brute force does a linear scan for it every time.
  4. Optimise. Walk the array once. For each value x, check whether target - x has already been seen. If yes, we have the pair. If no, remember x with its index. The dict turns each check into O(1) on average, so the whole job is O(n).
  5. Dry run. With nums = [2, 7, 11, 15] and target = 9, the table shows the state at each step.
ixneed = target - xIs need in seen?seen after the step
027no, seen is empty{2: 0}
172yes, at index 0, return [0, 1]not reached

Code

def two_sum(nums, target):
    seen = {}                        # value -> index where we saw it
    for i, x in enumerate(nums):
        need = target - x
        if need in seen:
            return [seen[need], i]
        seen[x] = i                  # remember this value for later elements
    return []

print(two_sum([2, 7, 11, 15], 9))
print(two_sum([3, 2, 4], 6))
print(two_sum([1, 2], 7))
[0, 1]

Time O(n) · Space O(n)

Pattern to rememberWhen you need a pair that satisfies a condition, ask "what do I need to find for this element?" and store what you have seen in a dict.

Product of Array Except Self (LeetCode 238)

Given an integer array nums, return an array answer where answer[i] is the product of every element of nums except nums[i]. You must do it in O(n) time and you may not use division. For nums = [1, 2, 3, 4], the answer is [24, 12, 8, 6].

How to think about it

  1. Understand. The output has the same length as the input. Zeros and negative numbers are possible. Division is forbidden, which rules out the shortcut "total product divided by nums[i]", because that breaks on zeros.
  2. Brute force. For each i, multiply all the other elements. That is O(n squared) time.
  3. Find the waste. For each i, the product splits into two parts: everything to the left of i, and everything to the right of i. Both parts are recomputed from scratch for every i, even though they only change by one element from one i to the next.
  4. Optimise. Compute the left products in one pass, storing each one directly in the answer. Then compute the right products in a second pass from the other end, multiplying each one into the answer. Both passes carry one running product, so the extra space is O(1), not counting the output.
  5. Dry run. The table below follows [1, 2, 3, 4]. In the left pass, prefix holds the product of everything before i. In the right pass, suffix holds the product of everything after i.

Code

def product_except_self(nums):
    n = len(nums)
    answer = [1] * n
    prefix = 1
    for i in range(n):                  # answer[i] = product of everything LEFT of i
        answer[i] = prefix
        prefix *= nums[i]
    suffix = 1
    for i in range(n - 1, -1, -1):      # multiply in everything RIGHT of i
        answer[i] *= suffix
        suffix *= nums[i]
    return answer

print(product_except_self([1, 2, 3, 4]))
print(product_except_self([-1, 1, 0, -3, 3]))
[24, 12, 8, 6]
[0, 0, 9, 0, 0]

Time O(n) · Space O(1) extra, not counting the output array

Pattern to rememberWhen each answer depends on everything to its left and everything to its right, make two passes that each carry one running value, instead of recomputing either side for every position.

Longest Consecutive Sequence (LeetCode 128)

Given an unsorted array of integers nums, return the length of the longest run of consecutive integers that can be formed from its values. The order of the values in the array does not matter, and you must solve it in O(n) time. For nums = [100, 4, 200, 1, 3, 2], the answer is 4, from the run 1, 2, 3, 4.

How to think about it

  1. Understand. Duplicates should not count twice. Each run is a set of values with no gaps, such as 1, 2, 3, 4. The answer for an empty array is 0.
  2. Brute force. Sort the array and scan for the longest run. Sorting costs O(n log n), which is too slow for the O(n) requirement. A second brute force starts from every value and counts upward with a linear search, which is O(n squared).
  3. Find the waste. Each run is discovered again from every one of its members. Starting from 2 repeats the work done from 1, even though both lead to the same run.
  4. Optimise. Put all the values in a set, so each membership test is O(1). Then only start counting from a value x when x - 1 is not in the set. That value must be the start of its run. Counting upward from it visits each value of that run once. Values in the middle of a run are skipped as starts, so no value is counted twice. The total work is O(n).
  5. Dry run. The table follows [100, 4, 200, 1, 3, 2]. It shows which values start a run and how long each run is.

Code

def longest_consecutive(nums):
    values = set(nums)                   # O(1) membership tests
    best = 0
    for x in values:
        if x - 1 not in values:          # only a run's first value starts a count
            length = 1
            while x + length in values:
                length += 1
            best = max(best, length)
    return best

print(longest_consecutive([100, 4, 200, 1, 3, 2]))
print(longest_consecutive([0, 3, 7, 2, 5, 8, 4, 6, 0, 1]))

First Missing Positive (LeetCode 41)

Given an unsorted integer array nums, return the smallest positive integer that does not appear in it. You must run in O(n) time and use O(1) auxiliary space, which means you may change the array but not allocate a large new structure. Examples: [1, 2, 0] gives 3, [3, 4, -1, 1] gives 2, and [7, 8, 9, 11, 12] gives 1.

How to think about it

  1. Understand. Negative numbers, zero and values larger than the array are irrelevant to the answer. The answer always lies between 1 and n + 1 for an array of length n, because n values can cover at most n of the numbers 1 to n. If all of 1 to n are present, the answer is n + 1.
  2. Brute force. Try candidates 1, 2, 3 and so on, and for each one scan the whole list to see whether it is present. The cost is O(n) per candidate and up to n + 1 candidates, so O(n squared) in the worst case, which is too slow.
  3. Find the waste. Each membership check is a linear scan. Sorting would make the scan faster but costs O(n log n). A set would give O(1) checks, but it uses O(n) extra space, which breaks the requirement.
  4. Optimise. Use the array itself as the hash table. Every useful value v lies in 1 to n, so it has a home slot at index v - 1. Move each value into its home slot by swapping, then scan once. Each swap places one value permanently in its home slot, so there are at most n swaps in total, which keeps the algorithm at O(n). The first index that does not hold its own number tells us the answer.
  5. Dry run. The table traces [3, 4, -1, 1]. The value 3 belongs at index 2, and so on. The check nums[v - 1] != v stops the swapping when a value is already home or when the value is useless.

def first_missing_brute(nums):
    candidate = 1
    while candidate in nums:            # a linear scan of nums on every check

    return candidate

The optimal version places values into their home slots in place, then looks for the first wrong slot.

def first_missing_positive(nums):
    n = len(nums)
    i = 0
    while i < n:
        v = nums[i]
        # v belongs at index v - 1 if it is in range and that slot is not already right
        if 1 <= v <= n and nums[v - 1] != v:
            nums[i], nums[v - 1] = nums[v - 1], nums[i]
        else:
            i += 1
    for i in range(n):
        if nums[i] != i + 1:
            return i + 1
    return n + 1

print(first_missing_positive([1, 2, 0]))
print(first_missing_positive([3, 4, -1, 1]))
print(first_missing_positive([7, 8, 9, 11, 12]))
3
2
1

Notice the order of the checks in the condition. The range test 1 <= v <= n comes first, so that nums[v - 1] is only read when the index is valid. Reading it with a negative or too-large index would either give a wrong answer or raise an error. The i index moves forward only when the current value is useless or already home, which is why the loop finishes.

Time O(n) · Space O(1) extra (the array is changed in place)

Pattern to rememberWhen the values are bounded by the array length, let the array's indexes act as a hash table. Place each value in its own slot, then look for the first slot that is wrong.
