Tuple calculus

Relational calculus lets you say WHAT rows you want from a database, not HOW to fetch them. Tuple calculus is the row-by-row version of this idea, and GATE uses it to test whether you can read and write precise database queries.

The idea in plain words

Imagine you ask a librarian, "Please give me the titles of all books written by Asha." You described the result you want. You did not say which shelf to walk to first or how to check each spine. The librarian decides the steps.

A database works the same way. A query is a question you ask the database. There are two styles:

  • Procedural style: you give a sequence of operations, such as "filter this table, then join it with that table". This is relational algebra. It is a recipe.
  • Declarative style: you describe the properties each answer row must have, and leave the recipe to the database. This is relational calculus. It is a rule.

Relational calculus comes in two flavours. Tuple relational calculus (TRC) talks about whole rows. Domain relational calculus (DRC) talks about single values inside rows. Both use ideas from logic, so you will see words such as "and", "or", "not", "there exists" and "for all". Each symbol is defined before it is used.

GATE Data Science and AI (paper DA) and Robotics and Automation (paper RA) ask questions of this kind. You may be asked to read a calculus expression and state its output, to write one for a plain request, to decide whether it is safe, or to match it with an equivalent algebra or SQL query.

Key terms

Read the plain meaning first. The precise definition comes after it.

Relation
A table. Plain meaning: a grid of rows and columns. Precise definition: a finite set of tuples that share the same attributes.
Attribute
A column name, such as cgpa. Precise definition: a named position in a relation, with a domain of allowed values.
Tuple
One row of a table. Plain meaning: one record. Precise definition: an ordered list of values, one for each attribute.
Domain
The allowed values of an attribute, such as numbers from 0 to 10. Precise definition: the set from which an attribute's values are drawn.
Tuple variable
A name that stands for any row of a table. Precise definition: a TRC variable whose range is the tuples of a relation.
Domain variable
A name that stands for any value in a column. Precise definition: a DRC variable whose range is the domain of an attribute.
Predicate
A yes or no statement about values, such as "is the cgpa at least 8.5?". Precise definition: a function that returns true or false.
Quantifier
A word that says how many rows you mean. Plain meaning: "at least one" or "every one". Precise definition: the existential quantifier ∃ ("there exists") and the universal quantifier ∀ ("for all").
Free variable
A variable not yet tied to a quantifier. Plain meaning: a name the answer is built from. Precise definition: a variable that occurs without being bound by ∃ or ∀.
Bound variable
A variable controlled by a quantifier. Plain meaning: a name that lives only inside its bracket. Precise definition: a variable in the scope of ∃ or ∀.
Active domain
All values that actually appear in the database, plus constants written in the query.
Safe expression
A calculus expression whose answer depends only on stored data. Plain meaning: it cannot produce endless answers. Precise definition: its result contains only values from the active domain.
Declarative
Describes what you want. Plain meaning: "give me the rows that satisfy this rule".
Procedural
Describes how to get the answer. Plain meaning: "do step 1, then step 2".
Relational algebra (RA)
A procedural language with operators σ (select), π (project), ⋈ (join), ∪, − and ×. Precise definition: operations that map relations to relations.

Concept 1: Tuple relational calculus (TRC)

The basic shape

In TRC, you describe a set of rows with one rule:

{ t | P(t) }

Read it as "the set of all tuples t such that P(t) is true". Each symbol means:

  • { ... } is "the set of", and the answer is a set of rows.
  • t is a tuple variable. It stands for one row at a time.
  • | means "such that".
  • P(t) is the rule each answer row must satisfy.

The atom Student(t) means "t is a row of the Student table". The expression t.cgpa means "the cgpa value of row t". Here is a query for names of students with cgpa at least 8.5:

{ t.name | Student(t) ∧ t.cgpa ≥ 8.5 }

The database reads it row by row:

  1. Take each row t of Student.
  2. Check Student(t). It is true for every row of Student.
  3. Check t.cgpa ≥ 8.5. Asha (9.1) passes. Ravi (7.8) fails. Meena (8.7) passes. Dev (6.9) fails. Kiran (8.2) fails.
  4. Keep the rows where both checks pass, and show their names.

The answer is Asha and Meena. The symbol ∧ means "and", so both parts must be true.

TipRead a TRC expression from the inside out. First understand the condition after the bar, row by row. Then look at the target list on the left.

A query that needs two tables

Now: "names of students enrolled in CS101". The name is in Student, but the course is in Enrol. We link them with sid, using a second tuple variable e that ranges over Enrol:

{ s.name | Student(s) ∧ ∃e (Enrol(e) ∧ e.sid = s.sid ∧ e.cid = 'CS101') }

For now, read ∃e (...) as "there is some enrolment row e that makes the bracket true". The next concept explains ∃ fully.

Work it out for each student:

  • Asha (101): CS101 is one of her rows, so she qualifies.
  • Ravi (102): his only row is EE201. He does not qualify.
  • Meena (103): she has CS101 with grade 10. She qualifies.
  • Dev (104): no enrolment rows at all. He does not qualify.
  • Kiran (105): only CS301. He does not qualify.

TrapThe equals sign in e.sid = s.sid is the join. If you forget it, every enrolment matches every student, and you get wrong names. Always write the link between tables.

The Python program below runs both queries on the sample tables. Each tuple is (sid, name, dept, cgpa).

students = [
    (101, "Asha", "CS", 9.1),
    (102, "Ravi", "EE", 7.8),
    (103, "Meena", "CS", 8.7),
    (104, "Dev", "ME", 6.9),
    (105, "Kiran", "CS", 8.2),
]
enrol = [
    (101, "CS101", 9), (101, "CS301", 8), (102, "EE201", 7),
    (103, "CS101", 10), (103, "CS301", 9), (105, "CS301", 6),
]

# TRC 1: { t.name | Student(t) and t.cgpa >= 8.5 }
q1 = [t[1] for t in students if t[3] >= 8.5]
print("Q1 names with cgpa >= 8.5:", q1)

# TRC 2: { s.name | Student(s) and exists e (Enrol(e) and e.sid = s.sid and e.cid = 'CS101') }
q2 = [s[1] for s in students
      if any(e[0] == s[0] and e[1] == "CS101" for e in enrol)]
print("Q2 names enrolled in CS101:", q2)

Q2 names enrolled in CS101: ['Asha', 'Meena']
Question: Why is Kiran missing from Q1, even though Kiran is in CS?

Q1 only tests cgpa. Kiran has 8.2, which is less than 8.5. The department is not part of this query.

Question: What does ∧ mean in a TRC expression?

It means "and". Both the left part and the right part must be true for a row to be in the answer.

Concept 2: The quantifiers, there exists and for all

The everyday meaning

Quantifiers talk about "how many" without counting:

  • There exists (∃): at least one row makes this true. Like searching a shelf until you find one matching book.
  • For all (∀): every row makes this true. Like checking every book on a shelf.
∃t ∈ R (P(t)) means at least one tuple t of relation R makes P(t) true
∀t ∈ R (P(t)) means every tuple t of relation R makes P(t) true

A worked ∀ example, step by step

Question: "Which students have every enrolled course with grade at least 8?"

{ s.name | Student(s) ∧ ∀e (Enrol(e) ∧ e.sid = s.sid → e.grade ≥ 8) }

The arrow → means "if ... then". The statement A → B is false only when A is true and B is false.

  1. Asha (101). Her rows have grades 9 and 8. For each row, "this row is hers" leads to "grade is at least 8". Both pass, so Asha qualifies.
  2. Ravi (102). His only row has grade 7. The row is his, and 7 is not at least 8, so the arrow is false. Ravi does not qualify.
  3. Meena (103). Grades 10 and 9. Both pass. Meena qualifies.
  4. Dev (104). No rows at all. There is nothing to check, so the ∀ statement is true. Dev qualifies.
  5. Kiran (105). One row with grade 6. Kiran does not qualify.

The answer is Asha, Meena and Dev.

TrapDev is included even though Dev has no grades. A "for all" statement with no rows to check is true. Mathematicians call this "vacuously true". Many students expect Dev to be left out. Always check the empty case.

Converting ∀ into ∃ with ¬

Any ∀ can be rewritten with ∃ and ¬:

∀t (P(t)) is the same as ¬∃t (¬P(t))

"Every row satisfies P" means "there is no row that fails P". Here is the same query in that form:

{ s.name | Student(s) ∧ ¬∃e (Enrol(e) ∧ e.sid = s.sid ∧ e.grade < 8) }

For Dev, there is no row that fails, so the "not exists" is true. Dev qualifies again. The two versions agree.

Key ideaAny ∀ can be written with ∃ and ¬, and any ∃ with ∀ and ¬. Choose the form that reads more easily, and check both with the empty case.

Question: Why is Dev in the ∀ query but not in the ∃ query for CS101?

The ∃ query needs at least one row, and Dev has none, so it fails. The ∀ query checks every row, and with no rows the check passes vacuously.

Question: Write "every enrolment of student s has grade at least 9" using ¬ and ∃.

{ s.name | Student(s) ∧ ¬∃e (Enrol(e) ∧ e.sid = s.sid ∧ e.grade < 9) }. The idea: no enrolment row with grade below 9 exists.

students = [
    (101, "Asha", "CS", 9.1),
    (102, "Ravi", "EE", 7.8),
    (103, "Meena", "CS", 8.7),
    (104, "Dev", "ME", 6.9),
    (105, "Kiran", "CS", 8.2),
]
enrol = [
    (101, "CS101", 9), (101, "CS301", 8), (102, "EE201", 7),
    (103, "CS101", 10), (103, "CS301", 9), (105, "CS301", 6),
]

# forall form: an implication A -> B is the same as (not A) or B
q3 = [s[1] for s in students
      if all((not (e[0] == s[0])) or e[2] >= 8 for e in enrol)]
print("Q3 every grade at least 8:", q3)

# not-exists form
q4 = [s[1] for s in students
      if not any(e[0] == s[0] and e[2] < 8 for e in enrol)]
print("Q4 same answer with not-exists:", q4)
print("Same result:", q3 == q4)

Q4 same answer with not-exists: ['Asha', 'Meena', 'Dev']
Same result: True

Concept 3: Domain relational calculus (DRC)

From rows to single values

In DRC, each variable stands for one value from one column. We write the Student atom with four positions:

Student(s, n, d, c) means there is a row with sid = s, name = n, dept = d and cgpa = c

The answer lists the variables you want to see, inside angle brackets:

{ <n> | ∃s ∃d ∃c (Student(s, n, d, c) ∧ c ≥ 8.5) }
  1. The target list is <n>, so the answer contains only names.
  2. The quantifiers ∃s, ∃d and ∃c say that sid, dept and cgpa are needed only for the check, not for the answer.
  3. The condition c ≥ 8.5 keeps rows with cgpa at least 8.5.
  4. On the sample table, the names are Asha and Meena.

TipIn DRC, every column not in the target list must be tied to an ∃ or ∀. A free variable outside the target list is a mistake.

Question: What is the difference between a target list variable and a quantified variable?

A target list variable (inside the angle brackets) appears in the answer. A quantified variable (after ∃ or ∀) is used only inside the condition.

Question: Write a DRC expression for the sids of CS students.

{ <s> | ∃n ∃c (Student(s, n, 'CS', c)) }. The answer is 101, 103 and 105.

Concept 4: Safe and unsafe expressions

The problem with endless answers

Suppose someone asks for "all tuples t that are not in Student". There are endlessly many such tuples, because nothing limits what a tuple can contain. A query that can give an unlimited answer is unsafe. Database systems reject unsafe queries.

A query is safe when every value in its answer comes from the active domain, which is the set of values really stored in the database, plus constants written in the query.

  • { t | ¬Student(t) } is unsafe. Nothing forces t to be a stored row.
  • { t | Student(t) ∧ t.cgpa ≥ 8 } is safe. Every answer row must be a Student row.
  • { t | Enrol(t) ∧ t.grade = 10 } is safe. Every answer row must be an Enrol row.
  • { t | ∃s ∈ Student (s.sid = t.sid) } is unsafe. The variable t is not tied to any relation, so its other values are free.

TrapA relation name appearing somewhere is not enough. The variable itself must be restricted to a relation, usually by an atom joined with ∧, as in Student(t) ∧ ....

Key ideaSafe means finite and based on stored data. Unsafe means the answer could be endless or could use values the database never stored.

Question: Is { t | Student(t) ∨ Course(t) } safe?

Yes. Each answer row must be a row of Student or a row of Course, so every answer is stored data.

Concept 5: Declarative versus procedural, and conversion

One question in three languages

The question is "names of CS students with cgpa at least 8.5".

LanguageQueryStyle
Tuple calculus{ t.name | Student(t) ∧ t.dept = 'CS' ∧ t.cgpa ≥ 8.5 }Declarative
Relational algebraπname ( σdept='CS' ∧ cgpa≥8.5 (Student) )Procedural
SQLSELECT name FROM Student WHERE dept = 'CS' AND cgpa >= 8.5;Declarative

SQL is declarative too. Its WHERE clause states the rule, and the database chooses the steps. Relational algebra is procedural, because each symbol is an operation applied in order.

  • σ (select): keeps rows that satisfy a condition, like a filter.
  • π (project): keeps chosen columns and removes duplicate rows.
  • ⋈ (natural join): joins two tables on their common column.

Converting TRC to algebra, step by step

  1. Each relation atom such as Student(s) becomes the table name.
  2. Each condition on one table, such as s.dept = 'CS', becomes a σ.
  3. Each equality between tables, such as e.sid = s.sid, becomes a ⋈ on that column.
  4. The target list becomes a π.

Take "names of students enrolled in CS101". Following the pattern gives:

πname ( Student ⋈ σcid='CS101'(Enrol) )

First select the CS101 rows (sids 101 and 103). Then join with Student on sid (Asha and Meena). Then project the name column. The result matches Concept 1.

Converting a ∀ query to SQL

Plain SQL has no ∀. We use the duality rule from Concept 2: "every enrolment has grade at least 8" becomes "no enrolment has grade below 8", written with NOT EXISTS:

SELECT s.name
FROM Student s
WHERE NOT EXISTS (
    SELECT *
    FROM Enrol e
    WHERE e.sid = s.sid AND e.grade < 8
);

This returns Asha, Meena and Dev, the same answer as the TRC query.

GATE loves thisQuestions ask which algebra or SQL expression is equivalent to a calculus expression. Check the target list, then the conditions on each table, then the joins. Equivalent means the same rows on every database.

TrapAn expression that gives the right answer on one sample table is not necessarily equivalent. σname='Ravi'(Student) returns Ravi here, but it never checks enrolment, so it is not equivalent to a query about EE201 students.

students = [
    (101, "Asha", "CS", 9.1),
    (102, "Ravi", "EE", 7.8),
    (103, "Meena", "CS", 8.7),
    (104, "Dev", "ME", 6.9),
    (105, "Kiran", "CS", 8.2),
]
enrol = [
    (101, "CS101", 9), (101, "CS301", 8), (102, "EE201", 7),
    (103, "CS101", 10), (103, "CS301", 9), (105, "CS301", 6),
]

# Relational algebra: pi_name( sigma_cid='CS101' (Enrol) join Student on sid )
sel = [e for e in enrol if e[1] == "CS101"]
joined = [(s, e) for s in students for e in sel if s[0] == e[0]]
ra = sorted({s[1] for s, e in joined})
print("RA result:", ra)

# Tuple calculus form of the same question
trc = sorted({s[1] for s in students if any(e[0] == s[0] and e[1] == "CS101" for e in enrol)})
print("TRC result:", trc)
print("Same answer:", ra == trc)

RA result: ['Asha', 'Meena']
TRC result: ['Asha', 'Meena']
Same answer: True
Question: Which operator removes duplicate rows?

The projection π. Relational algebra works on sets, so duplicates disappear when you project.

Which expressions are safe

Select all that apply. Which of these TRC expressions are safe?

(A) { t | ¬Student(t) }

(B) { t | Student(t) ∧ t.cgpa ≥ 8 }

(C) { t | Enrol(t) ∧ t.grade = 10 }

(D) { t | ∃s ∈ Student (s.sid = t.sid) }

How to think about it

  1. What is asked. Which expressions keep the answer inside stored data.
  2. Which idea applies. A table atom joined with ∧ forces each answer row to be stored.
  3. Work it out. (A) says only "not a Student row", so it is unsafe. (B) requires Student(t), so it is safe. (C) requires Enrol(t), so it is safe. (D) does not force t to be a row of any table, so it is unsafe.
  4. Check. The safe ones are the two with a table atom joined by ∧.

Answer: (B) and (C).

Calculus for course ids

Write the TRC expression for πcid(σgrade≥9(Enrol)), then give the set of course ids it returns on the Enrol table.

How to think about it

  2. Which idea applies. Select becomes a condition, project becomes the target list.

Exam-level 1: nested exists with a budget test (NAT, 2 marks)

A database has two tables. Emp(eid, dept, salary) has six rows: (1, CS, 50), (2, CS, 35), (3, EE, 42), (4, ME, 60), (5, EE, 28) and (6, CS, 44). Dept(dept, budget) has three rows: (CS, 900), (EE, 400) and (ME, 700). The query is { e.eid | Emp(e) ∧ e.salary ≥ 40 ∧ ∃d ∈ Dept (d.dept = e.dept ∧ d.budget > 500) }. Tuple calculus returns a set of answers, so each eid counts once. How many tuples does the query return?

How to think about it

  1. What is asked. The number of distinct eid values in the answer.
  2. Which idea applies. The tuple variable e ranges over Emp. The ∃ part is a join: it needs a Dept row with the same dept and a budget above 500.
  3. Work it out. Salary 40 or more keeps eids 1, 3, 4 and 6. The budget test passes for CS (900) and ME (700) but fails for EE (400). So eid 3 drops out, and eids 1, 4 and 6 remain.
  4. Check. The ∃ clause only asks whether a matching department exists, so it never adds duplicates. Three eids remain, which gives a count of 3.

Answer: 3 (the eids are 1, 4 and 6).

emp=[(1,'CS',50),(2,'CS',35),(3,'EE',42),(4,'ME',60),(5,'EE',28),(6,'CS',44)]
dept=[('CS',900),('EE',400),('ME',700)]
ans=[e[0] for e in emp if e[2]>=40 and any(d[0]==e[1] and d[1]>500 for d in dept)]
print(len(ans))
print(ans)

Exam-level 2: which algebra matches the query (MSQ, 2 marks)

Relations R(A, B) and S(A, B) hold R = {(1, x), (2, y), (3, z)} and S = {(1, q), (2, y)}. The TRC query is { t.A | R(t) ∧ ¬∃s ∈ S (s.A = t.A) }. Select all that apply. Which relational algebra expressions give the same answer as this query on this data?

(A) πA(R) − πA(S)

(B) πA(R − S)

(C) πA(R) − πA(R ∩ S)

How to think about it

  1. What is asked. Which algebra expressions return the same set of A values as the TRC query.
  2. Which idea applies. The query keeps the A values of R that have no matching A value in S. That is a set difference on the A column.
  3. Work it out. The query returns {3}. (A) gives {1, 2, 3} − {1, 2} = {3}, so it matches. (B) removes only the identical tuple (2, y), so R − S = {(1, x), (3, z)} and the projection gives {1, 3}. (C) subtracts the intersection {2}, which leaves {1, 3}.
  4. Check. Both wrong options keep the value 1, but S has an A value 1, so the query must exclude it.

Answer: (A) only. Why the others fail: (B) keeps 1 because the tuple (1, x) is not in S, even though S has an A value of 1; (C) removes only A values that appear in both relations with the same tuple, which leaves 1 and 3.

R={(1,'x'),(2,'y'),(3,'z')}
S={(1,'q'),(2,'y')}
q={t[0] for t in R if not any(s[0]==t[0] for s in S)}
A={a for a,b in R}-{a for a,b in S}
B={a for a,b in R-S}
C={a for a,b in R}-{a for a,b in R.intersection(S)}
print(sorted(q))
print(sorted(A)==sorted(q), sorted(B)==sorted(q), sorted(C)==sorted(q))

Exam-level 3: strong CS2 grades and distinct names (NAT, 2 marks)

Student(sid, name, cgpa) has five rows: (1, Asha, 9.1), (2, Ravi, 7.8), (3, Meena, 8.7), (4, Dev, 6.9) and (5, Kiran, 8.2). Enrol(sid, cid, grade) has eight rows: (1, CS2, 10), (1, CS2, 9), (2, CS2, 10), (3, EE1, 10), (3, CS2, 8), (4, CS2, 9), (5, CS2, 9) and (5, MA1, 10). The query is { s.name | Student(s) ∧ ∃e ∈ Enrol (e.sid = s.sid ∧ e.cid = 'CS2' ∧ e.grade ≥ 9) }. How many distinct names does the answer contain?

How to think about it

  1. What is asked. The number of distinct names in the answer.
  2. Which idea applies. The ∃ clause becomes a join condition on sid. Set semantics removes duplicate names.
  3. Work it out. CS2 rows with grade 9 or more belong to sids 1 (grades 10 and 9), 2 (10), 4 (9) and 5 (9). Meena's CS2 grade is 8, so she is out, and her EE1 grade of 10 does not count. Sid 1 has two qualifying rows but only one name.
  4. Check. Sids 1, 2, 4 and 5 give four names: Asha, Ravi, Dev and Kiran.

Answer: 4 (Asha, Dev, Kiran and Ravi).

students=[(1,'Asha',9.1),(2,'Ravi',7.8),(3,'Meena',8.7),(4,'Dev',6.9),(5,'Kiran',8.2)]

Exam-level 4: students who took every course (NAT, 2 marks)

Course has three rows: CS2, MA1 and EE1. Enrol(sid, cid) has ten rows: (1, CS2), (1, MA1), (1, EE1), (2, CS2), (2, MA1), (3, EE1), (4, CS2), (4, MA1), (4, EE1) and (4, CS2). The query finds every student who is enrolled in every course listed in Course. In tuple calculus, this uses a ∀ over Course with an ∃ inside it. How many students does the answer contain? Count each student once.

How to think about it

  1. What is asked. How many students take all three courses.
  2. Which idea applies. A ∀ over Course is a relational division. Each course must have an enrolment row for the same student.
  3. Work it out. Student 1 has CS2, MA1 and EE1. Student 2 has no EE1, so is out. Student 3 has only EE1. Student 4 has all three courses, and the repeated CS2 row changes nothing.
  4. Check. Students 1 and 4 remain, so the count is 2.

Answer: 2 (students 1 and 4).

courses={'CS2','MA1','EE1'}
enrol=[(1,'CS2'),(1,'MA1'),(1,'EE1'),(2,'CS2'),(2,'MA1'),(3,'EE1'),(4,'CS2'),(4,'MA1'),(4,'EE1'),(4,'CS2')]
sids=sorted({e[0] for e in enrol})
ans=[s for s in sids if all((s,c) in enrol for c in courses)]
print(len(ans))
print(ans)
2

Summary

Relational calculus
A declarative way to describe the rows you want, based on logic.
Tuple relational calculus (TRC)
Queries of the form { t | P(t) } where t is a whole row.
Domain relational calculus (DRC)
Queries of the form { <x, y> | P(x, y) } where each variable is one value.
Existential quantifier ∃
"There is at least one" such row or value.
Universal quantifier ∀
"Every" row or value satisfies the statement.
Duality rule
∀t P(t) is the same as ¬∃t ¬P(t).
Vacuous truth
A ∀ statement is true when there are no rows to check.
Free variable
A variable not bound by a quantifier, usually in the target list.
Active domain
All values stored in the database, plus constants in the query.
Safe expression
A query whose answer is always drawn from stored data.
Unsafe expression
A query that could return endless or non-stored answers, such as { t | ¬Student(t) }.
Declarative
Stating the properties of the answer, not the steps.
Procedural
Giving an ordered list of operations to produce the answer.
Relational algebra
The procedural language with σ, π, ⋈, ∪, − and ×.
NOT EXISTS
The SQL form used to express a ∀ query.
Equivalent queries
Queries that return the same rows on every database.

Remember these

  1. Calculus says WHAT you want. Algebra says HOW to get it.
  2. A TRC query has the form { target | condition }.
  3. Every column not in the DRC target list must be quantified.
  4. ∀ is true when there are no rows. This is vacuous truth.
  5. ∀t P(t) is the same as ¬∃t ¬P(t). Use it to convert to SQL NOT EXISTS.
  6. A safe expression forces each answer row to come from a stored relation.
  7. Equivalence means the same answer on every database, so test with an empty or unusual case.
