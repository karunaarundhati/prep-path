Graph (recap)

A graph is a set of points joined by lines, such as cities and roads or people and friendships. This quick recap covers how graphs are stored, the two ways of walking through them (breadth first and depth first), and the difference between weighted and unweighted graphs, all of which GATE asks about.

The idea in plain words

Imagine a map with five towns and some roads between them. Each town is a point, and each road is a line joining two points. Mathematicians call the points vertices and the lines edges. Together they form a graph.

Graphs are everywhere. A social network is a graph where people are vertices and friendships are edges. A computer network is a graph where machines are vertices and cables are edges. A web page with links is also a graph.

Once a problem is a graph, many questions become one of two things. Can I reach this vertex from that one? What is the shortest way to get there? To answer such questions we need a way to store the graph, and a systematic way to visit its vertices. Those are the two ideas on this page.

Why this matters for GATE: graph questions appear in the data structures and algorithms parts of GATE DA and RA. Typical questions ask for the order of a BFS or DFS, the space needed to store a graph, or the number of edges in a graph with a given degree pattern.

Key terms

Vertex
A point in a graph. Also called a node.
Edge
A connection between two vertices.
Undirected
Edges have no direction. An edge between A and B lets you go both ways.
Directed
Edges have a direction, written as A to B, and you can only follow them forward.
Degree
The number of edges touching a vertex. In an undirected graph, degree counts all its neighbours.
Neighbour
A vertex joined to another by one edge.
Path
A sequence of vertices where each consecutive pair is joined by an edge. Its length is the number of edges in it.
Weighted graph
A graph where each edge has a number, called its weight, such as a distance or a cost.
Unweighted graph
A graph where every edge counts the same, so only the number of edges matters.
Queue
A line where the first item in is the first item out (first in, first out).
Stack
A pile where the last item in is the first item out (last in, first out).

Storing a graph

There are two common ways to store a graph. Both must answer the question "who is joined to whom?", but they do it in different ways.

Adjacency list. For each vertex, keep a list of its neighbours. Take the triangle with vertices A, B and C, where every pair is joined. Its adjacency list is:

A: B, C
B: A, C
C: A, B

Adjacency matrix. Make a square table with one row and one column for each vertex. Put a 1 where two vertices are joined and a 0 where they are not. For the same triangle:

      A  B  C
  A [ 0  1  1 ]
  B [ 1  0  1 ]
  C [ 1  1  0 ]

The matrix is symmetric for an undirected graph. Each edge fills two cells, one above the diagonal and one below it, so the total number of 1s is twice the number of edges.

Key ideaThe list uses space about V + E for V vertices and E edges. The matrix uses V × V cells, whatever the number of edges. So a list is better when the graph is sparse, meaning it has few edges.

Here is a computation with the matrix. We count the edges and the degree of each vertex. Each row sum is a degree, and the total of all cells divided by 2 is the number of edges.

matrix = [
    [0, 1, 1],
    [1, 0, 1],
    [1, 1, 0],
]
edges = sum(sum(row) for row in matrix) // 2
print("edges:", edges)
for i, row in enumerate(matrix):
    print("vertex", i, "degree", sum(row))
edges: 3
vertex 0 degree 2
vertex 1 degree 2
vertex 2 degree 2

TrapDo not divide by 2 for a directed graph. A directed edge fills only one cell, so the number of 1s equals the number of edges.

Which storage is better for a graph with 1000 vertices and only 1500 edges?

The adjacency list. It needs about 1000 + 1500 units of space. The matrix needs 1000 × 1000 cells, most of them 0.

In an adjacency matrix, how do you check whether there is an edge between A and C?

Look up the cell in row A and column C. It takes one step, so the check is O(1).

Breadth first search (BFS)

Breadth first search explores a graph in rings. It first visits the start vertex, then all of its neighbours, then all the neighbours of those, and so on. It uses a queue, so the vertices are handled in the order they were found.

Everyday analogy: a ripple on a pond. The ripple reaches every point at distance 1 before any point at distance 2. That is why BFS gives the shortest number of edges from the start to each vertex in an unweighted graph.

The graph below is used on this page. It has six vertices. A is joined to B and C. B is joined to D. C is joined to D and E. D is joined to F. E is joined to F.

from collections import deque

graph = {
    "A": ["B", "C"],
    "B": ["D"],
    "C": ["D", "E"],
    "D": ["F"],
    "E": ["F"],
    "F": [],
}

def bfs(start):
    seen = [start]
    queue = deque([start])
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for nb in graph[node]:
            if nb not in seen:
                seen.append(nb)
                queue.append(nb)
    return order

print("BFS:", bfs("A"))
BFS: ['A', 'B', 'C', 'D', 'E', 'F']

Follow the queue. Start with A in the queue. Take A out and add its neighbours B and C. Take B out and add D. Take C out. D is already seen, so only E is added. Take D out and add F. Take E out. F is already seen. Take F out. The order of removal is the BFS order.

TipMark a vertex as seen when you put it in the queue, not when you take it out. Otherwise the same vertex can be queued many times.

In BFS, which vertex is removed from the queue right after B?

C. Both B and C were added from A, and they leave the queue in the order they were added.

Does BFS find the shortest path, counted in edges, from A to F?

Yes, for an unweighted graph. F is first reached from D at distance 3, and no shorter path exists. The path is A, B, D, F.

Depth first search (DFS)

Depth first search goes as far as it can down one path before backtracking. It is like exploring a maze: you follow one corridor until it ends, then go back to the last junction and try the next corridor. DFS uses a stack, often the call stack of recursion.

The code below uses recursion. The function marks the current vertex as seen, records it, and then calls itself on each unseen neighbour.

graph = {
    "A": ["B", "C"],
    "B": ["D"],
    "C": ["D", "E"],
    "D": ["F"],
    "E": ["F"],
    "F": [],
}

def dfs(node, seen, order):
    seen.add(node)
    order.append(node)
    for nb in graph[node]:
        if nb not in seen:
            dfs(nb, seen, order)
    return order

print("DFS:", dfs("A", set(), []))
DFS: ['A', 'B', 'D', 'F', 'C', 'E']

Trace it. Start at A and record it. Go to its first neighbour B, record it. From B go to D, record it. From D go to F, record it. F has no neighbours, so go back. D and B are finished. Back at A, try the next neighbour C, record it. C's neighbour D is seen, so try E, record it. E's neighbour F is seen. Done.

BFS and DFS visit the same set of vertices here, but in different orders. BFS went A, B, C, D, E, F. DFS went A, B, D, F, C, E.

TrapDFS does not give shortest paths in general. In the walk above, F was reached through A, B, D, which is 3 edges, but the order in which DFS finds vertices has no link to distance.

What data structure does the recursive DFS use to remember where to return to?

The call stack. Each pending call waits for the calls it made to finish.

In DFS from A, why is C not visited from B?

B is joined only to D. C is not a neighbour of B, so DFS reaches C only when it returns to A.

Weighted and unweighted graphs

In an unweighted graph every edge counts as one step. The shortest path is the one with the fewest edges, and BFS finds it. In a weighted graph each edge has a number, such as a distance in kilometres. The shortest path is the one with the smallest total weight, and the path with the fewest edges may be more expensive.

Here is an example. Vertices A, B and C have three edges: A to B with weight 10, A to C with weight 1, and C to B with weight 1. BFS looks only at the number of edges. From A it reaches B directly in one edge, so it uses the weight-10 edge. The route through C has two edges and total weight 2, which is cheaper.

weights = {("A", "B"): 10, ("A", "C"): 1, ("C", "B"): 1}
print(weights[("A", "B")])
print(min(weights[("A", "B")], weights[("A", "C")] + weights[("C", "B")]))
10
2

GATE loves thisBFS gives the shortest path only when every edge has the same weight. For weighted graphs the question is a different algorithm, which is outside this recap.

Does BFS find the minimum total weight path in the example above?

No. It finds the path with the fewest edges, which is A to B with weight 10. The cheaper path A to C to B has weight 2.

What is the difference between a weighted and an unweighted graph in one sentence?

In a weighted graph each edge has a number that counts toward the path cost, while in an unweighted graph every edge counts the same.

Ones in a matrix

An undirected graph has 4 vertices and 5 edges. Its adjacency matrix is stored in full. How many entries of the matrix are 1? This is a NAT question.

How to think about it

  1. What is asked. The count of 1s in the whole matrix.
  2. Which idea applies. Each undirected edge fills two cells, one above and one below the diagonal.
  3. Work it out. Each of the 5 edges gives 2 ones, so 5 times 2 is 10.
  4. Check. Run the code below.
edges = 5
print(2 * edges)
10

Answer: 10.

BFS from another start

The code below stores a graph as lists of neighbours, exactly as written: A has B and C, B has D, C has D and E, D has F, and E has F. What is the BFS order when the search starts at D?

How to think about it

  1. What is asked. The BFS order starting at D.
  2. Which idea applies. Start with D in the queue, then add neighbours in the order they are listed.
  3. Work it out. Start with D in the queue. Remove D and record it. Its list is only F, so F is added. Remove F and record it. F has an empty list. The queue is empty, so the order is D, F.
  4. Check. Run the code below.
from collections import deque

graph = {
    "A": ["B", "C"],
    "B": ["D"],
    "C": ["D", "E"],
    "D": ["F"],
    "E": ["F"],
    "F": [],
}

def bfs(start):
    seen = [start]
    queue = deque([start])
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for nb in graph[node]:
            if nb not in seen:
                seen.append(nb)
                queue.append(nb)
    return order

print(bfs("D"))
['D', 'F']

Answer: D, F.

Select all true statements about BFS and DFS

Select all that apply.

  • (A) BFS uses a queue.
  • (B) DFS uses a stack, either explicit or through recursion.
  • (C) On an unweighted graph, BFS finds a shortest path counted in edges.
  • (D) DFS always finds a shortest path counted in edges.

How to think about it

  1. What is asked. Which statements are true.
  2. Which idea applies. The data structure behind each search, and the ring idea of BFS.
  3. Work it out. (A) True. (B) True. (C) True, because BFS reaches each vertex at its minimum edge distance first. (D) False. The DFS route to F in the example went through 3 edges, but DFS does not check distances, so it can take a long route.
  4. Check. The reasoning above is enough. No code is needed.

Answer: (A), (B) and (C).

Shortest total weight

Vertices A, B and C have edges A to B with weight 10, A to C with weight 1, and C to B with weight 1. What is the total weight of the cheapest path from A to B? This is a NAT question.

How to think about it

  1. What is asked. The smallest total weight of any path from A to B.
  2. Which idea applies. In a weighted graph, add the weights along each path and compare the totals.
  3. Work it out. The direct path A to B costs 10. The path A to C to B costs 1 + 1 = 2. The smaller total is 2.
  4. Check. Run the code below.
direct = 10
via_c = 1 + 1
print(min(direct, via_c))
2

Answer: 2.

Pops and longest queue in BFS

Run BFS from A on the six-vertex graph of this page. Count how many vertices are taken out of the queue, and find the largest number of items the queue holds at any moment, counting after each addition. The answer is two numbers. Give them in that order.

How to think about it

  1. What is asked. The number of removals, then the largest queue length.
  2. Which idea applies. Trace the queue step by step, adding unseen neighbours and removing the front.
  3. Work it out. Start: [A]. Remove A, add B and C: [B, C], length 2. Remove B, add D: [C, D], length 2. Remove C, add E: [D, E], length 2. Remove D, add F: [E, F], length 2. Remove E, add nothing: [F], length 1. Remove F: [], length 0. There are 6 removals, and the largest length is 2.
  4. Check. Run the code below.
from collections import deque

graph = {
    "A": ["B", "C"],
    "B": ["D"],
    "C": ["D", "E"],
    "D": ["F"],
    "E": ["F"],
    "F": [],
}

queue = deque(["A"])
seen = {"A"}
pops = 0
longest = 1
while queue:
    node = queue.popleft()
    pops = pops + 1
    for nb in graph[node]:
        if nb not in seen:
            seen.add(nb)
            queue.append(nb)
    longest = max(longest, len(queue))
print(pops, longest)
6 2

Answer: 6 and 2.

Select all true statements about storage and checks

Select all that apply to a graph with V vertices and E edges.

  • (A) For a sparse graph, an adjacency list uses less space than an adjacency matrix.
  • (B) In an adjacency matrix, checking whether an edge exists takes O(1) time.
  • (C) In an adjacency matrix, listing all neighbours of one vertex takes O(V) time.
  • (D) An adjacency list always uses more space than an adjacency matrix.

How to think about it

  1. What is asked. Which statements are true.
  2. Which idea applies. Space is V + E for a list and V × V for a matrix. Each operation has a cost that depends on the layout.
  3. Work it out. (A) True, because V + E is much less than V × V when E is small. (B) True, one cell lookup. (C) True, one row must be scanned, which has V cells. (D) False. In a simple graph, E is at most V(V - 1)/2, so V + E is at most V + V(V - 1)/2. This is never more than V × V. For example, with V = 3 the list needs at most 3 + 3 = 6 units, and the matrix needs 9.
  4. Check. Take V = 2. A simple graph has at most 1 edge, so the list needs at most 2 + 1 = 3 units, while the matrix needs 4. The list is never the larger one here.

Answer: (A), (B) and (C).

Exam-level practice

Exam-level 1: Handshake lemma (NAT, 1 mark)

A simple graph has degrees 3, 3, 2, 2, 2, 4. How many edges does it have?

How to think about it

  1. What is asked. The edge count.
  2. Which idea applies. The sum of degrees equals twice the number of edges.
  3. Work it out. Sum = 16, so 8 edges.
  4. Check. The sum is even, so such a graph can exist.

Answer: 8.

For the cycle graph C4 with vertices 1-2-3-4-1, how many walks of length 3 go from vertex 1 to vertex 2?

  3. Work it out. A³ entry (1, 2) = 4.

Exam-level 3: Tree facts (MSQ, 2 marks)

Which are TRUE for a connected simple graph G with n vertices? (A) If G has n − 1 edges, G is a tree. (B) A tree with n ≥ 2 has at least two leaves. (C) Adding any edge to a tree makes exactly one cycle. (D) K4 has 4 spanning trees.

How to think about it

  1. What is asked. Basic graph facts.
  2. Which idea applies. Cayley's formula: Kn has nn−2 spanning trees.
  3. Work it out. (A) Connected with n − 1 edges means acyclic. True. (B) True. (C) True. (D) 42 = 16. False.
  4. Check. (D) undercounts badly.

Remember these

  • Use an adjacency list for sparse graphs and a matrix for quick edge checks.
  • In an undirected matrix, each edge gives two 1s.
  • BFS uses a queue and visits by distance rings.
  • DFS uses a stack or recursion and goes deep first.
  • BFS gives shortest paths only when edges are unweighted.
  • Mark a vertex as seen when you enqueue or push it.
