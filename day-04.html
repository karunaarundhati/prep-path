Structs, unions and enums

C has no classes, so when you need to keep related values together you use a struct. A struct is a named group of variables, called members, that the compiler stores one after another in memory. Each member has its own type and its own name. The struct itself is a new type, so you can declare variables of it, pass it to functions and return it from functions.

Declaring and using a struct

The keyword struct followed by a tag name defines the type. You then create variables with that type and set members with the dot operator (.). When you have a pointer to a struct, you use the arrow operator (->), which is shorthand for dereferencing the pointer and then taking the member: p->x means (*p).x. Here is a complete program that shows both operators and the most important fact about struct assignment: assigning one struct to another copies every member.

#include <stdio.h>

struct Point {
    int x;
    int y;
};

typedef struct {
    char name[16];
    int age;
} Person;

int main(void) {
    struct Point p = {3, 4};
    struct Point q = p;          /* copies every member, not a reference */
    q.x = 10;                    /* changing q does not change p */
    printf("p = (%d, %d)\n", p.x, p.y);
    printf("q = (%d, %d)\n", q.x, q.y);

    struct Point *ptr = &p;
    ptr->y = 7;                    /* same as (*ptr).y = 7 */
    printf("p.y after ptr->y = 7: %d\n", p.y);

    Person person = {"Asha", 21};
    printf("%s is %d\n", person.name, person.age);
    return 0;
}
p = (3, 4)
q = (10, 4)
p.y after ptr->y = 7: 7
Asha is 21

Read the program line by line. struct Point p = {3, 4}; is an initializer: the first value goes to x and the second to y. struct Point q = p; creates a second, independent struct with the same values. Changing q.x therefore leaves p.x at 3. The typedef on the anonymous struct lets us write Person instead of struct Person, which is the usual style in C code bases.

TipUse . when you hold the struct itself and -> when you hold a pointer to it. The compiler rejects the wrong one, so the error message tells you which operator to use.

Unions: one block of memory, several views

A union looks like a struct, but all of its members start at the same address. Only one member is meaningful at a time, because writing one member overwrites the bytes the others would read. The size of a union is the size of its largest member (plus any padding needed for alignment, covered in the next section). Unions save memory when a value can be only one of several kinds.

The usual pattern in real C code is a tagged union: a small field, called the tag, records which member is active, and the program checks the tag before it reads the union. This is how many parsers and interpreters store values that might be an integer or a string.

#include <stdio.h>

enum Kind { KIND_INT, KIND_TEXT };

struct Token {
    enum Kind kind;              /* the tag: says which member of "as" is active */
    union {
        int number;
        const char *text;
    } as;
};

static void print_token(const struct Token *t) {
    switch (t->kind) {
        case KIND_INT:
            printf("int token: %d\n", t->as.number);
            break;
        case KIND_TEXT:
            printf("text token: %s\n", t->as.text);
            break;
    }
}

int main(void) {
    struct Token a = { KIND_INT,  { .number = 42 } };
    struct Token b = { KIND_TEXT, { .text = "hello" } };
    print_token(&a);
    print_token(&b);
    return 0;
}
int token: 42
text token: hello

The switch reads the tag first and then reads only the member that the tag names. The braces with .number and .text are designated initializers, a C99 feature that says which member the value belongs to.

TrapReading a union member you did not last write gives you bytes reinterpreted under another type, and the result depends on the machine. Always keep a tag, or be sure which member was written last.

Enums: named integer constants

An enum defines a type whose values are named integer constants. If you do not give a value, the first name is 0 and each following name is one more than the previous one. If you give a value, the next names continue counting from it. Enums make code readable because BLUE says more than 2.

#include <stdio.h>

enum Color { RED, GREEN = 5, BLUE };

int main(void) {
    enum Color c = BLUE;
    printf("RED=%d GREEN=%d BLUE=%d\n", RED, GREEN, BLUE);
    printf("c=%d\n", c);
    if (c == BLUE) {
        printf("c is blue\n");
    }
    return 0;
}
RED=0 GREEN=5 BLUE=6
c=6
c is blue

RED starts at 0. GREEN is given 5 explicitly. BLUE has no value, so it is the previous value plus one, which is 6. The names are just integers after compilation, so you can compare an enum with ==, but C will also let you store any integer in an enum variable. That is a weakness compared with other languages, so treat enums as a naming aid, not as a strict set of allowed values.

Why does an enum without explicit values start at 0, and what value does the name after GREEN get?

The first enumerator defaults to 0. Every later enumerator without an explicit value is the previous enumerator plus one. After GREEN = 5, the next name gets 6, so enum Color { RED, GREEN = 5, BLUE } makes BLUE equal to 6.

Memory layout: padding, alignment and bit fields

A struct's members are stored in the order you declare them, but the compiler may leave unused gaps between them. Understanding those gaps explains why sizeof of a struct is sometimes bigger than the sum of its members, and why reordering members can shrink a struct without changing what the program does.

Alignment and padding

Most processors read an int fastest, or sometimes only, when its address is a multiple of its size. This requirement is called alignment. To satisfy it, the compiler inserts unused bytes called padding. A char needs alignment 1, an int usually needs alignment 4, and a double usually needs alignment 8 on a typical 64-bit system. The compiler also adds tail padding at the end of a struct so that an array of such structs keeps every element aligned.

The next program measures two structs that hold the same three members in different orders. The numbers below are what a typical 64-bit x86 compiler produces. The C standard does not fix the exact layout, so always check with sizeof and offsetof rather than guessing.

#include <stdio.h>
#include <stddef.h>

struct Bad {
    char a;      /* offset 0, 1 byte, then 3 bytes padding so b is aligned */
    int b;       /* offset 4, 4 bytes */
    char c;      /* offset 8, 1 byte, then 3 bytes of tail padding */
};

struct Good {
    int b;       /* offset 0, 4 bytes */
    char a;      /* offset 4, 1 byte */
    char c;      /* offset 5, 1 byte, then 2 bytes of tail padding */
};

int main(void) {
    printf("Bad  size=%zu offsetof(b)=%zu offsetof(c)=%zu\n",
           sizeof(struct Bad), offsetof(struct Bad, b), offsetof(struct Bad, c));
    printf("Good size=%zu offsetof(a)=%zu\n",
           sizeof(struct Good), offsetof(struct Good, a));
    return 0;
}
Bad  size=12 offsetof(b)=4 offsetof(c)=8
Good size=8 offsetof(a)=4

Walk through Bad. a sits at offset 0. b needs an address that is a multiple of 4, so the compiler skips offsets 1, 2 and 3. b is at offset 4 and occupies bytes 4 to 7. c is at offset 8. The struct now has 9 bytes of data, but the struct as a whole must be a multiple of its largest alignment (4), so 3 bytes of tail padding bring the size to 12. offsetof, defined in stddef.h, returns the byte offset of a member, which lets you see the layout directly.

Now Good has the same data with the largest member first. b is at 0, a at 4 and c at 5, so no gap is needed between members. Only 2 bytes of tail padding are needed, and the size drops from 12 to 8. If you build an array of a million of these structs, that is 4 MB saved for a one-line change.

Key ideaOrder members from largest alignment to smallest to remove most padding. The compiler never reorders members for you in C, because the order is part of the program's visible layout.

Bit fields: members measured in bits

A bit field is a struct member with a width given in bits after a colon. It is useful for hardware registers and flag sets where each flag needs one or a few bits. Bit fields must have an integer type. The compiler packs them into a storage unit, usually an unsigned int here.

#include <stdio.h>

struct Flags {
    unsigned int ready : 1;   /* 1 bit: values 0 to 1 */
    unsigned int mode  : 3;   /* 3 bits: values 0 to 7 */
    unsigned int level : 4;   /* 4 bits: values 0 to 15 */
};

int main(void) {
    struct Flags f = {0};
    f.ready = 1;
    f.mode = 5;
    f.level = 9;
    printf("ready=%d mode=%d level=%d\n", f.ready, f.mode, f.level);

    f.mode = 9;               /* 9 is 1001 in binary, only 3 bits fit, so the top bit is lost */
    printf("mode after storing 9: %d\n", f.mode);
    printf("sizeof(struct Flags)=%zu\n", sizeof(struct Flags));
    return 0;
}
ready=1 mode=5 level=9
mode after storing 9: 1
sizeof(struct Flags)=4

Read the bit-field program with care. ready takes one bit, so it can hold only 0 or 1. mode takes three bits, so it holds 0 to 7. f.mode = 9 is the interesting line. The binary form of 9 is 1001. Only the three lowest bits fit into mode, so the value stored is 001, which is 1. Unsigned bit fields wrap around like this in a defined way. The three members together use 8 bits, and they fit in one 4-byte unsigned int, which is why sizeof reports 4.

TrapStoring a value too large for a signed bit field is a different story: the result is implementation-defined. Use unsigned bit fields when you want the wrap-around behaviour shown above, and check the value range before you store it.

Bit fields also have limits you should know before using them in an interview answer. You cannot take the address of a single bit field with &. The order of bit fields inside the storage unit is implementation-defined. For this reason, bit fields are fine for a program's own flags but are a poor choice for data that must match a fixed binary layout, such as a file format. Use explicit masks and shifts for that job.

Why is the size of struct Bad 12 and not 9 when its members add up to 6 bytes of data?

The members are char, int and char, which hold 1 + 4 + 1 = 6 bytes of data. Padding is added, not removed. The int needs an address that is a multiple of 4, so 3 bytes are skipped after the first char, which puts the total at 9 bytes of data and offsets. The struct size must also be a multiple of its strictest alignment, 4, so 3 bytes of tail padding bring the size to 12.

The preprocessor and the build process

A C program does not go straight from source text to a running program. The work happens in stages, and each stage has its own tool. Knowing the stages helps you read compiler errors, because the error message tells you which stage failed.

The four stages

The preprocessor runs first. It is a text tool that handles lines starting with #. It copies the contents of header files named by #include, replaces names defined by #define, and keeps or removes blocks of code depending on #if, #ifdef and #else. The compiler then translates the preprocessed text into assembly language. The assembler turns the assembly into an object file that holds machine code, but with unresolved references to functions and variables defined elsewhere. The linker joins the object files and the standard library, fixes those references, and writes the final executable.

gcc -E hello.c -o hello.i   # stage 1: preprocess (expand #include, #define, #if)
gcc -S hello.i -o hello.s   # stage 2: compile to assembly text
gcc -c hello.s -o hello.o   # stage 3: assemble to an object file
gcc hello.o -o hello        # stage 4: link into an executable

In practice gcc hello.c -o hello runs all four stages in one command. The split commands above are useful for seeing what each stage produces, and gcc -E in particular is a good way to see what a macro really expanded to.

Macros with #define

A macro defined with #define is a text substitution. The preprocessor replaces every occurrence of the name with the replacement text before the compiler sees the code. Macros have no types and no function-call overhead, which is why they were popular before inline functions. The price is that they follow text rules, not C rules, and that causes the classic traps shown below.

#include <stdio.h>

#define SQUARE_BAD(x)  x * x
#define SQUARE_OK(x)   ((x) * (x))
#define DEBUG 1

int main(void) {
    int a = 5;
    printf("bad:  %d\n", SQUARE_BAD(a + 1));
    printf("good: %d\n", SQUARE_OK(a + 1));
#if DEBUG
    printf("debug build\n");
#else
    printf("release build\n");
#endif
    return 0;
}
bad:  11
good: 36
debug build

The macro SQUARE_BAD(a + 1) is replaced by the text a + 1 * a + 1. Multiplication binds tighter than addition, so the expression becomes 5 + 1 * 5 + 1, which is 11. SQUARE_OK wraps every parameter in parentheses, so the text becomes ((a + 1) * (a + 1)), which is 36. The rule is simple: put parentheses around each parameter and around the whole macro body.

TrapA macro argument with side effects runs more than once. SQUARE_OK(i++) increments i twice. Use a real function or an inline function when the argument has side effects.

Header guards and linking

A header file usually holds declarations: function prototypes, struct definitions and extern variables. When two source files include the same header, the declarations can appear twice in one compilation, which is an error. An include guard prevents that. The header below is a typical example. It is shown on its own because it is not a program; a complete example appears later in this unit.

/* math_utils.h */
#ifndef MATH_UTILS_H
#define MATH_UTILS_H

int add(int a, int b);     /* a declaration: says the function exists */

#endif

The first time the preprocessor sees the header, MATH_UTILS_H is not defined, so it keeps the code and defines the name. A second include finds the name already defined and skips the whole block. The definitions of add go into one .c file, and the linker connects each call to that single definition. If a call has no matching definition, you get an undefined reference error from the linker, not a compiler error. That message means "the compiler was happy, but no object file defines this name."

What is the difference between a compiler error and a linker error, and which stage produces an "undefined reference" message?

A compiler error means the source text breaks C rules, such as a missing semicolon or a wrong type. An "undefined reference" message comes from the linker. It means a function or variable was declared and used, but no object file or library supplies its definition.

File handling

A program keeps data in memory while it runs, but many programs must also read and write files. In C, the standard library handles files through a pointer to a FILE object. You open a file with fopen, which takes a name and a mode string and returns a FILE *. The most common modes are "r" to read an existing file, "w" to create or truncate a file for writing, and "a" to append to the end of a file. Adding a b, as in "rb", selects binary mode, which matters on systems that translate line endings.

The usual pattern has four steps. First, call fopen and check that the result is not NULL. Second, read or write with functions such as fgets, fread, fprintf or fwrite. Third, check for errors when the work is done. Fourth, call fclose, which flushes buffered output and releases the file handle. fgets reads one line into a buffer and keeps the newline character at the end, so programs often remove it, as the example does.

The example below uses tmpfile, a standard function that creates a temporary file, opens it for reading and writing, and deletes it when closed. That lets the program run without leaving files behind. The same steps apply to fopen on a named file.

#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void) {
    FILE *fp = tmpfile();          /* temporary file, removed automatically on fclose */
    if (fp == NULL) {
        perror("tmpfile");         /* prints the reason the system gave */
        return EXIT_FAILURE;
    }

    fprintf(fp, "alpha 1\nbeta 2\n");   /* write two lines */
    rewind(fp);                         /* move back to the start before reading */

    char line[64];
    int count = 0;
    while (fgets(line, sizeof line, fp) != NULL) {
        line[strcspn(line, "\n")] = '\0';   /* remove the newline, if present */
        count++;
        printf("%d: %s\n", count, line);
    }

    if (ferror(fp)) {
        perror("read");
    }
    fclose(fp);
    return 0;
}
1: alpha 1
2: beta 2

Look at what each call does. fprintf works like printf, but its first argument is the file. After writing, the file position is at the end, so rewind moves it back to the start, which lets fgets read from the top. The strcspn call finds the first newline, and assigning '\0' there cuts the string short. The loop stops when fgets returns NULL, which happens at the end of the file or on an error. The ferror check after the loop tells those two cases apart.

TrapForgetting to check the result of fopen is the most common file bug in C. If the file does not exist or you lack permission, the result is NULL, and the first read or write crashes. Check for NULL right away and report the problem with perror.

TipWhen you switch from writing to reading on the same stream, call rewind or fseek in between. Mixing reads and writes on one stream without a positioning call is undefined behaviour.

What does fgets keep at the end of a line, and why does the program remove it?

fgets keeps the newline character at the end of the line, as long as the buffer has room for it. The program replaces that newline with the null terminator so that the printed line and any later comparison see only the text.

OOP concepts in C

C has no classes, inheritance or virtual functions. It is still possible to organize a C program around objects, and many real systems do exactly that, including the Linux kernel and parts of the Python interpreter. The four pillars of object-oriented design can be built by convention:

  • Encapsulation: keep a struct's fields behind functions. Callers receive a pointer to an opaque type whose layout they cannot see, so only the module's own functions touch the fields.
  • Abstraction: callers use a small set of operations, such as area or name, and ignore how they are done.
  • Inheritance: a common prefix. Structs that begin with the same members can be treated as the base type.
  • Polymorphism: a struct holds a pointer to a table of function pointers. Different tables give different behaviour behind the same call.

The third pillar is the weakest in C, because the compiler does not check it for you. The fourth pillar is the important one for interviews, because it is how C++ virtual functions work underneath, as you will see in the C++ unit tomorrow.

Function pointers as a method table

A function pointer stores the address of a function. Its declaration names the return type and parameter list inside parentheses: double (*area)(const struct Shape *self) is a pointer named area that points to a function taking a const struct Shape * and returning a double. Grouping several function pointers into a struct gives a method table, called a vtable in C++ terminology. Each object stores a pointer to one table. Calling shape->ops->area(shape) therefore picks the right function at run time.

#include <stdio.h>

struct Shape;

struct ShapeOps {
    double (*area)(const struct Shape *self);
    const char *(*name)(const struct Shape *self);
};

struct Shape {
    const struct ShapeOps *ops;   /* the method table for this object */
    double w, h;
};

static double rect_area(const struct Shape *s) { return s->w * s->h; }
static const char *rect_name(const struct Shape *s) { (void)s; return "rectangle"; }
static const struct ShapeOps rect_ops = { rect_area, rect_name };

static double tri_area(const struct Shape *s) { return 0.5 * s->w * s->h; }
static const char *tri_name(const struct Shape *s) { (void)s; return "triangle"; }
static const struct ShapeOps tri_ops = { tri_area, tri_name };

int main(void) {
    struct Shape shapes[2] = {
        { &rect_ops, 3.0, 4.0 },
        { &tri_ops,  3.0, 4.0 },
    };
    for (int i = 0; i < 2; i++) {
        printf("%s area = %.2f\n",
               shapes[i].ops->name(&shapes[i]),
               shapes[i].ops->area(&shapes[i]));
    }
    return 0;
}
rectangle area = 12.00
triangle area = 6.00

Trace one loop iteration. For i = 0, shapes[0].ops points to rect_ops. The expression shapes[0].ops->area is therefore rect_area, and calling it with &shapes[0] computes 3.0 times 4.0, which is 12.00. For i = 1, the same source line finds tri_ops instead, so the same line of code runs a different function. This is runtime polymorphism in plain C. The loop does not know which shape it has, and it does not need to.

Notice that both functions take the object as the first argument. This is the convention C++ uses internally: a method is a function that receives this as a hidden first parameter. Writing it by hand makes the mechanism visible, which is why interviewers like this question.

Interviewers askHow do you get polymorphism in C? Answer: store a pointer to a table of function pointers in each object, and call through the table. The call site stays the same while the table decides the behaviour.

In the shape example, why is the pointer to the table declared const, and why is the table itself declared static const?

The table is the same for every rectangle, so it is created once and never changes. Declaring it static const places it in read-only memory and keeps its name private to the file. Objects store a pointer to it, and the pointer targets the constant table, so the methods cannot be replaced by accident.

Undefined behaviour and output questions

The C standard describes three kinds of behaviour that a program can have when a rule is broken or a result is not fixed. Implementation-defined behaviour is allowed to vary, but the compiler must document its choice, such as the size of int. Unspecified behaviour allows several outcomes without documentation, such as the order in which function arguments are evaluated. Undefined behaviour, usually shortened to UB, means the standard places no requirements at all. The compiler may produce a crash, a wrong answer, or code that appears to work today and breaks after an upgrade.

UB is the cause of most "what does this print?" interview questions. The usual sources are these:

  • Signed integer overflow, such as adding 1 to INT_MAX. Unsigned overflow wraps around and is defined.
  • Out-of-bounds access, reading or writing past the end of an array.
  • Use after free, reading memory after free has released it.
  • Uninitialized reads, using a local variable before any value was stored in it.
  • Modifying a string literal, such as writing into "hello" through a char *.
  • Unsequenced side effects, changing one variable twice without a sequence point between, such as i = i++ or x++ + ++x.
  • Null pointer dereference, following a pointer that is NULL.

A program that contains UB is wrong, even if the output looks right on your machine. Compilers are allowed to assume UB never happens and optimize based on that assumption, so a bug can appear far away from its cause. The safe approach is to write code that is defined and to check tools such as warnings with -Wall -Wextra.

TrapExpressions such as i = i++ and a[i] = i++ are UB because one variable is changed twice with no sequence point between the changes. Write the steps on separate lines and the question disappears.

Output questions with defined behaviour

Output questions often mix promotion rules, integer division and character types. The program below uses only defined behaviour, so every line is predictable. Each comment gives the reason for the result, which is the part interviewers listen for.

#include <stdio.h>
#include <limits.h>

int main(void) {
    printf("%d\n", 7 / 2);                      /* 3: integer division drops the fraction */
    printf("%d\n", -7 / 2);                     /* -3: C99 truncates toward zero */
    printf("%d\n", -7 % 3);                     /* -1: the remainder takes the sign of the left operand */
    printf("%d\n", 'A' + 1);                    /* 66: 'A' is an int with the value 65 */
    printf("%d\n", sizeof('a') == sizeof(int)); /* 1: a character constant has type int in C */

    int a[] = {10, 20, 30};
    printf("%d %d\n", *(a + 2), 2[a]);          /* 30 30: a[i] means *(a + i), so 2[a] also works */

    unsigned int u = 0;
    u = u - 1;                                  /* unsigned arithmetic wraps around */
    printf("%d\n", u == UINT_MAX);              /* 1 */

    int i = 0;
    if (0 && i++) {                             /* the right side is skipped, so i stays 0 */
    }
    printf("%d\n", i);                          /* 0 */
    printf("%zu\n", sizeof("abc"));             /* 4: three letters plus the terminating '\0' */
    return 0;
}

Three ideas explain almost every line. First, division of two integers truncates toward zero, so -7 / 2 is -3 and not -4. Second, a character constant such as 'A' is an int in C, not a char, which is why 'A' + 1 is 66 and why sizeof('a') equals sizeof(int). Third, the short-circuit operators && and || do not evaluate the right side when the left side already decides the answer, so i++ never runs.

Key ideaBefore answering any output question, ask three things: is there a conversion or promotion, is there integer division, and is any variable changed twice. Those three checks catch most traps.

Why does sizeof('a') give the size of int in C, and what would it give in C++?

In C, a character constant written with single quotes has type int, so sizeof('a') equals sizeof(int), usually 4. In C++, a character literal has type char, so the same expression gives 1. The difference is a common interview question about C versus C++.

Interview questions

Each answer below is written as you would say it in an interview: short, precise, and followed by the reason. Read the question, say the answer out loud, then open the answer to compare.

What is the difference between a struct and a union?

All members of a struct have their own storage, so its size is at least the sum of the member sizes. All members of a union share the same storage, so its size is the size of the largest member, plus padding. A struct can hold all of its members at once, while a union holds one meaningful member at a time.

Why can sizeof a struct be larger than the sum of its members?

The compiler inserts padding so each member starts at an address that suits its alignment, and it adds tail padding so the total size is a multiple of the strictest alignment. Reordering members from largest to smallest usually reduces the padding.

What is a bit field, and what should you avoid when using one?

A bit field is a struct member with a width in bits. It is useful for flags and hardware registers. Avoid using bit fields for data with a fixed external layout, because the order and packing of bit fields are implementation-defined, and you cannot take the address of one.

Why should you put parentheses around macro parameters?

A macro is text substitution, so without parentheses an argument such as a + 1 joins with the operators around it by normal precedence. Wrapping each parameter, and the whole body, in parentheses keeps the expansion grouped the way the caller intended.

What are the four stages that turn a C source file into an executable?

Preprocessing expands directives such as include and define. Compilation translates the result into assembly. Assembling turns the assembly into an object file. Linking joins object files and libraries, resolves references between them, and writes the executable.

What is an include guard, and why is it needed?

An include guard is a pair of preprocessor lines, an #ifndef test and a matching #endif, around a header's contents. The first include defines a macro name, and later includes skip the block. This stops declarations from appearing twice when several files include the same header.

Why must you check the result of fopen?

fopen returns NULL when the file cannot be opened, for example when it does not exist or permission is denied. Using the NULL pointer in a read or write call is undefined behaviour, usually a crash. Check the result, report the reason with perror, and return an error.

How do you get runtime polymorphism in C?

Store a pointer to a table of function pointers in each object, and call functions through that table. Each object can point to a different table, so the same call runs different code. This is the same mechanism C++ uses for virtual functions.

What is undefined behaviour, and why is i = i++ an example?

Undefined behaviour is code the standard does not define, so the compiler may do anything. The expression i = i++ changes i twice without a sequence point between the changes, so the final value is not defined.

What does the statement sizeof("abc") evaluate to, and why?

It evaluates to 4. A string literal is an array of characters that includes the terminating null character, so three letters plus one terminator make four bytes. Note that strlen("abc") gives 3, because strlen does not count the terminator.

Why does the two-pointer solution to 3Sum start by sorting the array?

Sorting makes the sum of the three values change in a known direction when a pointer moves. If the total is too small, moving the left pointer right increases it. If the total is too big, moving the right pointer left decreases it. Without sorting, moving a pointer would not tell you which way the total changes.

DSA: two pointers

The two pointers technique keeps two indexes into one sequence and moves them according to a rule. The most common version starts one pointer at the left end and one at the right end, then moves them toward each other. Another version has both pointers move forward at different speeds, which is used for cycle detection in linked lists. Both versions share one idea: each step rules out work that can never produce the answer, so the whole scan costs O(n) instead of the O(n^2) of trying every pair.

Two pointers works when you can decide, from the values at the two pointers, which pointer to move. Sorted input often makes that decision obvious. Before you code, ask: if the current pair is too small, which pointer should move to make it bigger? If the answer is clear, two pointers will work.

Pattern to rememberWhen you see a sorted array, a palindrome check, or a pair or triple with a target condition, think of two pointers that close in from both ends.

Valid Palindrome (LeetCode 125)

A phrase is a palindrome if, after you turn every uppercase letter into lowercase and remove every character that is not a letter or digit, it reads the same forwards and backwards. Given a string, return True if it is a palindrome. For example, "A man, a plan, a canal: Panama" is a palindrome, and "race a car" is not.

How to think about it

  1. Understand. Punctuation and spaces are ignored, and case does not matter. An empty string or a string with no letters counts as a palindrome.
  2. Brute force. Build a cleaned copy of the string, then compare it with its reverse. That takes O(n) extra space for the copy and the reverse.
  3. Find the waste. The cleaned copy is not needed. You can compare the original characters directly, skipping the ones you should ignore.
  4. Optimise. Put one pointer at the left end and one at the right end. Skip characters that are not alphanumeric, compare the two, and move both inward. This needs O(1) extra space.
  5. Dry run. Take "ab_a". Left is 0 ("a"), right is 3 ("a"): they match, so move to 1 and 2. Left is "b" and right is "_", which is skipped, so right moves to 1. Left and right now both point to "b", the loop ends, and the answer is True.

Code

def is_palindrome(s):
    left, right = 0, len(s) - 1
    while left < right:
        while left < right and not s[left].isalnum():
            left += 1
        while left < right and not s[right].isalnum():
            right -= 1
        if s[left].lower() != s[right].lower():
            return False
        left += 1
        right -= 1
    return True

print(is_palindrome("A man, a plan, a canal: Panama"))
print(is_palindrome("race a car"))
print(is_palindrome(" "))

False

Time O(n) · Space O(1)

Pattern to rememberWhen you must skip some characters, keep the skip loops inside the main loop and check left < right in each one, so the pointers never cross.

3Sum (LeetCode 15)

Given an array of integers, return all unique triplets of values that add up to 0. Each triplet must be a list of three numbers taken from different positions, and the same triplet must not appear twice. For example, [-1, 0, 1, 2, -1, -4] gives [[-1, -1, 2], [-1, 0, 1]].

How to think about it

  1. Understand. The answer is a list of value triplets, not index triplets, so duplicate values must not produce duplicate triplets. The array can be in any order and can contain repeats.
  2. Brute force. Three nested loops try every triple. That is O(n^3), too slow for large inputs.
  3. Find the waste. Fix the first number, then look for two numbers that add up to the negative of it. That is a pair search, which two pointers solve in one pass once the rest is sorted.
  4. Optimise. Sort the array. For each index i, put left at i + 1 and right at the last index. If the sum is negative, the left value is too small, so move left right. If the sum is positive, move right left. When the sum is 0, record the triplet and move both pointers. Skip repeated values for i, left and right so that each triplet appears once.
  5. Dry run. Sorted, the array is [-4, -1, -1, 0, 1, 2]. With i = 1 (value -1), left starts at 2 (value -1) and right at 5 (value 2). The sum is -1 + -1 + 2 = 0, so [-1, -1, 2] is recorded. Then left moves to 3 (value 0) and right to 4 (value 1). The sum is -1 + 0 + 1 = 0, so [-1, 0, 1] is recorded. Left and right cross, and the loop for i = 1 ends.

Code

def three_sum(nums):
    nums = sorted(nums)
    result = []
    n = len(nums)
    for i in range(n - 2):
        if i > 0 and nums[i] == nums[i - 1]:
            continue                      # skip a first value we have already used
        left, right = i + 1, n - 1
        while left < right:
            total = nums[i] + nums[left] + nums[right]
            if total < 0:
                left += 1
            elif total > 0:
                right -= 1
            else:
                result.append([nums[i], nums[left], nums[right]])
                left += 1
                right -= 1
                while left < right and nums[left] == nums[left - 1]:
                    left += 1
                while left < right and nums[right] == nums[right + 1]:
                    right -= 1
    return result

print(three_sum([-1, 0, 1, 2, -1, -4]))
print(three_sum([0, 1, 1]))
print(three_sum([0, 0, 0]))
[[-1, -1, 2], [-1, 0, 1]]

Container With Most Water (LeetCode 11)

You are given a list of heights, where each value is the height of a vertical line at that index. Choose two lines. Together with the x-axis they form a container, and its capacity is the width (the distance between the indexes) times the smaller of the two heights. Return the largest capacity. For [1, 8, 6, 2, 5, 4, 8, 3, 7], the answer is 49, from the lines of height 8 at index 1 and height 7 at index 8.

How to think about it

  1. Understand. Capacity depends on the shorter line, so a tall line next to a short one gives little water. The answer must be at least 1 when the list has two or more lines.
  2. Brute force. Try every pair of indexes and keep the best area. That is O(n^2) pairs with O(1) work each.
  3. Find the waste. Start with the widest container, the two ends. Its width is the largest possible. Moving a pointer makes the width smaller, so the only way to gain is for the height to grow. The shorter line is the limit, so moving the taller line can never help.
  4. Optimise. Put left at the start and right at the end. Compute the area. Then move the pointer that points to the shorter line inward, because that is the only line that can be replaced by something taller and make progress. This removes one line per step.
  5. Dry run. Heights [4, 3, 2, 1, 4]. Step 1: left 0 (4) and right 4 (4), width 4, area 16. Equal heights, so move right to 3. Step 2: width 3, min(4, 1) = 1, area 3. The shorter line is at right, so move right to 2. Step 3: width 2, min(4, 2) = 2, area 4. Move right to 1. Step 4: width 1, min(4, 3) = 3, area 3. The best area is 16.

Code

def max_area(height):
    left, right = 0, len(height) - 1
    best = 0
    while left < right:
        width = right - left
        h = min(height[left], height[right])
        best = max(best, width * h)
        if height[left] < height[right]:
            left += 1
        else:
            right -= 1
    return best

print(max_area([1, 8, 6, 2, 5, 4, 8, 3, 7]))
print(max_area([1, 1]))
print(max_area([4, 3, 2, 1, 4]))

1
16

Time O(n) · Space O(1)

Pattern to rememberWhen a pair's value depends on a limit that only moves in one direction, start from the widest pair and move the pointer at the limit. Moving the other pointer can never help.

Trapping Rain Water (LeetCode 42)

You are given an elevation map: a list where each value is the height of a bar of width 1. After rain, water stays in the dips between taller bars. Return how many units of water are trapped in total. For [0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1] the answer is 6. For [4, 2, 0, 3, 2, 5] it is 9.

How to think about it

  1. Understand. The water above one bar at index i is the lower of two numbers minus the height at i: the tallest bar to its left and the tallest bar to its right. If that difference is negative, the bar sticks out and holds no water. Each position is independent.
  2. Brute force. For each index, scan left to find the tallest bar, scan right to find the tallest bar, and add min(left, right) minus the height. This is correct and O(n^2) because each index scans the whole array. The code below checks that idea directly on a small input.
  3. Find the waste. The left scan and the right scan repeat the same work for neighbouring indexes. The tallest bar to the left of i only grows as i moves right, so it can be remembered in one number instead of searched again.
  4. Optimise. Keep a left pointer and a right pointer, and remember the highest bar seen so far on each side. Look at whichever end is shorter. Why is that safe? If the left end is shorter than the right end, the highest bar seen on the right is at least the right end, which is taller than the left end. So the water at the left end depends only on the highest bar seen on the left. Process it, then move the pointer. This needs O(n) time and O(1) extra space.
  5. Dry run. Heights [4, 2, 0, 3, 2, 5]. Start with left 0, right 5, left_max 0, right_max 0, total 0. The table shows each step.

Code

def trap_bruteforce(height):
    total = 0
    for i in range(len(height)):
        left_max = max(height[:i + 1])
        right_max = max(height[i:])
        total += min(left_max, right_max) - height[i]
    return total

def trap(height):
    left, right = 0, len(height) - 1
    left_max = right_max = 0
    total = 0
    while left < right:
        if height[left] < height[right]:
            if height[left] >= left_max:
                left_max = height[left]
            else:
                total += left_max - height[left]
            left += 1
        else:
            if height[right] >= right_max:
                right_max = height[right]
            else:
                total += right_max - height[right]
            right -= 1
    return total

print(trap([0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1]))
print(trap([4, 2, 0, 3, 2, 5]))
print(trap_bruteforce([4, 2, 0, 3, 2, 5]))

TrapUpdating the maximum after you use the height gives wrong answers. Compare first, then either update the maximum (the bar is a new peak and holds no water) or add the water (the bar is in a dip). Both branches must use the maximum that was known before the current bar.

Pattern to rememberWhen the answer at each position depends on a maximum from both sides, check which side is the limit. Process the smaller side, because the larger side is already known to be tall enough.

For interviews, state the three approaches in order: brute force O(n^2), prefix maxima in O(n) time and O(n) space, and two pointers in O(n) time and O(1) space. Mention that the two-pointer version is the one to code under time pressure, because it uses the same idea as the prefix approach with less memory.

Summary

Use this list to check your memory. Each entry is one idea from today, stated briefly.

Struct
A named group of members stored in declaration order, with padding between them.
Member access
The dot operator reads a struct value; the arrow operator reads a member through a pointer.
Struct assignment
Assigning one struct to another copies every member, not a reference.
Union
Members share one block of memory; its size is the largest member plus padding.
Tagged union
A union paired with a field that records which member is active.
Enum
Named integer constants; unnamed values count up from the previous one, starting at 0.
Alignment
The requirement that a value's address is a multiple of its size for fast or valid access.
Padding
Unused bytes the compiler inserts to satisfy alignment, inside and at the end of a struct.
Member ordering
Putting larger members first usually reduces padding and struct size.
Bit field
A struct member with a width given in bits, used for flags and register layouts.
Implementation-defined
Behaviour the standard lets the compiler choose, but the compiler must document.
Preprocessor
The first build stage, which expands include, define and conditional directives.
Macro
A text substitution made by the preprocessor, with no type checking.
Include guard
A preprocessor test that stops a header from being processed twice.
Compiler
Translates preprocessed C text into assembly language.
Assembler
Turns assembly into an object file of machine code with unresolved references.
Linker
Joins object files and libraries and resolves their references into an executable.
Undefined reference
A linker error: a name is used but no object file defines it.
FILE pointer
The handle that the standard I/O functions use for an open file.
fopen mode
The string that selects reading, writing, appending and binary mode.
NULL check
Test the result of fopen before using it, and report failures with perror.
Function pointer
A variable that stores the address of a function, called through the pointer.
Method table
A struct of function pointers that objects share, giving runtime polymorphism in C.
Undefined behaviour
Code the standard does not define, so the compiler may do anything with it.
Sequence point
A point where all earlier side effects are finished, which separates the steps of an expression.
Two pointers
A technique that moves two indexes by a rule so each step discards work that cannot help.
